### 3.4 学习过程中的追问（都是"真学会"的痕迹）

- 追问"`dir ..\..\..\第二周\day9\local_api.py` 为什么报找不到路径，明明有啊" → 学会 **PowerShell 相对路径 `..` 的层级要数对**：当前在 `第三周\day15`，`..` 到 `第三周`、`..\..` 才到仓库根 `大模型算法`（`第二周`/`第三周` 在这一层平级），所以只需两个 `..`、教程里写了三个（多跳到了 `技术学习`）→ 已修正教程该行；顺带学会"数 `..` 看共同父目录"的口诀；
- 追问"跑 ask.py 出来的怎么不是中文，是有问题还是正常" → 判断为**功能完全正常、链路已跑通**（乱码可按 UTF-8 被 GBK 误读还原出"服务端模型 = Qwen2.5-3B-Instruct-LoRA ✅ 与 profile 一致"【答案】"资料中没有提到"等关键信息）——根因是 `ask.py` 输出端强制 UTF-8、而 PowerShell 控制台显示端是 GBK（cp936）→ 学会"**输出端与显示端编码不匹配**"的判定逻辑与修法 `chcp 65001`；并识别出 `Tee-Object` 走的管道同样被 GBK 解码（日志文件也会乱码），需重存一份；
- 追问"`git check-ignore` 没输出，是对的吗" → 学会 `git check-ignore` 的**路径参数相对当前目录解析**：在 `day15` 里写 `第三周/day13/chroma_db` 会被拼成 `day15\第三周\...` 而匹配不上（无输出、exit=1）；回仓库根执行或写 `../day13/chroma_db` 才有输出——并实测验证了四种写法的差异，已把提醒补进教程 7.2；
- 追问"Day14 那条 commit 提示 no changes added to commit 是成功了吗" → 学会 git **拒绝空提交**的判定（成功标志是 `[main xxxxxx]` 行）；核实 Day14 遗留早已由 `3d82331` 单独提交，工作区无改动可提 → 无害，且证明 gitignore 生效后没有大文件混入。
