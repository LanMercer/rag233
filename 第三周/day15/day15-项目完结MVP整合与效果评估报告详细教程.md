> 对应《02-项目完结冲刺计划》Day15 第 1 条："把 `ask.py` 的 `API_URL` / `MODEL_NAME` 抽成配置文件（或命令行参数），支持一键切换'原模型 / 微调模型'"。
> 一句话：**把"变量"从代码里搬出去，代码从此只写"流程"**。这是你简历里能写"工程化"的第一个关键词——配置驱动。

### 1.1 先自己想：如果让你改 day10 的 ask.py，怎么支持"用不用微调模型"？

不急着看文件，先想 5 分钟。Day10 `ask.py` 的配置区长这样（写死的）：

```python
API_URL = "http://127.0.0.1:8000/v1/chat/completions"
MODEL_NAME = "Qwen2.5-3B-Instruct"   # 想换成 LoRA 就得改这一行代码
```

而"原模型"和"微调模型"其实是**两个不同的服务**（day9 的 `local_api.py` 和 day13 的 `local_api_lora.py`），它们轮流占用 8000 端口（6G 显存一次只能跑一个 3B）。所以"一键切换"的本质是：

- 服务层：停掉 A 服务、启动 B 服务（人来做，端口就一个）；
- 问答层：让 `ask.py` 知道"我现在该按哪个模型的名字去请求"（脚本要做的）。

最简单的实现：把 `MODEL_NAME`（以及 `TOP_K`、`TEMPERATURE` 等）挪到一个 JSON 文件里，准备两份配置（一份原模型、一份微调模型），脚本启动时用 `--profile` 选哪份。

> 数学视角：这就像统计建模时"把假设写清楚、参数和代码分开"——**配置 = 可复现实验的"参数记录"**。面试官问"你怎么控制变量做对比"，你可以答"同一份代码 + 两套配置文件 = 一次只换一个变量的实验"。

### 1.2 精读 config.json（MVP 的"参数面板"）

打开 `config.json`，对照下面逐块看：

```json
{
  "default_profile": "lora",
  "demo_questions": [
    "论文中 GMR 与哪些方法进行了对比？",
    "论文的实验在哪个数据集上进行？",

    "lora":     { "label": "微调模型（Qwen2.5-3B-Instruct-LoRA）", "model_name": "Qwen2.5-3B-Instruct-LoRA", "..." }
  }

```

- `default_profile`：不传 `--profile` 时默认用哪个（默认 lora = 微调模型，这是项目的"主角"）；
- `demo_questions`：冒烟用的 3 条题——2 条资料内（GMR 对比了谁 / 实验在哪个数据集）+ 1 条资料外（华为是否采用 GMR，考防幻觉），**两条链路用同一组题 = 控制变量**；
- `persist_dir`：相对路径 `../day13/chroma_db`，由 `ask.py` 的 `resolve_path()` 解析成绝对路径——配置文件里也**不写死绝对路径**，整个文件夹挪走也能跑；
- `embed_model`：本地 bge 路径（注意 JSON 里用的是正斜杠 `/`，Windows 也认），必须和建库时一致；
- `profiles.original / lora`：两个"模型档案"，每个含 `label`（给人看的说明）、`model_name`（请求接口时写的模型名）、`top_k`、`temperature`、`api_url`（两个都是同一个 8000 端口）。

**注意一个细节**：`api_url` 两个 profile 是**同一个地址**（都是 `http://127.0.0.1:8000/v1/chat/completions`）——因为两个服务是"轮流占同一个端口"。所以切换的真正动作 = ① 换服务（停一开一）＋ ② 让 ask.py 知道用哪个模型名（`--profile`）。

### 1.3 精读 ask.py：和 day10 比，改了哪三处？（40 分钟精读）

`ask.py` 与 day10 的 `rag_demo/ask.py` 相比，**检索逻辑、模板 09、生成调用一行没动**，只改了配置的"来源"。重点看三处新增：

**改动一：配置从"写死"变成"读文件"（第 2 区）**

```python
SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
CONFIG_PATH = os.path.join(SCRIPT_DIR, "config.json")

def load_config():
    with open(CONFIG_PATH, encoding="utf-8") as f:
        return json.load(f)

def resolve_path(p):
    if os.path.isabs(p):
        return p
    return os.path.normpath(os.path.join(SCRIPT_DIR, p))
```

- `os.path.abspath(__file__)`：拿到本脚本的绝对路径，再取它的目录 = `SCRIPT_DIR`。这样不管你在哪个盘符哪个目录运行，都按"脚本自己所在位置"去找配置文件——**不依赖"当前在哪个目录"**；
- `load_config()`：把 `config.json` 读成一个 Python 字典（`encoding="utf-8"` 是因为配置里有中文）；
- `resolve_path()`：配置里 `../day13/chroma_db` 是相对路径（相对 day15 目录），运行时拼回绝对路径 `第三周\day13\chroma_db`。

**改动二：加了一个"服务身份检查"（第 5 区）——Day14 踩坑的代码化**

```python
def check_server(api_url, expected_model):
    base = api_url.rsplit("/v1/chat/completions", 1)[0]
    r = requests.get(base + "/v1/models", timeout=10)
    served = r.json()["data"][0]["id"]
    if served == expected_model:
        return True, f"服务端模型 = {served} ✅ 与 profile 一致"
    return False, f"⚠ 服务端模型 = {served}，但 profile 要求 = {expected_model}。..."
```

Day14 你踩过一个坑：8000 端口被**残留的原模型服务**占着，评测差点用错模型。今天把这个教训写进代码——ask.py 开跑前先 GET 一次 `/v1/models`（这个接口会返回服务端**真实加载的模型名**），和 `--profile` 要求的不一致就直接停下提醒。从此"服务在跑 ≠ 服务正确"这个坑不用靠人肉记了。

> 追问一句：为什么 GET `/v1/models` 能拿到真实模型名，而 POST 响应里的 `model` 字段不行？——因为接口代码是"把请求里的 model 名回显回去"（`"model": request.model`），你写啥它回啥；而 `/v1/models` 的 `data[0].id` 用的是服务端常量 `MODEL_NAME`（加载时写死的）。所以**验身份看** `/v1/models`**，别看响应回显**（day13 冒烟记录里强调过）。

**改动三：main() 里按 --profile 选配置（第 7 区）**

```python
parser = argparse.ArgumentParser(...)
parser.add_argument("--profile", default=None, ...)
parser.add_argument("questions", nargs="*", ...)
args = parser.parse_args()

cfg = load_config()
profile_name = args.profile or cfg.get("default_profile", "lora")
profile = cfg["profiles"][profile_name]
```

- `argparse` = Python 自带的"命令行参数解析器"，`python ask.py --profile original` 里的 `--profile original` 就是靠它读进来的；
- `args.profile or cfg["default_profile"]`：没传 `--profile` 就用配置文件里的默认（lora）；
- `args.questions`：命令行剩下的位置参数当"自定义问题"，不填就跑 `demo_questions` 那 3 条。

其余部分（`load_store`、`ask_one` 里的 `similarity_search_with_relevance_scores`、模板 09 拼接、POST 生成、打印 Top-K + 答案）和 day10 完全同源——**你精读过的代码，今天只是换了"参数从哪来"**。

### A. 力扣 34. 在排序数组中查找元素的第一个和最后一个位置（中等 · 二分边界 · 必做进阶）

**题目**：升序数组 `nums` 可能含重复值，给定 `target`，返回它的第一个和最后一个下标；不存在返回 `[-1, -1]`。

**思路**：Day14 你做了 35（找第一个 `≥ target` 的位置 = `bisect_left`）。34 就是它的"左右两次应用"——用两个二分分别找 `nums[i] >= target` 的分界（第一个 target）和 `nums[i] > target` 的分界（最后一个 target + 1），再判断 target 存不存在。

**数学视角**：定义两个单调谓词——`P1(i) = (nums[i] >= target)` 和 `P2(i) = (nums[i] > target)`。二分能找边界的前提是**谓词单调**（假假假…真真真）。`P1` 第一次变真的位置 = 左边界；`P2` 第一次变真的位置 = 右边界右一格。**"数组排好序" = 谓词天然单调**，这正是 34 能用两次二分解的原因；把边界逻辑各包一个 `bisect_left`，比裸写 while 更不容易错。

```python
class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def bisect_left(k: int) -> int:      # 第一个 >= k 的位置（等价于 python 的 bisect_left）
            lo, hi = 0, len(nums)
            while lo < hi:
                mid = (lo + hi) // 2
                if nums[mid] < k:
                    lo = mid + 1
                else:
                    hi = mid
            return lo

        left = bisect_left(target)                     # P1: nums[i] >= target 的分界 = 第一个 target
        if left == len(nums) or nums[left] != target:  # target 不存在
            return [-1, -1]
        right = bisect_left(target + 1) - 1            # P2: 第一个 > target 的位置 - 1 = 最后一个 target
        return [left, right]
```

**复杂度**：两次二分，O(log n) 时间、O(1) 空间。

### B. 力扣 69. x 的平方根（简单 · 牛顿法 / 二分 · 数学加成题 ⭐）

**题目**：非负整数 `x`，返回整数平方根（向下取整，如 `sqrt(8)=2`）。要求不调内置 `sqrt`。

**思路一（二分，稳）**：找最大的 `m` 使 `m² ≤ x`。等价于在 `[0, x]` 上找谓词 `P(m) = (m² > x)` 第一次变真的位置减 1——和 34/35 同一个框架。

**思路二（牛顿法，数学主场）**：求 `sqrt(x)` = 求方程 `f(t) = t² − x = 0` 的正根。牛顿迭代公式：

```
t_{n+1} = t_n − f(t_n)/f'(t_n) = t_n − (t_n² − x)/(2t_n) = (t_n + x/t_n)/2
```

从 `t₀ = x` 出发迭代，每次把 `t_n` 换成"它和 `x/t_n` 的平均数"。为什么收敛快？在根附近 `f` 近似线性，一步就把误差从 ε 压到约 ε²——**二次收敛**：精度每轮翻倍，通常几步就到机器精度。这在面试里是"数学思维加分"的招牌讲法。

```python
class Solution:
    def mySqrt(self, x: int) -> int:
        if x < 2:
            return x
        # 牛顿法：先算实数根近似（float 精度足够），再向下取整修正
        t = float(x)
        while True:
            nt = (t + x / t) / 2        # 牛顿迭代：中点 = 新估计
            if abs(nt - t) < 1e-7:      # 收敛（相邻两步差足够小）
                break
            t = nt
        r = int(t)
        while r * r > x:                # 浮点误差兜底：向下修正
            r -= 1
        while (r + 1) * (r + 1) <= x:   # 兜底：如果还能加就加
            r += 1
        return r
```

**数学视角一句话**：牛顿法 = 用**切线**逐步逼近根——每次在当前估计点做一阶泰勒展开、找切线与 x 轴交点作为新估计；离根近时误差按平方速度收缩（二次收敛），所以"几轮就够"。而二分法每次只砍一半（线性收敛，但绝对稳健）。**面试讲牛顿法重点讲二次收敛**，能推导 `t_{n+1} = (t_n + x/t_n)/2` 就更稳。
