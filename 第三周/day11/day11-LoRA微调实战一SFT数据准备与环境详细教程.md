## 🧱 第 1 步：概念先行——SFT / QLoRA / PEFT（30~40 分钟）

> 对应周计划 8/15 第 1 条："概念先行（新名词必带简介）"。今天的三个新名词是进入微调实操的门票，每个都要能"一句话大白话"讲出来。

### 1.1 三个核心名词（新名词必带简介）

- **SFT = Supervised Fine-Tuning（监督微调）** = 用"问题-答案"配对数据把预训练模型再训一遍，让模型学会特定风格/能力。**一句话**：拿标准答案教模型"这种题该这么答"，就像带实习生——预训练（通用常识）是大学文凭，SFT（配对数据训练）是入职培训。
  - 为什么"监督"？因为我们给模型的每条数据都带**标准答案（output）**，模型答错了就按答案纠正——这是有老师看着的"监督学习"（Supervised Learning，带标签的学习），区别于无监督。
  - 概率语言：SFT 就是在调整 `P(答案 | 问题)` 这个条件概率分布，把它从"大而平"（什么都会一点）收成"小而尖"（专攻你的领域）。你 Day 7 学的 few-shot 是"现场示范几例"，SFT 是"直接把分布改掉"——更彻底。

- **QLoRA = Quantized LoRA（量化版 LoRA）** = 4bit 量化底座 + 低秩适配器（LoRA），让 6G 显存也能微调 3B 模型。**一句话**：先把模型压成 4bit 精度的"瘦身版"（省显存），再在它旁边挂一个很小的可训练适配器（省参数），双管齐下。
  - 拆开看：**Quantized（量化）** = Day5 学的把参数从 16bit 压到 4bit（NF4 格式）；**LoRA（低秩适配）** = Day5 学的只训练低秩增量 B·A。QLoRA = 两个"省"叠加。
  - **为什么 6G 能跑**：3B 模型 4bit 底座权重约 1.54GB（Day5 测算表），加上激活值/梯度的开销，训练时再算上 LoRA 的小参数（只占 0.084%），6G 显存刚好够。**全量微调 3B 直接爆显存**（第 3 周避坑表第 1 条）。

- **PEFT = Parameter-Efficient Fine-Tuning（参数高效微调）** = HuggingFace 的高效微调工具箱，LoRA/QLoRA 都从这个库里配置。**一句话**：一个"只训少量参数就把模型调好"的工具箱，LoRA 只是它支持的一种方法。
  - 你只需要知道：微调脚本里 `from peft import LoraConfig, get_peft_model` 就是从 PEFT 库拿工具，Day12 用。PEFT 还支持 Prefix-Tuning、P-Tuning 等别的方法，面试知道"PEFT 是个家族，LoRA 是其中最常见的一种"即可。

> 一句话串起来：**SFT 是"怎么训"（用配对数据监督训练），PEFT 是"从哪拿工具"（高效微调工具箱），QLoRA 是"用哪种省钱方案"（4bit 量化 + LoRA 适配器）。三者关系：用 PEFT 的工具，走 QLoRA 的方案，做 SFT 这件事。**

### 1.2 为什么微调"风格/能力"，而 RAG 管"事实"？（本周心法，面试必答）

| 对比 | RAG（第二周已跑通） | 微调（本周开始） |
| ---- | ----------------- | ---------------- |
| 管什么 | **事实性资料**：最新研报、私有 PDF | **风格/能力**：机器人口吻、专业术语、会算账 |
| 改什么 | 不改模型参数，临时拼资料 | 改模型参数（LoRA 适配器） |
| 更新速度 | 加一段资料立刻生效 | 要重新训练（小时级） |
| 项目里分工 | "答对" | "答得像" |

> **一句话记忆**：RAG 是"考试带资料进考场翻书"，微调是"平时把套路练进肌肉记忆"——两者配合就是项目的完整形态。这也是本周心法：**RAG 管事实、微调管风格，缺一不可。**

### 1.3 顺便复习两个"老朋友"（Day5/周报提过，现在正式对上）

- **LoRA = Low-Rank Adaptation（低秩适配）** = 冻结底座权重 W0，只训练两个小矩阵 B·A，让 `W = W0 + B·A`。微调的"改动量 ΔW"在真实场景里是低秩的（奇异值谱衰减快），用秩 r 的小矩阵就能几乎无损表达。参数账：`d² → 2dr`，节省 `1 - 2r/d`，Qwen2.5-7B（d=3584, r=8）省 **99.55%**。
- **灾难性遗忘（Catastrophic Forgetting）** = 完整微调把旧知识冲掉了（Day5 demo 里任务 A 误差 0 → 3.93 那个例子）。LoRA 因为只改低秩增量、保留底座，天然更不容易忘。微调后如果模型"说胡话"，先查数据质量（避坑表）。

### 3.1 先懂 SFT 数据长什么样（10 分钟）

SFT 数据标准格式是 JSON 三字段，每条长这样：

```json
{
  "instruction": "请从以下埃斯顿的年度报告中，提取营业收入的数据。",
  "input": "埃斯顿发布年度报告。报告期内公司营业收入为 69.5 亿元，同比增长3.2%。截至2023年末，公司订单金额达到 556.0 亿元。",
  "output": "埃斯顿2023年营业收入为 69.5 亿元，同比增长3.2%。"
}
```

| 字段 | 是什么 | 类比 |
| ---- | ------ | ---- |
| `instruction` | **指令**：告诉模型要做什么（"请提取…""请总结…""请计算…"） | 上司派活 |
| `input` | **输入材料**：任务需要看的内容（公告原文、研报摘要）；没有材料就留空 `""` | 派活时给的资料 |
| `output` | **标准答案**：期望模型输出的内容 | 干活的交付结果 |

> 概率语言：每条数据都是在教模型 `P(output | instruction + input)`——**固定的"问法 → 答案"映射**。数据里问法越多样，模型学会的分布越"尖"；答案越标准，分布越"准"。

**自己动手造 300 条，用代码模板生成**（不是手写）：写一个生成脚本，从语料池（公司名、指标、公告类型…）里随机组合出各种指令，再按模板拼出标准答案。好处：① 条数足（300 条落在 200~500 区间）；② 格式绝对统一（不会手滑漏字段）；③ 可复现（固定随机种子，每次跑结果一样，方便验收）。

### A. 力扣 912. 排序数组（中等 · 快排）⭐ 必做

**题目**：给你一个整数数组 `nums`，请你升序排列它（要求实现排序算法，面试常考快排/归并）。

**快排思路（Quick Sort，分治）**：选一个基准（pivot），把比它小的放左边、比它大的放右边，然后递归两边。今天用**原地快速排序**（in-place，不用额外大数组）：

**数学视角**：快排每次把区间分成"小/基准/大"三段，递归深度期望 O(log n)——**期望 O(n log n)**。为什么是"期望"？因为基准选得随机时，每次划分"运气"好的期望是平衡的（一半一半），这是**随机化算法**的典型分析（`E[深度] = O(log n)`）。最坏 O(n²) 只在"每次基准都恰好是最大/最小"时出现——现实中极难发生。

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        import random
        def quick(l, r):
            if l >= r:
                return
            pivot = nums[random.randint(l, r)]   # 随机选基准，避免最坏情况
            i, j = l, r
            while i <= j:
                while nums[i] < pivot: i += 1     # 左边找 >= pivot 的
                while nums[j] > pivot: j -= 1     # 右边找 <= pivot 的
                if i <= j:
                    nums[i], nums[j] = nums[j], nums[i]  # 交换
                    i += 1; j -= 1
            quick(l, j); quick(i, r)              # 递归左右两段
        quick(0, len(nums) - 1)
        return nums
```

**复杂度**：期望 O(n log n) 时间、O(log n) 栈空间（递归深度）。

### B. 力扣 215. 数组中的第 K 个最大元素（中等 · 快速选择）⭐ 概率加成题

**题目**：在未排序的数组中找到第 K 个最大的元素。（K 从 1 开始，即第 1 大是最大值）

**快速选择思路（Quick Select）**：快排的"只进一边"版本——每轮随机选基准做分区，得到基准的位置 p：
- p 正好是第 K 个 → 返回它；
- p 在 K 左边 → 答案在右半区，只递归右边；
- p 在 K 右边 → 只递归左边。

**数学视角（概率加成，必讲）**：期望时间 **O(n)**——为什么？每次分区只走一边，且随机基准使两边"期望对半"，所以总工作量是 `n + n/2 + n/4 + ... = 2n = O(n)`（等比级数求和，你的数学强项）。最坏 O(n²)（每次都切最差的一边，几乎不可能随机发生）。

```python
class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        import random
        k = len(nums) - k          # 第 K 大 = 第 (n-K) 小（0 基）
        def quick_select(l, r):
            pivot = nums[random.randint(l, r)]
            i, j = l, r
            while i <= j:
                while nums[i] < pivot: i += 1
                while nums[j] > pivot: j -= 1
                if i <= j:
                    nums[i], nums[j] = nums[j], nums[i]
                    i += 1; j -= 1
            if k < i and k > j:    # 基准正好落在这个缺口 = 找到了
                return pivot
            if k <= j:             # k 在左半段
                return quick_select(l, j)
            return quick_select(i, r)  # k 在右半段
        return quick_select(0, len(nums) - 1)
```

**复杂度**：期望 O(n)、最坏 O(n²)；空间 O(log n)。

### C. 统计八股：评估指标复习（10~15 分钟）

> 对应第三周计划 8/15："评估指标复习：精确率 / 召回率 / F1 / AUC 的适用场景 + 混淆矩阵回顾（衔接 RAG 评测）。"你在第二周 Day7/Day8 学过这些，今天**快速过一遍并和 RAG 评测接上**（Day14 写 `eval.py` 时会用到）。

**混淆矩阵（Confusion Matrix）**——一切评估指标的地基，四格背熟：

| 预测 \ 真实 | 正类 (P) | 负类 (N) |
| ----------- | -------- | -------- |
| 预测正类 | TP（真阳，对了） | FP（假阳，误报） |
| 预测负类 | FN（假阴，漏报） | TN（真阴，对了） |

**三个核心指标（公式背熟）**：

| 指标 | 公式 | 大白话 | 什么时候用 |
| ---- | ---- | ------ | --------- |
| 精确率 Precision | TP / (TP+FP) | 预测为正的里面，有多少真对 | 误报代价高（如垃圾邮件拦截） |
| 召回率 Recall | TP / (TP+FN) | 真正的正类里，捞回多少 | 漏报代价高（如癌症筛查、RAG 检索召回） |
| F1 | 2×P×R / (P+R) | 精确率和召回率的**调和平均** | 两者都重要、取平衡 |

> **调和平均 vs 算术平均（数学视角）**：F1 用调和平均 `2/(1/P + 1/R)`，因为它对"一个指标特别低"更敏感——P=1、R=0 时算术平均 0.5 显得还行，但调和平均是 0（直接露馅）。这正是统计里"调和平均惩罚不均衡"的思想。

**AUC（Area Under the ROC Curve）**：ROC 曲线下面积，衡量"模型把正类排在负类前面的能力"，取值范围 [0.5, 1]。0.5 = 瞎猜，1 = 完美排序。**概率口径**：AUC = 随机抽一个正样本、一个负样本，正样本得分高于负样本的概率 `P(正分 > 负分)`（Day7 你证明过 0.833 那个例子）。

**和 RAG 评测怎么接（提前预告，Day14 落地）**：
- **检索层**：对 20 条评测问题，看"正确答案是否被 Top-K 召回"——这就是召回率（Recalled at K）；检索结果里无关片段占多少 = 精确率；
- **生成层**：答案正确率、F1 等；
- **数学加成**：RAG 检索本质是排序问题，`命中率` 就是"top-K 里有没有真答案"，这正是指标的直接落地。

> 面试加分句式："评估指标的核心是先把混淆矩阵四格摆清楚，Precision 管误报、Recall 管漏报、F1 用调和平均惩罚不均衡，AUC 则是从排序角度衡量正负样本的可分性——在 RAG 项目里，我用 Recall@K 衡量检索层是否捞回正确答案。"
