## 三、每日详细学习内容

### 8/15 周六 · LoRA/QLoRA 微调实战（一）：SFT 数据准备 + 环境

**主线（4~5h）：**
1. **概念先行（新名词必带简介）**：
   - **SFT** = Supervised Fine-Tuning，监督微调 = 用"问题-答案"配对数据把模型再训一遍，学会特定风格/能力；
   - **QLoRA** = 量化版 LoRA = 4bit 量化底座 + 低秩适配器，6G 显存也能微调 3B 模型；
   - **PEFT** = Parameter-Efficient Fine-Tuning 库，HuggingFace 的高效微调工具箱（LoRA/QLoRA 都从这里配）。
2. **回顾 LoRA 数学**（第一周 Day5 储备）：低秩增量 `ΔW = B·A`、参数账 99.55%、灾难性遗忘实验，重跑 `lora_math_demo.py` 热个身。
3. **自制 SFT 数据**：写 `make_sft_data.py` 生成 **200~500 条中文"指令-回复"数据**（JSON 三字段 `instruction / input / output`），题材与项目领域一致（机器人行业公告 / 研报问答），一鱼两吃：既是微调数据，又是项目能力。
4. **环境检查**：`transformers / peft / bitsandbytes / accelerate / datasets`（+ trl 或 Qwen 官方微调脚本）版本核对，Windows + 6G 显存确认 QLoRA 方案可行。
5. **验收**：`datasets` 能正确加载自制数据（字段 / 条数 / 抽样打印），能讲清 SFT 三字段含义与"LoRA 为什么省显存、省参数"。

**零散时间：** 力扣 912、215（排序）｜ 统计八股：评估指标复习
**产出：** `sft_data.json`（200~500 条）+ `make_sft_data.py` + 数据检查脚本

### 8/16 周日 · LoRA/QLoRA 微调实战（二）：跑通微调训练

**主线（4~5h）：**
1. 写微调脚本 `train_lora.py`，**文件头写清五件套**：模型=Qwen2.5-3B-Instruct + QLoRA（r=8, alpha=16）、数据=自制 SFT 数据、损失=交叉熵（LM loss）、优化器=AdamW + 学习率 1e-4~2e-4、训练=若干 epoch + 验证集观察 loss。
2. **PEFT 配置**：`LoraConfig`（r / alpha / dropout / target_modules）+ `BitsAndBytesConfig`（4bit nf4，复用第二周部署配置）+ `get_peft_model`。
3. **训练并观察**：`torch.cuda.memory_allocated()` 盯显存（6G 预算内），观察 loss 下降；训完**只保存 adapter**（`save_pretrained` 到 `lora_adapter/`，不是全量模型）。
4. **效果对比**：加载"原模型" vs "原模型 + adapter"，同一组 3~5 个测试问题对比输出 → 产出**微调前后效果对比表**。
5. **验收**：对比表至少 3 个问题有肉眼可见差异；能讲清"LoRA 只存 adapter、推理时合入权重"与本周参数账 / 显存账。

**零散时间：** 力扣 56、75（排序应用）｜ 统计八股：交叉验证
**产出：** `train_lora.py` + `lora_adapter/`（权重不进 git，另行说明）+ `微调前后效果对比表.md`

### 8/17 周一 · 项目主线开发（一）：项目定性与架构定型

**主线（4~5h）：**
1. **项目定性**：垂直领域 RAG 问答系统——领域定为"机器人行业"（方向建议，可换自己的领域）；**明确 MVP 边界**：不做多轮对话、不做并发、不做前端花活，小而完整。
2. **架构定型**：四层组件各司其职——Qwen（生成层）+ 微调 adapter（风格/能力层）+ `rag_demo/`（检索层）+ 模板库 v2（答案组织层）→ 画**项目架构图**（参考 day10 `draw_rag_structure.py` 改）。
3. **数据组织**：确定知识库资料（机器人行业研报 / 技术文档 / 论文 PDF，复建库脚本）；准备 **20 条评测问题集**（两类各半："资料内有答案" + "资料外/反事实"，为后天评测铺路）。
4. **接口切换**：把微调后的模型接入 day9 `local_api.py`（换模型路径 + 加载 adapter），确认 `/v1/chat/completions` 依旧兼容（curl 冒烟测试）。
5. **验收**：架构图成型、评测问题集 ready、切换微调模型后问答仍通。

**零散时间：** 力扣 104、226（递归）｜ 统计八股：特征工程
**产出：** 项目架构图（png）+ 评测问题集（20 条）+ 接口切换冒烟测试记录

### 8/18 周二 · 项目主线开发（二）：检索调优 + 效果量化

**主线（4~5h）：**
1. **检索调优**：`TOP_K`（4→8）、`chunk_size`（500 vs 800）、Embedding 模型（`bge-small-zh` 基线 vs 候选）三组变量跑 2~3 组对比，看对答案质量的影响。
2. **生成调优**：temperature / top_p、prompt（模板 09 基线 → 针对项目领域迭代），看对"格式合规 / 事实准确"的影响。
3. **统计量化（本周数学主场）**：写 `eval.py`——对 20 条评测问题分别算**检索层**（命中率 = 正确答案是否被 Top-K 召回，可算精确率 / 召回率）与**生成层**（规则或人工判分，正确率 / F1），产出量化表格。
4. **防幻觉复测**：资料外问题是否如实答"资料中没有提到"（复用模板 09 约束链路）。
5. **验收**：2~3 组调优实验有数字对比；首版评测表跑出（检索命中率 + 生成正确率）。

**零散时间：** 力扣 704、35（二分）｜ 统计八股：样本不均衡
**产出：** `eval.py` + 调优实验记录 + 首版评测表

## 五、本周常见坑位与避坑

| 坑位 | 应对 |
|---|---|
| 6G 显存微调 3B 全量爆显存 | 只用 QLoRA（4bit 底座 + adapter）；关浏览器等占显存程序；必要时 `gradient_accumulation_steps` 摊薄显存峰值 |
| peft / bitsandbytes 版本不匹配报错 | `pip show` 核对版本，按 transformers / PEFT 官方兼容矩阵安装 |
| 微调后模型"说胡话"（灾难性遗忘 / 能力退化） | 优先检查数据质量与数据量（≥200 条）；r 别太大、学习率别太高；可混入少量通用指令数据保底 |
| 训练 loss 不降 | 检查三字段格式（`instruction/input/output`）、学习率区间（1e-4~2e-4）、确认真加载了 4bit 底座 |
| 误把 adapter 存成全量模型 | PEFT 保存的是 adapter（`adapter_config.json` + safetensors），不要 `save_pretrained` 整个模型 |
| 加载 adapter 报错 | 用 `AutoPeftModelForCausalLM` 或"先加载同款基座再 `load_adapter`"；基座与训练时保持同款量化配置 |
| 检索效果差 / 答非所问 | 对比 TOP_K（4→8）、chunk_size（500 vs 800）、Embedding 模型 2~3 组；先单独验证 Embedding 输出 |
| 评测没数字、全靠感觉 | 固定"20 条问题 + 命中判定规则"，先出基线再优化，一切用数字说话 |
| 生成仍幻觉 | 模板 09 约束（资料没提到就说没有）+ 温度调低 + 检索片段带段落号强制引用出处 |
| 微调模型接入接口后格式不对 | 复用 day9 `local_api.py` 的 ChatML 拼装逻辑，换模型路径前先 curl 冒烟测试 |
