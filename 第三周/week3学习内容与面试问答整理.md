### 1.2 全周知识链条（一段话串讲，用概率语言）

微调 = **把通用底座往你的任务方向拧**：SFT 用 300 条"问题-答案"配对数据（instruction/input/output 三字段）调整 `P(答案|问题)`，把分布从"大而平"收成"小而尖"（管"答得像"）；实现上走 QLoRA（4bit 量化底座 + LoRA 低秩适配器，PEFT 工具箱配置），**只训 0.4827% 的参数**、3 epoch、只存 20~30MB adapter，推理时 `W = W0 + B·A` 合入——改动量 ΔW 低秩所以小参数够用、天然抗灾难性遗忘。

项目 = **"机器人行业垂直领域 RAG 问答系统"**：把第二周的 RAG demo 产品化。四层解耦——检索层（Chroma + bge + Top-K，管"找到段落"）、答案组织层（模板 09，管"只依据资料 + 带 [资料§N] 出处 + 没有就直说"）、生成层（Qwen2.5-3B 4bit）、风格层（LoRA adapter，管"像行业专家"）。数学视角：`P(答案|问题) ≈ P_生成(答案 | 模板09(检索(问题)))`——**端到端条件概率分解成逐层条件概率**，每层独立调优、出错能定位到层。

评测 = **先定口径再报数**：20 条题（资料内 10 + 资料外 10），三组指标——检索层命中率 = 答案段落是否被 Top-K 召回（**Recall@K**）、生成层正确率 = 资料内关键词命中、防幻觉正确率 = 资料外如实拒答，外加**防幻觉 F1**（把"该不该拒答"当二分类算混淆矩阵）。首版基线：检索 2/10=20%、生成 2/10=20%、防幻觉 6/10=60%、总 8/20=40%、F1=0.667（P=0.75/R=0.60）——**数字不高，但每个低都能归因到具体层**（主瓶颈 = 检索召回），这正是四层架构的回报。规则判分 + 人工复核（MANUAL_FIXES）双保险保证数字诚实。

完结 = **把项目做成"可投"**：`config.json` + `ask.py --profile` 一键切换原模型/微调模型（配置驱动 + 服务身份检查防"服务在跑≠服务正确"）；README + 效果评估报告 + 面试四问 + 简历数字回填；对照"完结验收 5 条"（能演示/能量化/有文档/有报告/已存档）全部 ✅。

### 模块 A：微调基础概念（Day 11）

**Q1. 什么是 SFT？和预训练有什么区别？**
> SFT（Supervised Fine-Tuning，监督微调）= 用"问题-答案"配对数据把预训练模型再训一遍，让模型学会特定风格/能力。区别：预训练在海量通用文本上学"语言先验"（大学文凭），SFT 用小而精的配对数据学"这个领域该这么答"（入职培训）；预训练是无监督/自监督，SFT 是**带标准答案的监督学习**。
> [数学加分] SFT 就是在调整 `P(答案|问题)` 条件分布，从"大而平"（什么都会一点）收成"小而尖"（专攻领域）；few-shot 是"现场示范几例"（推理时临时给示例），SFT 是"直接把分布改掉"（训练时永久改参数）——更彻底。

**Q2. QLoRA 是什么？为什么 6G 显存能微调 3B？**
> QLoRA = 4bit 量化底座 + LoRA 低秩适配器，两个"省"叠加：4bit（NF4）把底座权重压到约 1/4 显存，LoRA 只训练低秩增量 B·A（我的实测只训 0.4827% 参数），激活/梯度开销小 → 6G 显存刚好够。全量微调 3B 直接爆显存。
> [数学加分] 微调改动量 ΔW 是低秩的（奇异值谱衰减快），所以用 r=8 的小矩阵 B·A 就能表达——参数从 d² 降到 2dr；改动少 = 保留底座知识 = 天然抗灾难性遗忘。

**Q3. PEFT 是什么？和 LoRA 什么关系？**
> PEFT（Parameter-Efficient Fine-Tuning）= HuggingFace 的高效微调工具箱，LoRA/QLoRA 都从它配置（`from peft import LoraConfig, get_peft_model`）。**PEFT 是个家族，LoRA 是其中最常见的一种**（还有 Prefix-Tuning、P-Tuning 等）。
> 一句话串三者：**用 PEFT 的工具、走 QLoRA 的方案、做 SFT 这件事**。

**Q4. 为什么说"RAG 管事实、微调管风格"？（本周心法，必答）**
> RAG 管事实性资料：最新研报/私有 PDF，不改参数、加一段资料立刻生效、答案带出处——管"答对"；微调管风格/能力：行业口吻、术语、回答格式，但改参数、更新要重新训练——管"答得像"。类比：RAG = 考试带资料进考场翻书，微调 = 平时把套路练进肌肉记忆。我项目里 QLoRA 负责"像机器人行业专家说话"，RAG 负责"别答错别编造"，两者缺一不可。

**Q5. 微调数据怎么准备？你造的数据长什么样？**
> 三字段 JSON：`instruction`（指令）/ `input`（需要看材料的原文，解释/计算类留空）/ `output`（标准答案）。我造了 **300 条机器人行业公告/研报问答**（20 家产业链公司 + 行业术语语料池），6 类任务：公告信息抽取 61 / 研报观点问答 72 / 要点总结 57 / 数据计算 44 / 合规判断 44 / 概念解释 22。
> [数学加分] 数据三原则：① **领域对齐**（微调数据要和项目语料同领域，我特意从建议的"金融"改成"机器人行业"，与 GMR 论文一致）；② **质量 > 数量**（200~500 条就够，三字段规范 + 去重 + 无空值，监督信号充分即可）；③ **去重**（完全重复会被重复学习放大偏置，我加 `if key in seen: continue` 后复测重复 = 0）。`input` 留空与否 = 区分"要不要看材料"的两类任务。

### 模块 B：训练五件套细节（Day 12，重点）

**Q6. LM loss（交叉熵）具体怎么算？为什么用 -100 掩码？**
> 模型对每个 token 位置输出一个覆盖整个词表的概率分布；正确答案是 one-hot，交叉熵求和后只剩一项：`Loss = -log p(真实答案)`。**-100 掩码**：ChatML 对话里"题干/历史"部分不算 loss（模型已经会读了，算它白学），只对"答案部分"token 算，非答案位置标签填 -100 让 PyTorch 自动跳过。
> [数学加分] 为什么 log：连乘变连加（数值稳定）+ log 凸、对"概率低却该高"惩罚更狠（梯度大学得快）。损失函数只盯着"标准答案位置的概率" = 训练目标不是"说得像人话"，而是"把对的词顶上去"。

**Q7. AdamW 是什么？和 SGD/Adam 什么区别？**
> AdamW 三件套：① 动量（EMA，记梯度方向惯性）；② 自适应步长（按梯度历史 RMS 归一，每个参数独立步长，陡坡小步缓坡大步）；③ 权重衰减（每步把权重往 0 拉一点 = L2 正则防过拟合）。W = 把权重衰减从 L2 正则中解耦出来（Adam 的 L2 会被自适应步长抵消，W 版本修正了这点）。
> 一句话：SGD 像"只看当前坡度迈步"，Adam 像"带惯性 + 知道每个方向的历史坡度"，W 额外加"别长太大"。

**Q8. 微调的学习率为什么用 2e-4 这么小？epoch 设多少？**
> 底座已有通用能力，微调只是小幅"拧方向"——学习率太大直接把底座知识冲掉（灾难性遗忘）。我 300 条数据训 3 epoch：够模型把风格/格式学会，刷太多会背题过拟合。配合 90/10 留出验证集每 epoch 看 eval_loss 防过拟合。
> [数学加分] 把模型参数想成概率分布的参数：学率太大 = 一次更新跨太大步，把 `P(答案|问题)` 从"通用但稳"的位置推飞；小步多次 = 温和地把分布往目标方向拧。

**Q9. 什么是梯度累积？为什么用它？**
> 显存只装得下 2 条样本的梯度，那就攒 8 步再更新一次参数（gradient_accumulation_steps=8）——**等效 batch 16** 的优化效果，把显存峰值摊薄。本质是"把一个大 batch 的梯度分成小份攒起来一次用"。

**Q10. "LoRA 只存 adapter"是什么意思？推理时怎么用？**
> PEFT 训练完 `save_pretrained` 只存 `adapter_config.json` + `adapter_model.safetensors`（我的约 20~30MB），**不是几 GB 的全量模型**。推理时加载同款 4bit 基座，再用 `PeftModel.from_pretrained` 挂上 adapter，等效权重 `W = W0 + B·A`（底座冻结 + 低秩增量合入）。
> 我项目里把这一步做成了"补丁式挂载"：Day9 的 `/v1/chat/completions` 接口代码一行不改，只在服务启动时多挂一个 adapter（`local_api_lora.py`）——**风格层与生成层解耦**的实证。

**Q11. 你怎么验证训练脚本没问题再跑正式训练？（冒烟测试）**
> 先写临时 1 步冒烟脚本：加载 4bit 底座 → 挂 LoRA → 数据转换 → Trainer 跑 1 步，真实跑通打印 SMOKE_OK（我那次 loss 0.87）再跑正式训练，冒烟脚本跑完即删不污染仓库。这招在踩到 transformers 5.x API 变更后尤其有用——改完心里没底，先小步验证。

**Q12. 微调后效果怎么验证？你怎么做前后对比？**
> 写 `compare_lora.py` **依次**加载"原模型 → 释放显存 → 原模型 + adapter"（6G 放不下两个 3B 同时推理），同一组 5 个测试问题贪心解码（do_sample=False 保证可复现），自动生成对比表再人工复核。结果：5 题 4 题明显更贴任务——抽取格式 = SFT 模板、计算题学会"先列式再代入"、概念题用上行话且**纠正了原模型"水银"幻觉**、总结分点凝练；Q5 合规判断答错，如实记录并归因数据侧。
> [诚实评估，面试加分] 格式学会 ≠ 内容学会：Q5 模型学了"合规。"开头的格式但内容没学对，还编造依据。这正是"微调管风格、RAG 管事实"的证据——这类需要判断的问题靠检索资料兜底。**敢报"4/5 有效、1 题答错并讲清原因"比只说"微调很有用"可信得多。**

### 模块 C：训练与部署踩坑（本周高频坑，每个都能讲 1 分钟）

**Q13. 起服务报"页面文件太小 os error 1455"是怎么回事？（版本/资源类坑）**
> 一度以为显存不够，其实**是内存不是显存**：`from_pretrained` 默认把 3.7GB 的 fp16 shard **整块读进系统内存**再做 4bit 量化，当时可用 RAM 只剩 3.5GB 就炸了。修法：`low_cpu_mem_usage=True` 流式逐张量加载 + 顺手把 transformers 5.x 弃用的 `torch_dtype` 换成 `dtype`，修复后加载 434/434 权重仅 6 秒。
> **教训：报错先看是资源问题还是版本问题——环境问题看资源、生成问题看参数。**

**Q14. 低温度生成为什么会出现"复读循环"？（生成参数类坑）**
> 评测时某题整段无限复读模板指令、刷满 512 token（finish_reason=length）。原因：temperature=0.2 把分布压得很尖 + 没有防复读参数，一旦开始复读"只输出答案；如果资料里没有…"就锁死出不来——自回归的**退化吸收态**。修法双保险：`repetition_penalty=1.15`（软约束，对已出现过的 token 降概率）+ `no_repeat_ngram_size=4`（硬约束，禁止 4-gram 二次出现）。
> [数学加分] 复读是"概率陷阱"：当前分布把概率都压在"继续说模板"上，模型越走越深出不来；两个参数一个软化一个硬禁，把吸收态打断。**低温度不是越低越好，防复读参数要跟温度配套。**

**Q15. transformers 5.x 有哪些 API 变更你踩到过？**
> 三个：`Trainer(tokenizer=...)` → **`processing_class`**（我查 `inspect.signature` 定位的）；`warmup_ratio` → **`warmup_steps`**（弃用警告提示 v5.2 移除）；`torch_dtype` → **`dtype`**。**教训：大版本升级先看 release note / 用 inspect 查新签名，改完用 1 步冒烟验证。**

**Q16. 你微调的数据/显存/参数"账"是怎么算的？（会算账 = 差异化）**
> 三张账：① 参数账——LoRA 全量 `d² → 2dr` 省 99.55%（Day5 理论），实测 trainable 14,966,784 / 总 3.10B = **0.4827%**；② 显存账——4bit 底座加载实测 1.92GB，微调服务 1.98GB，训练峰值 6G 内（预算 3.0GB 被实测持续刷新得更省）；③ 数据账——300 条 / 三字段 / 6 类 / 0 重复 / 平均 input≈80 output≈52 字符。面试随口报数字，比"我用了 LoRA"强一个量级。

### 模块 D：项目定性与架构（Day 13，简历项目核心）

**Q17. 介绍一下你的项目（30 秒版）。**
> "我做了个**机器人行业垂直领域 RAG 问答系统**：上传机器人行业 PDF（如 GMR 论文）自动建库，用户自然语言提问，系统检索资料、由 **QLoRA 微调过的 Qwen2.5-3B** 基于资料生成带出处回答。RAG 管事实、微调管风格，20 条评测题量化出检索/生成/防幻觉三组指标 + F1，数字能定位到具体层。"（面试官追哪句展开哪句）

**Q18. 为什么选"机器人行业"做垂直领域？**
> 三个原因：① 秋招目标江浙沪央国企数字化/AI 岗，**制造业是重点行业**；② 我自己的 GMR 论文（General Motion Retargeting，机器人运动重定向）就是现成的高质量私有语料，能讲"上传自己的论文能问答"；③ 领域有真实痛点——私有资料大模型不知道、通用回答不像行业专家，RAG + 微调正好各解决一半。SFT 数据的 20 家机器人产业链公司语料也是同领域对齐的。

**Q19. 项目架构为什么这么分层？（数学视角，本周最值钱的问题）**
> 四层：检索层（Chroma + bge-small-zh 余弦 Top-K）→ 答案组织层（模板 09：资料带 [N] 编号 + 强制 [资料§N] 出处 + 没有就说没有）→ 生成层（Qwen2.5-3B 4bit OpenAI 兼容接口）+ 风格层（LoRA adapter，`W = W0 + B·A`）。
> [数学加分] **分层 = 条件概率分解**：`P(答案|问题) ≈ P_生成(答案 | 模板09(检索(问题)))`。把端到端的条件分布拆成逐层条件分布，好处：① 每层独立调优（改检索不动生成）；② **出错能定位到层**——评测分数低，我能判断是"检索没召回答案段落"还是"生成没忍住编造"，而不是黑盒"系统不行"。这套框架让"评测 → 归因 → 优化"成为闭环。

**Q20. MVP 的"不做"清单是什么？为什么刻意砍？**
> 不做多轮对话、不做并发、不做前端花活。因为 9 月投递在即，简历要的是"完整可讲的项目"不是"半成品功能"——**小而完整 > 大而烂尾**。面试主动讲取舍：砍掉非关键路径是工程判断力，"为什么不做"和"做了什么"同样重要。

**Q21. 把微调模型接进接口，怎么做到代码一行不改？**
> Day9 就把模型包成了 OpenAI 兼容接口（FastAPI + `/v1/chat/completions`）。接微调模型只需改服务端：lifespan 里加载 4bit 底座后加两行 `PeftModel.from_pretrained(model, ADAPTER_PATH)` 挂 adapter，模型名改 `Qwen2.5-3B-Instruct-LoRA`。客户端/应用层零改动——**接口 = 面向抽象编程，换实现不换签名**。curl 三接口冒烟全通（/health → /v1/models → /v1/chat/completions），显存 1.98GB。

**Q22. 怎么判断服务端"跑的是不是我要的模型"？（一个隐蔽的坑）**
> POST 响应里的 `model` 字段是**回显请求名**（你写啥它回啥），不可信；要看 GET `/v1/models` 返回的 `data[0].id`（服务端加载时写死的常量）。我 Day14 差点用残留的原模型服务跑评测，后来把"先 GET /v1/models 验身份"写进了代码（`check_server`）。

### 模块 E：效果量化评测（Day 14，本周核心，面试重点）

**Q23. 你怎么量化 RAG 系统的效果？为什么不用一个"总正确率"糊过去？**
> 把 RAG 两种核心能力拆开量化：**检索层命中率**（答案段落是否被 Top-K 召回，= 信息检索的 Recall@K）、**生成层正确率**（资料内 10 题期望关键词命中）、**防幻觉正确率**（资料外 10 题是否如实答"没有提到"）、**防幻觉 F1**（把"该不该拒答"当二分类算精确率/召回率/F1）。一个总正确率会把"没召回"和"没答对"混在一起，拆开才能定位瓶颈。
> 首版基线：检索 2/10=20%、生成 2/10=20%、防幻觉 6/10=60%、总 8/20=40%、F1=0.667（P=0.75/R=0.60）。

**Q24. 防幻觉 F1 的混淆矩阵怎么摆？每个格子什么意思？**
> 把 20 条题当二分类（真实"该不该拒答" vs 模型"拒不拒答"）：TP=6 真防住（资料外题拒答了）、FP=2 该答没答（资料内有答案却拒答，过拒答）、FN=4 幻觉漏网（资料外题没拒住，编造了）、TN=8 正常作答。精确率 = 6/(6+2)=0.75（拒答时拒得对不对），召回率 = 6/(6+4)=0.60（该拒的题拒住了多少），F1 = 2×0.75×0.60/1.35 ≈ 0.667。

**Q25. 你的自动判分规则是什么？为什么不让大模型当"阅卷老师"？**
> 两套规则：in_material 看**期望关键词子串命中**；out_of_material 看**拒答词表**（`REFUSAL_MARKERS`，如"资料中没有提到"）。不找另一个大模型判分是因为：会引入它的风格/幻觉偏差 + 不可复现 + 花钱。但规则是"宽松近似"——所以我**跑完逐题人工复核**，误判写进 `MANUAL_FIXES` 修正表。
> [诚实案例] 我改回过两处：Q9 答案给了别家仓库（NVLabs/ProtoMotions）、`github` 关键词碰巧命中被判对，实际答错；Q18 先编造一串引用统计数字（425/679/248…）、末尾补一句"资料中没有提到"，拒答词漏网被判防幻觉成功。**规则只看词不看内容，人工复核兜底，数字要诚实——改完数字变低了我也接受，因为要进简历。**

**Q26. 你的评测数字不高（40%），是不是系统很烂？**
> 不是"烂"，而是**数字会说话、能归因**：8/10 资料内题连答案所在段落都没被 Top-K 召回（检索命中 20%）——生成层"巧妇难为无米之炊"，主瓶颈在**检索层召回**；防幻觉 FN=4 说明生成层偶发编造（Q18 那种），temperature=0.2 下单次生成仍有随机性。评测的价值不是报一个数，而是**把低分归到具体层**——这直接指到我的 P1 优化方向（TOP_K 4→8 / chunk_size / Embedding 对比），数字低是"待优化"不是"不能投"。
> [数学底气] n=20 点估计置信区间宽（±0.22），所以我看量级 + 错误归因，不抠小数点；评测分布 ≠ 真实分布（真实用户问题大多是资料内），讲数字必说口径。

**Q27. 微调模型和原模型，评测上哪个更强？（诚实回答）**
> 功能上两条链路都通。**风格**上微调模型明显更凝练专业（接口层 143 token 百科式 vs 21 token 定义式；双链路冒烟里微调链路更"结论式"）；**事实正确**上单次问答各有胜负（冒烟里微调 Q2 未点名数据集、原模型答对；Day14 评测里微调 Q5 答对）——**"风格变好 ≠ 事实一定答对"**，两者要分开评估。原模型 vs 微调模型在同一评测集上的定量对比（第二版评测表）列为 P2，我能用 `--profile` 一键切换的底座直接跑。

**Q28. 评测有哪些局限？你会主动说吗？**
> 主动讲四句：① 样本量小（n=20，置信区间宽，看量级）；② 规则判分是宽松近似（人工复核兜底）；③ 评测分布 ≠ 真实分布（两类各半是为同时测两个方向，真实场景正确率预期更高）；④ 单次生成有随机性（temperature=0.2 已压熵未消除，严谨做法是每题多次取多数）。**主动说局限 + 给改进方案，比被追问出来可信得多。**

### 模块 F：项目完结与工程化（Day 15）

**Q29. "一键切换原模型/微调模型"怎么实现的？**

**Q32. 下一步优化计划是什么？**

### 模块 G：统计建模副线八股（本周零散时间，覆盖风控岗）

**Q33. 精确率/召回率/F1/AUC 怎么区分？和你的 RAG 评测什么关系？**
> 混淆矩阵四格：TP/FP/FN/TN。Precision = TP/(TP+FP) 管误报，Recall = TP/(TP+FN) 管漏报，F1 = 2PR/(P+R) 用**调和平均**惩罚不均衡（P=1、R=0 时算术平均 0.5 显得还行，调和平均是 0 直接露馅）；AUC = 随机抽一正一负、正样本得分更高的概率（排序质量）。
> [和项目连线] RAG 的检索层命中率 = 答案段落是否被 Top-K 召回 = **Recall@K** 的直接落地；防幻觉 F1 就是把这个公式用在了"拒答"这个二分类上——八股和项目完全打通。

**Q34. 为什么需要验证集？K 折和留一法区别？**
> 超参数不能拿训练集自己评（分数永远虚高，模型"背过"了），要一块"没见过的"数据评真实水平。K 折 = 训练集均分 K 份轮流验证取平均（K=5/10 常用）；留一法 LOO = K=N 的极端（小数据最充分、贵 N 倍）。权衡：K 大偏差小但 K 次训练高度重叠（方差大）且贵，5~10 折是折中点。
> [连线] 我微调用 90/10 留出法看 eval_loss；Day14 的 20 条评测题 = 固定"测试集"，先定口径再谈优化——整套评估流程跟交叉验证是同一个思想。

**Q35. 特征工程四大块怎么讲？（缺失/编码/缩放/选择）**
> 缺失值：删除（高缺失）/均值/中位数填充（数值型，偏态用中位数）/众数（类别型）/建模预测（= 用条件期望 `E[X_missing|X_observed]` 估计）；缺失机制 MCAR（可删）/ MAR（与观测变量有关，删除有偏）/ MNAR（难修复）。
> 类别编码：标签编码只用于**有序类别**（学历），无序用会引入"3>2>1"伪大小；one-hot 适合无序（类别进单位向量空间，两两距离相等、正交）。
> 标准化 vs 归一化：**看算法不看数据**——Z-score 适合有异常值/算法假设正态（SVM、逻辑回归、PCA）；Min-Max 适合有界无异常值（神经网络输入）。
> 特征选择：过滤式（方差/卡方/相关，快但忽略交互）/ 包裹式（RFE，考虑交互但贵）/ 嵌入式（L1 正则自动稀疏——拉普拉斯先验，解落在菱形约束面坐标轴上）。本质 = **降维打击 + 防过拟合**（维度灾难：特征多 → 高维稀疏 → 方差大）。

**Q36. 样本不均衡怎么处理？为什么 accuracy 会骗人？**
> accuracy = 两类正确率按样本占比加权平均——1% 欺诈时全猜"正常"也有 99%，衡量不了你关心的类。解法：SMOTE（特征空间沿样本与近邻连线**插值**，比复制好——复制会让模型背下重复点过拟合；只在训练集做）、欠采样（删多数类，配 NearMiss/Tomek Links 改进）、类权重（`w = n/(k·n_j)`，等价"软版过采样"不占内存）。评估口径：报 precision/recall/F1/PR-AUC，不报裸 accuracy；极不均衡用 PR 曲线（ROC 假阳性率分母太大被多数类"撑场面"）。

### 模块 H：刷题中的数学谈资（零散时间素材）

**Q37. 第三周哪道题最能体现数学思维？（215 快速选择举例）**
> 快速选择 = 快排"只进一边"版：每轮随机基准分区后只递归答案所在半边。期望 O(n)：随机基准使两边期望对半，总工作量 = `n + n/2 + n/4 + … = 2n`（**等比级数求和**）。这是随机化算法"用随机性驯服最坏情况"的典型——快排的随机化分析同理（期望 O(n log n)）。数学背景讲概率期望，正是差异化谈资。

**Q38. 二分查找的"数学本质"怎么讲？**
> 二分 = **在单调谓词上找分界点**：定义 `P(i) = (nums[i] >= target)`，P 从假变真的位置就是答案；二分有效的前提是谓词单调（假假假…真真真）。704 是"找等于"、35 是"找第一个 ≥"（= `bisect_left`）、34 是 35 的左右两次应用（`P1: >= target` 与 `P2: > target` 两个谓词）、69 的二分版是找 `P(m)=(m²>x)` 分界。**一整套二分题 = 一个单调谓词框架**，复杂度 O(log n) = 区间砍半 → 决策树高度同源。

**Q39. x 的平方根为什么用牛顿法？（数学加分题）**
> 求 `sqrt(x)` = 求 `f(t) = t² − x = 0` 的正根，牛顿迭代 `t_{n+1} = (t_n + x/t_n)/2`（推导：`t − f(t)/f'(t)` = `t − (t²−x)/(2t)`）。**离根近时误差按平方收缩（二次收敛），精度每轮翻倍，几步就到机器精度**；二分是线性收敛但绝对稳健。能现场推导迭代公式 + 讲清二次收敛 = 面试"数学思维加分"的招牌。

**Q40. 递归为什么必然正确？怎么给面试官讲？**
> 递归 = 数学归纳法/结构归纳法的代码化：只要**归纳基**（终止条件，空树返回 0）和**归纳步**（`depth(node) = 1 + max(depth(left), depth(right))`）都对，递归必然正确——不用脑补递归怎么展开。翻转二叉树 = 结构归纳：先信任子树已翻好（子问题已解决），只交换当前节点左右孩子。两个词让递归从"玄学"变"证明"。

## 第三部分 · 面试开场白/自我介绍素材（本周沉淀）

> 一句话定位（对着镜子练）：
> "我是数学（概率统计）背景，能真正用概率语言理解大模型——微调是调条件概率分布、LoRA 是低秩近似、评测是混淆矩阵和 F1。我这个月从零跑通了部署、Prompt 工程、RAG 和微调，用 QLoRA 在 6G 显存上只训 0.48% 参数就改变了 Qwen2.5-3B 的回答风格，做出了一个机器人行业垂直 RAG 问答系统，20 条评测题量化出检索、生成、防幻觉三组指标 + F1，每个数字都能定位到具体层。"

三个可随时报出的"数学视角"结论：

| 讲什么 | 概率语言版 |
|---|---|
| 微调 / QLoRA | 微调 = 用配对数据调 `P(答案\|问题)`（收分布）；QLoRA = 4bit 底座 + 低秩增量，改动量 ΔW 低秩所以只训 0.4827% 参数够用 |
| 四层架构 | `P(答案\|问题) ≈ P_生成(答案\|模板09(检索(问题)))`：条件概率逐层分解，评测低分能归因到层 |
| 评测口径 | 检索命中率 = Recall@K、生成正确率 = 关键词命中、防幻觉 F1 = "该不该拒答"的二分类混淆矩阵 |
