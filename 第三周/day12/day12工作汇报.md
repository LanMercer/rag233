### 3.1 主线任务（4~5h）

| 任务 | 完成情况 | 说明 |
|---|---|---|
| 概念补课：训练五件套详解 | ✅ | 五个概念全部按"一句话大白话 + 数学视角 + 通俗类比"讲透：**LM loss（交叉熵）** = 模型对词表输出概率分布，损失 = 标准答案位置概率的负对数 `-log p(真实答案)`，只对答案部分打分（题干标签 -100）；**AdamW** = 动量（EMA 方向惯性）+ 自适应步长（按梯度 RMS 标准化）+ 权重衰减（L2 正则防过拟合）；**学习率 2e-4** = 微调只在底座上小幅调整，太大灾难性遗忘；**epoch** = 数据刷几遍（3 遍刚好）；**验证集** = 留出法（90/10 切分，eval_loss 防过拟合）；**梯度累积** = 显存只装得下 2 条，攒 8 步再更新（等效 batch 16）。两版解释（技术版 + "摸黑下山"通俗版）都写进了教程 |
| 读懂 `train_lora.py`（逐区块） | ✅ | 教程新增 **2.5 节"逐区块精读（Python 入门版）"**，按执行顺序逐行拆解（docstring → 导入区 → 配置区 → mem_report → main 四步流水线 → 入口），每个 Python 语法点（三元表达式 / zip / 切片 / -100 掩码 / 嵌套函数 / f-string 等）都标注；随后**应学习反馈把全部详细注释写进了 `train_lora.py` 文件本身**（428 行，逐行中文注释），以后读代码直接看文件 |

## 四、踩坑与解决（过程真实记录）

| # | 问题 | 解决办法 |
|---|---|---|
| 1 | `train_lora.py` 训练前 `TypeError: Trainer.__init__() got an unexpected keyword argument 'tokenizer'`（transformers 5.14.1 的 API 变更） | 用 `inspect.signature` 查新签名：新版 `Trainer` 把 `tokenizer` 参数改名为 **`processing_class`**；改为 `processing_class=tokenizer` 后解决 |
| 2 | `warmup_ratio` 报弃用警告（提示 v5.2 移除） | 按警告改用 **`warmup_steps`**（按总步数 3% 折算 ≈ 2 步），并同步更新配置区常量为 `WARMUP_STEPS = 2` |
| 3 | `torch_dtype` 报弃用警告 | 按警告改用 **`dtype`**（`dtype=torch.float16`） |
| 4 | 改完心里没底，怕还有别的坑 | 写临时冒烟脚本（加载 4bit 底座 → 挂 LoRA → 数据转换 → Trainer 跑 1 步），真实跑通打印 SMOKE_OK（1 步 loss 0.87、grad_norm nan 为 1 步正常现象），确认整条链路没问题再跑正式训练；冒烟脚本跑完即删，不污染仓库 |
| 5 | 对比表 Q5 合规判断：微调后答"合规"（应为"需要评估"） | 人工复核发现：训练数据 `JUDGE_POOL` 里"回购/安全认证"等条目答案以"合规。"开头，模型学了"开头直接给结论"的格式但内容没学对，还编造"R&D 成果可自由出境"。如实写进对比表并给出优化方向（给"需要评估"类条目加样本/加权；数据里年份字段混杂导致 Q4 补"2023年"的轻微幻觉） |
