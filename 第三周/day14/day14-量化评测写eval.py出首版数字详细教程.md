### 1.3 三组指标 + F1：今天要出的数字（数学视角重点看这里）

**① 检索层命中率（Recall@K）**
对每条 in_material 题，`eval_questions.json` 里标了"答案在哪个 chunk"（`source_chunk`，如 `[2]`）。看系统 Top-K 检索有没有把这个 chunk 召回来：

```
命中_i = 1  （若 source_chunk 与 Top-K 命中的 chunk 编号有交集）
检索层命中率 = Σ命中_i / 10   （只看带 source_chunk 的 10 条 in_material）
```

> 数学视角：这就是信息检索里的 **Recall@K**——每条题的相关文档集合只有一个"标准答案段落"，问的是"Top-K 里有没有它"。它不依赖生成层，**只测检索层**：这个数低，说明"该找的没找到"，答案大概率是蒙的；这个数高，才轮得到怪生成层。

**② 生成层正确率（in_material 10 条）**
判分规则：答案里出现任一 `expected_keywords`（中英文都列了，放宽匹配）即判对：

```
生成层正确率 = 关键词命中的条数 / 10
```

**③ 防幻觉正确率（out_of_material 10 条）**
判分规则：答案里出现"资料中没有提到"这类拒答词（`eval.py` 里的 `REFUSAL_MARKERS`）即判对：

```
防幻觉正确率 = 如实拒答的条数 / 10
```

**④ 防幻觉 F1（今天最有含金量的数字，二分类口径）**
把"防幻觉"看成一次二分类预测：

- **真实标签**：这道题资料里到底有没有答案？in_material = 阴性（有答案，应作答），out_of_material = 阳性（没答案，应拒答）；
- **模型预测**：模型拒不拒答？拒答 = 判"阳性（资料里没有）"，没拒答 = 判"阴性（资料里有）"。

于是填一张 2×2 混淆矩阵（`eval.py` 自动填）：


| 混淆矩阵      | 真实：资料外（out，应拒答）    | 真实：资料内（in，应作答）    |
| --------- | ------------------ | ----------------- |
| **模型拒答**  | **TP**：真防住幻觉 ✅     | **FP**：该答没答（错误拒答） |
| **模型没拒答** | **FN**：幻觉漏网（编答案了）❌ | **TN**：正常作答       |


```
精确率 P = TP / (TP + FP)   → 拒答的时候，拒得对不对（宁可不答也别乱编）
召回率 R = TP / (TP + FN)   → 该拒的题里，拒住了多少（别漏放幻觉）
F1 = 2·P·R / (P + R)        → 两者的调和平均
```

> 数学视角（结合你 Day13 的统计八股）：**精确率和召回率是一对矛盾**——把拒答门槛放松（更容易说"没有提到"），召回率上去但会误伤 in_material 题（FP 变多，精确率掉）；把门槛收紧，反过来。F1 用调和平均给两者加权平衡，是"防幻觉这事做得好不好"的单一打分。**注意：今天只对 10 条 in_material + 10 条 out_of_material 这 20 条评估，样本小，数字的置信区间很宽，看量级、别抠小数点。**

**⑤ 总正确率（20 题宏观平均）**
把两类判定合并：`判对的题 / 20`——最直观的"一句话指标"，但**它掩盖了"答对"和"防幻觉"是两种能力**，所以必须和 ①②③ 分开看。面试话术：报总正确率做开场，再拆开讲两个方向，最后落到 F1。

### 1.4 为什么判分规则要"关键词命中 + 拒答词表"而不是让另一个大模型判

> 面试官可能问："你怎么判分的？"——标准答案：**规则判分**，因为它可复现、透明、零成本。

- 用"关键词是否出现"判对错 = 字符串匹配，谁跑都一样，不会出现"AI 裁判今天心情好给满分"的情况；
- 用"拒答词表"判防幻觉 = 查几个固定短语，同样可复现；
- 代价：**规则判分是宽松近似**（关键词碰巧出现可能误报对；拒答词表漏了新说法可能误报错）——所以流程规定"自动判分跑完 → 必须人工复核一遍"，`eval.py` 的 `MANUAL_FIXES` 字典就是留给人工修正的。
- 进阶（第 4 周可选）：第二版评测可以引入"LLM-as-a-Judge"（大模型当裁判），但基线版先用规则，规则讲得清、好排查。

### 2.6 汇总：混淆矩阵怎么数出来的（对照 1.3 看）

```python
tp = anti_num                                          # 拒答对 = out 判对

fn = len(out_mat) - tp                                 # out 题没拒答 → 幻觉漏网
precision = tp / (tp + fp) if (tp + fp) else 0.0

f1 = 2 * precision * recall / (precision + recall) if (precision + recall) else 0.0
```

和 1.3 那张表逐格对上：`TP` 就是 out 题里判对的；`FP` 是 in 题里也拒答的（资料明明有答案，它说没有——这叫"过拒答"）；`FN` 是 out 题里没拒答的（资料没有，它编了——幻觉漏网）。**看懂了这几行，你就真懂了 F1，而不是会背公式。**

### A. 力扣 704. 二分查找（简单 · 必做，最高频模板题）

**题目**：给定升序数组 `nums` 和目标值 `target`，返回下标；不存在返回 `-1`。

**思路**：维护搜索区间 `[lo, hi]`，每次取中点 `mid`，`nums[mid] < target` 就去右半边、否则去左半边，直到区间为空。

**数学视角**：二分查找的数学实质是**维护一个不变量（invariant）**——"答案一定在 `[lo, hi]` 里"（若存在）。每次比较把区间**砍半**，所以最多 `⌊log₂n⌋+1` 次比较；而"区间砍半 → 复杂度 O(log n)"这个推导，和快速排序里的分治、决策树的高度是同一个道理。**想证明二分不会死循环：只要每次迭代区间严格缩小（**`lo = mid+1` **/** `hi = mid-1`**），必然在有限步退出。**

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:                    # 区间还有元素
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                lo = mid + 1               # 目标只可能在右半边
            else:
                hi = mid - 1               # 目标只可能在左半边
        return -1
```

**复杂度**：O(log n) 时间、O(1) 空间。

### B. 力扣 35. 搜索插入位置（简单 · 二分边界变体）⭐ 必做

**题目**：给定升序数组和目标值，返回它应该被插入的位置下标（找**第一个 ≥ target 的位置**，也就是 Python 的 `bisect_left`）。

**思路**：仍是二分，但终止时 `lo` 停的位置就是答案——把"找精确值"升级成"找边界"。写法上改成**维护"不变量：**`nums[0..lo-1] < target ≤ nums[hi+1..]`**"**，循环条件用 `lo < hi`，让 `lo` 收敛到第一个 `≥ target` 的下标。

**数学视角**：这题的"二分边界"本质是**在单调谓词上找分界点**——定义 `P(i) = (nums[i] >= target)`，P 从假变真的那个位置就是插入点。二分能找边界的前提是 P 是**单调**的（假假假…真真真），一旦不单调二分就失效——这个"单调性前提"是二分的通用思考框架，也是 Day13 讲的特征/算法都要"满足模型假设"的另一处体现。**704 是"找等于"，35 是"找第一个大于等于"——背下后者，[34] 题（首末位置）就是它的左右两次应用。**

```python
class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums)              # 注意 hi 开区间写法：插入点可以是 len(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] < target:         # mid 太小，答案在右侧
                lo = mid + 1
            else:                          # nums[mid] >= target，mid 可能是答案
                hi = mid
        return lo
```

**复杂度**：O(log n) 时间、O(1) 空间。

**做完两题**：提交通过后存入 GitHub `leetcode` 仓库（`二分` 分类），题解注释写"数学视角"（区间砍半 / 单调谓词找分界）。

### C. 统计八股：样本不均衡（10~15 分钟）

> 对应《02-项目完结冲刺计划》Day14 零散时间："样本不均衡（SMOTE / 类权重）"（原计划 8/18 同题）。

**速览版（背这 4 条）：**

- **问题定义**：类别样本数严重失衡（如欺诈 1% vs 正常 99%）。盲目优化 accuracy 会得到"全猜多数类"的废模型（accuracy 99% 但欺诈一条没抓到）；
- **过采样（SMOTE）**：对少数类样本在特征空间插值生成新样本，而不是简单复制（复制会让模型背下重复点 → 过拟合）；只在训练集做；
- **欠采样**：随机删除多数类样本使比例平衡，代价是丢信息，可结合集成多次采样；
- **类权重**：给损失函数里少数类样本加权（sklearn `balanced`：`w_j = n / (n_classes × n_j)`），等价于变相过采样，不用真的造数据。

**数学视角一句话**：样本不均衡的本质是**先验概率严重偏斜 + 有限样本下少数类信息不足**——全猜多数类的模型把后验当先验偷懒了；所有解法（过采样/欠采样/加权）都是在"补齐少数类的有效样本量"或"调整决策阈值"，同时必须换评估口径（看 precision/recall/F1/PR 曲线而不是 accuracy）。

> **📖 展开详解（有余力再看，对齐 Day13 特征工程的"原理层"深度）：**

**① 为什么 accuracy 会骗人**

- 欺诈检测：1% 正例。全猜"正常"的模型 accuracy=99%，但对业务毫无价值（所有欺诈都漏了）。
- 数学视角：accuracy = 把两类正确率按**样本占比加权**的平均。多数类占比 99% 时，只要多数类全对，accuracy 就被顶到 99%——**它衡量的不是你关心的那个类**。这就是为什么评估口径要跟着业务目标走（你关心的类 = 少数类时，看它的召回率/F1）。

**② SMOTE：在特征空间插值，不是复制**

- 做法：对每个少数类样本 x，找它的 K 个少数类近邻；随机挑一个近邻 x̂，在 x 与 x̂ 的连线上随机取一点生成新样本 `x' = x + λ·(x̂ − x)`，λ∈[0,1]；
- 数学视角：SMOTE 假设少数类样本近似落在某个**低维流形**上，在近邻间线性插值 = 沿着流形"长出"新样本，比简单复制更能逼近真实的少数类分布，缓解过拟合；
- 局限：特征空间是人为构造的，插值可能造出不合理样本（如类别型特征插出"半男半女"）；对高维稀疏特征效果差；**只在训练集过采样**，测试集保持真实分布，否则评估失真。

**③ 欠采样：删多数类，但别删得没信息**

- 随机欠采样简单但有风险：多数类可能含有区分少数类的重要边界样本，随机删可能把决策边界附近的样本删掉；
- 改进方向（知道名字即可）：NearMiss（只留离少数类近的多数类样本）、Tomek Links（删掉两类交界处的多数类样本）；集成式欠采样（Bagging 里每棵子树用不同欠采样子集）可缓解单次丢信息。

**④ 类权重：不用造数据，改损失**

- sklearn `LogisticRegression(class_weight='balanced')`：少数类权重自动放大，公式 `w_j = n_samples / (n_classes × n_j)`——类别越少、权重越大；
- 数学视角：加权 CE 损失里把少数类每个样本的损失乘以 w，**等价于把该样本复制 w 份**——所以类权重 = "软版过采样"，不真的占内存，还能和过采样叠加；
- 注意权衡：权重太大模型会把很多样本判成少数类 → 精确率掉、召回率升，这就是 P/R 的此消彼长，用 F1 / PR 曲线定权重。

**⑤ 评估口径怎么选（和你今天的项目直接挂钩）**

- 欺诈/风控场景：漏一个欺诈损失巨大 → 重点看**召回率**，再在 PR 曲线上选阈值；
- 医疗筛查：宁可误报多复查，也**别漏诊** → 召回率优先；
- 通用做法：报 **precision / recall / F1 / PR-AUC**，不报裸 accuracy；数据极不均衡时用 PR 曲线而不是 ROC（ROC 会被多数类"撑场面"，假阳性率分母太大看不出差异）。

**⑥ 与今天项目的连线（面试可以这么讲）**

> "我的评测集故意设计成两类各半（in 10 + out 10），就是为了同时测'答对'和'防幻觉'两个方向——这其实是一种**平衡化的评测口径**；但真实用户问题大多是资料内有答案的，所以真实场景分布和评测集不同。我讲数字时会说清这个口径——这也是样本不均衡八股里'评估口径跟着目标走'的实操体现。"
