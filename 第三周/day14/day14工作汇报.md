### 3.4 学习过程中的追问（都是"真学会"的痕迹）

- 追问"1455 报错是为什么" → 学到 `os error 1455` = Windows 提交额度（commitment limit）超限，发生在 `from_pretrained` 把 fp16 shard（单文件 3.7GB）**整块读进系统内存再做 4bit 量化**的瞬间；不是显存问题、也不是代码 bug，是"可用 RAM 只剩 3.5GB"的环境问题 → 修法是 `low_cpu_mem_usage=True` + 关占内存程序，还顺带适配了 transformers 5.x 的 `dtype` 新签名；
- 追问"10048 报错是不是因为我已经启动了、无需再启动" → 一半对一半错：端口确实被占用，但占着的是**昨天残留的原模型服务**（PID 27212，`/v1/models` 返回 `Qwen2.5-3B-Instruct`），而评测要打的是微调模型 → 学会"服务在跑 ≠ 服务正确"，必须用 `/v1/models` 验证模型名 + 停旧起新（6G 放不下两个 3B）；
- 追问"为什么 Q5 一直复读模板指令" → 学到自回归生成的**退化重复循环（吸收态）**：低温度把分布压尖 + 无防复读参数，一旦复读就锁死出不来，`finish_reason` 会是 `length` 而非 `stop`；并发现判分被复读文本里的"资料中没有提到"骗成"拒答"——规则判分局限的活教材；
- 追问"MANUAL_FIXES 我这样改对吗（Q9 改错、Q13 改对）" → Q9 改对；**Q13 不能改对**——它答的是参考文献条目冒充期刊，是真实幻觉，不满足备注"答 arxiv 可放宽"的口径；学会人工复核要**对着每题的备注口径**判断，而不是套"答得克制就放宽"的笼统规则；
- 追问"检索命中率/生成正确率都低，为什么精确率召回率却 0.8，是不是我人工检验还有错" → 学会三组指标**考三件事**（10 条 in 的答题 vs 20 条的二分类拒答），手工重算混淆矩阵验证自洽；并借这次复核挖出 **Q18 拒答词漏网**（编造内容后补一句拒答词 = 规则只看词不看内容）与 **Q5 假误拒**（模板回声含拒答词导致 FP 虚高 1 席，属代码口径局限，已在报告口径中备注）。
