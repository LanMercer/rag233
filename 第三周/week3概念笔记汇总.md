## 第二部分 · 微调入门三概念 + LoRA 数学（Day 11）

### 2.1 SFT / QLoRA / PEFT（新名词必带简介）

| 名词 | 是什么 | 一句话记忆 |
|---|---|---|
| **SFT**（Supervised Fine-Tuning，监督微调） | 用"问题-答案"配对数据把预训练模型再训一遍，让模型学会特定风格/能力 | 拿标准答案教模型"这种题该这么答"——预训练是大学文凭，SFT 是入职培训 |
| **QLoRA**（Quantized LoRA） | 4bit 量化底座 + 低秩适配器，两个"省"叠加 | 先把模型压成 4bit"瘦身版"（省显存），再在旁边挂很小的可训练适配器（省参数） |
| **PEFT**（Parameter-Efficient Fine-Tuning） | HuggingFace 高效微调工具箱，LoRA/QLoRA 都从这里配 | 一个"只训少量参数就把模型调好"的工具箱（LoRA 是家族里最常见的一种） |

- 概率语言：SFT 就是在调整 `P(答案|问题)` 条件分布，从"大而平"（什么都会一点）收成"小而尖"（专攻领域）——**few-shot 是"现场示范几例"，SFT 是"直接把分布改掉"，更彻底**。
- 三者关系一句话：**用 PEFT 的工具、走 QLoRA 的方案、做 SFT 这件事。**

### 2.2 RAG vs 微调（本周心法，面试必答）

| 对比 | RAG（Day10 已跑通） | 微调（本周完成） |
|---|---|---|
| 管什么 | 事实性资料：最新研报、私有 PDF | 风格/能力：行业口吻、专业术语、会算账 |
| 改什么 | 不改模型参数，临时拼资料 | 改模型参数（LoRA adapter） |
| 更新速度 | 加一段资料立刻生效 | 重新训练（小时级） |
| 项目分工 | "答对" | "答得像" |

> 一句话：RAG 是"考试带资料进考场翻书"，微调是"平时把套路练进肌肉记忆"——**两者配合 = 项目完整形态**。

### 2.3 LoRA 数学复习（Day5 储备 + 今日重跑实证）

- 微调的改动量 `ΔW = Wf - W0` 是**低秩**的（真实场景奇异值谱衰减快）；LoRA 用 `B·A`（B 是 d×r、A 是 r×d，r << d）近似它，`W = W0 + B·A`；
- **r 是"改动大小"的旋钮**：r 小 = 温和（保留旧知识多），r 大 ≈ 全量微调（学得快但忘得多）；默认 **r=8**；
- 参数账：`d² → 2dr`，节省 `1 - 2r/d`，7B 模型省 **99.55%**；
- 灾难性遗忘（Catastrophic Forgetting）= 完整微调把旧任务冲掉（Day5 demo 任务 A 误差 0→3.93）；LoRA 只改低秩增量、保留底座，天然更不容易忘。

### 2.4 SFT 数据工程（亲手跑出来的账）

- **三字段格式**：`instruction`（指令）/ `input`（需要看材料的原文，解释/计算类留空 `""`）/ `output`（标准答案）；
- **题材对齐**：语料池 = 20 家机器人产业链公司（埃斯顿 / 汇川技术 / 绿的谐波 / 拓斯达 / 大族激光 / 优必选 / 禾川科技 等）+ 机器人术语（谐波减速器 / RV 减速器 / 伺服电机 / 六轴机器人 / 运动规划 / PID 控制 等），**与 Day10 GMR 论文领域对齐**（微调数据要和项目领域一致）；
- **6 类任务分布**（300 条）：公告信息抽取 61 / 研报观点问答 72 / 公告要点总结 57 / 数据计算 44 / 合规判断 44 / 概念解释 22；
- **为什么去重**：完全重复的样本会被模型重复学习、放大偏置 → `random.seed(42)` + 生成循环 `if key in seen: continue`（instruction+input 相同即跳过）→ 复测重复 = 0；
- **为什么 200~500 条就够**：SFT 是"示范风格"不是"喂知识"——数据质量（三字段规范、去重、领域一致）优先于数量，监督信号充分即可，6G 显存训练也快；
- 数据账：300 条 / 三字段 / 6 类 / 0 重复（平均 input≈80、output≈52 字符）。

## 第三部分 · 训练五件套（Day 12 · 数学主场）

### 3.1 训练五件套速记

| 件 | 内容 | 一句话 |
|---|---|---|
| 模型 | Qwen2.5-3B-Instruct + QLoRA（4bit NF4 底座冻结 + LoRA r=8 alpha=16 挂 7 类线性层） | 底座只读、适配器可训 |
| 数据 | 300 条机器人行业 SFT 三字段 → ChatML → token；90/10 切出验证集 | 数据决定"学成什么样" |
| 损失 | LM loss = 交叉熵：`-log p(真实答案)`，只对答案部分打分（题干标签 -100） | 只罚"该答的没答好" |
| 优化器 | AdamW + 学习率 2e-4 | 动量惯性 + 自适应步长 + 权重衰减 |
| 训练 | 3 epoch + 每 epoch 看 eval_loss + 梯度累积 8 步（等效 batch 16） | 刷 3 遍、盯着别过拟合 |

### 3.2 LM loss（交叉熵）——本周数学第一主菜

- 模型对每个 token 位置输出一个覆盖整个词表的概率分布；训练目标 = 让"标准答案那个词"的概率尽量大；
- 独热分布视角：正确答案分布是 one-hot（只在真词上是 1），交叉熵求和后只剩一项 → `Loss = -log p(真实答案)`；
- 为什么用 log：连乘变连加（数值稳定）+ log 是凸函数、对"概率很低却该高"的情况惩罚更大（梯度大、学得快）；
- **标签掩码 -100**：ChatML 里"题干部分"（instruction + 历史）也算 loss 就白学了——只对"答案部分"的 token 算 loss，非答案位置标签填 -100，PyTorch 自动跳过；
- 实测：冒烟 1 步 loss 0.87；正式 3 epoch train/eval loss 均下降。

### 3.3 优化器与超参

- **AdamW** = 三件套：① 动量（EMA，记梯度方向惯性，像下山记住惯性）；② 自适应步长（按梯度历史 RMS 归一，每个参数独立步长，陡坡小步、缓坡大步）；③ **权重衰减**（W 项，每步往 0 拉一点 = L2 正则防过拟合）。W = Adam 改进（把权重衰减从 L2 正则中解耦）；
- **学习率 2e-4 为什么这么小**：底座已有通用能力，微调只是小幅"拧方向"——学习率太大直接把底座知识冲掉（灾难性遗忘）；
- **epoch = 数据刷几遍**：3 遍刚好（刷太多会背题过拟合）；
- **验证集（留出法）**：90/10 切分，eval_loss 防过拟合（训练集分数永远虚高，因为模型"背过"了）；
- **梯度累积**：显存只装得下 2 条样本，攒 8 步（gradient_accumulation_steps=8）再更新一次 = 等效 batch 16 的效果，把显存峰值摊薄。

### 3.4 参数账 / 显存账 / 只存 adapter

- **参数账（实测）**：trainable params 14,966,784 / 总参数 3.10B = **0.4827%**（<0.5%）——"LoRA 只训不到 1%"实锤；
- 显存账：4bit 底座加载实测 1.92GB，训练峰值在 6G 内；微调服务实测 1.98GB；
- **只存 adapter**：PEFT `save_pretrained` 存的是 `adapter_config.json` + `adapter_model.safetensors`（约 20~30MB），不是几 GB 的全量模型；
- **推理时合入权重**：`W_eff = W0 + B·A`——底座冻结参数 + 低秩增量，加载时先把 adapter 合进原权重（或推理框架里显式加）；
- transformers 5.x 兼容笔记：`Trainer(tokenizer=...)` → **`processing_class`**；`warmup_ratio` → **`warmup_steps`**；`torch_dtype` → **`dtype`**（训练/加载脚本新签名）。

### 3.5 微调效果对比（5 题 4 有效，诚实评估）

- 方法：`compare_lora.py` **依次**加载"原模型 → 释放显存 → 原模型 + adapter"（6G 放不下两个 3B 同时推理），同一组 5 题贪心解码（do_sample=False 可复现）；
- **4/5 明显更贴任务**：Q1 抽取输出 = SFT 标准答案格式（公司+年份+指标+数值+同比）；Q2 计算题学会"先列式→再代入→给结果"一行式；Q3 概念解释用上"弹性变形"、**纠正了原模型"波发生器充满水银"的事实幻觉**；Q4 要点总结分点凝练；
- **Q5 合规判断答错（如实记录）**：应答"需要评估"却答"合规"+ 编造"R&D 成果可自由出境"——根因在数据侧（`JUDGE_POOL` 里"合规。"开头答案偏多，模型学了"开头直接给结论"的格式但内容没学对）；
- 连带发现 Q4 微调后补"2023年"（材料没给年份，原模型也幻觉"2022年"）——摘要类数据年份字段混杂，学了"带年份"说话习惯；
- **教训**：格式学会 ≠ 内容学会；"微调管风格、RAG 管事实"——Q5 这类需要"判断"的问题本就该靠检索资料兜底。

## 第四部分 · 项目定性与四层架构（Day 13）

### 4.1 项目一句话（背下来）

**"机器人行业垂直领域 RAG 问答系统"**——上传机器人行业 PDF（如 GMR 论文）自动建库，用户自然语言提问，系统检索资料、基于资料生成带出处回答。拆成三件事：做什么（垂直 RAG 问答）+ 怎么做（RAG 管事实 + QLoRA 微调管风格）+ 怎么证明（20 条评测题量化精确率/召回率/F1）。

### 4.2 MVP 边界（"不做"清单 = 面试的取舍意识）

不做多轮对话 / 不做并发 / 不做前端花活——**小而完整 > 大而烂尾**。面试可主动讲"为什么不做"：MVP 要的是"一条完整链路 + 可量化 + 可讲清"，砍掉非关键路径才是工程判断力。

### 4.3 四层架构（各司其职 + 数学视角）

| 层 | 组件 | 负责什么 | 来源 |
|---|---|---|---|
| 检索层 | Chroma 向量库 + bge-small-zh + 余弦相似度 Top-K | 找到相关段落（"答对"的前提） | Day10 |
| 答案组织层 | 模板库 v2 · 模板 09（资料带段落编号 + 强制出处 + 防幻觉约束） | 把资料拼成"只依据资料 + 带出处"的提示词 | Day8 |
| 生成层 | Qwen2.5-3B-Instruct 4bit（`/v1/chat/completions`） | 把提示词变成通顺答案 | Day6/9 |
| 风格/能力层 | QLoRA LoRA adapter（`W = W0 + B·A`） | 让回答贴近行业专家口吻（"答得像"） | Day12 |

- **数学视角（本周最值钱的面试框架）**：`P(答案|问题) ≈ P_生成(答案 | 模板09(检索(问题)))`——把端到端的条件概率**分解成逐层条件概率**：每层只干一件事、只接收上一层的输出（检索的输出是模板的输入，模板的输出是生成的输入）。好处：① 每层可独立调优；② 评测分数低能**定位到具体层**（检索没召回 vs 生成没忍住），而不是黑盒"系统不行"；
- **adapter 是"补丁式挂载"**：风格层与生成层解耦，接口代码一行不用改——Day13 用 `PeftModel.from_pretrained` 把 adapter 挂进 lifespan，curl 冒烟即通过。

### 4.4 评测问题集设计（先定卷子再打分）

- 20 条题、**两类各 10**：`in_material` 资料内有答案 10 条（测"答对"）+ `out_of_material` 资料外/反事实 10 条（测"防幻觉"）；
- 每条题带可自动判分的字段：`expected_keywords`（期望关键词）或 `expected_behavior`（期望行为）+ `source_chunk`（答案所在段落，供检索层判定）+ `note`（出题依据/判定口径）；
- **出题原则（数学视角）**：① 题要**可判定**（关键词命中或明确行为，别出主观题）；② **难度分层**（事实抽取 vs 综合理解）；③ 反事实题先拿 `ask.py` 验证"确实不在资料里"再入库（保证标准答案成立）；
- 知识库 = GMR 论文（General Motion Retargeting for Humanoid Motion Tracking，9 页 → 复建库约 105 chunk）。

### 4.5 微调模型接入接口（Day9 → Day13 改造）

- `local_api_lora.py`：加 `ADAPTER_PATH`、模型名改 `Qwen2.5-3B-Instruct-LoRA`；**关键两行**在 lifespan 里按序执行——加载 4bit 底座 → `PeftModel.from_pretrained(model, ADAPTER_PATH)` 挂 adapter → `model_ready=True`（顺序错了接口会在模型没挂好时就响应）；
- 启动日志实证：`[OK] LoRA adapter 已加载：...\day12\lora_adapter` → `[OK] 模型已就绪：Qwen2.5-3B-Instruct-LoRA，显存占用约 1.98 GB`；
- curl 三接口全通：`/health`（`{"status":"ok","model_ready":true}`）→ `/v1/models`（`data[0].id` = 真实加载模型）→ `/v1/chat/completions`（OpenAI 兼容格式保留）；
- **接口层对比实证**：同一问题原模型 143 token 百科式展开 vs 微调模型 21 token 一句话定义式（"运动重定向：把某角色的动作移植到新角色上，实现'换壳'。"）；
- **坑提醒**：HTTP 响应里的 `model` 字段是"回显请求名"，判断当前跑的是哪个模型要看**服务端启动日志** / GET `/v1/models`。

## 第五部分 · 量化评测（Day 14 · 数学主场）

### 5.1 三组指标口径（先定口径再报数字）

| 指标 | 口径 | 测什么 |
|---|---|---|
| 检索层命中率 | 资料内 10 题中，`source_chunk`（标准答案所在段落）被 Top-K 召回的占比 | 该找的段落有没有找到（= 信息检索的 Recall@K） |
| 生成层正确率 | 资料内 10 题中，答案命中期望关键词的占比 | 找到段落之后，答没答对 |
| 防幻觉正确率 | 资料外 10 题中，如实答「资料中没有提到」的占比 | 没有答案时能不能忍住不编 |
| 防幻觉 F1 | 把"该不该拒答"当二分类，算精确率 / 召回率 / F1 | 拒答准不准、漏放多少幻觉 |

- **三组指标考三件事、不矛盾**：检索/生成正确率只考 10 条 in 的"答得对不对"；防幻觉 F1 把 20 条当二分类评"拒不拒得准不准"；
- **评测配置**：Qwen2.5-3B-Instruct-LoRA ｜ TOP_K=4 ｜ temperature=0.2 ｜ 模板 09（默认配置先出基线，不做调优）。

### 5.2 首版数字（最终确认版）与混淆矩阵

| 指标 | 数值 |
|---|---|
| 检索层命中率 | **2/10 = 20%** |
| 生成层正确率（资料内） | **2/10 = 20%** |
| 防幻觉正确率（资料外） | **6/10 = 60%** |
| 总正确率（20 题） | **8/20 = 40%** |
| 防幻觉 F1 | **0.667**（精确率 0.75 / 召回率 0.60） |

**防幻觉 2×2 混淆矩阵**（真实"该不该拒答" vs 模型"拒不拒答"）：

| | 真实：资料外（应拒答） | 真实：资料内（应作答） |
|---|---|---|
| 模型拒答 | TP = 6（真防住） | FP = 2（该答没答，过拒答） |
| 模型没拒答 | FN = 4（幻觉漏网） | TN = 8（正常作答） |

- F1 = 2·P·R/(P+R) = 2×0.75×0.60/1.35 ≈ 0.667；P = 拒答的时候拒得对不对，R = 该拒的题里拒住了多少。

### 5.3 判分方式（规则 + 人工复核双保险）

- **规则判分**：in_material 看期望关键词子串命中；out_of_material 看拒答词表（`REFUSAL_MARKERS`）——可复现、零成本；
- **为什么不让另一个大模型判**：会引入第二个模型的风格/幻觉偏差 + 不可复现 + 花钱；
- **`MANUAL_FIXES` 人工修正表**：自动判分后逐题人工复核（对着每题 `note` 口径），误判写进表里改判——本周改回 2 处：Q9（`github` 关键词碰巧命中别家仓库）、Q18（先编造引用统计数字、末尾补拒答词 = 规则只看词不看内容漏网）；
- **数字诚实**：修正后数字变低也坦然接受（Q18 改判 + 采样随机性让最终版低于中间版），因为要进简历。

### 5.4 修复的三个系统性问题（面试"踩坑"素材）

1. **启动内存 `os error 1455`**：Windows 提交额度超限——`from_pretrained` 把 3.7GB 的 fp16 shard 整块读进系统内存再做 4bit 量化，可用 RAM 只剩 3.5GB 就炸（是内存不是显存）→ `low_cpu_mem_usage=True` 流式逐张量加载 + `torch_dtype`→`dtype`，修复后加载 434/434 仅 6 秒；
2. **Q5 复读循环（退化吸收态）**：低温度把分布压尖 + 无防复读参数，一旦开始复读模板指令就锁死出不来（`finish_reason=length`）→ `repetition_penalty=1.15`（软约束降重复概率）+ `no_repeat_ngram_size=4`（硬约束禁 4-gram 二次出现）双保险；
3. **规则判分误判**：关键词/拒答词子串匹配可能误报 → 人工复核 + `MANUAL_FIXES` 兜底。

### 5.5 评测局限（诚实声明，主动讲）

1. **样本量小**：n=20，点估计 95% 置信区间宽度约 ±0.22——看量级、不抠小数点；
2. **规则判分是宽松近似**：关键词/拒答词子串匹配可能误报（已用人工复核兜底）；
3. **评测分布 ≠ 真实分布**：真实用户问题大多属于资料内，评测集"两类各半"为同时测两个方向——真实场景总正确率预期高于 40% 口径；
4. **单次生成有随机性**：temperature=0.2 已压熵但未消除（双链路冒烟中微调链路 Q2 单次未点名 LAFAN1、Day14 评测 Q5 却答对）——严谨做法是每题多次取多数。

## 第七部分 · 统计建模副线（本周 4 块，全部能和实操接上线）

### 7.1 评估指标复习（8/15，衔接 RAG 评测）

- 混淆矩阵四格：TP（正判正）/ FP（负判正）/ FN（正判负）/ TN（负判负）；一切指标的地基；
- Precision = TP/(TP+FP)：预测为正的里面多少真对（管**误报**）；Recall = TP/(TP+FN)：真正的正类里捞回多少（管**漏报**）；F1 = 2PR/(P+R)；
- **调和平均 vs 算术平均（数学视角）**：F1 用调和平均 `2/(1/P+1/R)` 对"一个指标特别低"更敏感——P=1、R=0 时算术平均 0.5 显得还行，调和平均是 0（直接露馅）；
- AUC = 随机抽一正一负、正样本得分更高的概率 `P(正分>负分)`（Day7 证明过 0.833 双视角等价）；
- **和 RAG 的衔接（本周实际落地）**：检索层命中率 = "答案段落是否被 Top-K 召回" = **Recall@K**；检索结果里无关片段占比 = 检索层精确率。面试加分句：RAG 检索本质是排序问题，用 Recall@K 衡量是否捞回正确答案。

### 7.2 交叉验证（8/16）

- 为什么需要验证集：模型超参数不能拿训练集自己评（训练集分数永远虚高，模型"背过"了）→ 90/10 留出法（hold-out）看 eval_loss；
- **K 折**：训练集均分 K 份，轮流 1 份验证、K-1 份训练，K 个分数取平均（常用 K=5/10）；**留一法 LOO** = K=N 的极端（小数据最充分、贵 N 倍）；
- 偏差-方差权衡：K 大 → 训练数据多（低偏差）但 K 次训练高度重叠（高相关、方差大）且贵；K 小 → 便宜但偏差大——**5~10 折是经验折中点**。

### 7.3 特征工程（8/17）

- **缺失值处理**：删除（缺失比例高）/ 均值/中位数填充（数值型，偏态用中位数）/ 众数填充（类别型）/ 建模预测填充（= 用条件期望 `E[X_missing|X_observed]` 估计）；**缺失机制**：MCAR（完全随机，删除安全）/ MAR（与观测变量有关，删除有偏）/ MNAR（与缺失值本身有关，任何填充都难修复）；
- **类别编码**：标签编码（0/1/2…）只适合**有序类别**（学历、满意度），无序类别用会引入"3>2>1"伪大小关系；one-hot（每类一列 0/1）适合**无序类别**——把类别放进单位向量空间，任意两类距离相等（√2）、互相正交；
- **标准化 vs 归一化（看算法不看数据）**：Z-score `(x-μ)/σ` 适合有异常值/算法假设正态（线性回归、逻辑回归、SVM、PCA）；Min-Max `(x-min)/(max-min)` 压到 [0,1] 适合分布有界无异常值（神经网络输入层）；
- **特征选择**：过滤式（方差/卡方/相关系数，快但忽略交互）/ 包裹式（RFE 递归消除，考虑交互但贵）/ 嵌入式（L1 正则 = Lasso，自动稀疏——对应拉普拉斯先验，解落在"菱形"约束面的坐标轴上）；本质 = 降维打击 + 防过拟合（维度灾难：特征多 → 高维稀疏 → 方差大）。

### 7.4 样本不均衡（8/18）

- 问题本质：**先验概率严重偏斜 + 有限样本下少数类信息不足**——全猜多数类的模型 accuracy 99% 但一条欺诈都抓不到；
- **SMOTE**：对每个少数类样本在特征空间沿"样本与近邻连线"插值生成新样本（`x' = x + λ(x̂ - x)`），比复制好（复制会背下重复点过拟合）；只在训练集做；
- **类权重** = 软版过采样：`w_j = n/(k·n_j)`（sklearn `balanced`），不真造数据；权重太大会把 P 打掉换 R（此消彼长，用 F1/PR 定权重）；
- **评估口径**：报 precision/recall/F1/PR-AUC，不报裸 accuracy；极不均衡用 PR 曲线（ROC 假阳性率分母太大被多数类"撑场面"）；
- 与项目连线：评测集"两类各半"是一种**平衡化的评测口径**，讲数字时要说清"评测分布 ≠ 真实分布"。

## 第九部分 · 面试一句话速查（按概率语言讲）

- **微调的本质**："微调 = 用配对数据调整 `P(答案|问题)`，把输出分布从大而平收成小而尖——few-shot 是现场示范几例，SFT 是直接把分布改掉。"
- **QLoRA**："QLoRA = 4bit 量化底座 + LoRA 低秩适配器，两个'省'叠加，6G 显存微调 3B；我只训 0.4827% 的参数就改变了模型的回答风格。"
- **为什么 LoRA 有效**："微调的改动量 ΔW 是低秩的（奇异值谱衰减快），用 B·A 近似它，参数从 d² 降到 2dr——改动少 = 保留底座知识，天然抗灾难性遗忘。"
- **RAG vs 微调**："RAG 管'事实'（答对）：考试带资料翻书、更新快、答案带出处；微调管'风格'（答得像）：把套路练进肌肉记忆。两者配合才是项目完整形态。"
- **LM loss**："LM loss = 交叉熵 `-log p(真实答案)`，只对答案 token 打分、题干用 -100 掩码——模型的训练目标不是'说得像人话'而是'把标准答案位置的概率顶高'。"
- **分层架构**："`P(答案|问题) ≈ P_生成(答案|模板09(检索(问题)))`——把端到端条件概率分解成逐层条件概率，每层独立调优，评测分数低能定位到是检索没召回还是生成没忍住。"
- **评测口径**："评测先定口径再报数：检索命中率 = Recall@K、生成正确率 = 关键词命中、防幻觉 = 如实拒答，外加把'该不该拒答'当二分类的 F1——三个指标考三件事，不矛盾。"
- **数字诚实**："自动判分跑完必须逐题人工复核——我改回过 Q9（关键词碰巧命中）和 Q18（先编造再补拒答词漏网），改完数字变低也坦然接受，因为要进简历。"
- **评估指标**："Precision 管误报、Recall 管漏报，F1 用调和平均惩罚不均衡；RAG 检索层命中率就是 Recall@K 的直接落地。"
- **L1 vs 特征选择**："L1 正则 = 拉普拉斯先验，解落在菱形约束面的坐标轴上，自动把无关特征系数压到 0——降维打击 + 防过拟合。"
