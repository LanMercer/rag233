## 第二部分 · Qwen 本地部署（Day 6）

### 2.1 部署全流程
- **下载**：用 **ModelScope（魔搭）**（阿里出品的国内模型社区，下载快）下载 `Qwen/Qwen2.5-3B-Instruct`，13 个文件约 6GB，含 2 个权重分片 `.safetensors`（safetensors = 一种安全高效的模型权重格式）+ 分词器 + config。

  - **量化（Quantization）** = 把模型参数从 16/32 位压到 4/8 位省显存；**bitsandbytes** 是实现 4bit 加载的库；**NF4（NormalFloat4）** = 专为权重设计的 4bit 量化格式，精度损失更小。
- **显存实测**：`torch.cuda.memory_allocated()` 实测**已分配 1.92GB / 缓存 1.98GB**——比第一周预算的 3.0GB 还省约 1.1GB。差异来自 `device_map="auto"` 自动分配 + 双重量化生效；预算里没算上的"缓存"（CUDA 上下文 + KV Cache，KV Cache = 生成时缓存历史键值对、加速生成的内存）会多占一点。

### 2.2 temperature / top_p 数学原理（面试默写重点）
- 模型生成不是"选概率最大的词"，而是**按条件概率分布抽样**：分布尖 → 输出稳定可预测；分布平 → 输出多样不可预测。

**temperature（温度）= 拧分布的形状**：
```
p_i = exp(z_i / T) / Σ_j exp(z_j / T)
```
- `z_i` 是词 i 的打分（logits），T 是温度，T=1 就是普通 softmax（第一周手算过）；
- T 越小 → 分数差被放大 → 分布越尖（T→0 退化成贪心解码 greedy decoding，每次都选最大）；
- T 越大 → 分数差被拉平 → 分布越均匀（T→∞ 退化成均匀分布）；
- **和熵（信息量）的关系**：`H = -Σ p_i·log(p_i)`，分布越平熵越大越随机。完整因果链：**T 变大 → 分布更均匀 → 熵变大 → 输出更随机**。调温度 = 连续调节概率分布的熵。
- **3 词数值例子**（打分 z=[3,2,1]）：

| T | 苹果 | 香蕉 | 西瓜 | 熵 H（nats） |
|---|---|---|---|---|
| 0.5 | 0.87 | 0.12 | 0.02 | ≈ 0.44 |
| 1 | 0.67 | 0.24 | 0.09 | ≈ 0.83 |
| 2 | 0.51 | 0.31 | 0.19 | ≈ 1.02 |

（3 词均匀分布熵上限 ln3 ≈ 1.10。）

**top_p（核采样 nucleus sampling）= 拧抽样的候选范围**：
- 做法：把 softmax 概率**从大到小排序并累加**，累加到 ≥ p 时截断，只在这部分词里**重新归一化再抽样**；
- 例子（0.67/0.24/0.09）：top_p=0.9 → 累加到 0.91 ≥ 0.9，候选集 = {苹果, 香蕉}（西瓜被踢出），重归一化 0.74/0.26；
- top_p=0.5 最保守、0.9 推荐值、1.0 等于关闭 top_p。

**两者区别（面试常问）**：temperature 动的是**每个词的概率值**（分布形状）；top_p 动的是**抽样候选集合**（哪些词有资格被抽）。一个动"概率"、一个动"名单"，两个维度正交，配合使用。
**一句话记忆**：**温度 = 拧"熵"，top_p = 切"名单"。**

## 第三部分 · Prompt 工程入门（Day 7）

### 3.1 核心概念速记
| 概念 | 是什么 | 一句话记忆 |
|---|---|---|
| **Prompt 工程** | 设计给模型的文字（prompt），引导输出 | 给聪明助手写一份它看得懂的"需求文档" |

| **思维链 CoT** | 让模型把推理过程一步步写出来再给结论（"Let's think step by step"） | 把"心里算"改成"写算式" |
| **五件套** | 角色 + 任务 + 输入 + 输出格式 + 约束条件 | 结构化提示词公式 |

- 吴恩达课两条黄金准则：写得清晰具体（分隔符 / 结构化输出 / 条件检查 / few-shot）+ 给模型思考时间（拆步骤 / 先推导再结论）。

### 3.2 数学原理小课堂（概率语言，本周主菜）

**few-shot = 用样本修正条件概率分布（后验调整）**：
- 零样本时分布 `P(回答 | 问题)` 很"野"（高熵）；few-shot 拼入 k 个示例后按 `P(回答 | 问题, 示例₁…示例ₖ)` 抽样；
- 示例 ≈ 从"目标输出分布"里抽来的小样本 → 用样本对输出分布做**后验调整**（贝叶斯视角：先验 `P(回答|问题)` 被示例"更新"成后验）；
- **一句话：few-shot 把输出分布从"大而平"收成"小而尖"**，和 Day 6 调温度拧的是同一个东西——熵（温度是旋钮，示例是数据）。
- 小抄：先验 = 看到数据前你猜的；后验 = 看到数据后更新的；贝叶斯定理 `P(H|D) = P(D|H)·P(H) / P(D)`（后验 = 先验 × 数据支持度，再归一化）。

**思维链 = 把高方差估计拆成多步低方差估计**：
- 一步到位 = 一步估计复杂函数 `f(问题)`，任何小环节出错就全崩（**高方差估计**）；
- 思维链 = 先输出中间步骤 s₁→s₂→…，每步只估计更简单的条件分布 `P(sᵢ₊₁ | 问题, s₁…sᵢ)`——候选空间小、分布尖、单步出错率低；
- 概率表达（链式法则）：`P(过程, 答案 | 问题) = P(s₁|q)·P(s₂|q,s₁)·…·P(答案|q, 全部步骤)`；
- 方差分解：`Var(Y) = E[Var(Y|X)] + Var(E[Y|X])`——显式写中间步骤 X 当条件变量，剩余方差 ≤ 总方差，逐步降方差；
- **数字直觉**：整体一次做对 0.8；拆 3 步后每步因候选变少升到 0.95 → 0.95³ ≈ 0.857 > 0.8。注意：真正原因不是"多步"而是"条件化让每步分布变尖"；
- 实测证据：思维链把数学题正确率 **60%→84%**（Day7，N=5）；Day8 复测 **20%→50%**（N=20，2.5 倍）。

**五件套 = 压缩输出分布的支持集**：
- 每加一项约束（角色/输出格式/约束条件），都在缩小"模型可能输出的集合"（**支持集 support**）→ **条件熵下降** → 输出更稳更可预测；
- 与 Day 6 打通：温度是"连续旋钮式"调熵，约束条件是"结构式"压熵；
- **面试话术**：写提示词的本质 = 不断给模型加条件信息，把条件概率分布往你要的方向压缩。

## 第四部分 · Prompt 工程进阶（Day 8）

### 4.1 四个进阶技巧（各配一句概率语言）
| 技巧 | 是什么 | 概率语言 | 实测证据 |
|---|---|---|---|
| **角色扮演** | 给模型明确身份/人设 | 给条件分布一个**强先验**，把输出锁定到"该角色"的子分布（`P(回答|问题,角色=R)`） | 模板 11：风控专家 vs 普通助手，输出框架/结论完全不同 |
| **输出格式约束** | 强制 JSON/表格/CSV 等输出形状 | 把支持集从"所有文本"压成"一个 schema"，**条件熵断崖式下降** | JSON 可被程序直接解析、表格直接可用 |
| **迭代优化** | "写→跑→看→改"循环 | **手动梯度下降**：跑模板=前向传播、看差距=算 loss、改提示词=反方向更新文字参数 | 模板 07：v1 乱码 → v2 部分修复 → v3 四字段全对 |
| **抑制幻觉** | 防编造 | **分布尖 ≠ 分布准**（校准差）：模型置信度给的是"像不像人话"，不是"是不是事实" | 模板 09 资料外问题答"资料中没有提到" |

### 4.2 模板 07 迭代闭环（面试可完整复述的"迭代链"）
- **v1（Day7 遗留）**：`person: "王小明, 李芳"`（合并两人）、`date: "3月1laoday"`（乱码）；
- **v2（加约束 + 降温度 0.2）**：date 修好、person 不再合并，但**暴露新问题**——person 抽成次要人物"李芳"（示例只有单人没教"客户 vs 经理谁是主体"）、amount 抽空 null（示例"存入5万元"与测试"办理了10万元"表述对不上）；
- **v3（few-shot 换成与测试文本同构的双人示例 + 字段级约束写死）**：实测**四字段全对** `{"person": "王小明", "date": "3月15日", "location": "上海浦东发展银行", "amount": "100000"}`；
- **教训**：few-shot 示例要和测试文本同构，约束要写到字段级。

### 4.3 知识卡片：模板 14 算术错误 = "AI 不会做数学题"微缩现场
- **LLM 的算术不是"计算"而是"回忆/模式匹配"**：单个乘法（`8×0.4=3.2`）= 训练语料里背过的映射；多步组合（`8×0.4+6×0.3+7×0.3`）= 语料里没有，只能从"像决策表格输出"的分布里猜一个数字——**格式 100% 像真的，数字大概率是错的**；
- 实测对照：模板 14 直接给加权总分 → 错（7.2/7.5/5.7 vs 正确 7.1/6.7/4.4）；模板 18 先写过程再给答案 → 对（52000）；
- 这就是《Chain-of-Thought Prompting》的核心发现：把中间步骤逼出来 = 给它一张草稿纸（外部工作记忆）；
- **工程原则：推理归模型、计算归代码**——RAG 应用里数值聚合、统计计算一律走 Python，模型只负责理解和组织答案；
- 2026 现状：o1/R1 用"强化学习 + 超长思维链"推进了推理层，但精确计算仍靠调用计算器，工业界早就不让模型自己算了。

### 4.4 RAG 标准版模板 09（Day 8 打磨，Day 10 直接复用）
- 结构：**角色（严谨的资料问答助手）+ 【资料】（段落编号 [N]）+ 【问题】+ 输出格式（只输出答案）+ 约束条件（只依据资料 / 没有就说「资料中没有提到」/ 每条要点标 [资料§N] / 答案不超过 3 句）**；

## 第五部分 · 统计建模副线（本周 4 个主题）

### 5.1 逻辑回归（Day 6）
- `P = sigmoid(线性组合)`：把线性回归的输出塞进 sigmoid（S 形函数），把任意实数压到 0~1 变成概率；
- 与线性回归区别：**线性回归预测连续数值**（房价），**逻辑回归预测概率**（是否违约）；
- 为什么银行风控爱用：输出是概率、有数学可解释性、能直接算风险评分。

### 5.2 准确率 / 精确率 / 召回率（Day 7）
- 混淆矩阵四格：**TP**（正例判成正）/ **FP**（负例判成正）/ **FN**（正例判成负）/ **TN**（负例判成负）；
- **Accuracy** = (TP+TN)/全部——类不平衡会骗人（99 负 1 正时"全判负"也有 99%）；
- **Precision** = TP/(TP+FP)（查出来的里有多少对的）；**Recall** = TP/(TP+FN)（该找出的里找回多少）；
- 风控例子：精确率高 = 少误伤（拒错好人少）；召回率高 = 少漏网（漏掉的真违约少）；此消彼长，用 F1 平衡。

### 5.3 F1 / AUC（Day 8）
- **F1** = `2·P·R/(P+R)`，精确率与召回率的**调和平均**——对"小值"敏感，优化 F1 = 强迫 P、R 同时不能差；适用于正负样本不平衡。
- **AUC 双视角等价证明**（风控例子，3 正 4 负：P₁=0.9, P₂=0.8, N₁=0.75, N₂=0.6, P₃=0.55, N₃=0.3, N₄=0.2）：
  - **概率视角**：共 3×4=12 对，数"正样本分数 ≥ 负样本"的对数：(4+4+2)/12 ≈ **0.833**；
  - **几何视角**：t 从高往低扫，ROC 阶梯面积：(1/4×2/3)+(1/4×2/3)+(1/4×1)+(1/4×1) = 5/6 ≈ **0.833**；
  - 两者严格等价：ROC 阶梯只有"垂直上升 = 抓真违约"和"水平右移 = 冤枉好人"两种动作，每个正样本贡献的面积 = 排在它前面的负样本比例 → **AUC = Mann-Whitney U 统计量 U/(n_pos×n_neg)**；
- 一句话：**AUC 测的是排序质量**——随机抽一正一负，正样本分数更高的概率；AUC=0.8 就这么解读；
- F1 vs AUC：F1 = 固定阈值下这个操作点好不好；AUC = 所有阈值下的整体排序能力；AUC<0.5 = 方向反了（取反得 ≈1−AUC）；AUC 不看校准只看排序，类别不平衡下依然有效。

### 5.4 偏差 / 方差（Day 9）
- **偏差（Bias）** = 平均预测偏离真值的程度（欠拟合）；**方差（Variance）** = 换一批数据预测值波动多大（过拟合）；
- 推导（数学主场，可手写）：设 `y = f(x) + ε`（ε 零均值噪声）：
  ```
  E[(y − f̂)²] = E[(f + ε − f̂)²]
              = E[(f − f̂)²] + σ²                    （交叉项 E[(f−f̂)ε]=0，因 ε 与 f̂ 独立且 E[ε]=0）
  E[(f − f̂)²] = (E[f̂] − f)² + E[(f̂ − E[f̂])²]     （中间加减一项 E[f̂]）
  合起来：MSE = 偏差² + 方差 + 噪声σ²
  ```
- 与复杂度关系（U 形曲线）：太简单偏差大、太复杂方差大；正则化（L2 / dropout / 早停）= 用一点偏差换很多方差；
- 与大模型的联系：大模型低偏差高方差 → 靠海量数据压方差；RLHF/指令微调 ≈ 一种"正则化"（Day 7/8"压支持集"思想的训练层版本）；思维链降低输出方差是"独立误差平均"在推理时的体现。

## 第六部分 · 本地模型接口化（Day 9）

### 6.1 五个名词（新名词必带简介）
| 名词 | 大白话 |
|---|---|
| **HTTP** | 超文本传输协议，计算机之间传消息的通用规则：请求/响应；GET = 取数据、POST = 提交数据 |
| **JSON** | 通用数据格式，`{"键": 值}`，Python 字典天然兼容（`json.loads` 一行解析） |
| **OpenAI 兼容 API** | 与 OpenAI 官方接口格式完全一致（同 URL `/v1/chat/completions`、同请求体 messages、同返回结构 choices）——所有"会调 OpenAI 的程序"改个地址就能调本地模型 |
| **FastAPI** | Python 现代 Web 框架：`@app.post(...)` 标注一个普通函数，它就自动变成接口 = 把"函数"变成"网上服务"的胶水 |
| **uvicorn** | 跑 FastAPI 的服务器（ASGI 服务器）：在端口上监听，来了请求转给 FastAPI 处理 |
| **ChatML** | Qwen 的对话标记格式（Chat Markup Language）：用 `<|im_start|>` 区分 system/user/assistant 三段；`build_chatml()` 是"接口格式 → 模型格式"的翻译官 |

### 6.2 返回 JSON 逐字段（面试默写素材）
```
{"id": "chatcmpl-xxxx", "object": "chat.completion", "created": 1750000000,
 "model": "Qwen2.5-3B-Instruct",
 "choices": [{"index": 0, "message": {"role": "assistant", "content": "回答"}, "finish_reason": "stop"}],
 "usage": {"prompt_tokens": 30, "completion_tokens": 80, "total_tokens": 110}}
```
- **骨架一句话**：快递面单（`id`/`created`/`model`）+ 装回答的数组 `choices`（`choices[0].message.content` 就是要的东西）+ 用量小票 `usage`；
- 逐字段：`chatcmpl` = chat completion 缩写、`object` = 类型标签、`created` = Unix 时间戳（1970 起秒数）、`finish_reason` = stop（自然说完）/ length（被 max_tokens 截断）、`usage` 三项 = 输入/输出/总计 token 数（token = 词元/令牌，模型处理文本的最小单位，中文约 1 字 1~2 token）。

### 6.3 为什么接口化（验收必答四点）
1. **前后端分离**：模型独立进程/机器跑，应用代码只发 HTTP 请求，模型挂了/换了应用零改动；
2. **统一调用**：OpenAI 格式是行业事实标准，切模型只改地址和模型名；
3. **语言无关**：HTTP + JSON 任何语言都能调（网页前端 / Java 后端 / 手机 App）；
4. **为 RAG demo 打底**：检索（Chroma）与生成（Qwen）松耦合拼起来。

### 6.4 无缝切换实证
- `ChatOpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY", model="Qwen2.5-3B-Instruct")` 调本地 Qwen 成功；
- **三处切换点**：`base_url` / `api_key` / `model`，其余代码一行不动；
- 数学类比：`f(x)` 调用方只依赖"签名"，不依赖"实现" = **面向接口编程，而不是面向实现编程**。

## 第七部分 · RAG 全链路（Day 10）

### 7.1 六个名词（新名词必带简介）
| 名词 | 大白话 |
|---|---|
| **RAG**（Retrieval-Augmented Generation，检索增强生成） | 先从资料库"查答案"，再让模型"组织答案"，专治模型不知道的私有/新资料 |
| **Embedding**（嵌入/文本向量化） | 把文本变成一串数字（向量），语义相近的向量距离近 |
| **Chroma** | 开源向量数据库：存"向量 + 原文"，负责相似度检索 |
| **余弦相似度** | `cos(a,b) = (a·b)/(|a||b|)`，两向量夹角的余弦，衡量方向一致程度 |
| **Top-K** | 取相似度最高的前 K 个片段 |
| **文本切块** | 把长文档按中文标点切成小块（chunk_size=500, chunk_overlap=50） |

### 7.2 全链路六步
```
PDF → ① 加载(PyPDF) → ② 切块(RecursiveCharacterTextSplitter，分隔符加中文标点。！？) 
   → ③ Embedding(bge-small-zh，每块 512 维向量) → ④ 入库(Chroma，余弦空间，存"向量+原文") 
   → ⑤ 检索(问题向量化 → 与库中向量算余弦相似度 → 取 Top-K) 
   → ⑥ 拼接模板 09（[N] 编号资料 + 问题）→ 交给 Qwen（Day9 接口，temperature=0.2）→ 带 [资料§N] 出处的答案
```

### 7.3 数学视角（两周知识打通的关键连接点）
- **检索 = 高维向量空间里的最近邻问题**：每段文本是 512 维向量，问题也是 512 维向量，"找最相关段落" = 找离问题向量最近的 K 个邻居；
- **"打分 → 取 Top-K → 融合"就是注意力三步走的同款套路**：
  ```
  第一周 Attention：对序列每个位置打分(softmax) → 取权重 → 加权求和(融合)
  今天 RAG：        对资料库每段打分(余弦相似度) → 取 Top-K → 拼进上下文(融合)
  ```
  Attention = 模型内部对 token 做**软性检索**；RAG = 模型外部对文档做**硬性筛选**；
- 切块 = 把"一大段高维混合信息"拆成"多块局部信息"，每块向量更纯净；重叠 50 字符保证关键信息不被从中间切断；chunk 编号 = 模板 09 里 [资料§N] 的 N。

### 7.4 为什么用 RAG 不用重新训练（三点对比）
| 对比 | 重新训练/微调 | RAG |
|---|---|---|
| 成本 | 要算力、数据、时间（小时~天级） | 只需 Embedding 向量化（分钟级）+ 检索 |
| 更新速度 | 每次资料更新都要重训 | 往向量库加一段立刻能检索 |
| 可解释性 | 说不清知识存哪了 | 答案带 [资料§N] 出处，能回溯 |

> 一句话：训练 = 把知识背进大脑；RAG = 考试时带资料进考场翻书。两者可配合（RAG 管事实性资料、微调管风格/能力）。

### 7.5 实测数字（全部亲手跑出）
- 默认 PDF（attention 论文中文版）：14 页 → 49 chunk；自己的 **GMR 论文**：9 页 → 105 chunk；
- GMR 论文 3 问全对（原理 / 优点 / 缺点），答案带 [资料§N] 出处、Top-K 检索片段与答案一一对应；
- **防幻觉验证**：问"GMR 的缺点"检索未召回相关段落 → 模型如实答「资料中没有提到」，没有编造；
- **手写版 vs LangChain 版**：`normalize_embeddings` 归一化 → `doc_vecs @ query_vec`（一行算余弦相似度）→ `np.argsort(scores)[::-1][:k]`（取 Top-K），结果与 LangChain 版基本一致——LangChain 只是把原理封装了；
- **实测坑位**（已修复）：langchain 1.x 拆包、bge 用 ModelScope 本地化、Chroma 重复入库（建库前自动清库）、Windows GBK 打不出 emoji（UTF-8 加固）。

## 第八部分 · 第二周综合自查卡（Q&A）

| 问题 | 答案 |
|---|---|
| 4bit 量化省多少显存？ | 权重压到 4 位 ≈ 1/4；实测 1.92GB 比预算 3.0GB 还省 1.08GB |
| temperature 数学上是什么？ | `p_i = exp(z_i/T)/Σexp(z_j/T)`，调概率分布形状（熵）；T 小尖、T 大平 |
| top_p 怎么运作？ | 概率排序 → 累加 → 截断（≥p）→ 重归一化 → 抽样 |
| 温度 vs top_p 区别？ | 温度动"概率值"（分布形状），top_p 动"候选名单"；一个动概率、一个动名单 |
| few-shot 为什么有效？ | 用示例做后验调整，把输出分布从高熵收成低熵 |
| 思维链为什么有效？ | 把高方差估计拆成多步低方差估计（条件化让每步分布变尖，0.95³≈0.857>0.8） |
| 五件套是什么？ | 角色 + 任务 + 输入 + 输出格式 + 约束条件 |
| 角色扮演的本质？ | 给条件分布强先验，触发预训练里的专家子分布 |
| 抑制幻觉的机制？ | 分布尖 ≠ 分布准；限定资料源 + 允许说不知道 + 要求标出处 |
| 模板 07 迭代结果？ | v1 乱码/合并 → v2 部分修复（date 好但 person 抽错）→ v3 四字段全对（双人同构示例 + 字段级约束） |
| LLM 算术为什么错？ | 算术是模式匹配不是计算；推理归模型、计算归代码 |
| AUC 的概率含义？ | 随机抽一正一负，正样本分数更高的概率（双视角同算 0.833） |
| MSE 分解？ | 偏差² + 方差 + 噪声σ² |
| 为什么接口化？ | 前后端分离 / 统一调用 / 语言无关 / 为 RAG 打底 |
| OpenAI 兼容 API 好处？ | 改 base_url / api_key / model 三处无缝切换 |
| ChatML 是什么？ | Qwen 的对话标记格式（`<|im_start|>` 区分角色），build_chatml = 翻译官 |
| RAG 是什么？ | 检索增强生成：先查资料再组织答案 |
| RAG 六步？ | 加载 → 切块 → Embedding → 入库 → 检索 Top-K → 拼接生成 |
| RAG 与注意力的关系？ | "打分→Top-K→融合"与注意力三步走同构（软性检索 vs 硬性筛选） |
| 为什么 RAG 不用重训？ | 成本低 / 更新快 / 可解释（带 [资料§N] 出处） |
| bge 向量多少维？ | bge-small-zh 输出 512 维 |

## 第九部分 · 面试一句话速查（按概率语言讲）

- **温度**："temperature 调的是 softmax 分布的熵——T 大熵大输出随机，T 小熵小输出稳定，等于连续调节概率分布的形状。"
- **top_p**："top_p 把候选词按概率排序累加、切掉长尾，只从核心词集里重新归一化抽样——一句话，温度动概率、top_p 动名单。"
- **few-shot**："few-shot = 用示例做后验调整：给几个输入-输出示例，把输出条件概率分布从大而平收成小而尖，风格格式判断标准全部对齐。"
- **思维链**："思维链 = 把一步到位的高方差估计拆成多步低方差估计，每一步条件化后分布变尖，全对概率反而更高——我本地实测正确率从 60% 提到 84%。"
- **写提示词的本质**："写提示词就是给模型加条件信息，把条件概率分布往目标方向压缩，约束每加一项支持集就小一圈。"
- **抑制幻觉**："分布尖不等于分布准——模型高置信的是'像不像人话'，不是'是不是事实'，所以 RAG 要限定资料源、允许说不知道、逼它标出处。"
- **LLM 算术**："我实测发现 3B 模型输出决策表格格式很标准但加权总分算错，说明 LLM 的算术是模式匹配不是计算——所以我的工程原则是推理归模型、计算归代码。"
- **接口化**："OpenAI 兼容接口 = 给模型装标准插座，应用只依赖函数签名不依赖实现，改 base_url/api_key/model 三处就能从 OpenAI 切到本地 Qwen。"
- **RAG**："RAG = 检索增强生成：先从向量库检索 Top-K，再让模型照资料组织答案；检索 = 高维最近邻 = 注意力三步走（打分→Top-K→融合）在模型外部的版本。"
- **AUC**："AUC = 随机抽一对正负样本，模型给正样本更高分的概率，测的是排序质量不是分数大小。"
