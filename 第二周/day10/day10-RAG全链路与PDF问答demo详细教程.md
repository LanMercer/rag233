## 📌 今天你要做什么（大白话版）

Day 9 结束时，你的 Qwen 是一个"什么都会点、但只知道训练时见过的旧资料"的助手。你问它**你自己最近写的论文、刚出的研报**，它只会瞎编或说不知道——因为它没见过这些资料。

今天你要给它装一个"**查资料的秘书**"，这个能力叫 **RAG**（检索增强生成）：

1. **先建资料库**：把你准备好的 PDF 切成小块（chunk），每块转成一个"向量"（数字串），连同原文一起存进 **Chroma**（向量数据库）；
2. **再问答**：用户提问时，先把问题也转成向量，到库里找出**最相似（Top-K）**的几段，把这几个段落拼进提示词（模板 09），连问题一起交给 Day 9 的本地接口；
3. **模型照着资料回答**：回答里带出处 `[资料§N]`，资料里没有的就说"资料中没有提到"——**专治大模型不知道的私有/新资料，顺便防幻觉**。

**今天结束时的"验收标准"一句话：**

> 上传一个自己准备的 PDF（论文 / 研报 / 教材章节），问 3 个基于 PDF 内容的问题，全部答对并能指出出处；能画出 RAG 链路结构图。

**和你的数学背景接上的点（今天会反复出现）：**

- **Embedding = 把文本映射到高维向量空间**：一段话变成 512 个实数，语义相近的两段话在空间里靠得近。检索本质上是在**高维空间里做"最近邻"查找**；
- **余弦相似度 = 两个向量夹角的余弦**：`cos(a,b) = (a·b) / (|a||b|)`，只关心"方向是否一致"，不关心长度——这在文本检索里比欧氏距离更常用；
- **Top-K = 取相似度最高的前 K 个**：这就是个排序问题，`argsort` 一行搞定；
- **检索 = "打分 → 取 Top-K → 融合"**：和你第一周学的**注意力三步走是同一个套路**——Attention 是"对序列里每个位置打分、加权求和"，RAG 是"对资料库每个片段打分、取最相关的拼起来"。**Attention 在模型内部做检索，RAG 在模型外部做检索**，思想完全同源。

## 🧱 第 1 步：概念先行（30~40 分钟）

> 对应周计划 8/12 第 1 条："概念：RAG = Retrieval-Augmented Generation……"。今天新名词有点多，但**每个都是"用大白话一句话讲清 + 一个类比"**，别被术语吓住。



### 1.1 六个核心名词（新名词必带简介）

- **RAG（Retrieval-Augmented Generation，检索增强生成）** = 先从资料库里"查答案"（Retrieval），再把查到的片段拼进提示词，让模型"组织答案"（Generation）。**一句话**：模型回答前先"翻书"，翻完书再答，而不是凭记忆瞎答。
  - 为什么需要它？**大模型的知识只到训练截止日期、且不含你的私有资料**。你问它自己刚写的研报内容，它不可能知道。RAG 让它"现查现答"——**不用重新训练，就能知道最新/私有的资料**。
- **Embedding（嵌入，文本向量化）** = 把一段文本变成一串数字（向量）。语义相近的两段话，它们的向量在空间里也靠得近。**一句话**：给文本"测坐标"，语义越像坐标越近。中文里常用 **bge**（BAAI 智源开源的 Embedding 模型，`bge-small-zh-v1.5` 专为中文优化，输出 512 维向量）。
- **向量数据库（Vector Database）** = 专门存"向量 + 原文"并支持**按相似度检索**的数据库。今天用 **Chroma**（开源、轻量、本地文件即可）。**一句话**：一个"按语义搜索"的仓库——不按关键词搜，按"意思像不像"搜。
- **余弦相似度（Cosine Similarity）** = 两个向量夹角的余弦值：`cos(a,b) = (a·b) / (|a||b|)`，取值范围 [-1, 1]。越接近 1 说明方向越一致（语义越像）。**一句话**：只问"方向一不一致"，不问"长短"——这是文本检索比欧氏距离更常用的原因（文本长度差异不影响"意思像不像"）。
- **Top-K（前 K 个）** = 排序后取相似度最高的前 K 个片段。K=4 是常用起点（答非所问时调到 8）。**一句话**：检索不是只拿 1 段，而是拿"最像的 K 段"一起喂给模型，信息更足。
- **文本切块（Chunking / 切分）** = 把长文档按规则切成小块（chunk）。为什么切？① 模型输入长度有限；② 一块一向量，检索"颗粒度"才合适——**整本书一个向量，检索就没意义了**。今天用 `RecursiveCharacterTextSplitter`（递归字符分割器）：按分隔符优先级从粗到细切分，分隔符列表里**加入中文标点（。！？；）**，否则中文句子会被从中间切碎（第二周避坑表第 4 条）。

> 顺带把两个工具名词也带上：**PyPDF** = 纯 Python 读 PDF 文本的库（对应全链路"文档加载"）；**LangChain** = Day 9 见过的大模型应用框架，今天用它的组件把六步串起来。



### 1.2 为什么是"检索"而不是"重新训练"？（面试必答）

面试官问"为什么 RAG 不用重新训练模型"，三个对比点背下来：


| 对比   | 重新训练/微调            | RAG（检索增强）                 |
| ---- | ------------------ | ------------------------- |
| 成本   | 要算力、要数据、要时间（小时~天级） | 只需 Embedding 向量化（分钟级）+ 检索 |
| 更新速度 | 每次资料更新都要重训         | 往向量库加一段，立刻就能被检索到          |
| 可解释性 | 说不清知识存哪了           | 答案带 `[资料§N]` 出处，能回溯       |


> **一句话记忆**：训练是"把知识背进大脑"，RAG 是"考试时带资料进考场翻书"——前者慢且贵，后者快且可追溯。实际应用中两者可以配合（RAG 管"事实性资料"，微调管"风格/能力"），但那是第 3 周 LoRA 微调的主题了。



### 1.3 数学视角：RAG 的"魂"是最近邻 + 注意力同款套路

- **检索 = 高维向量空间里的最近邻问题**：每段文本是一个 512 维向量，问题也是一个 512 维向量。"找最相关段落" = 在 512 维空间里找离问题向量"最近的 K 个邻居"。这个"近"用余弦相似度度量；
- **"打分 → 取 Top-K → 融合"就是注意力三步走的同款套路**：

```
第一周 Attention：对序列每个位置打分(softmax) → 取权重 → 加权求和(融合)
今天 RAG：        对资料库每段打分(余弦相似度) → 取 Top-K → 拼进上下文(融合)
```

  Attention 是"在模型内部、对 token 做软性检索"；RAG 是"在模型外部、对文档做硬性筛选"。**面试时主动说出这个类比，会非常加分**——说明你把两个模块打通了。

### 2.1 第 ① 步：文档加载（PyPDF）

- **输入**：一个 PDF 文件；**输出**：按页读出的文本列表。
- `PyPDFLoader(path).load()` 返回 `list[Document]`，每个 `Document` 有 `page_content`（该页文本）和 `metadata`（页码等）。
- **坑**：PDF 分两种——"文本型"（能直接抠出文字，论文/研报大多如此）和"扫描图片型"（抠不出字，需要 OCR，今天不涉及）。如果建库后检索结果很怪，先 `print` 几页看看抽出来的文字是不是正常的。



### 2.2 第 ② 步：文本切块（RecursiveCharacterTextSplitter）

- **输入**：整篇文档；**输出**：`chunk_size` 大小的多个 chunk，相邻重叠 `chunk_overlap`。
- 今天配置（周计划避坑表第 4 条的落地）：`chunk_size=500`、`chunk_overlap=50`，`separators=["\n\n", "\n", "。", "！", "？", "；", ".", "! ", "? ", "; ", " ", ""]`。
- 为什么要**重叠**？一句话的语义可能横跨两块——重叠 50 字符能尽量保证"关键信息不刚好被从中间切断"。
- **数学视角**：切块 = 把"一大段高维混合信息"拆成"多块局部信息"，让每块向量更"纯净"——类比把一个复杂分布拆成几个好估计的子分布（Day 8 少样本思想的老朋友）。
- 代码里顺手给每个 chunk 编了号 `chunk_id`（0,1,2,...）——**这就是模板 09 里** `[资料§N]` **的 N**，建库时自动编号，Day 8 模板原样复用。



### 2.3 第 ③ 步：Embedding（bge-small-zh）

- **输入**：一批文本；**输出**：每个文本一个 512 维向量（`len=512` 的浮点数组）。
- `HuggingFaceEmbeddings(model_name=本地bge路径)` 一行拿到模型。代码指向 `download\bge-small-zh-v1.5`（第 0.5 步下载好的本地目录，**本地加载免联网**）。bge 模型输出 512 维向量。
- **数学视角**：这个模型训练时学会的是"把意思相近的句子映射到相近的向量"——本质是学了一个从"句子空间"到"512 维语义空间"的映射，余弦距离越小 = 语义越近。**这就是把 NLP 问题变成了几何问题**，正是你的主场。



### 2.4 第 ④ 步：存入 Chroma

- **输入**：chunks + embedding 模型；**输出**：一个持久化在 `.\chroma_db` 的向量库。
- `Chroma.from_documents(documents=chunks, embedding=embedder, persist_directory=...)`——它会自动：给每块算向量 → 存向量 + 原文 + metadata → 落盘。
- **关键配置**：`collection_metadata={"hnsw:space": "cosine"}` 指定用**余弦空间**做相似度度量（Chroma 默认是 L2 距离，不指定的话后面"余弦相似度"就不名副其实）。
- **为什么存原文**？向量只用来"比谁近"，但最终喂给模型的必须是**人类可读的原文**——所以库里是"向量（用于检索）+ 原文（用于生成）"成对存的。



### 2.5 第 ⑤ 步：检索（余弦相似度 + Top-K）

- **输入**：一个问题；**输出**：Top-K 个最相似的 chunk（带相似度分数）。
- 过程：问题 → 同样用 bge 向量化 → 和库中 N 个向量逐个算余弦相似度 → 降序排序 → 取前 K 个。
- **数学视角**：这就是"高维空间最近邻问题"——N 个候选，一次矩阵乘法全算完（`向量库矩阵 @ 问题向量`），再用 `argsort` 排序。512 维 × 几百个 chunk 对这种"暴力最近邻"毫无压力；数据量大了才需要 ANN（近似最近邻）算法加速（这是后话，面试知道名字即可）。



### 2.6 第 ⑥ 步：拼接上下文 + 生成

- **输入**：Top-K 片段 + 问题；**输出**：带出处的答案。
- 拼接：每段格式化成 `[N] 文本`（N = chunk_id），多段用换行拼成"资料"，套进 **模板 09**（Day 8 打磨好的 RAG 标准版：角色 + 【资料】+ 防幻觉约束 + 出处要求 + 长度约束）。
- 生成：把这个提示词 POST 给 Day 9 的 `/v1/chat/completions` 接口（`temperature=0.2` 低温——**RAG 问答要"稳"，不要发散**）。
- 这一步的价值：**模型的任务从"凭记忆回答"变成"照着资料组织答案"**——资料给了它事实，模板约束它别编造、标出处，这就是 RAG 防幻觉的机制。

## 🔬 第 4 步：手写简化版（40~60 分钟）⭐ 懂原理

> 对应周计划 8/12 第 4 条后半："再手写简化版（懂原理）"。LangChain 一行 `similarity_search` 就把检索封装了，你反而看不到"余弦相似度"到底长什么样——手写版把这一层拆开，**让你亲手写出"打分 → 排序 → 取 Top-K"**。



### 4.1 为什么要手写？

面试被问"RAG 的检索具体怎么算的"，你不能只说"调了个库"。手写版让你能讲出：

> "检索 = 把问题和每段资料都转成 512 维向量，算余弦相似度 `cos(a,b)=a·b/(|a||b|)`，归一化后点积即可；然后降序取前 K 个拼进提示词。"

——这比"我用了 Chroma"有说服力得多。

### 4.2 手写版 vs LangChain 版（对照表）


| 环节    | LangChain 版（ask.py）     | 手写版（manual_rag.py）                        |
| ----- | ----------------------- | ----------------------------------------- |
| 数据    | 从 Chroma 库读             | 从 `chunks.json` 读（**同一批切块**，保证可比）         |
| 向量化   | `HuggingFaceEmbeddings` | `SentenceTransformer`（底层同一个 bge 模型）       |
| 余弦相似度 | Chroma 内部算              | `doc_vecs @ query_vec` **自己算**（归一化后点积=余弦） |
| Top-K | 库方法返回                   | `np.argsort(scores)[::-1][:k]` **自己取**    |
| 生成    | 调 Day9 接口               | 调 Day9 接口（同一处）                            |


**结论**：两个版本检索结果应该高度一致（相似度排名基本相同），生成层完全同一个接口——这就验证了"LangChain 只是把原理封装起来了"。

### 4.3 读 `manual_rag.py` 的关键三行

1. **向量化**：`model.encode(texts, normalize_embeddings=True)`——`normalize_embeddings=True` 让所有向量长度=1，于是点积 = 余弦相似度（分母 `|a||b|=1` 消失了）；
2. **余弦相似度**：`scores = doc_vecs @ query_vec`——一行矩阵乘法，算出问题向量和 N 个 chunk 向量的所有相似度（数学上就是 N 个点积）；
3. **Top-K**：`np.argsort(scores)[::-1][:k]`——从大到小排序取前 k 个下标。

> 额外一个 bge 小技巧：bge 官方建议检索时给**问题**加固定前缀 `"为这个句子生成表示以用于检索相关文章："`（库内文档不加）——能提升检索精度。手写版里演示了，LangChain 版为了简单没加，跑出来效果差异不大，但知道这个 trick 面试能聊。

### A. 力扣 382. 链表随机节点（中等 · 蓄水池抽样）⭐ 数学加成收官题

**题目**：给定一个单链表，随机返回一个节点的值，要求每个节点被选中的概率相等（不允许事先知道链表长度，也不能用额外数组存全部值）。

**蓄水池抽样（Reservoir Sampling）** 思路：从头到尾遍历，维护一个"幸运儿"：

- 第 1 个节点：直接选它（概率 1）；
- 第 i 个节点（i≥2）：以概率 `1/i` 替换当前幸运儿，以概率 `(i-1)/i` 保留原幸运儿。

**数学视角（必考，能推导）**：为什么最终每个节点被选中的概率都是 `1/n`？
对第 k 个节点，它被选中的充要条件是：在 k 时刻被选中（概率 `1/k`），且之后每个时刻 i（k<i≤n）都**不被替换**（概率 `(i-1)/i`）。连乘：

```
P(第k个节点最终胜出) = (1/k) × (k/(k+1)) × ((k+1)/(k+2)) × … × ((n-1)/n)
                    = 1/n
```

中间的分子分母全部约掉，只剩 `1/n`——**这就是一个裂项相消**，所有节点对称地都是 `1/n`。这题是总纲点名的"概率/统计类题务必拿下"的收官题。

**实现**（O(n) 时间、O(1) 空间）：

```python
class Solution:
    def __init__(self, head):
        self.head = head

    def getRandom(self) -> int:
        ans, i = self.head.val, 1
        cur = self.head.next
        while cur:
            i += 1
            if random.randrange(i) == 0:   # 以 1/i 概率替换
                ans = cur.val
            cur = cur.next
        return ans
```

做完提交到 GitHub `leetcode` 仓库（`链表` 分类），题解注释写"数学视角"（概率连乘 + 裂项相消）。
