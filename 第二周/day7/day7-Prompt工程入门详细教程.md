## 🧠 第 2 步：三个核心概念 + 结构化提示词公式（30~40 分钟）

> 对应周计划 8/9 第 2、3 条。**新名词必带简介**——下面每个概念都按"是什么 / 一句话记忆 / 例子"来写。

### 2.1 Prompt 工程（提示词工程）

- **是什么**：设计给模型的文字（叫 **prompt**，提示词），引导它输出我们想要的结果。写提示词 = 给模型设条件、框边界。
- **为什么重要**：模型的能力一半靠模型本身，一半靠你怎么"说话"。对应用开发者来说，Prompt 是**性价比最高的"参数"**——不花钱、不用训练，改几个字就能提升输出质量。
- **一句话记忆**：Prompt 工程 = 给聪明助手写一份它看得懂的"需求文档"。

### 2.2 few-shot（少样本学习 / 少样本提示）

- **是什么**：**few** = 少，**shot** = 例子。在提示词里给几个"输入 → 输出"示例，模型照着示例的风格、格式、判断标准来回答。
- **三步演示**（你可以在纸上感受一下）：

  ```
  输入: "苹果"   → 输出: "水果"
  输入: "老虎"   → 输出: "动物"
  输入: "玫瑰"   → 输出: ___（模型会答"花"，因为前面两个例子教会了它"输出类别"）
  ```
- **对应名词**：
  - **zero-shot（零样本）** = 不给示例直接问；
  - **one-shot / few-shot** = 给 1 个 / 给几个示例；
  - 示例给太多（几十个）效果不一定更好，还占上下文窗口，常用 1~5 个。
- **什么时候用**：输出格式复杂（JSON、表格）、需要特定风格（正式/幽默）、需要模型模仿某种判断标准时——"光说不练假把式"，给例子比下命令好用。
- **一句话记忆**：few-shot = **先示范，再让模型照着做**。

### 2.3 思维链（Chain of Thought，简称 CoT）

- **是什么**：让模型**把推理过程一步步写出来，再给结论**。触发词常用"请一步步思考""Let's think step by step"。
- **为什么有用**（对比例子）：
  - 直接问："小明有 3 个苹果，又买了 5 个，吃掉 2 个，还剩几个？" → 模型可能直接猜；
  - 加一句"**请一步步计算**" → 模型先写 3+5=8，再写 8−2=6，答案稳了。
- **适用于**：数学题、逻辑推理、多条件判断、复杂抽取。**不适用于**：简单任务（杀鸡用牛刀，还浪费 token）。
- **一句话记忆**：思维链 = **把"心里算"改成"写算式"**——过程和结果一起给你。

### 2.4 结构化提示词公式：`角色 + 任务 + 输入 + 输出格式 + 约束条件`（五大件）

这是今天最重要的"生产工具"，所有模板库的模板都按它拆解：

| 部件 | 作用 | 示例 |
|------|------|------|
| **角色** | 设定立场/知识背景 | "你是一名资深的风险分析师" |
| **任务** | 让模型做什么 | "请评估这笔贷款申请是否通过" |
| **输入** | 要处理的对象 | 用户提供的文本、数据、问题 |
| **输出格式** | 规定长什么样 | "只输出 JSON""用 3 个要点列出" |
| **约束条件** | 划边界 | "只依据资料回答，没有就说不知道""不超过 100 字" |

一个标准模板（对照着看五件套）：

```
你是一名资深的风险分析师。（角色）
请根据下面这笔贷款的申请信息，判断是否批准。（任务）
申请信息：{input}（输入）
只输出 JSON，字段为 approved（bool）和 reason（string）。（输出格式）
请只依据申请信息做判断，信息不足时 reason 写"信息不足"。（约束条件）
```

### 2.5 🔢 数学原理小课堂：few-shot 与思维链为什么有效

> 先看懂原理，再动手。这一节是今天"数学视角"的主菜，正好接上 Day 3 的 softmax 和 Day 6 的温度实验。

**先回顾两件旧事：**
1. 模型每生成一个词，都是从条件概率分布 `P(下一个词 | 上文)` 里抽样；整段回答 = 一路乘条件概率；
2. 温度调的是这个分布的**熵**（形状），熵越大输出越随机（Day 6 你亲手验证过）。

今天的核心视角是：**"上文"里拼进什么，模型的分布就"条件"在什么上。写提示词，就是在给模型设条件。**

---

**2.5.1 few-shot = 用样本修正条件概率分布**

- **零样本时**：模型可依据的只有问题 x，输出分布是 `P(回答 | 问题)`。这个分布很"野"——模型不知道你期望什么风格、什么格式、什么判断标准，可能用任何方式回答（高熵）。
- **few-shot 时**：你把 k 个示例对 (x₁,y₁)…(xₖ,yₖ) 拼进提示词，模型实际按 `P(回答 | 问题, 示例₁…示例ₖ)` 抽样。示例相当于**观测数据**：模型用预训练知识 + 示例"更新"输出分布，把概率质量压到"跟示例同分布"的区域——风格、格式、判断标准全部对齐。
- **统计语言**：示例 ≈ 从"目标输出分布"里抽来的小样本；few-shot ≈ 用样本对输出分布做**后验调整**（贝叶斯视角：先验 `P(回答|问题)` 被示例"更新"成后验）。
- **一句话**：**few-shot 把输出分布从"大而平"（高熵）收成"小而尖"（低熵）**，示例越贴任务，输出越可控。这和 Day 6"调温度"拧的是同一个东西——熵，只是改法不同：温度是旋钮，示例是数据。

---

**💡 小贴士：先验 / 后验 / 贝叶斯，到底是什么？**（第一次看到这三个词的新手必读）

只用 10 秒记三个词：**先验 = 你猜的；后验 = 看到数据后修正的；贝叶斯 = 一套"用数据修正猜测"的数学规则。**

**① 先验（prior）——"还没看到数据前，你先入为主的判断"**

- 在拿到任何证据之前，你基于经验/常识/上一轮知识就有的"底数"。
- 例：你明天面一家银行，我先猜"拿 offer 的概率 70%"——这个 70% 就是先验；我完全不认识你随便猜"50% 对半"——那也是个先验（更无信息的先验）。

**② 后验（posterior）——"看到数据之后，更新过的判断"**

- 先验 + 新证据，按贝叶斯规则算出来的新概率。
- 例：我原本猜 70%（先验），然后收到新信息"这个岗已经内定别人了"→ 我立刻把概率下调到 5%——**这个 5% 就是后验**。
- 后验永远"掌握当前所有信息"下的概率，明天来了新消息还会变；而且**后验会变成下一轮的先验**（这就是贝叶斯能持续学习的原因）。

**③ 贝叶斯定理（Bayes' Theorem）——"更新的数学公式"**

\[
P(H|D) = \frac{P(D|H)\cdot P(H)}{P(D)}
\]

| 符号 | 含义 | 大白话 |
|---|---|---|
| \(P(H)\) | 先验 | 看到数据 D **之前**，假设 H 成立的概率 |
| \(P(D\|H)\) | 似然 | 假设 H 真成立时，产生这堆数据 D 的概率（数据对假设的"配合程度"） |
| \(P(D)\) | 证据 | 无论假设成不成立，产生 D 的总概率（起"归一化"作用，保证概率加起来等于 1） |
| \(P(H\|D)\) | **后验** | 看到 D **之后**，H 成立的概率 |

整个公式的直觉一句话：**后验 = 先验 × 数据对假设的支持程度，再归一化。** 数据越支持假设 → 后验比先验更相信它；数据不支持 → 后验更怀疑它；数据与假设无关 → 后验 ≈ 先验（没更新）。

**④ 套回 few-shot（教程那句话的完整版）**

| few-shot 概念 | 套贝叶斯语言 |
|---|---|
| 只有问题、没有示例时，模型"可能随便怎么答"的输出分布 | **先验** \(P(回答\|问题)\) |
| 你塞进 2 个示例 (x₁→y₁)(x₂→y₂) | **新数据** |
| 示例给出你期望的风格/格式/标准，相当于数据对回答的支持度 | \(P(D\|H)\)（似然） |
| 模型最后"照着示例风格输出"的分布 | **后验** \(P(回答\|问题, 示例)\) |

所以那句话 = **给示例 = 给模型喂新数据 = 让输出分布从"没看过示例"更新到"看过示例"**。"示例把分布从高熵收成低熵"，用贝叶斯话讲就是"先验被更新成后验，不确定性下降"。

**⑤ 一个统计人秒懂的类比**：贝叶斯更新和你做**样本均值估计**是同构的——先验 μ₀ 和样本均值 \(\bar{x}\) 按"精度"（方差倒数）加权平均：样本越多越偏向数据、先验被稀释；样本越少先验主导。**先验是起点，数据是方向盘，后验是终点。**

**2.5.2 思维链 = 把高方差估计拆成多步低方差估计**

- **一步到位**：直接回答一个复杂问题，等价于**一步估计一个复杂函数** `f(问题)`。真实推理里任何一个小环节出错，最终答案就崩——这是**高方差估计**：方差大，容易整体翻车。
- **思维链**：让模型先输出中间步骤 s₁ → s₂ → … → 答案。每一步只估计一个**更简单**的条件分布 `P(sᵢ₊₁ | 问题, s₁…sᵢ)`——候选空间小、分布更尖、单步出错率低。
- **概率表达（链式法则）**：

  ```
  P(过程, 答案 | 问题) = P(s₁|q) · P(s₂|q,s₁) · … · P(答案|q, 全部步骤)
  ```

  模型显式写出中间变量 = 把"答案的概率"分解成一步步条件概率的乘积，每一步都在自己最有把握的地方做判断，而不是最后一步"一锤定音"。
- **统计同学最好记的版本（方差分解）**：

  ```
  Var(Y) = E[Var(Y|X)] + Var(E[Y|X])
  ```

  引入条件变量 X（中间步骤）能消掉一部分**不可控方差**。思维链干的正是这件事：用中间步骤当"条件变量"，把整体估计逐步降方差、降出错率。
- **一句话**：**一步到位 = 高方差点估计；思维链 = 用中间变量把复杂估计拆细，逐步降方差。**

---

**💡 展开详解：为什么"拆成多步"就比"一步到位"更稳？（新手友好版）**

**① 先打个比方：考试写过程 vs 直接填答案**

想象你考一道 4 步应用题，满分 10 分：

- **版本 A（一步到位）**：你直接在答题卡写"6"。只要中间任何一步算错，6 就是错的，整题 0 分；
- **版本 B（思维链）**：你写"3+5=8，8−2=6，所以答案 6"。就算某一步笔误，你自己在写的过程中也更容易发现；而且每写一步，下一步的选择范围就缩小一圈。

模型完全一样：直接问 → 它"一口气"从巨大输出空间里猜一个答案，任何小错都直接进答案；让它把过程写出来 → 每写一步都只面对一个很小的"下一步选择"，写的过程本身在帮它锁定正确路径。

**② 关键数字直觉：不是"多步"本身降方差，而是"每一步变简单"**

假设模型"一次性做对整道题"的概率是 0.8；拆成 3 步后，每一步因候选变少、任务变简单，单步做对概率升到 0.95：

- 一步到位整体做对：0.8 = 80%
- 思维链三步全对：0.95 × 0.95 × 0.95 ≈ 0.857 = 85.7%

> 注意：如果拆步后单步正确率还停在 0.8，那 0.8³ = 0.512 反而更差。所以思维链有效的**真正原因不是"多步"，而是"条件化让每一步的分布变尖"**——候选少 → 熵低 → 单步方差小 → 乘起来整体反而更稳。

**③ 苹果题逐步演示（对应上面那条链式法则）**

问题："小明有 3 个苹果，又买了 5 个，吃掉 2 个，还剩几个？"

| 做法 | 过程 | 候选空间 | 熵/方差 |
|---|---|---|---|
| 一步到位 | 直接猜最终答案 | {3, 5, 6, 8, 10, 不知道, …} | 高熵、高方差，任何小错全盘皆输 |
| 思维链第 1 步 | 写 \(3+5=8\) | 几乎只有 8 一个候选 | 极低熵 |
| 思维链第 2 步 | 写 \(8-2=6\) | 上文已是"3+5=8"，只需算 8−2 | 更低熵 |
| 思维链第 3 步 | 写"答案 6" | 过程已写全，无歧义 | 几乎零方差 |

每一步都在"已知上一步"的条件下继续 → 条件分布一个比一个尖 → 单步出错率低 → 乘起来整体正确率高。

**④ 方差分解公式逐词翻译**

\[
Var(Y) = E[Var(Y|X)] + Var(E[Y|X])
\]

把 \(Y\) 当"最终答案"，\(X\) 当"中间步骤"：

- 左边 \(Var(Y)\)：**一步到位时**，模型对最终答案估计的总方差（总不确定性）；
- 右边第一项 \(E[Var(Y|X)]\)：**已知中间步骤 X 之后**，答案剩余的平均不确定性；
- 右边第二项 \(Var(E[Y|X])\)：由 X 的变化"解释/引起"的那部分方差。

公式直接告诉我们：**条件化只会让剩余方差 ≤ 总方差**（\(E[Var(Y|X)] \le Var(Y)\)）。思维链干的就是把中间步骤 \(X\) 显式写出来当条件，让模型不再"一次扛下全部方差"，而是逐步消化——每多一个条件，剩余方差就往下压一截。

> 统计版直觉：这和你做回归/ANOVA"每引入一个解释变量，残差就变小一块"是同一个道理。

**⑤ 一个你本行的记忆锚点：条件期望分层**

对统计硕士，"先按 X 分层、再在层内估计"最对味：

- **一步到位 = 不分层硬猜**——整个 Y 的分布一起估计，方差全扛；
- **思维链 = 一层层缩小范围再猜**——先定 s₁，再在 s₁ 条件下定 s₂……每层都在一个更细的"分层"里做判断，层内候选空间小、方差小。

\[
Var(Y) = E[Var(Y|X)] + Var(E[Y|X])
\]

就是那个"分层方差分解"的公式，一模一样。

**⑥ 一句话收尾**

> 一步到位 = 高方差，一个小错全盘皆输；思维链 = 把答案拆成条件概率的乘积，每一步候选变少、分布变尖、方差变小，最后"全对"的概率反而更高。

---

**2.5.3 结构化提示词公式 = 压缩输出分布的支持集**

- 角色 / 任务 / 输出格式 / 约束条件，每加一项，都在缩小"模型可能输出的集合"（数学上叫**支持集** support）→ **条件熵下降** → 输出更稳、更可预测。
- 和 Day 6 打通：温度是"连续旋钮式"调熵，约束条件是"结构式"压熵。两者管的是同一个东西——**输出的不确定性**。
- 面试话术（拿去用）：**写提示词的本质 = 不断给模型加条件信息，把条件概率分布往你要的方向压缩。**这句话，面试官听了会点头。

### 加餐 0：先看实验设计（30 秒，记住核心逻辑）

A/B 实验的标准套路：**控制变量，只改一个条件，重复 N 次，统计"成功/合规"的频率**。

| 实验 | 对照组 | 实验组 | 量化指标 |
|------|--------|--------|---------|
| 实验 A | zero-shot（不给示例） | few-shot（给 2 个示例） | 输出"格式合规率" |

| 实验 C | temperature=0.2 | temperature=0.9 | 输出"合法 JSON 比例" |

- N 默认 5 次（可加命令行参数改），每次生成都在**新的独立抽样**下进行；
- 频率 = 成功次数 / N，就是我们估计的"真实概率"——这正是你统计课里最熟的 `频率 ≈ 概率`（大数定律）。

### A. 力扣刷题 2 道（字符串进阶）

1. **14. 最长公共前缀**（简单）：逐个字符串、逐列比较所有字符串同一位置字符是否一致。**数学视角**：公共前缀 = 多个集合的"交集"最前段，逐列做"一致性和检验"，遇到不一致就停。
2. **415. 字符串相加**（数学思维）：两个数字字符串逐位相加，模拟进位。**数学视角**：这就是小学列竖式加法——从低位到高位逐位加，`carry`（进位）像"余数"一样向高位传递。

做题方法不变：先自己想 10 分钟 → 看题解 → 用自己的话讲一遍 → 提交到 GitHub `leetcode` 仓库（按 `字符串` 分类）。

### B. 统计八股 10 分钟：准确率 / 精确率 / 召回率

- 先记混淆矩阵四格：**TP**（正例判成正）、**FP**（负例判成正）、**FN**（正例判成负）、**TN**（负例判成负）；
- **准确率 Accuracy** = (TP+TN) / 全部。适用：正负样本均衡时；类不平衡时会骗人（99 个负例 1 个正例时"全判负"准确率也有 99%）；
- **精确率 Precision** = TP / (TP+FP)。回答"**查出来的里有多少是对的**"；
- **召回率 Recall** = TP / (TP+FN)。回答"**该找出来的里找回了多少**"；
- 银行风控例子（把"违约"当正例）：精确率高 = 被拒客户里真违约的比例高（少误伤）；召回率高 = 真违约的人被拦下得越多（少漏网）。两者此消彼长，实际用 F1 平衡（明天 8/10 学）。

> 零散时间就 10 分钟，能说清三个公式和"查全 vs 查准"的权衡就够。

## 🚧 常见问题速查表（出问题先看这里）

| 现象 | 原因 | 解决办法 |
| ----------------------------------- | --------------------------- | ------------------------------------------------------------------------- |
| 模型加载报错"找不到模型" | 模型路径不对 | 检查 `prompt_test.py` 顶部 `MODEL_PATH` 与 `download\Qwen2.5-3B-Instruct` 实际位置是否一致 |
| 第一个模板就 `CUDA out of memory` | 显存被占满 | 关浏览器等程序、重开终端；`MAX_NEW_TOKENS` 改小（如 100） |
| 某个模板答非所问 | 提示词太笼统 | 用五件套补齐：加角色、加输出格式、加约束条件 |
| JSON 输出不合法（带多余文字） | 模型自由发挥了 | 约束条件写明"只输出 JSON 对象，不要任何解释文字"；`temperature` 降到 0.3 重试 |
| 想要固定格式但模型不听话 | 零样本描述不够 | 加 1~3 个 few-shot 示例，比改命令管用 |
| 生成到一半被截断 | `max_new_tokens` 太小 | 调大；或在约束里写"答案 3 句以内" |
| 中英文模板混着用结果混乱 | 提示词语言与要求不匹配 | 中文模板写中文指令、英文模板写英文指令，指令语言和期望输出语言保持一致 |
| 终端中文乱码 | Windows 控制台编码 | 先执行 `chcp 65001` 再运行 |

## 📎 附录：prompt_test.py 怎么读（给想看懂代码的你）

结构很简单，按顺序读：

1. **头部五件套注释**：模型（Qwen2.5-3B-Instruct 4bit）、数据（10 个手工模板 + 测试输入）、损失（无）、优化器（无）、做的事（加载 → 逐模板生成 → 输出实测记录）；
2. `build_chat_prompt()`：把 system / user 文字套进 Qwen 的 ChatML 对话格式（和 Day 6 一致）；
3. `generate()`：核心生成函数，`temperature=0.7, top_p=0.9`（Day 6 实验过的最稳组合）；
4. `TEMPLATES` 列表：10 个模板，每个是 `{id, name, category, lang, template, test_input}`——`template` 里的 `{input}` 占位符会在运行时被 `test_input` 替换；
5. 主流程：加载模型 → 按命令行参数（默认全部）依次生成 → 打印结果。

**想加新模板**：在 `TEMPLATES` 列表末尾复制一个字典，改 `id/name/template/test_input` 即可，无需改其他代码。想改生成长度：改 `MAX_NEW_TOKENS`。

## 📎 附录 B：prompt_ab_test.py 怎么读（加餐实验脚本）

结构和 `prompt_test.py` 一致，多出来的三个实验函数是重点：

1. **`run_experiment_a()`**（few-shot 实验）：同一道"词分类"题，zero-shot 只写指令、few-shot 在前面加 2 个示例；各跑 N 次，用 `is_format_ok()` 判断输出是否为四类词之一，统计合规率；
2. **`run_experiment_b()`**（思维链实验）：5 道小学数学题，直接问 vs 加"请一步步思考"；各跑 N 次，用 `is_correct()`（在输出里找正确答案数字）判分，统计正确率；
3. **`run_experiment_c()`**（温度实验）：同一个 JSON 抽取模板，`temperature=0.2` vs `0.9`；各跑 N 次，用 `try_parse_json()`（截取 `{}` 后 `json.loads`）判断合法性，统计合法比例；
4. **命令行**：`python prompt_ab_test.py` 默认每组 5 次；`python prompt_ab_test.py 3` 改每组 3 次；`python prompt_ab_test.py 3 A C` 只跑实验 A 和 C。

**想改实验内容**：改对应实验函数里的 `zero_shot_prompt` / `few_shot_prompt` / 题目列表 / 判断函数即可。判断规则写得简单（找数字、找 JSON），只是为了**方向性**结论——真实论文里需要更严格的自动判分，但对我们今天的"感受变数字"目标足够。

> 提醒：加餐实验每个条件重复 N 次，单次生成是**随机的**（temperature>0），所以你的具体数字每次跑会略有不同——这是正常的抽样波动，看方向和大致量级即可，别纠结单次数值。

> 提醒：教程里所有"预期输出"都是示例，**以你实际跑出的结果为准**——跑出来不一样先别慌，看是不是方向性差异（比如 JSON 是否合法、few-shot 是否更贴合要求），把截图发我一起看。
