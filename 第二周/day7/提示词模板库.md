## 一、怎么用这个模板库（30 秒上手）

1. **挑模板**：按"类别 + 语言"找；
2. **替换占位符**：把模板里的 `{input}` 换成你的内容；
3. **发给模型**：本地 Qwen（`python prompt_test.py`）或任意兼容 API；
4. **调参数**（Day 6 的知识）：事实问答 `temperature` 用 0.2~0.5；创意写作 0.8~1.2；JSON 输出务必调低温度。

**五件套回忆**：角色 + 任务 + 输入 + 输出格式 + 约束条件 —— 每个模板都能拆成这五件。

## 三、模板详情

### 模板 01｜中文要点总结

- **类别 / 语言**：总结 / 中文 ｜ **适用场景**：新闻、报告、论文段落压缩成要点
- **提示词模板**：
  ```
  请把下面这段文字总结成 3 个要点，每个要点不超过 20 个字，用「-」开头逐条列出：

  {input}
  ```
- **测试输入**：
  ```
  LangChain 是一个用于构建大模型应用的框架，它把模型调用、提示词管理、向量检索、工具调用等能力封装成标准组件，让开发者能快速拼装出完整的 AI 应用。它支持多种大模型、多种向量数据库，是目前 RAG 应用开发最常用的框架之一。
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  - LangChain 是构建 AI 应用的框架
  - 支持多种大模型和向量数据库
  - 快速拼装完整 AI 应用
  ```
- **备注 / 可改造点**：可加 few-shot 示例（见教程 3.5）；要点数量、字数约束都是可调参数

### 模板 02｜English Summarize

- **类别 / 语言**：总结 / 英文 ｜ **适用场景**：英文文献、英文新闻压缩成一句话
- **提示词模板**：
  ```
  Summarize the following text in ONE sentence (no more than 30 words).
  Output only the summary:

  {input}
  ```
- **测试输入**：
  ```
  Retrieval-Augmented Generation (RAG) is a technique that combines a retrieval system with a text generator. Given a question, the system first searches a knowledge base for relevant passages, then feeds those passages to the language model as context. This allows the model to answer questions about private or recent documents that it has never seen during training.
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  RAG uses a retrieval system to find relevant documents and a text generator to answer questions based on that context, enabling responses to private or recent information not seen during training.
  ```
- **备注 / 可改造点**：字数限制"no more than X words"是约束条件，可调

### 模板 03｜中译英

- **类别 / 语言**：翻译 / 中→英 ｜ **适用场景**：中文材料翻译成英文
- **提示词模板**：
  ```
  请把下面的中文翻译成英语，要求准确、自然、忠实原意，只输出译文：

  {input}
  ```
- **测试输入**：
  ```
  机器学习是一门前沿学科，它让计算机从数据中自动学习规律，而无需人工编写每一条规则。
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  Machine learning is an emerging field that enables computers to automatically learn patterns from data without the need for manual programming of each rule.
  ```
- **备注 / 可改造点**：加角色"你是一名专业译者"；可加风格约束（正式/口语）

### 模板 04｜英译中

- **类别 / 语言**：翻译 / 英→中 ｜ **适用场景**：英文资料翻译成中文
- **提示词模板**：
  ```
  Please translate the following English into natural Chinese.
  Output only the translation:

  {input}
  ```
- **测试输入**：
  ```
  Prompt engineering is the practice of designing input text that guides a language model to produce the desired output. Well-designed prompts can dramatically improve answer quality without retraining the model.
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  prompt 工程是设计输入文本以引导语言模型生成所需输出的实践。精心设计的提示可以在不重新训练模型的情况下显著提高回答的质量。
  ```
- **备注 / 可改造点**：可要求"保留术语不译"或"加术语注释"

### 模板 05｜正式化改写

- **类别 / 语言**：改写 / 中文 ｜ **适用场景**：口语、草稿改成书面汇报风格
- **提示词模板**：
  ```
  请把下面这句话改写成更正式、更适合书面汇报的风格，保持原意不变，只输出改写结果：

  {input}
  ```
- **测试输入**：
  ```
  这个模型跑起来挺快的，显存占得也不多，用来做问答 demo 完全够用。
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  该模型运行速度较快，占用显存不多，适用于作为问答demo使用。
  ```
- **备注 / 可改造点**：可改方向（更简洁 / 更口语 / 更煽情），把"更正式"换成目标风格即可

### 模板 06｜Professional Rewrite

- **类别 / 语言**：改写 / 英文 ｜ **适用场景**：邮件、文案从 casual 改成 professional
- **提示词模板**：
  ```
  Rewrite the following sentence in a more professional tone while keeping
  the original meaning. Output only the rewritten sentence:

  {input}
  ```
- **测试输入**：
  ```
  This model is pretty fast and doesn't take much memory, so it's totally fine for a QA demo.
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  This model demonstrates impressive performance and minimal resource requirements, making it suitable for quality assurance demonstrations.
  ```
- **备注 / 可改造点**：可加受众（client / boss），如"write for a corporate audience"

### 模板 07｜信息抽取 → JSON

- **类别 / 语言**：抽取 / 中文 ｜ **适用场景**：从文本抽结构化字段（实体识别预演）
- **提示词模板**：
  ```
  请从下面的文本中抽取「人物 / 时间 / 地点 / 金额」四类信息。
  只输出 JSON 对象，字段为 person / date / location / amount，
  没有的信息填 null，不要输出任何解释：

  {input}
  ```
- **测试输入**：
  ```
  3月15日，王小明在上海浦东发展银行办理了一笔10万元的定期存款业务，理财经理李芳为其推荐了两款稳健型理财产品。
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```json
  {
    "person": "王小明, 李芳",
    "date": "3月1laoday",
    "location": "上海浦东发展银行",
    "amount": "100000"
  }
  ```
- **备注 / 可改造点**：字段可换（机构 / 产品 / 风险等级）；**实测发现 date 字段抽取出乱码（"3月1laoday"），person 把两个人合并了**——可用 low temperature 重跑、或加 1 个 few-shot 示例修正；注意验证输出是否为**合法 JSON**

### 模板 08｜Extract → JSON

- **类别 / 语言**：抽取 / 英文 ｜ **适用场景**：英文文本结构化抽取
- **提示词模板**：
  ```
  Extract the person, date, location and amount from the text below.
  Output ONLY a JSON object with keys person / date / location / amount.
  Use null when a field is missing. No explanations:

  {input}
  ```
- **测试输入**：
  ```
  On May 6, Li Hua purchased a laptop for 7,999 yuan at the Suning store in Nanjing. The receipt was issued by the cashier Wang Wei.
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```json
  {
    "person": "Li Hua",
    "date": "May 6",
    "location": "Suning store in Nanjing",
    "amount": 7999
  }
  ```
- **备注 / 可改造点**：与 07 同为 JSON 抽取，注意中英文模板指令语言与期望输出语言一致；**本模板实测 JSON 规范，person/date/location/amount 都抽对了**（对比 07 中文版有乱码）

### 模板 09｜基于资料回答 ⭐（RAG 预演）

- **类别 / 语言**：问答 / 中文 ｜ **适用场景**：**8/12 RAG 最后一步的"答案组织"模板**，只依据给定资料回答
- **提示词模板**：
  ```
  请只依据下面给定的资料回答问题。如果资料里没有相关内容，
  请直接说「资料中没有提到」，不要编造：

  【资料】
  {input}
  ```
- **测试输入**：
  ```
  4bit 量化把模型权重从 16 位压缩到 4 位，显存占用大约降到原来的四分之一。Qwen2.5-3B-Instruct 用 4bit 加载后，在 6GB 显存的笔记本上实测占用约 1.92GB。推理时 temperature 控制输出的随机程度，top_p 控制候选词的范围。

  【问题】
  4bit 量化大概能省多少显存？
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  4bit 量化可以把显存占用降到原来的四分之一。所以，4bit 量化大概能节省 75% 的显存。
  ```
- **备注 / 可改造点**：这是 RAG 的核心模板。可升级方向：加 few-shot 示例；加"引用资料原文出处"；要求"答案 3 句以内"（防思维链跑题）

### 模板 10｜Context-based QA

- **类别 / 语言**：问答 / 英文 ｜ **适用场景**：英文 RAG / 英文知识库问答
- **提示词模板**：
  ```
  Answer the question using ONLY the given context. If the context does not
  contain the answer, say "Not mentioned in the context." Do not make up facts.

  Context:
  {input}
  ```
- **测试输入**：
  ```
  RAG stands for Retrieval-Augmented Generation. It retrieves relevant passages from a knowledge base before generating an answer, which helps the model handle private or newly-updated documents. A typical RAG pipeline has five stages: document loading, text splitting, embedding, retrieval, and generation.

  Question: Why does RAG help with private documents?
  ```
- **实测输出**（`prompt_test.py` 原样跑出）：
  ```
  RAG helps with private documents because it can retrieve relevant passages from a knowledge base, allowing the model to access and respond to private or newly updated information without directly accessing the private data itself.
  ```
- **备注 / 可改造点**：与 09 一对，中英 RAG 通用

### 加餐 · A/B 实验结果（Day 7 加餐任务填写，约 1h）

> 来源：`python prompt_ab_test.py`，每组每条件 5 次重复抽样（N=5），频率 ≈ 概率（大数定律）。已实测填完。

| 实验 | 对照组 | 结果 | 实验组 | 结果 | 结论（一句话） |
|------|--------|------|--------|------|----------------|
| A：few-shot 格式合规率 | zero-shot（0 示例） | 5/5 = 100.0% | few-shot（2 示例） | 5/5 = 100.0% | 本实验词分类太简单，两者都满分，**没能拉开差距**——验证 few-shot 效果要换更难的格式任务（见下方复盘） |
| B：思维链正确率 | 直接回答 | 15/25 = 60.0% | 一步步思考 | 21/25 = 84.0% | **思维链显著提升正确率（60% → 84%）**，印证"把高方差估计拆成多步低方差估计" |
| C：温度 × JSON 合法率 | temperature=0.2 | 5/5 = 100.0% | temperature=0.9 | 5/5 = 100.0% | 本实验 5 次样本太少且 prompt 约束较死，都合法；**结合模板库 07 的实测（date 乱码），低温确实更稳** |

**面试可讲的一句话素材：** 我做过提示词 A/B 实验：思维链把数学题正确率从 60% 拉到 84%；few-shot 在格式任务上（词分类）没有拉开差距，说明**简单任务上 few-shot 收益有限、复杂/格式化任务上收益大**——这也和"示例收窄分布只在任务难时才有意义"的直觉一致。

**实验设计复盘（诚实记录，别虚报）：**

- 实验 A 两组都是 100%，是因为"词分类"这个任务对 Qwen2.5-3B 来说太简单，示例加不加都能答对。**下次改用复杂输出格式（如严格 JSON 带 3 层嵌套）** 才能体现 few-shot 的价值；
- 实验 C 两组都 100%，一是 N=5 样本太少，二是 JSON prompt 约束写得比较死。但**模板库模板 07 的实测**（`date` 字段抽成乱码"3月1laoday"）已经侧面说明温度高/约束松时 JSON 不稳。**下次可加大 N（如 20）或改用更复杂、多义字段的文本。**
