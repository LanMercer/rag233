## 四、踩坑与解决（过程真实记录）

| # | 问题 | 解决办法 |
| --- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 1 | **Markdown 预览只渲染到第 2 步**，后面的第 3/4 步、加餐等章节在预览里看不到（文件本身内容完整，519 行都在） | 排查发现电脑装了 `markdown-preview-enhanced` 和 `markdown-all-in-one` 两个第三方预览插件，对长文档/列表内嵌代码块解析挑剔；把"列表项内直接跟缩进代码块"的非标准写法改成前后加空行的标准写法，并用内置预览验证。**教训：预览渲染问题先怀疑插件，别急着改内容** |
| 2 | **模板 07（中文 JSON 抽取）date 字段抽出乱码"3月1laoday"，person 把两人合并** | 温度偏高或约束不够紧导致模型"自由发挥"。改进方向已写进模板库备注：降 temperature（0.2~0.3）重跑 / 加 1~2 个 few-shot 示例 / 约束写明"每类只抽一个主体"。A/B 实验 C 的结论（低温 JSON 更稳）正好印证这一点 |
| 3 | **加餐 A/B 实验 A、C 组没有拉开差距**（few-shot 100% vs 100%、低温 100% vs 100%） | ① 词分类任务对 Qwen2.5-3B 太简单，示例加不加都能答对；② N=5 样本量太小，频率波动掩盖差异。已在模板库"实验设计复盘"如实记录，改进方向：换复杂输出格式任务（如 3 层嵌套 JSON）、N 加大到 20 |
| 4 | 运行后出现 `__pycache__` 文件夹（含 `.pyc` 字节码文件） | Python 自动生成的编译缓存：运行脚本时把 `.py` 编译成字节码存起来加速下次启动，**可删可忽略**；`.gitignore` 已含 `__pycache__/` 和 `*.pyc`，不会进 git |
| 5 | PowerShell 里用 `&&` 连接命令报错（`&&` 不是该版本 PowerShell 的有效分隔符） | Windows 老版 PowerShell 不支持 `&&`，改用 `;` 分隔命令（如 `git add ...; git status`） |
| 6 | `git add` 时 `LF will be replaced by CRLF` 警告 | Windows 上 Git 默认把 LF（换行）转成 CRLF（回车+换行），仅针对脚本里的文本文件，**无害**，可忽略（Day 6 已遇到过同款） |
