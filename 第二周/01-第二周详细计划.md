## 三、每日详细学习内容

### 8/8 周六 · 承接日：Qwen 本地部署执行 + 第一周复盘

**主线（3~4h）：**
1. **第一周复盘（30 分钟）**：按"完成情况 / 卡点 / 下周调整"三部分写《第一周复盘笔记》，卡点重点记录显存估算误差、下载速度、控制台编码坑。
2. **Qwen 模型下载**：用 ModelScope 或 hf-mirror 镜像下载 `Qwen/Qwen2.5-3B-Instruct` 权重（4bit 加载，无需全精度权重）。
3. **4bit 量化加载**：`transformers` + `bitsandbytes` 的 `load_in_4bit=True` 加载，注意 Windows 上 bitsandbytes 版本兼容。
4. **推理脚本**：写 `qwen_inference.py`（文件头写清五件套：模型=Qwen2.5-3B-Instruct 4bit、数据=手工输入的问题、损失=生成任务无显式损失、优化器=无（纯推理）、做的事=加载→生成→输出）。
5. **显存实测**：用 `torch.cuda.memory_allocated()` 打印占用，与第一周预算（≈3.0GB）对比，校验"部署账"算得准不准。
6. **采样参数实验**：同一问题分别用 temperature=0 / 0.7 / 1.2、top_p=0.9 生成，对比输出差异并截图（把第一周欠的温度实验补上）。
7. **验收**：本地 Qwen 成功生成文本 + 显存实测数字 + 参数对比截图。

**零散时间：** 力扣 344、125（字符串 + 双指针）｜ 统计八股：逻辑回归
**产出：** `qwen_inference.py` + 推理截图 + temperature/top_p 对比 + 第一周复盘笔记

### 8/9 周日 · Prompt 工程入门

**主线（3~4h）：**
1. 学习吴恩达《ChatGPT Prompt Engineering for Developers》核心章节（中文笔记/搬运课均可，4~5 课足够）。
2. 三个核心概念（新名词必带简介）：
   - **Prompt 工程** = 提示词工程，设计给模型的文字，引导它输出我们想要的结果；
   - **few-shot** = 少样本学习，在提示词里给几个输入-输出示例，模型照着示例回答；
   - **思维链**（Chain of Thought）= 让模型把推理过程一步步写出来再给结论。
3. 结构化提示词公式：`角色 + 任务 + 输入 + 输出格式 + 约束条件`。
4. 用概率语言理解：few-shot 示例 = 用示例调整模型输出的条件概率分布；思维链 = 把"一步到位"的高方差估计拆成多步低方差估计，降低整体出错概率（呼应第一周 softmax / 温度的知识）。
5. 在本地 Qwen 上实测：写 10 个提示词模板（总结 / 翻译 / 改写 / 抽取 / 问答各 2 个），中英文各半。
6. **验收**：能讲清 few-shot 与思维链的原理，并有一个可复用的结构化模板。

**零散时间：** 力扣 14、415（字符串进阶）｜ 统计八股：准确率 / 精确率 / 召回率
**产出：** `提示词模板库.md` v1（10 个模板）

### 8/10 周一 · Prompt 工程进阶 + 模板库成型

**主线（3~4h）：**
1. 进阶技巧：角色扮演、JSON/表格等输出格式约束、迭代优化（输出不对 → 改提示词再试）、抑制幻觉（要求"资料没有就说不知道"）。
2. 整理模板库 v2：分类为"通用助手 / 文本处理 / 抽取结构化 / 推理问答 / 代码"，每个模板附 1~2 次实测输出记录。
3. 结合下周 RAG 预写一个"**基于给定资料回答**"的模板（为 RAG 拼接上下文做准备）。
4. **验收**：模板库 v2（20 个模板）成型，能在 3 分钟内套用任意一个。

**零散时间：** 力扣 206、21（链表入门）｜ 统计八股：F1 / AUC
**产出：** `提示词模板库.md` v2 + 实测记录

### 8/11 周二 · 本地模型 OpenAI 兼容接口化

**主线（3~4h）：**
1. 概念（新名词必带简介）：
   - **OpenAI 兼容 API** = 与 OpenAI 的 `/v1/chat/completions` 接口格式一致的接口，客户端代码可以无缝切换供应商；
   - **FastAPI** = Python 的现代 Web 框架，用来快速写出接口服务。
2. 方案 A（推荐）：用 **FastAPI** 写 `local_api.py`：启动时加载 Qwen 模型 → 提供 `/v1/chat/completions` 接口 → 收到请求后生成 → 按 OpenAI 格式返回 JSON。
3. 方案 B（本周不优先）：官方 `vllm` / openai-api server；vLLM 吃显存，6G 显卡先不碰。
4. 测试：终端 `curl` 调用接口返回标准 JSON；再用 Python `requests` 测一次中文对话；把 LangChain 里的模型换成"OpenAI 兼容端点"验证无缝切换。
5. **验收**：curl 调通本地接口，返回 `{"choices":[...]}` 格式；能讲清"为什么接口化"（前后端分离、统一调用、为 RAG demo 打底）。

**零散时间：** 力扣 141、160（快慢指针 + 相交链表数学思想）｜ 统计八股：决策树
**产出：** `local_api.py`（FastAPI 服务）+ curl 调用测试截图

### 8/12 周三 · RAG 全链路 + PDF 问答 demo（未完成部分顺延至下一周工作日）

**主线（3~4h）：**
1. 概念：**RAG** = Retrieval-Augmented Generation，检索增强生成 = 先从资料库里"查答案"，再让模型"组织答案"，专治大模型不知道的私有/新资料。
2. 全链路六步：
   - 文档加载：`PyPDF` 读入 PDF；
   - 文本切块：`RecursiveCharacterTextSplitter`，分隔符加中文标点（。！？）；
   - **Embedding** = 文本向量化，把每块文本变成一串数字（向量），语义相近的向量距离近；
   - 存入 **Chroma** = 开源向量数据库，存向量 + 原文，负责相似度检索；
   - 检索：问题向量与库中向量算**余弦相似度**（两向量夹角的余弦，衡量方向一致程度），取 **Top-K** 最相似片段；
   - 拼接上下文 + 交给 Qwen 按 8/10 写的"基于资料回答"模板生成答案。
3. 结合数学背景：检索 = 高维向量空间里的最近邻问题；"打分 → 取 Top-K → 融合"就是第一周注意力三步走的同款套路。
4. 实现方式：先用 LangChain 组件串通（跑得快），再手写简化版（懂原理）；Embedding 用中文友好的 `bge-small-zh`（智源开源的中文向量模型）。
5. 验收：上传一个自己准备的 PDF（论文 / 研报 / 教材章节），问 3 个基于 PDF 内容的问题，全部答对并能指出出处。
6. 睡前：本周全部产出 git 存档 + 整理周报素材。

**零散时间：** 力扣 382 链表随机节点（蓄水池抽样）｜ 牛客真题 1 套复盘
**产出：** `rag_demo/`（RAG 脚本）+ PDF 问答测试截图 + RAG 链路结构图

## 五、本周常见坑位与避坑

| 坑位 | 应对 |
|---|---|
| HuggingFace 下载慢 / 失败 | 用 ModelScope（`pip install modelscope`）或 hf-mirror.com 镜像站 |
| 6G 显存加载 Qwen 3B 4bit 爆显存 | 关掉浏览器等占显存程序；`max_new_tokens` 别设太大；重开终端释放显存；仍不够再试 `load_in_8bit` |
| bitsandbytes 在 Windows 上报错 | `pip show bitsandbytes` 确认版本与 Python/transformers 匹配，必要时按 transformers 建议版本安装 |
| 4bit 加载仍缺依赖 | `pip install accelerate`；确认 `quantization_config`（BitsAndBytesConfig）写法正确 |
| FastAPI 改代码不生效 | 用 `uvicorn local_api:app --reload`；注意 --reload 下模型会重复加载，调试好后再去 reload |
| Windows 终端 curl 中文乱码 | 先执行 `chcp 65001` 切换 UTF-8 再测试 |
| PDF 中文切块把句子切碎 | `RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)`，separators 加入中文标点 |
| Chroma 检索为空 / 报错 | 先单独测 Embedding 模型能否正常输出向量；中文用 `bge-small-zh` |
| RAG 答非所问 | 提高 Top-K（4 → 8）、调大 chunk_size、prompt 写明"只依据资料回答，没有就说不知道" |
| 思维链输出太长被截断 | prompt 约束"逐步推理，最终答案 3 句以内"；控制 `max_new_tokens` |
