## 四、踩坑与解决（过程真实记录）


| #   | 问题                                                                                                       | 解决办法                                                                                                                  |
| --- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 1   | `git add .` 时把 `download\` 下 **6GB 模型权重**（两个 `.safetensors` 大文件）误加入暂存区——仓库会膨胀 6GB，且单文件超 100MB 推不上 GitHub | 新建 `.gitignore` 排除 `download/`，用 `git rm --cached` 把模型移出暂存区（工作区文件保留，模型仍正常可用）。**教训：模型权重永远不进 git，可随时从 ModelScope 重新下载** |
| 2   | 在仓库根目录运行 `python qwen_inference.py` 报错：`can't open file ... No such file or directory`                   | 脚本在 `第二周\day6\` 里，不在根目录。先 `cd "D:\...\第二周\day6"` 再运行即可（教程 0.2 已写明此步骤）                                                 |
| 3   | 加载时提示 `[transformers] torch_dtype is deprecated! Use dtype instead!`                                     | 新版 transformers 的弃用提示（warnings），**不影响功能**。后续可把脚本里 `torch_dtype` 换成 `dtype` 消除提示（非必须）                                  |
| 4   | 参数总量显示 1699 百万，不是预期的约 3000 百万                                                                            | 4bit 量化加载后，部分权重（如量化后合并/冻结的部分）不参与 `numel()` 统计，属正常现象，不是下载不完整。以推理效果和显存实测为准                                              |
| 5   | `git add .` 时大量 `LF will be replaced by CRLF` 警告                                                         | Windows 上 Git 默认把 Linux 风格换行符（LF，换行）转成 Windows 风格（CRLF，回车+换行）。仅针对模型里的文本配置文件，**无害**，可忽略                                |
