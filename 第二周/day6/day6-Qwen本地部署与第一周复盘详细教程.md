### 3.1 先搞清楚"4bit 量化"到底是什么

- **量化（Quantization）** = 把模型权重从高精度压缩到低精度，就像把高清照片压缩成小图。第一周学过：权重本来是 fp16（16 位浮点数，浮点 = 带小数点的数），现在压到 4bit（4 位），**显存占用降到约 1/4**，代价是模型输出稍微"粗糙"一点点。
- **NF4（NormalFloat4）** = 一种专门为权重设计的 4bit 数据格式，量化误差比普通 4bit 小，是今天用的格式（quant_type="nf4"）。
- **bitsandbytes** = 做量化的那个库，transformers 调用它完成 4bit 加载。

### 4.2 🔢 数学原理小课堂：temperature 与 top_p 是什么、数学上怎么运作

> 先看懂原理，再跑 4.3 / 4.4 的实验。这一节是今天"数学视角"的主菜，正好用你概率统计的本行话讲透。

**先回到一件事：大模型是怎么"开口"的？**

模型最后一层 softmax 输出的，是一个**覆盖整个词表的概率分布** `P(下一个词 | 上文)`——每个候选词一个概率，加起来等于 1。模型生成时做的不是"选概率最大的词"，而是**按这个分布抽样（sample）**：概率大的词更常被抽到，但概率小的词偶尔也会被抽到。

- 分布越"尖" → 大概率集中在少数词上 → 抽来抽去都是那几个词 → 输出**稳定、可预测**；
- 分布越"平" → 每个词概率都差不多 → 抽到谁都有可能 → 输出**多样、不可预测**。

temperature 和 top_p 就是两个"调节旋钮"：一个拧**分布的形状**，一个拧**抽样的候选范围**。下面分开讲。

---

**4.2.1 temperature（温度）——拧分布的形状**

**是什么**：一个除法旋钮。把 softmax 前的原始打分（**logits**，模型对每个候选词的得分，越大表示越倾向选它）**除以 T** 之后再 softmax：

```
p_i = exp(z_i / T) / Σ_j exp(z_j / T)
```

其中 `z_i` 是词 i 的打分，T 是 temperature，`p_i` 是最终概率。**T=1 就是普通 softmax**（第一周 Day 3 你手算过的那个）。

- **T 越小（如 0.3）**：`z_i / T` 把分数差放大 → 好词更好、差词更差 → softmax 后分布更尖 → 几乎只抽概率最大的词。T→0 时退化成"每次都选最大那个"（**贪心解码 greedy decoding**，greedy = 贪心，每次都挑眼前最好的）。
- **T 越大（如 1.2）**：`z_i / T` 把分数差拉平 → softmax 后分布更均匀 → 概率小的词也有机会被抽到。T→∞ 时退化成完全均匀分布（纯随机）。

**一个 3 个词的例子（亲手对一遍）**：假设模型对"苹果 / 香蕉 / 西瓜"的打分是 `z = [3, 2, 1]`，四个温度下：


| T   | 苹果   | 香蕉   | 西瓜   | 熵 H（nats） | 抽签感觉         |
| --- | ---- | ---- | ---- | --------- | ------------ |
| 0.5 | 0.87 | 0.12 | 0.02 | ≈ 0.44    | 几乎必中"苹果"，不随机 |
| 1   | 0.67 | 0.24 | 0.09 | ≈ 0.83    | 大概率苹果，偶尔其他   |
| 2   | 0.51 | 0.31 | 0.19 | ≈ 1.02    | 三个都差不多，很随机   |


（3 词均匀分布的熵上限是 ln3 ≈ 1.10，T 越大越接近它。）

**和熵（信息量）的关系——把上次那个问题接住**：

熵的公式 `H = -Σ_i p_i · log(p_i)`，衡量一个分布"有多难猜"：

- 分布越平 → 越难猜 → 熵越大 → 抽样结果越不可预测 → **输出越随机**；
- 分布越尖 → 几乎总能猜中 → 熵≈0 → 输出确定。

所以完整因果链是：**T 变大 → 打分差距被拉平 → softmax 后分布更均匀 → 熵变大（不确定性更大）→ 每次抽样更不可预测 → 输出看起来更随机**。反过来 T 变小 → 熵变小 → 输出更稳。**调温度，本质就是在连续调节概率分布的熵**。

> ⚠️ 提醒：熵大 ≠ 输出好。T 拉到 5 以上，3B 模型很快输出乱码——熵很高但毫无意义。事实问答用低 T（稳），创意写作用高 T（花），后面 4.3 实验你会亲眼看到。

---

**4.2.2 top_p（核采样阈值）——拧抽样的候选范围**

**是什么**：也叫 **nucleus sampling**（核采样，nucleus = 原子核，只从"核心的一小撮词"里抽）。做法：把 softmax 概率**从大到小排序并累加**，累加到刚好 ≥ p 时截断，**只在这部分词里重新归一化，然后抽样**。

**步骤（还是那 3 个词，T=1 时概率 0.67 / 0.24 / 0.09）**：

1. 排序：0.67（苹果）→ 0.24（香蕉）→ 0.09（西瓜）；
2. 累加：0.67 → 0.91 → 1.00；
3. 设 `top_p = 0.9`：累加到 0.91 ≥ 0.9，截断 → 候选集 = {苹果, 香蕉}（西瓜被踢出局）；
4. 重新归一化：苹果 0.67/0.91 ≈ 0.74，香蕉 0.24/0.91 ≈ 0.26，只在这两个词里抽。


| top_p | 候选集      | 效果                       |
| ----- | -------- | ------------------------ |
| 0.5   | 只有苹果     | 最保守，几乎只有最大概率词            |
| 0.9   | {苹果, 香蕉} | 去掉长尾小概率词，兼顾多样与稳定         |
| 1.0   | 全部词      | 等于关闭 top_p，长尾词（西瓜）也可能冒出来 |


**和 temperature 的区别（面试常问）**：temperature 改的是**每个词的概率值**（分布形状）；top_p 改的是**抽样的候选集合**（哪些词有资格被抽）。一个动"概率"，一个动"名单"，两个维度正交，所以实践上配合用：先用温度调好分布形状，再用 top_p 把不靠谱的长尾切掉。

**一句话记忆**：温度 = 拧"熵"，top_p = 切"名单"。

### 4.3 temperature 对比（同一个问题，3 个温度）

脚本第 4 步会打印三组输出，对照看：


| temperature | 概率分布       | 输出特点            |
| ----------- | ---------- | --------------- |
| 0（贪心解码）     | 每次必选概率最大的词 | 最保守、最死板，可能复读一句话 |
| 0.7         | 正常的分布      | 自然、连贯（日常推荐值）    |
| 1.2         | 分布更均匀      | 更多样、更发散，可能跑题    |


> 💡 复习提示：数学原理见 4.2 小课堂——T 越大 → 分布越平 → 熵越大 → 输出越随机；T 越小则越稳。



### 4.4 top_p 对比（核采样阈值）

脚本第 5 步会打印 top_p=0.5 / 0.9 / 1.0 三组输出：


| top_p | 含义                | 输出特点           |
| ----- | ----------------- | -------------- |
| 0.5   | 只在"累积概率占 50%"的词里选 | 很保守，基本只从大概率词里挑 |
| 0.9   | 默认值，兼顾多样与稳定       | 推荐值            |
| 1.0   | 所有词都参与            | 等于关闭 top_p，更发散 |


> 💡 复习提示：top_p 的数学原理见 4.2 小课堂——排序 → 累加 → 截断 → 重新归一化，动的是"候选词名单"。

## 📎 附录：脚本怎么读（给想看懂代码的你）

`qwen_inference.py` 结构很简单，按顺序读：

1. **头部五件套注释**：模型（Qwen2.5-3B-Instruct 4bit）、数据（手工问题）、损失（无）、优化器（无）、做的事（加载→生成→对比）——不读代码也能知道它在机器学习的哪一环；

4. 主流程 5 步：加载 → 显存 → 单次生成 → 温度对比 → top_p 对比。

想改问题：改主流程里 `question = "..."` 那一行。想改生成长度：改 `MAX_NEW_TOKENS`。
