## 一、怎么用这个模板库（30 秒上手）

1. **挑模板**：先按**分类**（A 通用助手 / B 文本处理 / C 抽取结构化 / D 推理问答 / E 代码）找，再按语言（中/英）找；
2. **替换占位符**：把模板里的 `{input}`（或 `{context}` / `{question}`）换成你的内容；
3. **发给模型**：本地 Qwen（`python prompt_test_v2.py 编号`）或任意兼容 API；
4. **调参数**（Day 6 的知识）：事实问答 `temperature` 用 0.2~0.5；创意写作 0.8~1.2；**JSON 输出务必调低温度**（本库模板 07 已内置 0.2）。

**五件套回忆**：角色 + 任务 + 输入 + 输出格式 + 约束条件 —— 每个模板都能拆成这五件。

### A 通用助手

#### 模板 11｜角色扮演·风控专家 ⭐ 进阶技巧①

- **类别 / 语言**：通用助手 / 中文 ｜ **适用场景**：专业咨询、面试模拟、需要特定领域语气与判断标准
- **提示词模板**：
  ```
  你是一名有 10 年经验的银行资深风控分析师，擅长信贷审批，说话严谨专业。
  请从风险角度分析下面这笔贷款申请，指出主要风险点，并给出是否批准的建议。
  要求：分 3 点列出，每点不超过 40 字。

  {input}
  ```
- **测试输入**：
  ```
  客户李某，28 岁，在互联网公司工作 2 年，月薪 1.8 万元，申请信用贷款 30 万元，用途为购买新能源汽车，名下无房贷，近半年征信查询记录 6 次。

- **实测输出**（`python prompt_test_v2.py 11` 跑出，两次运行）：
  ```

  1. 贷款用途不明确；
  2. 工作年限短，稳定性差；
  3. 近期征信查询次数多。

  建议：不予批准。
  ```
  ```
  运行 2（角色A 风控专家）：
  风险点：
  1. 职业稳定性不足；
  2. 征信查询次数过多；
  3. 月收入波动大；
  建议：
  否批准。
  ```
  ```
  运行 3（角色B 普通助手）：

  2. **信用记录**：征信查询 6 次，频率较高，需提高个人信用水平。
  3. **用途合理性**：用于购买新能源汽车，符合国家政策导向，有助于促进节能减排。
  ```
  ```
  运行 4（角色B 普通助手 · Day 8 全量复测）：
  1. **收入稳定**：李某在互联网公司工作两年，月收入稳定，有偿还贷款的能力。
  2. **风险控制**：李某近半年征信查询记录较多，需谨慎评估其还款意愿和能力。
  3. **合理用途**：购买新能源汽车符合贷款用途，但应进一步了解其购车目的和计划。
  ```
- **备注 / 可改造点**：✅ **角色对比实验已完成**（`prompt_test_v2.py` 注释互换两次运行，同一测试输入）。
  **「带角色 vs 不带角色」输出差异：**
  - **风控专家**（角色A）：用"风险点 / 建议"框架，说话直断，结论明确——"不予批准"；措辞偏信贷术语（征信查询、贷款用途），两次措辞略有差异 = temperature 0.7 采样随机性，方向一致；
  - **普通助手**（角色B）：无固定框架，三点评测偏"全面评估"，语气更温和——把"还款能力/信用记录/用途合理性"并列，甚至给"符合国家政策导向"这种中性甚至偏正面的评价，**没有下"批准/不批准"的结论**。
  **一句话结论**：角色 = 给条件分布强先验——风控专家把输出锁定到"专家子分布"（框架 + 术语 + 敢下结论）；普通助手则落在"通用友好"子分布（全面、温和、不下判断）。这正是教程 1.2 "角色 = 强先验锁定专家子分布"的直接证据，也是面试可讲的实证。
  **注意**：模板 11 的 `name` 字段已改为引用全局变量 `TPL11_NAME`，**随注释切换自动改名**——角色A（风控专家）↔ 角色B（普通助手）时，注释互换即可让终端标题同步变化（运行 3/4 的标题"角色扮演·普通助手"即由此机制显示）。

#### 模板 14｜决策分析·加权打分

- **类别 / 语言**：通用助手 / 中文 ｜ **适用场景**：offer 选择、方案对比、任何多维度决策
- **提示词模板**：
  ```
  你是一名理性的决策分析师。下面是需要评估的方案、评估维度和各维度权重（权重和为 1）。
  请给每个方案在各维度上打 1~10 分，计算加权总分，并给出你的推荐及理由。
  只输出 Markdown 表格和一句推荐结论。

  {input}
  ```
- **测试输入**：
  ```
  方案：A=国企数据分析岗（稳定、成长中、薪资中），B=互联网大厂算法实习（成长快、不稳定、薪资高），C=继续读博（成长慢、不确定性大、长期上限高）。
  维度与权重：稳定 0.4，薪资 0.3，成长 0.3。
  ```
- **实测输出**（`python prompt_test_v2.py` 全量跑，Day 8 实测）：
  ```
  | 方案 | 稳定 | 薪资 | 成长 | 加权总分 |
  | :---: | ---: | ---: | ---: | ---: |
  | A | 8 | 6 | 7 | 7.2 |
  | B | 4 | 9 | 8 | 7.5 |
  | C | 2 | 3 | 9 | 5.7 |
  推荐结论：选择方案A，其综合得分最高，且最符合你的理性分析要求，即在保证薪资和成长的同时，也较为重视岗位的稳定性。
  ```
- **备注 / 可改造点**：⚠️ **数学校验点（教程 5.2 观察清单第 1 条）——加权总分算错了！**
  - 正确计算：A = 8×0.4+6×0.3+7×0.3 = **7.1**（模型写 7.2）；B = 4×0.4+9×0.3+8×0.3 = **6.7**（模型写 7.5）；C = 2×0.4+3×0.3+9×0.3 = **4.4**（模型写 5.7）。
  - **结论**：模型"表格格式"合规 ✅，但**算术不可靠** ❌——3B 模型做多位小数乘法容易出错。这次碰巧推荐结论（A）选对了，但分数是错的，**不能直接信**。
  - **这正是"分布尖 ≠ 分布准"的又一个实证**：模型对"像不像决策表格"置信很高，对"数字算没算对"没有把握。
  - **改进方向**：① 让模型先写算式再填表（思维链）；② 用代码/外部计算器算分；③ 评分用整数简单化权重（如权重 4/3/3 而非 0.4/0.3/0.3）。**这个发现值得写进面试**——"我发现 3B 模型算加权总分不可靠，所以 RAG 应用里数值计算应该走代码而不是让模型算"。
  - 📖 **延伸阅读**：这个现象 = 当年全网刷屏的"AI 不会做数学题"的微缩现场，完整机制分析 + 面试话术见教程 **知识卡片 5.2-A**。

  def fibonacci(n: int) -> int:
      """
      返回第 n 个斐波那契数（n 从 1 开始计数）。

      参数：
      n -- 要查找的斐波那契数的索引位置（从 1 开始）

      返回值：
      第 n 个斐波那契数
      """
      if n <= 0:
          raise ValueError("n 必须大于 0")
      if n == 1 or n == 2:
          return 1
      a, b = 1, 1
      for _ in range(3, n + 1):
          a, b = b, a + b
      return b
  ```
