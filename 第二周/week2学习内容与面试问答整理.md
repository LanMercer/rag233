## 第二部分 · 面试高频问答（重点）

> 按主题分 9 个模块。每题给：**你该说的核心答案** + **[数学加分]** 概率/统计视角。先自己开口讲一遍，再看参考答案。

### 模块 A：本地部署与量化（Day 6）

**Q1. 你 6G 显存怎么把 Qwen 跑起来的？**
> 用量化：把模型参数从 16/32 位压到 4/8 位来省显存。我用 bitsandbytes 的 `load_in_4bit=True` + NF4 格式 + `device_map="auto"` 加载 Qwen2.5-3B-Instruct，实测 `torch.cuda.memory_allocated()` 只有 1.92GB，6G 显存跑得很舒服；模型下载走 ModelScope（魔搭，国内快）。
> [数学加分] 量化 ≈ 用更少的比特存参数，相当于对权重做一次"有损压缩"，4bit 就是把 16 位权重信息压到 4 位表达，省到约 1/4 显存，代价是少量精度损失——这正好是信息论里"码率-失真"权衡的实例。

**Q2. NF4 是什么？bitsandbytes 呢？**
> bitsandbytes = 专门做低精度量化的 Python 库；NF4（NormalFloat4）= 它提供的一种 4bit 量化格式，专为神经网络权重分布设计，精度损失更小，是 4bit 加载的推荐格式。我用的配置是 `BitsAndBytesConfig(load_in_4bit=True, quant_type="nf4", double_quant=True)`。

**Q3. 部署时的"账"是怎么算的？实测和预算对上了吗？**
> 第一周我先按权重规模算了账：3B 模型 fp16 权重约 6GB，4bit 后权重约 1.5GB，加上 CUDA 上下文 + KV Cache 等运行开销，估 ≈3.0GB。第二周实测只有 1.92GB——方向对、估偏大，差异来自 `device_map="auto"` 自动分配和双重量化生效。
> [数学加分] 这种"先估算再实测对账"的习惯正是统计人的本能：预算=先验估计，实测=数据，两者差异就是"模型更新"，下次估得更准。

**Q4. 模型推理时是怎么"开口说话"的？**
> 模型最后一层 softmax 输出一个覆盖整个词表的**概率分布** `P(下一个词 | 上文)`，生成时按这个分布抽样：概率大的词更常被抽到，但概率小的词偶尔也会被抽到。分布越尖输出越稳，越平输出越随机。
> [数学加分] 一句话：生成 = 一路做条件概率抽样，整段话 = 条件概率的连乘 `P(w₁)P(w₂|w₁)…`，这正是概率论里的链式法则。

### 模块 B：解码采样参数 temperature / top_p（Day 6，高频）

**Q5. temperature 是什么？数学上怎么运作？**
> temperature（温度）是 softmax 前的一个除法旋钮：`p_i = exp(z_i/T) / Σ_j exp(z_j/T)`。T 越小，分数差被放大 → 分布越尖 → 输出越稳定（T→0 退化成贪心解码，每次选最大）；T 越大，分数差被拉平 → 分布越均匀 → 输出越多样（T→∞ 退化成均匀分布）。
> [数学加分] 温度调的本质是分布的**熵**：T 大 → 熵大 → 输出不可预测；T 小 → 熵小 → 输出确定。我实测过同一问题 T=0 / 0.7 / 1.2：0 最保守、0.7 自然、1.2 更发散。我还算过 3 词例子的熵对照表（T=0.5 时熵≈0.44，T=2 时熵≈1.02）。

**Q6. top_p 是什么？和 temperature 什么区别？（面试常问）**
> top_p（核采样 nucleus sampling）是切"候选名单"：把 softmax 概率从大到小排序累加，累加到 ≥ p 时截断，只在这部分词里重新归一化再抽样。区别：**temperature 动"概率值"（分布形状），top_p 动"候选集合"（哪些词有资格被抽）**——一个动概率、一个动名单，两个维度正交，实践上配合用。
> [数学加分] top_p=0.9 意思是"我只要累积概率占 90% 的核心词集"，把长尾小概率词（可能是不靠谱的词）直接排除——相当于给抽样分布做一个"截断 + 重归一化"，在数学上就是条件化到某个高概率集合上再抽样。

**Q7. 事实问答和创意写作分别该用高温度还是低温度？**
> 事实问答用低温（如 0.2~0.5）：分布尖、少编造、答案稳；创意写作用高温（如 0.9~1.2）：分布平、输出多样。我用 RAG 问答时就把接口温度设成 0.2——RAG 要"稳"不要发散，这是我在项目里的实际配置。

### 模块 C：Prompt 工程基础（Day 7）

**Q8. 什么是 few-shot？它为什么有效？**
> few-shot（少样本提示）= 在提示词里给几个"输入→输出"示例，模型照着示例的风格、格式、判断标准回答。有效的原因（概率语言）：不给示例时，模型按 `P(回答|问题)` 抽样，分布很"野"（高熵）；给了 k 个示例后，实际按 `P(回答|问题, 示例₁…示例ₖ)` 抽样——**示例 = 观测数据 = 对输出分布做后验调整**（贝叶斯视角：先验被更新成后验），把概率质量压到"跟示例同分布"的区域。
> [数学加分·一句话] few-shot 把输出分布从"大而平"收成"小而尖"，示例给得越贴任务，输出越可控——这和温度调的是同一个东西（熵），只是温度是旋钮、示例是数据。

**Q9. 什么是思维链（Chain of Thought）？为什么有效？**
> 思维链 = 让模型把推理过程一步步写出来再给结论（"请一步步思考"）。有效的原因：直接答一个复杂问题 = **一步估计一个高方差函数**，任何小环节出错全盘皆输；思维链把答案拆成多步，每一步只估计一个更简单的条件分布 `P(sᵢ₊₁|问题, s₁…sᵢ)`——候选空间小、分布尖、单步出错率低。
> [数学加分] 用方差分解公式讲：`Var(Y) = E[Var(Y|X)] + Var(E[Y|X])`——显式写出中间变量 X 当条件，剩余方差 ≤ 总方差。数字直觉：一步做对概率 0.8；拆 3 步后每步因为变简单升到 0.95，0.95³ ≈ 0.857 > 0.8。注意真正的机制不是"多步"，而是"条件化让每步分布变尖"。**我在本地实测：思维链把数学题正确率从 60% 提到 84%（N=5 实验），后来 N=20 复测又复现了 2.5 倍的提升。**

**Q10. 结构化提示词的五件套是什么？**
> 角色 + 任务 + 输入 + 输出格式 + 约束条件。例：你是一名资深风控分析师（角色）/ 评估这笔贷款（任务）/ 申请信息 {input}（输入）/ 只输出 JSON（输出格式）/ 信息不足就写"信息不足"（约束）。
> [数学加分] 每加一项约束，都在缩小"模型可能输出的集合"（支持集 support）→ 条件熵下降 → 输出更可预测。写提示词的本质 = 不断给模型加条件信息，把条件概率分布往你要的方向压缩。

**Q11. 吴恩达 Prompt 工程课的两条黄金准则？**
> ① 写得清晰具体：用分隔符分开指令和文本、要求结构化输出、让模型先检查条件、用 few-shot；② 给模型思考时间：把复杂任务拆成步骤、让模型先自己推导再下结论（这就是思维链雏形）。

### 模块 D：Prompt 工程进阶（Day 8）

**Q12. 角色扮演为什么有效？**
> 模型预训练读过海量"带角色文本"，给它一个明确角色（"10 年信贷审批经验的风控分析师"）等于触发预训练里和该角色绑定的**专家子分布**。概率语言：不加角色时输出是 `P(回答|问题)` 的混合分布（高熵），加角色 R 后变成 `P(回答|问题, 角色=R)`，概率质量被拉向"该角色会怎么说"的区域——**给条件分布一个强先验**。
> [数学加分] 我做过对照实验：同一笔贷款，普通助手语气温和不下判断，"风控专家"会主动用"风险点/建议"框架、敢下"不予批准"结论——角色 = 强先验的直观证据。

**Q13. 怎么让模型输出稳定的 JSON？**
> 用输出格式约束：明确字段名与类型、缺省填 null、只输出 JSON 不要解释、必要时加 few-shot 示例；再配低温（0.2~0.3）。格式约束把"可能输出的集合"从"所有文本"压成"符合 schema 的结构"→ 条件熵断崖式下降。
> [数学加分] 我实测过一个真实的迭代优化案例（模板 07 抽取中文信息到 JSON）：v1 把日期抽成乱码"3月1laoday"、把两个人名合并；我迭代三轮——加约束 + 降温度把乱码修好，但暴露"抽错主体、金额抽空"两个新问题；最后把 few-shot 示例换成**与测试文本同构的双人文本**并写字段级约束，四字段全对。这个"写→跑→看→改"的闭环我可以完整讲给面试官。

**Q14. 什么是幻觉（Hallucination）？为什么模型会一本正经地编？**
> 幻觉 = 模型一本正经地编造不存在的事实。因为大模型本质是"概率接龙器"，训练目标是"下一个词像人话"而不是"下一个词是事实"——它只最大化文本流利度，不查资料、不算数。
> [数学加分·重点] 模型的"置信度"来自条件概率分布，**分布尖（高置信）≠ 分布准（正确）**——模型对"这段话像不像人写的"置信很高，但对"这个数字是不是真的"毫无置信，这叫**校准（calibration）差**。所以防幻觉靠工程约束而不是靠模型自己：限定资料源 + 允许说不知道 + 要求标出处 + 低温。

**Q15. 为什么 LLM 会算错数学题？（可以讲我的实测）**
> 因为 LLM 的算术不是"计算"而是"回忆/模式匹配"：单个乘法（`8×0.4=3.2`）是训练语料里背过的映射所以会；但多步组合（`8×0.4+6×0.3+7×0.3`）语料里没有，它只能从"像决策表格"的分布里猜一个数字——格式 100% 像真的，数字大概率错。我实测：让 3B 模型直接输出加权总分，它给 7.2/7.5/5.7，正确是 7.1/6.7/4.4；但让它先一步步写过程，同模型的答案就是对的——这就是《Chain-of-Thought Prompting》的核心发现：写中间步骤 = 给模型一张草稿纸（外部工作记忆）。
> [工程原则·面试直接说] **推理归模型、计算归代码**——RAG 应用里数值聚合、统计计算一律走 Python，模型只负责理解和组织答案。这也是 Agent + 工具调用（tool use）的核心理念。

**Q16. 你做过提示词相关的实验吗？怎么设计？**
> 做过，这是我的统计学主场。方法：**控制变量 + 只改一个条件 + 重复抽样 N 次 + 频率≈概率**。三组对照：A 组 zero-shot vs few-shot 看"格式合规率"，B 组直接问 vs 思维链看"正确率"，C 组低温 vs 高温看"JSON 合法率"。结果：思维链把正确率从 60% 拉到 84%；few-shot 和低温在简单任务/只看结构合规的判分下没拉开差距——我如实汇报并分析了原因（判分粒度问题、结构是分布问题而数值/推理是能力问题）。**"会科学设计实验 + 诚实汇报未拉开差距的结果"本身就是加分项。**

### 模块 E：本地模型接口化（Day 9）

**Q17. 什么是 OpenAI 兼容 API？为什么要接口化？**
> OpenAI 兼容 API = 与 OpenAI 官方接口格式一致的接口：同样的 URL（`/v1/chat/completions`）、请求体（messages 数组 + temperature）、返回结构（`{"choices":[{"message":{"content":...}}]}`）。接口化四点理由：① **前后端分离**——模型独立进程跑，应用只发 HTTP 请求，模型挂了/换了应用零改动；② **统一调用**——OpenAI 格式是行业标准，切模型只改三处（base_url / api_key / model）；③ **语言无关**——HTTP + JSON 任何语言都能调；④ **为 RAG 打底**——检索（Chroma）和生成（Qwen）松耦合拼接。

**Q18. FastAPI 和 uvicorn 是什么关系？**
> FastAPI = Python 现代 Web 框架，你写一个普通函数、用 `@app.post("/v1/chat/completions")` 标注，它就变成接口（收请求→调函数→返回 JSON）——把"函数"变成"服务"的胶水；uvicorn = 真正跑起来监听端口的服务器（ASGI 服务器）。类比：FastAPI 是"餐厅后厨的做菜流程"，uvicorn 是"前台接单员"。

**Q19. 本地模型是怎么"一次加载、一直服务"的？**
> 用 FastAPI 的 lifespan（生命周期）钩子：服务进程"出生"时加载一次模型、关闭时释放显存；所有请求共用这同一个模型实例。解决了以前"每次跑脚本都要重新加载模型 1~3 分钟"的问题。

**Q20. ChatML 是什么？**
> ChatML（Chat Markup Language）= Qwen 这类模型规定的对话格式，用 `<|im_start|>` 标记区分 system/user/assistant 三段，模型读到 `<|im_start|>assistant` 就知道该自己接话了。接口收到 OpenAI 格式的 messages 后，`build_chatml()` 负责把它"翻译"成 ChatML 文本再喂给模型——是"接口格式 → 模型格式"的翻译官。

**Q21. OpenAI 返回的 JSON 你怎么跟面试官讲？**
> 骨架一句话：快递面单（`id`/`created`/`model`）+ 装回答的数组 `choices`（`choices[0].message.content` 就是答案）+ 用量小票 `usage`。关键字段：`finish_reason` 是 stop（自然说完）还是 length（被 max_tokens 截断），排查看它；`usage` 三项（prompt_tokens/completion_tokens/total_tokens）是 token 账本（token = 词元，模型处理文本的最小单位，中文约 1 字 1~2 token）。

**Q22. 怎么证明你的接口是"无缝切换"的？**
> 我写了个测试：用 LangChain 的 `ChatOpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY", model="Qwen2.5-3B-Instruct")` 指向本地端点，直接跑通。要切回 OpenAI 官方只需改三处：base_url、api_key、model，其余代码一行不动。数学类比：调用方只依赖函数"签名"不依赖"实现" = 面向接口编程。

### 模块 F：RAG 全链路（Day 10，本周核心，面试重点）

**Q23. 什么是 RAG？为什么用检索不用重新训练？（高频）**
> RAG（Retrieval-Augmented Generation，检索增强生成）= 先从资料库"查答案"，再让模型"组织答案"，专治模型不知道的私有/新资料。为什么不用重新训练/微调，三点对比：① **成本**——微调要算力、数据、时间（小时~天级），RAG 只需 Embedding 向量化（分钟级）+ 检索；② **更新速度**——每次资料更新都要重训，RAG 往向量库加一段立刻能检索到；③ **可解释性**——微调说不清知识存哪了，RAG 答案带 [资料§N] 出处能回溯。一句话：训练 = 把知识背进大脑，RAG = 考试带资料进考场翻书。

**Q24. RAG 全链路是哪六步？每一步输入输出是什么？**
> ① 文档加载（PyPDF）：PDF → 每页文本；② 文本切块（RecursiveCharacterTextSplitter，chunk_size=500、overlap=50，分隔符加中文标点。！？）：整篇 → 若干 chunk；③ Embedding（bge-small-zh）：每块文本 → 512 维向量；④ 存入 Chroma：向量+原文落盘，用 cosine 空间；⑤ 检索：问题向量化 → 与库中向量算余弦相似度 → 取 Top-K；⑥ 拼接上下文 + 生成：Top-K 片段套模板 09 → 交给 Qwen（温度 0.2）→ 输出带 [资料§N] 出处的答案。
> [数学加分] 我建议把第②步切块类比成"把一大段高维混合信息拆成多块局部信息，让每块向量更纯净"；chunk 的编号就是模板 09 里 [资料§N] 的 N，检索到哪段、答案引哪段，全程可追溯。

**Q25. Embedding 是什么？为什么语义近的向量距离近？**
> Embedding（嵌入/文本向量化）= 把文本变成一串数字（向量）。它由一个专门训练过的模型完成（我用 bge-small-zh），训练目标就是"让意思相近的句子映射到相近的向量"。bge-small-zh 是智源开源的中文向量模型，输出 512 维向量，我本地化下载约 96MB，用 ModelScope 拉取免联网。
> [数学加分] Embedding 本质是学了一个从"句子空间"到"512 维语义空间"的映射——把自然语言问题变成**几何问题**（语义相近 = 空间距离近），这是把 NLP 变成数学的经典例子，正好是我的主场。

**Q26. 余弦相似度是什么？为什么用它算"相关"？**
> 余弦相似度 = 两向量夹角的余弦：`cos(a,b) = (a·b)/(|a||b|)`，衡量方向一致程度，取值 [-1,1]，越接近 1 越相似。它只看方向不看长度，适合文本向量这种"谁跟谁语义更近"的比较。我手写版 RAG 里就一行：把向量归一化后 `doc_vecs @ query_vec`（归一化后点积 = 余弦相似度），再用 `np.argsort(scores)[::-1][:k]` 取 Top-K。
> [数学加分] 检索 = **高维向量空间最近邻问题**：每段文本是一个 512 维向量、问题也是 512 维向量，"找最相关段落" = 找最近的 K 个邻居。几百个 chunk 用暴力矩阵乘法就够；数据量大了才需要 ANN（近似最近邻）算法。

**Q27. RAG 和注意力机制有什么关系？（两周知识打通，主动讲加分）**
> "打分 → 取 Top-K → 融合"就是注意力三步走的同款套路：第一周 Attention 是 `对序列每个位置打分(softmax) → 取权重 → 加权求和`，RAG 是 `对资料库每段打分(余弦相似度) → 取 Top-K → 拼进上下文`。**Attention = 模型内部对 token 的软性检索；RAG = 模型外部对文档的硬性筛选。** 这个类比能把两周的知识串成一条线。

**Q28. RAG 怎么防幻觉？你验证过吗？**
> 三层防护：① 提示词（模板 09）限定"只依据给定资料回答"，资料里没有就说「资料中没有提到」、要求每条要点标 [资料§N] 出处、答案 3 句以内、温度降到 0.2；② 检索层只把 Top-K 相关片段拼进上下文，模型"凭记忆回答"的空间被压缩；③ 出处在输出里强制可见，编造会露馅。我实测验证过：对我的 GMR 论文问一个检索没召回相关段落的问题（论文缺点），模型如实答"资料中没有提到"，没有编造。

**Q29. 你怎么把 RAG demo 讲成项目？（简历核心）**
> 背景：8 月从零做一个"上传 PDF 能问答"的大模型应用（解决私有资料问答），本机 6G 显存。做法：LangChain 串通（PyPDF 加载 → 中文标点切块 → bge-small-zh Embedding → Chroma 向量库 → 余弦相似度 Top-K 检索 → 模板 09 → 本地 Qwen 接口生成）。验证：先用 attention 论文（14 页 49 chunk）跑通，再换**自己准备的 GMR 论文**（9 页 105 chunk）问 3 个问题全部答对且带 [资料§N] 出处；资料外问题能正确答"没有提到"（防幻觉通过）；还写了一个**手写简化版**（自己算余弦相似度、自己取 Top-K），结果与 LangChain 版一致，证明原理掌握到代码行级别。产出：`rag_结构图.png` 架构图。
> [数学加分·串讲] 我能把"检索 = 最近邻 = 注意力三步走"讲通，还能讲清每个模块（加载/切块/Embedding/检索/生成）的输入输出——说明不是只会调框架。

### 模块 G：统计建模副线八股（本周零散时间，覆盖风控岗）

**Q30. 逻辑回归是什么？和线性回归什么区别？**
> 逻辑回归 = 把线性组合的输出塞进 sigmoid（S 形函数）压到 0~1 当概率：`P = sigmoid(w·x + b)`。与线性回归区别：线性回归预测连续数值（房价），逻辑回归预测概率（是否违约）。为什么银行风控爱用：输出是概率、数学可解释、能直接算风险评分。

**Q31. 准确率 / 精确率 / 召回率怎么区分？**
> 混淆矩阵四格：TP（正判正）/ FP（负判正）/ FN（正判负）/ TN（负判负）。Accuracy = (TP+TN)/全部（类别不平衡会骗人：99 负 1 正时全判负也有 99%）；Precision = TP/(TP+FP)，回答"查出来的里有多少对的"；Recall = TP/(TP+FN)，回答"该找出的里找回多少"。风控例子：把"违约"当正例，精确率高 = 少误伤好人，召回率高 = 少漏网真违约，此消彼长。

**Q32. F1 是什么？AUC 的概率含义是什么？（数学加分题）**
> F1 = `2·P·R/(P+R)`，精确率与召回率的**调和平均**——对小的那个值敏感，优化 F1 = 强迫 P、R 同时不能差，适合类别不平衡。AUC = **随机抽一对正负样本，模型给正样本更高分的概率**，测的是排序质量而不是分数大小；AUC=0.8 就这么解读。
> [数学加分·我能证明等价] 我亲手做过双视角等价证明：3 正 4 负的例子，概率口径（数 12 对配对里正≥负的对数）和几何口径（手画 ROC 阶梯算面积）算出同一个 0.833。原理：ROC 阶梯只有"垂直上升=抓住真违约"和"水平右移=冤枉好人"两种动作，每个正样本贡献的面积 = 排在它前面的负样本比例 → AUC = Mann-Whitney U 统计量 U/(n_pos×n_neg)。附：AUC<0.5 说明方向反了（取反得 ≈1−AUC）；AUC 不看校准只看排序，类别不平衡下依然有效。

**Q33. 偏差-方差分解讲一下？（可以现场推导）**
> 设真实规律 `y = f(x) + ε`（ε 零均值噪声）、模型 f̂。把平方误差对训练集随机性取期望展开：交叉项消掉（ε 与 f̂ 独立且 E[ε]=0），中间加减一项 E[f̂]，得到 **MSE = 偏差² + 方差 + 噪声σ²**。偏差² = 平均预测离真值多远（欠拟合）；方差 = 换批数据预测抖多厉害（过拟合）；σ² 谁都降不了。模型太简单偏差大、太复杂方差大（U 形曲线），正则化（L2/dropout/早停）= 用一点偏差换很多方差。
> [数学加分·联系大模型] 大模型参数巨大 → 天然低偏差高方差 → 要靠海量数据压方差；RLHF/指令微调 ≈ 一种"正则化"（把输出约束到人类偏好子集）；我在本地实测思维链能显著降低输出方差 = "独立误差平均"在推理时的体现。

**Q34. 决策树怎么选分裂特征？过拟合怎么办？**
> 决策树 = 递归做"哪个特征最能把数据分开"的选择，分裂准则两种：**信息增益**（分裂前熵 − 分裂后加权平均熵，越大越好，ID3 用）、**基尼系数**（`1−Σpᵢ²`，越小越纯，CART 用）。两者本质都是"分裂后子集的分布更尖（纯度更高）"——和写提示词压熵一个思想。过拟合 = 树长到每个叶子只有一个样本（方差大），**剪枝**解决：预剪枝（限制深度/叶子最少样本数）、后剪枝（建完整树再自底向上剪），本质是用一点偏差换方差。

**Q35. Bagging 和 Boosting 一句话区别？随机森林和 GBDT 呢？**
> Bagging（装袋）= **并行**训练多棵独立树（每棵用有放回抽样 + 随机特征子集），投票/平均融合 → **降方差**；Boosting（提升）= **串行**训练，每棵新树纠正前面树的错误（拟合残差）→ **降偏差**。所以：随机森林 = Bagging + 决策树（管方差），GBDT = Boosting + 决策树（管偏差）。
> [数学加分] GBDT 每棵新树拟合前一轮的残差（负梯度）= **在函数空间做梯度下降**，每棵树是沿负梯度方向走一小步——和神经网络梯度下降是同一套语言。GBDT 及其变体 XGBoost/LightGBM 是银行风控最常用的模型族。

### 模块 H：刷题中的数学谈资（零散时间素材）

**Q36. 第二周哪道题最能体现数学思维？（拿 382 蓄水池抽样举例）**
> 382 链表随机节点：要求等概率返回链表任一节点值，但链表长度未知、内存装不下（不能先数 N 再随机索引）。解法 = **蓄水池抽样**：遍历时第 i 个节点以概率 1/i 替换当前"幸运儿"。证明（裂项相消）：第 k 个节点最终胜出 = 第 k 次被选中 × 之后都没被替换 = (1/k)×(k/(k+1))×…×((n-1)/n) = 1/n，每个节点等概率。这是总纲点名的"数学概率加成题"，和洗牌算法、生日问题同类。

**Q37. 160 相交链表为什么是"数学思维加分题"？**
> 双指针解法：a 从 A 头、b 从 B 头同步走，谁走到头就跳到对方链表头继续。数学本质：设 A 公共前缀长 a、B 公共前缀长 b、公共部分长 c，a 指针全程走 a+c+b、b 指针全程走 b+c+a——**总路程恒相等 a+b+c**，所以交换起点后必然同时到达交点（或同时到 null）。这是"路程相等→相遇"的追及思想，也是"用路程差消除长度差"。

**Q38. 字符串相加（415）怎么用数学讲？**
> 两个数字字符串逐位相加 = 小学列竖式：从低位到高位逐位加，`carry`（进位）像"溢出/余数"一样向高位传递。代码上就是当前位 = `(a+b+carry) % 10`，进位 = `(a+b+carry) // 10`——模 10 运算 + 整除的模拟。
