### 3.5 学习过程中的追问（都是"真学会"的痕迹）

- 追问"**运行一半的终端好像误触关了，还能恢复吗**" → 得到完整排查链：① Cursor 终端缓冲**不落盘**，屏幕内容找不回；② 查端口 + `Get-Process python` 确认**无孤儿进程**（不是上次 7860 那种"孤儿占端口"）；③ 从 **PowerShell 历史文件** `%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt` 定位到最后一条命令是 `python eval_v2.py --limit 2 --runs 1 --dry-run`；④ 结论是**那一轮 12:30:03 已正常跑完**——因为 `eval_v2.py` 自带 `Tee` 双写，`run_log.txt` 里 `[1/2]`~`[2/2]`、汇总指标、可复制的「日志行」**一句不缺**。**由此确立一条新纪律：长任务优先用"自己会落盘"的脚本，服务单独一个终端、收工用 `Ctrl+C`。**
- 追问"跑 `eval_v2.py` 报 `UnicodeEncodeError: 'gbk' codec can't encode ...` 是哪里的问题" → 判定不是脚本 bug，而是**输出端（脚本强制 UTF-8）与显示端（PowerShell 默认 GBK/cp936）编码不匹配**；解法 `chcp 65001 | Out-Null` + `$env:PYTHONIOENCODING='utf-8'`；并进一步识别出 `>` / `Tee-Object` 重定向也会按控制台编码解码子进程输出（日志会乱码）→ **最终解法是让 Python 自己写日志**（`Tee`），不依赖 shell 重定向。
- 追问"`python app.py` 报 `TypeError: Blocks.launch() got an unexpected keyword argument 'show_api'`" → 认识 **Gradio 6.x 的 API 变更**：`show_api` 已移除、`theme` 从 `Blocks()` 构造函数移到 `launch()`；学会用 `inspect.signature(gr.Blocks.launch)` 现查真参数，而不是照抄旧教程。
- 追问"`taskkill /PID 38648 /F` 报`错误: 没有找到进程`，是失败了吗" → 学会**判成功要看作端口，而不是看 `taskkill` 输出**：该 PID 已不存在（杀过一次/自己退出），属正常；确认方式 `netstat -ano | findstr :7860` 无输出 = 端口已释放。**已把这段连同"终端关了也能停服务"的三种方法写进教程附录 D。**
- 追问"`--append-log` 明明成功了，行怎么跑到别的表里去了" → 定位到 `append_log()` 用的是 `open(..., "a")`，即**追加到文件末尾**，于是落进了「三、失败尝试记录」表——**脚本"跑成功"不等于"记对地方"**；已把 R2 行移回「一、实验记录表」，并把该 bug 记为待修项。
- 追问"B0 跑出来了，算是复现成功吗" → 学会**分层看待"复现"**：检索（2/10）与防幻觉（6/10）**完全复现**，说明新尺子量的就是旧尺子那件事；但生成（1/10 vs day14 的 2/10）与 F1（0.750 vs 0.667）不一致，根因是 **temperature=0.2 下单次生成仍有随机性**（同题答案在两次运行里不同：Q3 从错到对、Q5 从对到错、Q4 从错到对；FP 也从 2 变 0）。**结论**：受控实验的"复现"要区分"口径复现"与"数值复现"——前者是脚本正确性，后者受模型随机性影响，**只有 `--runs 3` 投票才能把数值稳住**。
- 追问"Q5 明明答的是 LAFAN 数据集，为什么判 ❌" → 发现**判分关键词过严**：`eval_questions.json` 里 Q5 的关键词是 `LAFAN1`，模型答 "a diverse LAFAN dataset"（语义正确）→ 被规则判错。**这是"尺子自身的刻度问题"，属于今天任务的正题（O0 尺子校准）**——教训：改判据必须**在全量重跑前一次性统一**，否则前后口径不一致、数字就没法比。
