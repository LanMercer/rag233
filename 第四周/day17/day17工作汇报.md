### 3.2 今日关键数字（三组受控对照）⭐ 今天最重要的产出

**同一套 20 题（in 10 + out 10）、同一模型（Qwen2.5-3B-Instruct-LoRA）、同库同模板（09 v1）、temperature=0.2、runs=3 多数投票、判据补丁 on**

| 指标 | B0r3：k=4，无前缀 | R1：k=4，**+前缀** | R1R2：k=8，+前缀 | 参考：day16 R2（k=8，无前缀，runs=1） |
|---|---|---|---|---|
| 检索命中 · strict | 2/10 = 20.0% | **0/10 = 0.0%** ⬇ | 3/10 = 30.0% | 4/10 = 40.0% |
| 检索命中 · loose | 3/10 = 30.0% | 2/10 = 20.0% ⬇ | 4/10 = 40.0% | 5/10 = 50.0% |
| 生成正确率（in） | 2/10 = 20.0% | 2/10 = 20.0% → | 4/10 = 40.0% ⬆ | 4/10 = 40.0% |
| 防幻觉正确率（out） | 6/10 = 60.0% | 5/10 = 50.0% ⬇ | **8/10 = 80.0%** ⬆ | 7/10 = 70.0% |
| 防幻觉 F1 | 0.706（TP6 FP1 FN4 TN9） | 0.625（TP5 FP1 FN5 TN9） | **0.842**（TP8 FP1 FN2 TN9） | 0.824 |
| 总正确率 | 8/20 = 40.0% | 7/20 = 35.0% ⬇ | **12/20 = 60.0%** ⬆ | 11/20 = 55.0% |
| 生成一致率 | 0.950 | 0.933 | **0.967** | ——（runs=1） |

**归因三问（实跑回答）：**

1. **前缀贡献了多少？** = R1 − B0r3（只差前缀）→ 检索 strict **20% → 0%（−2 题）**、防幻觉 60% → 50%、F1 0.706 → 0.625、总 **40% → 35%（−1 题）**。
   → **假设①（"bge 查询侧缺 instruction 前缀导致系统性欠对齐"）证伪**。这是今天最有价值的一条发现（机制见下）。
2. **多取 4 条（k）贡献了多少？** = R1R2 − R1（只差 k）→ 检索 strict **0% → 30%（+3 题）**、生成 20% → **40%**、防幻觉 50% → **80%**、F1 0.625 → **0.842**、总 **35% → 60%（+5 题 = +25 个百分点）**。
   → **k 贡献很大，且是今天唯一真正把指标拉起来的变量。**
3. **两个变量能简单相加吗？** 用 day16 R2（k=8 无前缀）做交叉验证：前缀效应 **−2 题**、无前缀下 k 效应 **+2 题**，简单相加预测 `2 − 2 + 2 = 2/10`；**实际 R1R2 = 3/10** → **不可加，两个变量存在交互（interaction）**。

**机制追查（这是"为什么"的答案）——前缀到底"伤"在哪：**

| 题 | B0r3（k=4，无前缀） | R1（k=4，+前缀） | R1R2（k=8，+前缀） |
|---|---|---|---|
| Q5（实验数据集，期望 `[3]`） | `[103, 4, 25, **3**]` → chunk 3 在**第 4 名** ✅ | `[103, 25, 74, 4]` → **跌出前 4** ❌ | `[…, **3**, …]` → 第 **5** 名 ✅ 又命中 |
| Q9（代码仓库，期望 `[3]`） | `[103, 52, 25, **3**]` → 第 4 名 ✅ | `[103, 52, 25, 50]` → 跌出前 4 ❌ | 第 5 名 ✅ |
| Q3（作者学校，期望 `[0,6]`） | —— | —— | chunk 6 **跌出前 8**（day16 无前缀时是第 6 名 ✅） |

**结论**：前缀**并没有让向量"变差"**，而是把期望段**整体下压了 1 名**——**chunk 3 从第 4 名掉到第 5 名**：
- **k=4 时第 5 名看不到 → 命中集合 `{Q5,Q9}` → `{}`（新增 0 条、丢失 2 条）**，这就是"strict 0/10"的全部来源；
- **k=8 时第 5 名仍在窗口内 → 没损失** → 这就是"前端在 k=4 有害、k=8 不致命"的**交互效应来源**；
- 但前缀在 k=8 下**仍净丢 Q3**（chunk 6 跌出前 8），也解释了"**R1R2 的 strict 3/10 反而低于 day16 R2 的 4/10**"——**把前缀关掉、只保留 k=8，strict 大概率能回到 4/10**。

> **面试可直接讲的一句话**：
> "我按 bge 官方文档给查询侧加了 instruction 前缀，**结果检索命中率反而从 20% 掉到 0%**。逐题追查发现：前缀并没有让向量'变差'，而是把几段关键资料**从第 4 名推到第 5 名**——k=4 时刚好掉出窗口，所以全灭；把 k 提到 8 之后它们又在窗口内了。这说明**前缀的效应与 k 有交互，不能只看单一变量的平均值**；也说明'官方推荐做法'在具体语料上不一定有效，**必须用自己的固定评测集验证**。最终我选择关掉前缀、保留 k=8。"

**B0r3（校准后基线）读表结论**：

- **检索 strict/loose 与防幻觉三栏与 day16 B0 完全一致** → **尺子没被改坏、前后可比**（这是"判据校准"没有副作用的关键证据）；
- **生成 2/10 回到 day14 口径，但归因不是补丁**——本轮 Q5 答的是 "outperform open-source methods…"、**根本未提 LAFAN**，补丁没救到它；2/10 来自 Q4/Q8 在投票下稳定答对。→ **重要边界：判据补丁只治"答对了但被关键词误杀"，治不了"答错内容"**；
- **一致率 0.950**（20 题里仅 Q5/Q8/Q11 为 0.67）→ **这条基线数字可以对外引用**，不再是"某一次抽样的结果"；

| 任务 | 完成情况 | 说明 |
|---|---|---|
| **力扣 70. 爬楼梯**（简单 · 一维 DP 模板题） | ✅ | 三写法对照：① 朴素递归 `f(n)=f(n-1)+f(n-2)` **O(2ⁿ)**（定义直译，n=45 就跑不动）→ ② 记忆化 O(n) 时间 / O(n) 空间 → ③ **递推 + 滚动变量 O(n) 时间 / O(1) 空间**（本题最优）。核心是"**最后一步只有两种可能**"（从 `n-1` 走 1 步 / 从 `n-2` 走 2 步）→ `dp[n]=dp[n-1]+dp[n-2]`，即**斐波那契的平移**（`dp[n]=F(n+1)`）；与昨天的 509 对照，体会"**同一套骨架、不同的故事**"（从"求数列项"迁移到"求方案数"） |
| **数学视角（面试加分点）** | ✅ | ① **方案数的组合表达**：`dp[n] = Σ_{k=0}^{⌊n/2⌋} C(n-k, k)`（若用了 `k` 次"两步"，位置组合数即此）；`n=4` 验算 `C(4,0)+C(3,1)+C(2,2)=1+3+1=5` ✅。② **递推与杨辉三角是同一个恒等式**：展开即**帕斯卡恒等式** `C(m,r)=C(m-1,r)+C(m-1,r-1)` → `dp[i]=dp[i-1]+dp[i-2]` 不过是"二项式系数沿杨辉三角往下走"的另一种写法。③ **矩阵快速幂** `M=[[1,1],[1,0]]` → `O(log n)`；特征值 φ、ψ，主导项 φⁿ（黄金比）→ 解释了这类递推为何**指数增长**。**但 n≤45 时 O(n) 已够快**——"**能更快**"与"**该不该更快**"是两件事 |
| **统计八股：偏差-方差权衡**（第 3 周欠账收尾） | ✅ | 分解式：`E[(y − f̂(x))²] = Bias² + Variance + σ²`；模型太简单 → 偏差高（欠拟合），太复杂 → 方差高（过拟合），拉锯即 **U 型曲线**。**并逐项接到本项目**（这是关键，面试官最烦背概念）：**判据过严**（Q5 答对被 `LAFAN1` 误杀）= 尺子的**系统性偏差** → 用 `KEYWORD_PATCH` 修；**temperature=0.2 下单次生成随机性**（B0 与 day14 同配置却 1/10 ≠ 2/10）= **方差现场演示** → 用 `--runs 3` 压；**300 条合成 SFT 数据 = 模板套壳** = **高偏差（欠拟合）**，正是 HR 说"没意义"的根因（→ F 线真实数据整改）；**模型背评测题 / k 调太大引入上下文噪声** = **过拟合（高方差）**。**降方差手段**：多测取多数 / 固定评测集与配置 / 低温 / 增大 n（20 → 100） |

### 3.5 当天逐个查清的关键问题（都留了实证）

- **"加了 instruction 前缀，到底要不要重建向量库？"** → **不用**。因为只重写了 `embed_query`（查询侧），`embed_documents`（段落侧）**一个字没动** → 段落向量和建库时**一模一样**。"改了 embedding 就要重建库"只对"段落侧参数也变了"成立；需要重建库的情况是**换 embedding 模型本身**或**改 chunk 参数**（那是 Day18 的 O1-R3 chunk 矩阵要处理的，且必须改成按配置存不同 `persist_dir`）。
- **"前缀到底生效没有？"** → 做了**两级验证**（先验封装、再验接线）：① 向量层：`cos(base, qi)=0.9108`、`same=False`、`dim=512` → 前缀进了编码、模型没坏、只是"刻度对齐"；② 检索层：dry-run 里 **Q2 的 Top-K 从 `[14,22,1,9]` 变成 `[14,22,9,1]`** → **排序真的动了**。**先证明"变量接上了"，再跑全量下结论**——这个顺序避免了"改了半天其实没生效"的假实验。
- **"`inspect.signature` 看不出支持 `query_instruction`，是不是就真不支持？"** → 不能只看 signature（被 `**kwargs` 吞了）。**要再查 `model_fields`（pydantic 实际字段，里面确实没有）+ 读 `embed_query` 源码（确实没拼前缀）**，才能确定"不仅不支持、而且不会偷偷生效"。→ **照抄旧教程会翻车，现查真参数才可靠**。（注：`langchain_community` 里确有 `HuggingFaceBgeEmbeddings` 支持它，但已标 sunset 弃用，本项目主线用 `langchain_huggingface`，故走薄封装。）
- **"判据补丁加上去，Q5 就该被救回来了吧？"** → **没有**。这轮 Q5 答的是 "GMR consistently outperform existing open-source methods…"，**根本没提 LAFAN** → 补丁帮不上忙。**结论（重要边界）：判据补丁只治"答对了但被关键词误杀"，治不了"答错内容"。** 报告里要如实写，**别把"判据放宽"当成"检索/生成变好了"**（那会变成自己给自己刷分）。
- **"前缀让命中率掉到 0，是不是说明 bge 的 instruction 是错的？"** → 不是。逐题追查看出**前缀改变的是"排序的相对位置"而非语义质量**：关键段落被整体下压 1 名，**恰好卡在 k=4 的边界上**（chunk 3 从第 4 → 第 5）。→ **"理论上更对齐" ≠ "在有限 Top-K 下更优"**：这是**评估窗口（k）与编码方式耦合**的结果，也解释了为什么"前缀在 k=8 时不致命、在 k=8 下仍丢 Q3"。**这也是"两个变量不可加"（交互效应）的机制解释**——双因素实验里单看主效应会骗人，必须先固定另一个变量再比。
- **"B0r3 和 day16 B0 数字不一样，是不是尺子又出问题了？"** → 不是。**分层看**：**检索（2/10）与防幻觉（6/10）完全一致 → 口径复现（脚本正确性）**；生成与 F1 的差异来自**模型输出的单次随机性**（`runs=1` vs `runs=3`）。→ 这正是今天要做 `--runs 3` 的动机；而 **一致率 0.950** 就是对"投票把波动压掉多少"的量化。
- **"三组跑完，怎么开 Day18？"** → **先看数字、再走决策门**：strict 3/10（未达 ≥4/10）、前缀有害、唯一有效的是 k。→ 判定"瓶颈不在取几条、也不在编码约定"，于是**不做 O1-R3 chunk 矩阵**（那是"检索路线有效"时才走的），转 **O1-R8 数据自检 + O1-R4 HyDE 冒烟**，并评估 **O1-R5 混合检索**。
