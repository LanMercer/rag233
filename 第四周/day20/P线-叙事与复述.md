## 二、端到端复述脚本（P2-1：从"介绍下你的项目"讲 10 分钟不断线）

### 第 0 步 · 开场（30 秒，先给结论）

> "我做了一个**机器人领域的 RAG 文档问答系统**，用一个机器人重定向论文（GMR）当知识库，
> 目标不是"能跑"，而是**能把优化过程说清楚**：
> 同一套 20 题固定评测集上，检索命中率从 **20% 提到 40%**、防幻觉 F1 从 **0.667 提到 0.824**，
> 其中**每一步单独重跑、贡献可拆解**；数据侧把原来的 300 条合成数据整改成
> **201 条可追溯的真实数据**（论文 90 + 行业 111）。
> 交付形态是一个**开箱即用的 Web 工具**（上传 PDF → 提问 → 带出处回答 → 可切换原模型/微调模型）
> 加两个在线链接。"

> 🔧 数字替换点：`20% → 40%` 与 `0.667 → 0.824` 来自**定稿行**（R3/R6）。
> 若今天重跑了定稿行，**以 `定稿数字表.md` 为准**；口径要一起讲（见第 3 步）。

### 第 1 步 · 数据流全景（2 分钟，边说边画四个框）

```

用户提问  ->  [检索层] 余弦 Top-K (k=8)  ->  拼上下文(带 [资料§N] 编号)
                                                      |
                                          [生成层] 模板 09 + Qwen2.5-3B-Instruct(+LoRA)
                                                      |
                                          [交付层] 引文白名单剪除非法编号  ->  答案 + 出处
```

| 环节 | 对应文件 / 命令 | 一句话说清"我在哪儿做了什么" |
|---|---|---|
| 切块 + 向量化 + 存库 | `第三周\day12\build_db.py`、`第三周\day13\chroma_db\` | 中文切块 + `bge-small-zh-v1.5`（**中文查询、中文语料**） |

### 第 3 步 · 评测体系（2 分钟，讲"尺子"）

- **为什么 20 题**：资料内 10 + 资料外 10，**n=20 的 95% CI 约 ±0.22** →
  **结论看量级与归因，不抠小数点**（这句话必须主动说，这是加分项）。
- **为什么要 `--runs 3` 投票**：day16 实测过"同一配置单次运行会波动"（生成 1/10 vs 2/10，
  F1 0.750 vs 0.667）→ **日常实验 runs=1，对外引用的数字必须 runs=3**，并给**一致率**（≥0.93 才算稳）。
- **双轨检索判据**：strict 偏严（必须召回标注的 `source_chunk`），loose 治反例
  （Q4 那种"没召回该段却答对了"）→ **两列并列报，口径透明**。
- **F1 必须带混淆矩阵**：同一个 F1 可能来自完全不同的结构；本项目**两次**出现"FP 是判据假阳性"
  （答案中间带了拒答词，规则就记成"该答没答"）。

### 第 4 步 · 优化故事线（2 分钟，**这是 HR 意见① 的正面回答**）

| 顺序 | 做了什么 | 结果（定稿口径） | 一句机制 |
|---|---|---|---|
| O0 | 校准尺子（判据补丁 + runs=3） | day14 → B0r3：检索 20%→20%、总 40%→40%（**不变**） | **尺子没被改坏**，数字从此可引用（一致率 0.950） |
| **O1-R2** | **TOP_K 4→8** | 检索 **20%→40%**、总 **40%→55%** | ⭐ 唯一稳定有效：期望段从"第 5 名"回到窗口内 |
| O1-R1 | bge instruction 前缀 | 检索 20%→**0%** | **负结果**：不是语义变差，是**排名位移**（chunk 3 第 4→5 名，k=4 掉出窗口） |
| O1-R4 | 模型自动改写（term/hyde/both 三档） | 总 55%→**45%/50%/55%**（**无一档超过基线**） | `term` 伤专名；`hyde` 让资料外题"有话说" |
| O2-G2 | 模板 09 v2 + **逐句消融** | 防幻觉 7/10→**3/4/6**；F1 0.824→**0.462/0.571/0.706** | **归因锁死在一句提示语**（"资料里有依据就照实回答"）——资料外题的 Top-K 永远有 8 条 |
| **O2-G3** | **引文强制白名单（strip）** | 交付口径非法引用 **5→0 处**、**F1 逐格不变（0.824）** | ⭐ 唯一**零副作用**的工程兜底（但"非法 0 处"≠"答案干净"） |
| F3 | 真实数据 adapter v2 | F1 0.824→**0.333**（**负结果**） | ⚠ **"来源"与"数量"两个变量没拆开** → 今天补 v3 配比版 |
| **F3v3** | 真实 201 + 合成 99 = 300（**已跑完**） | F1 **0.429**（3/1/7/9）、防幻觉 **3/10**、总 **40%**（检索 4/10、5/10 **与 R3 逐位相同**） | **仍远低于 R3（0.824）⇒ 退化主因是"数据分布与评测集不匹配"，不是数量**（数量对齐只回 1 题） |
| **F4** | 原模型 vs 微调模型（**已跑完**） | 原模型 F1 **0.947**（9/0/1/10）、总 **80%** **＞** 微调 0.824 / 55%（检索两列**逐位相同**） | ⭐ **逆预期：原模型全面占优** ⇒ **这版微调在防幻觉上是负收益**；边界：≠"微调无用"（收益在风格/术语/格式），且 n=20、CI≈±0.22 |

> **一句话收口**："**加大 k 是唯一稳定有效的优化**；**引文白名单是唯一零副作用的工程兜底**；
> 提示词改约束、查询改写、换真实数据这三类，在当前规模与 3B 模型下**都没有净增益**——
> 而这三条**都是可复现、有机制解释的负结果**。
> **更硬的一条**：把变量拆开后（数量对齐到 300）退化仍在，说明**瓶颈不在样本数量**；
> 而**原模型 F1 0.947 全面高于微调 0.824**——**这版微调在防幻觉上是负收益，我照实写进报告。**"

- **分层归因评测 + 人工复核诚实改判**：检索层/生成层/防幻觉层三组指标 + F1（混淆矩阵口径），
  能把每个低分定位到具体环节；引入"引文强制白名单"使交付口径非法引用 **5→0 处**（判定零翻转）
- **主动把"坏消息"跑成结论**：把不公平对比的两个变量**拆开重做**（真实 201 + 合成 99 = 300）→
  数量对齐后 F1 仍只有 **0.429**（vs 基线 0.824）⇒ 主因是**分布不匹配**；
  同一把尺子量**原模型 vs 微调**（同库同参、检索两列**逐位相同**）→ **原模型 F1 0.947、总 80%** 全面高于微调 0.824 / 55%，
  **照实写成"这版微调在防幻觉上是负收益"**（含 n=20、CI≈±0.22 的边界说明）
