**F3 结论（如实写，不硬编"提升"）**：

1. **检索层没变**（✅ 自检通过）→ 说明"换数据"只影响生成层，符合单变量纪律；
2. **生成正确率略有上升（4→5）**，但**防幻觉大幅退化（7→2）**——净效果是**总正确率 −4 题**；
3. **⚠ 不能据此说"真实数据不好"**——本轮是**"真实 201 条" vs "合成 300 条"**，**两个变量同时变了（来源 + 数量）**。要拆开必须再跑一轮"真实 201 + 合成补到 300"的配比版 → **已按 §六 生成配比数据集并开跑**（`day20\sft_data_v2_mix.json`，真实 201 + 合成 99 = 300，**把"数量"对齐**），结果出来后把数字填回本行；
4. **HR 要的是"数据真实"，不是"数据一定带来分数提升"**——本项目的处理是：**把真实数据作为交付物（201 条可追溯）**，把"真实 vs 合成"作为**一次如实记录的负结果**，并写明下一步如何拆变量。

### 5.2 负结果清单（同样要讲，这是"可归因优化"的证据）

1. **提示词加约束治不了"误读型幻觉"**（R5/R5a/R5b 三档全线回退）——模型"看过"那些字，不认为自己在编；
2. **查询改写无净增益**（R4 三档无一超过 R3）——`term` 伤专名、`hyde` 伤拒答；
3. **`retry` 兜底有害**（F1 0.824→0.737）——给 3B 任何"允许拒答"的措辞，它就把出口当答案；
4. **真实数据微调在此规模下未提升**（F1 0.824→0.333）——**已拆开变量**：数量补齐到 300（真实 201 + 合成 99）后 F1 仅回到 **0.429** ⇒ 主因是**分布不匹配**，不是数量（见 §六）；
5. **RRF 混合检索有害**（BM25 中文近零信号）；
6. ⭐ **原模型全面优于微调模型**（F1 **0.947 vs 0.824**、总正确率 **80% vs 55%**，检索两列逐位相同）——**逆预期的负结果，仍如实写进 §七**。

### 5.3 ⭐ 必须写进报告的两句"防误读声明"

1. **「HyDE 上界 100%（10/10）不是成绩」**——那是**人工手写的理想查询**跑出来的上界，只用来证明**"瓶颈在查询侧"**；模型自动改写的真实现落在 **50%（hyde 档）**，**兑现率 ≠ 1**。
2. **「非法 0 处 ≠ 答案干净」**——`strip` 抓的是**数字编号**；交付答案里仍有 **23 处非数字伪引文**（`[资料©]` 等），**正则覆盖不到**。

### 5.4 口径边界（三处"看起来是错、其实是判据"的坑，已踩两次）

- **R4c / R5b 的 `FP=1` 是判据假阳性**：模型答案**中间**出现拒答词（如 `① … [2]；② … [52]；资料中没有提及③ …`），而 `fp = sum(1 for r in in_mat if r["refused"])` **只看"答案里有没有拒答词"** → 被记成"该答没答"。
- **R6 总正确率 +1 题不是兜底的功劳**：R6 是**重新生成**（T=0.2 重掷），且**轮内 raw vs delivered 逐题零改动** → 这 +1 题归**生成随机性**。
- **F2「市场与产业链」类目超标（28.8% vs 建议 ~15%）**：如实标注，**没有为了分布好看去删已有数据**。

## 六、F3 拆变量轮：真实 201 + 合成 99 = 300

### 6.1 为什么要加这一轮

§四 的 F3v2 是**负结果**，但**它不可归因**——因为它同时动了两件事：

| | 合成 300 条（baseline v1） | 真实 201 条（v2） | 差在哪 |
| --- | --- | --- | --- |
| 数据**来源** | 全合成 | 全真实 | ⬅ 变量 A |
| 数据**数量** | 300 | 201 | ⬅ 变量 B |

**"防幻觉 7/10 → 2/10"这个退化，到底是"真实数据不好"还是"少了 99 条"？** 这一轮就是为了把它拆开。

### 6.2 做法：配比到 300，只让"来源"变

```powershell
cd 第四周\day20
python build_mix_data.py --dry-run     # 先看清楚要捡多少条、剔多少条
python build_mix_data.py               # 生成 sft_data_v2_mix.json（真实 201 + 合成 99 = 300）
python train_lora_v3.py                # 产出 lora_adapter_v3（与 v1/v2 只差 3 个常量）
python -m uvicorn local_api_lora_v3:app --host 127.0.0.1 --port 8000
python eval_v2.py --profile lora_v3 --runs 3 --top-k 8 ...   # 结果目录 result_lora_v3_runs3
python collect_finals.py               # 自动把数字补进 定稿数字表.md
```

**池子账（`--dry-run` 实测输出）**：真实 201 条全收；合成池可用 **208 条**（剔除 **92 条**）→ 从 208 里按固定种子抽 **99 条**补足 300。
> 剔掉的 92 条是**合成池内部重复**（不是"与真实数据重复"）→ 说明真实数据与合成数据**本来就没有相互污染**，这一步是为了让三档训练集**除了"来源"之外尽量同分布**。

### 6.3 三档对比（这一轮跑完才填）

| 轮次 | 训练集 | 来源 | 数量 | 检索 strict/loose | 生成(in) | 防幻觉(out) | F1（TP/FP/FN/TN） | 总正确率 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| F3v1（=R3） | 合成 300 | 全合成 | 300 | 4/10、5/10 | 4/10 | 7/10 | 0.824（7/0/3/10） | 55% |
| F3v2 | 真实 201 | 全真实 | 201 | 4/10、5/10 | 5/10 | **2/10** | **0.333**（2/0/8/10） | 35% |
| **F3v3** | **真实 201 + 合成 99** | **混合** | **300** | 4/10、5/10 | **5/10** | **3/10** | **0.429**（3/**1**/7/9） | **40%** |

### 6.4 判读规则（**先写死，避免跑完"看图说话"**）

- **若 F3v3 回到 R3 水平（防幻觉 ≥6/10）** ⇒ 退化主因是**数量**（201 太少，模型在 3B 上"样本饥饿"），**"真实数据"本身没问题**；
- **若 F3v3 仍显著低于 R3（防幻觉 ≤3/10）** ⇒ 才轮到谈**"这批真实数据与评测集分布不匹配"**（真实 QA 以长句归纳为主，与评测题"短问短答 + 英文专名"的风格不同）；
- **检索两列必须与 R3 逐位相同（4/10、5/10 ✅）**——这是**单变量自检**：换数据只能动生成层，检索层变了就说明实验脏了，**数字作废**。

### 6.5 结论（✅ 本轮落在"情况 B"：F1 = 0.429）

**补齐数量后仍退化 ⇒ 退化的主因是"数据与评测集的分布不匹配"。**

评测题出自 GMR 论文（术语 / 方法 / 实验 / 结论），而 v2 数据里 **111 条（55%）是行业语料**（市场 / 公司经营 / 政策），
两者话题分布差异大 → **领域适配被"摊薄"**。

**实测依据**：F3v3 防幻觉 **3/10**、F1 **0.429**，相比 F3v2（2/10、0.333）**只回了 1 题**，而 R3 是 **7/10、0.824**
→ **"差的这 99 条"最多只能解释一小部分差距**，差距主体只能归到**分布不匹配**。

> ✅ **同时要主动说出边界**：F3v3 仍比 F3v2 好一点点，说明"掺入合成数据"有**微弱正作用**；
> 但这**不能**写成"真实数据没用"——**只说明"这批真实数据的分布不适合这套评测题"**。
> 真实数据的价值在**交付物层面（每条可追溯、可逐字回查）**，不在"同规模下必然涨分"。

**下一步**（写进 §5.5 收尾清单）：要么按评测分布重新配比真实数据（提高论文 QA 占比），要么把评测集扩到覆盖行业问题。

⚠ **三条不许做的事**：① 不许为了好看回去改配比；② 不许挑着样本说（说"来源不匹配"时必须同时报出"55% 是行业语料"）；③ 不许用一次运行下结论（要引用一致率 ≥0.93）。

### 7.2 对比表（这一轮跑完才填）

| 轮次 | 检索 strict | 检索 loose | 生成(in) | 防幻觉(out) | F1（TP/FP/FN/TN） | 总正确率 | 一致率 |
| --- | --- | --- | --- | --- | --- | --- | --- |

| **F4l**（微调） | 4/10 | 5/10 | 4/10 | 7/10 | 0.824（7/0/3/10） | 55% | 0.950 |
| **差值（微调 − 原模型）** | **0** | **0** | **−3/10** | **−2/10** | **−0.123** | **−5/20 = −25pt** | −0.05 |

### 7.4 结论（⚠ **逆预期：反例成了主结论**）

**✅ 自检通过**：检索两列**完全相同（4/10、5/10）** → 两组确实只差 adapter，**差异可以干净地归因到"微调"这一个变量**。

1. ~~若微调侧生成正确率更高~~ → **未发生**：微调侧 **4/10**，比原模型 **7/10 低 3 题**；
2. ✅ **若微调侧防幻觉更低 —— 这正是本轮结果**：防幻觉 **7/10 vs 9/10（−2 题）**、F1 **0.824 vs 0.947（−0.123）**。
   如实写：**这版 LoRA 在"资料外拒答"上不但没帮忙，反而拖低了**——一种合理解释是 3B 容量有限，
   微调把"照本宣科 / 该拒就拒"的能力挤掉一部分，模型变得更"愿意顺着上下文说"（**假说，本轮未单独验证**）。
3. ✅ **反例已成主结论（必须写）**：不是"个别题原模型更好"，而是**原模型在两个生成类指标上全面占优**。
   **但边界必须同时写**：① 这只能说明"**这版数据 / 配置的微调在防幻觉上是负收益**"，**不能**推广成"微调无用"；
   ② 微调的收益体现在**风格 / 术语 / 格式遵循**（可展示，但不是本评测集的判据）；
   ③ n=20、CI≈±0.22，但 **−0.123 的 F1 差 + 全项同向** 足以支撑"负收益"这个**量级**判断。

### 7.3 读法（三条纪律）

1. **检索两列若不相同 → 这组对比作废**：两轮跑的是**同一个库、同一份评测集、同一套判据**，检索层**必须逐位相同**；不同就说明服务/库/参数有一个不对（最常见：**端口上跑着旧 adapter**，用 `check_service()` 拦）。
2. **差异只在生成层**，所以结论只能落在"**回答风格 / 拒答倾向 / 专名复述**"这类生成侧行为上——**不要说成"微调提升了检索"**。
3. **必须如实记录反例**：如果出现"微调后某题反而不如原模型"（day15 冒烟就出现过一次：Q5 数据集名 `LAFAN1`，微调链单次没点名、原模型点出来了），**照写**——单次现象不算结论，但**隐瞒就成了虚报**。
