| # | 问题 | 答要点 | 对应文件 / 数字 |
|---|---|---|---|
| 24 | 说一下你印象最深的一个坑 | **`.gitignore` 只管"未跟踪文件"**：我把 57MB 的 adapter 权重提交过一次，之后**再加规则也拦不住**，而且 `git status` 里它**根本不显示**——"看起来很干净"是假象。修法是四步：确认提交没 push → 加规则 → `git rm -r --cached`（保住磁盘文件）→ 改写那笔提交；**验收判据**是 `git rev-list --objects main \| Select-String "adapter_model"` **返回空**。 | `day19工作汇报.md` 踩坑 #8 |
| 25 | 还有别的坑吗？ | **`git push` 三层坑串联**：① 代理开着 ≠ git 在用（要显式 `-c http.proxy=...`）；② Git LFS 的"锁校验"API 经代理断（本项目根本没有 LFS 文件，只关 `locksverify` 即可）；③ Git for Windows 默认 TLS 后端经代理握手失败（换 `http.sslBackend=openssl` + `HTTP/1.1`）。**关键认知：它们是串联的，修好一层又报新错是正常的**。 | `day19` 教程 §7.3.1 |
| 26 | 文档/流程上的坑呢？ | **`--date` 占位符被抄了 4 次**：教程里写 `--date 9/23` 当占位，结果每轮都带着"计划日"进日志，导致日期列与实际执行日不符。修法是把占位符改成 `--date 填你的执行日` + 红字警告。**教训：模板里的示例值一定会有人照抄，所以要让它抄不出错。** | `实验日志.md`「日期口径」注 |
