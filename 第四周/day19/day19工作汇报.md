1. **失败模式是"改写太自信"，不是"改写没生效"**：面对库里没有的事实（机构 / 期刊 / GPU 数 / 参数量 / 被引次数），模型**编一个具体答案**而**不保留原词**；
2. **最危险的一类已实锤：`真实存在但语义错位`** —— Q15 写 `4,096 parameters`，库里确有 `4096`（**2** 次），但原意是"**仿真跑了 4096 次**"；同类还有 `Generalized Mean Regression`（**统计学里真实存在的另一个术语**）、Q16 把 `GMR` 写成 `GMRES`（**数值线性代数算法名**）→ **"像真词"的伪实体比乱码更坏：它们会稳定地把排名带偏**；
3. **多一个连字符就丢 BM25 信号**：`LAFAN1` → `LAFAN-1`，而 `TOKEN_RE=[a-zA-Z0-9]+` 会切成 `lafan`+`1`，库内 token 是 `lafan1` → **稀疏通道直接打不中**（可验证机制，不是猜测）；
4. **指令泄漏**：`可能出现的表述：` 出现在 **7 题**的 `hyde` 档（提示词第 3 条被当成"要抄的模板文字"），8 个汉字中文小句混进英文查询会稀释向量。

### 3.5 当天逐个查清的关键问题（都留了实证）

- **"抽查 3 条改写全不合格，为什么 R4 的检索 strict 还能打平、甚至涨到 6/10？"** → 因为**四看查的是"改写产物本身"，成绩行算的是"检索/生成的最终结果"**，两者不是一回事：改写**编造的实体**确实把一些题带偏（`term` 档伤专名 → `v∪b` 7→6），但它**同时唤醒了 BM25**（中文→英文词），把另一批题（Q2/Q3/Q5/Q9）救回来 → **"+4/−4 的上下换手"**。**这就是"上界 100% 落到真实现只有 50%"的构成**：不是改写没用，是**它一半在帮忙、一半在帮倒忙**。
- **"`term` 档明明是把中文换成英文，为什么反而伤检索？"** → 因为它**替换掉了专名**：库里的真专名是 `PHC` / `ProtoMotions` / `Unitree`，改写给了 `approaches` / `techniques`（**泛化词**）→ 原来靠专名命中的题（Q1/Q4/Q7）失守。**另一头**：Q10 的原句 `embodiment gap` **本来已经对齐**（plain 向量 Top-8 含 chunk 5），改写**多塞了几个泛化词，把 chunk 5 挤出前 8**。→ **改写不是免费午餐：它会稀释原本已经对齐好的原句。**
- **"`hyde` 档检索 loose 涨到 8/10，是最好的一档吗？"** → **检索最好，生成最差**。它把 out 从 7 打到 **4**（F1 0.571，四轮最低）。机制：拿"**假设答案片段**"当查询，**检索到的段落更像答案本身**——对 in 题是好事（多对 2 题），对 out 题是灾难（**HyDE 提升"对齐"，它不区分"资料里到底有没有答案"**）。→ **这条要作为一个"结构性权衡"讲，而不是"hyde 更好/更差"。**
- **"day18 说 RRF 融合有害，今天怎么又翻正了？"** → **错的不是融合，是"在什么查询下融合"**。plain 时 BM25 对中文**近乎零信号**（4 题 `top=[]`），而 RRF **仍给它等权** → 等于给有效排序掺一半噪声；改写后 **BM25 的空列表从 4 题降到 0 题**，两路都有信号，融合就正常工作了。**更干净的一条证据**：**上界（三通道并集）恒为 7/10 没变**，变的是**兑现率 3/7 → 6/7** → **融合的价值是"把并集里已有的题捞进 Top-8"，不是"做大并集"**。
- **"模板 v2 三档全部回退，到底是哪一句该死？"** → **②"只有当资料确实找不到相关信息时才拒答；资料里有依据就照实回答"**。判据很硬：**带 ② 的两档（v2 / v2a）out 只有 3~4/10，不带 ② 的 v2b 有 6/10**（差 2~4 题，**超出波动范围**）。机制：**out 题的 Top-K 永远返回 8 条**（检索总会给你东西），② 等于告诉模型"**有东西就是有依据**" → 它把**检索到的相邻话题段落**当依据答了。→ **"乐于助人"的提示语在 out 题上是负资产。**
- **"那既然 v2b（去掉②）比 v2 好，为什么不改成 v2b？"** → **因为 v2b 的 F1 0.706 仍低于 v1 的 0.824、总分 50% < 55%**。→ 正确结论是"**这一版提示词对生成层没有净收益**"，而不是"留 ③④ 去掉 ②"。**这个区分很重要**：前者是"这条路走不通（在当前提示词形态下）"，后者是"再调调就好了"——**前者才是数据支持的。**
- **"Q11/Q14/Q18 到底是'编造'还是别的？"** → **回 `chunks.json` 逐句核对后，三条里没有一条是凭空编造**：**Q11** 把资料里的**伪影 / 指标定义 / 用户研究结论**逐条搬来、统一贴上「缺点」标签（唯一凭空的是"缺点"这个框）；**Q14** 是 **chunk 76 原文照抄**，错在**答非所问** + 引用格式崩坏；**Q18** 是**把参考文献页码当成"被引次数"**、**把参考文献编号 `[41][42][43]` 当成段落号**。→ **内容确实"看过了"、只是用错了，所以模型不认为自己在编** → **"禁止编造数字/引用"这类提示词天然治不了它们**（这正是 v2b 只治住 Q18、治不住 Q11 的原因）。
- **"引文白名单 `strip` 达标了（非法 5→0），为什么 F1 一分没涨？"** → **因为它治的不是这个病**。Q18 那句 `[1][36][37][41][42][43][84] = 7。` 剪完仍剩 `[84] = 7。` —— **它本来就不是拒答句**，剪引用改变不了"该拒没拒"这个事实。→ **out 题真正缺的判据是"是否答非所问"，不是"引文是否合法"**。**并且**：`非法 0 处` **不等于**答案干净（R6 仍有 **23 处伪引文**，如 `[资料©]` —— 模型在用"引文的样子"伪装内容，而正则只认数字）。
- **"`retry`（点名非法编号后重答）为什么反而更差？"** → **与 R5 规则②同型**：**给 3B 任何"允许拒答"的措辞，它就把出口当答案**。重答指令里那句"资料不足就只输出拒答句"被滥用成三条后果：**Q3 本来 ✅ 的题被改成拒答**（FP +1）、**Q1 交出半截答案**（`SMPL: A skinnied multi-person linear modell [资料中没有提及]`，FP +1）、**Q5 交出空字符串**（3 次重答全被剪空）。→ **F1 0.824 → 0.737，FP 0→2。不采用。**
- **"F3 换了真实数据，防幻觉为什么反而从 7/10 崩到 2/10？是不是说明真实数据没用？"** → **不能这么说。** 本轮是「**真实 201 条**」vs「**合成 300 条**」——**"来源"与"数量"两个变量同时变了**。退化完全可能来自**样本少了 99 条**。**要拆开必须再跑一轮配比版**（真实 201 + 合成补至 300）。→ **HR 要的是"数据真实"，不是"数据一定涨分"**：真实数据作为**交付物**保留（201 条可追溯），"真实 vs 合成"作为**一次如实记录的负结果** —— **硬编一个"提升"才是自毁证据链**。
- **"为什么要把负结果一条条写进报告？"** → 因为**《优化成果报告》的价值不在"数字好看"，而在"每一步的贡献可归因"**。面试官问"你做了什么优化"，能答"**我试了三类，两类没有净增益，机制分别是 X 和 Y，所以最终只保留了 Z**"——这比"我涨了 15 个点"**更难被追问倒**，因为**它证明的是判断力，不是运气**。
- **"加了 `.gitignore` 为什么 `git check-ignore` 还是没输出？"** → **因为 `.gitignore` 只管"未跟踪文件"**。权重**已经进过一次提交**，成了**已跟踪文件**，再加规则也拦不住；而且 **`git status` 里它根本不显示**（不显示为未跟踪，也不显示为修改）—— **"看起来很干净"是假象**。→ 修法：`git rm -r --cached`（**保住磁盘上的权重**）+ **改写那个提交**（本例 17 个提交全没 push，**改写是安全的**）。**判据**：`git rev-list --objects main | Select-String "adapter_model"` 返回**空**才算真的干净。
- **"三花智控同一家公司两份文件口径相反（年报乐观 / 监管问询说没有量产订单），该采哪条？"** → **两条都采**。一份真实数据集应该**同时保留"公司叙事"和"监管口径"** —— 只留好听的那条就是**自我美化**，也会让 SFT 数据带上系统性偏差。**这条和"砍掉乱码来源换干净来源"是同一套价值观：宁可不完整，不可不真实。**

| 1 | **`requests.exceptions.HTTPError: 500 Server Error`**（`rewrite_queries.py`，**只有一句 500、看不到原因**）⭐ | 服务端 `HTTPException(500, f"生成失败：{e}")` 把真实异常藏在**响应体 `detail`** 里，而 `raise_for_status()` 不打印它。→ **两处修**：① 客户端改成 `if r.status_code != 200: raise RuntimeError(r.text[:500])` 直接看到 `detail`；② 根因是 **`temperature=0.0`** —— 服务端 `do_sample=True`，`transformers` 的 `TemperatureLogitsWarper` **拒收 0**（`must be a strictly positive float`）→ 改 **`0.01`**（**要确定性就取极小正值，不能用 0**）。**判据：报错只有一句 500，去服务端那个终端看 traceback / 或让客户端打印 `detail`** |
