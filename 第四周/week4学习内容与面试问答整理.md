### 1.2 全周知识链条（一段话串讲，用概率语言）

**评测 = "先造一把准的尺子，再谈优化"**：把评测从"一次性脚本"升级成**受控实验系统**——固定 20 题（资料内 10 + 资料外 10）、**每参数化一个变量**（Top-K / 前缀 / 模板 / 数据 / adapter）、**每题多跑取多数降方差**、**判据双轨透明**、**结果分数落盘**。用概率语言说：**优化 = 在固定评测集上做受控实验**；**提升 Δ = 优化后的估计 − 优化前的估计**，所以尺子有偏差（判据过严 → 假阳性）或方差大（单次抖动），这个差就没意义。这正是"**先修偏差、再压方差、然后才敢说提升了多少**"的顺序纪律。

**检索优化（O1 线）= 从"调参数"走到"钉瓶颈"**：第一轮受控实验（`B0r3 → R1 → R1R2`）发现 **TOP_K 4→8 是唯一稳定有效的变量**（检索 20%→40%），而**官方推荐的 bge instruction 前缀是负贡献**（20%→0%）——机制不是"语义变差"，而是**排名位移**（chunk 3 第 4 名→第 5 名，撞上 k=4 的窗口边界），且**前缀与 k 有交互效应**（不能把两个变量的效果简单相加）。于是转去查"卷子"（数据自检 9/10 自洽 → 排除标注错）与"问法"（**同库同判据、只把中文问句换成英文术语：strict 40% → 100%**）⇒ **瓶颈在查询侧的语言错位（中文问句 ↔ 英文段落）**。把上界落成真实现（模型自动改写三档）后**无一超过基线**——因为 **HyDE 的"假设答案片段"不区分"资料里到底有没有答案"**：它让 in 题更容易命中，却让 out 题"有话说"，**帮 in、害 out**。

**生成层（O2 线）= "提示词改不动的那部分"**：模板 09 v1 带三件事（出处格式 `[资料§N]` / 拒答出口句 / 防幻觉约束）；用**逐句消融**（v2/v2a/v2b）把退化**归因锁死在一句提示语**（"资料里有依据就照实回答"）——因为 **out 题的 Top-K 永远返回 8 条**，这句话等于告诉模型"有东西就是有依据"。把三条典型幻觉逐句回 `chunks.json` 核对后，进一步确认**它们都不是凭空编造**（语义误读 / 答非所问 / 编号张冠李戴）⇒ **"禁止编造"这类提示词天然治不了"误读型幻觉"**。唯一拿到净收益的生成侧改动是**引文强制白名单（strip）**：非法引用 5→0 处、**判定与拒答零翻转、F1 逐格不变**（零副作用）；而"点名重答（retry）"反而把正确答案改成拒答（F1 0.737）。

**真实数据（F 线）= 拆变量才叫归因**：用 90 条论文真实 QA（`source.page + chunk_id + quote`，**逐字回查 90/90**）+ 111 条行业真实 QA（带 URL / 日期 / 原文摘录，26 个机构、最大占比 10.8%）替换 300 条合成数据 → F1 掉到 0.333，但**"来源"与"数量"两个变量同时变了**（**混杂因素 = 样本数量**）。补 **F3v3**（真实 201 + 合成 99 = 300，数量对齐）后 F1 **仍只有 0.429** ⇒ **数量解释不了差距 ⇒ 主因是"数据分布与评测集不匹配"**（v2 里 55% 是行业语料，而评测题出自论文）。**相关 ≠ 因果**，所以必须拆开。

**双模型对比（F4）= 把"坏消息"跑成主结论**：同一把尺子、同库同参、**只差 adapter**（检索两列**逐位相同** 4/10、5/10）→ **原模型 F1 0.947 / 总 80% 全面高于微调 0.824 / 55%** ⇒ **这版微调在"资料外拒答"上是负收益**（假说：3B 容量有限，微调把"该拒就拒"挤掉一部分）。**边界三句必须同时写**：① 只能说"这版微调在防幻觉上负收益"，不能说"微调无用"；② 微调收益在风格/术语/格式遵循；③ n=20、CI≈±0.22，但 **−0.123 的 F1 差 + 全项同向**足以支撑量级判断。**顺带得到的正面结论**：原模型在检索层完全一样的前提下靠"读好上下文 + 该拒就拒"拿到 80% ⇒ **知识确实来自检索层**——这就是"**为什么选 RAG 而不是直接微调**"的实测回答。

**交付（D 线）= 把"能跑"变成"能用且可验证"**：本地开箱即用（Gradio + 一键启动 + 不加载模型防显存爆）→ 在线 Demo（魔搭创空间，检索层 CPU 真跑、生成层 DeepSeek API 且**三处一致标注**）→ 公开仓库（权重/adapter/向量库一律不入库）→ 静态博客交接包。**四个"不报错也查不出来"的隐形坑**：重复建库（不传 `collection_name` 导致 105→210 条）、**近似检索参数 `hnsw:search_ef` 默认只有 10（比库容量还小）导致线上出处与离线对不上**、`gr.Progress` 为假值时 `IndexError`、内存向量库被线程生命周期销毁（`no such table: collections`）。用一句话收口：**"服务能起" ≠ "服务能用"**。

**叙事（P 线）= 让每个数字指向一个文件**：8 条个性化点（数学视角 / 分层归因 / 人工复核诚实改判 / 手写与框架对拍 / 6G 显存全链路 / 工程防御细节 / 数据可追溯 / 负结果透明）；10 分钟端到端复述脚本；简历"过程句 → 结果句"改写。

### 1.4 本周"新增名词"小抄（面试初次出现即解释）

| 名词 | 一句话 |
|---|---|
| **受控实验（Controlled Experiment）** | 固定评测集、**只改一个变量**、其余全同——"优化"就是"看指标怎么动" |
| **一致率（Consistency）** | 同题 `runs=3` 多数判定的占比；**≥0.93 才算"数字稳、可对外引用"** |
| **strict / loose 双轨判据** | strict = 是否召回标注的 `source_chunk`（偏严）；loose = 期望关键词是否落在 Top-K（治反例） |
| **Bias-Variance** | 判据过严 = 系统性**偏差**；单次抖动 = **方差**；先修偏差、再压方差、才谈提升 |
| **HyDE（Hypothetical Document Embeddings）** | 先"假设一个答案片段"再拿它去检索，让查询更像文档 |
| **RRF（Reciprocal Rank Fusion）** | 按 `1/(k+rank)` 把多路检索的名次融合；**只看名次、不看某路可不可信** |
| **兑现率（Capture Rate）** | 三通道**并集**里的题，真正进 Top-K 的比例（上界 vs 成绩的分母） |
| **误读型幻觉** | 内容**确实取自检索**但被用错（语义误读/答非所问/编号张冠李戴）——提示词治不了 |
| **轮内双口径（raw vs delivered）** | 引入"会改答案的后处理"后，跨轮比较在生成层失效 → 只能靠轮内对照判断副作用 |
| **全幺模（Totally Unimodular）** | 约束矩阵全幺模 ⇒ LP 松弛最优解自动是整数解（打家劫舍有多项式解法的理论解释） |
| **ANN / `hnsw:search_ef`** | 近似最近邻检索；`search_ef` 是候选列表大小，默认 **10**——小于库容量就会让边界结果抖动 |
| **混杂因素（Confounder）** | 第三变量（此处=样本数量），它让"相关"看起来像"因果" |
| **配对实验（Paired）** | 同样的题、只改一个变量，逐题对比（比两组独立平均更省样本、更能抓差异） |

### 模块 A：HR 必答三问 + 动机（Day16~20 · 本周最优先）

**Q1. 这个项目做完了吗？做成了什么能用的东西？**
> 做完了，形态是**能用的工具 + 能看的链接**：① **本地开箱即用**（Gradio UI + 一键启动脚本 + 内置示例库：上传 PDF → 提问 → 带出处答案 → 切换原模型/微调模型）；② **在线可交互 Demo**（魔搭创空间 `modelscope.cn/studios/LanMercer/rag233`，直达 `lanmercer-rag233.ms.show`，**不上传文件也能直接提问**）；③ **代码仓库**（`github.com/LanMercer/rag233`，Public）；④ 静态展示页文章已定稿，交另一个 agent 建页发布。**不依赖我的电脑开着。**
> ⚠ **诚实标注**：在线 Demo 的**检索层是本项目真实实现，生成层用的是 DeepSeek API，不是本地微调模型**——这一点在页面/README/文章三处都标了；**评测数字只归属本地 Qwen2.5-3B-Instruct-LoRA 版本**。

**Q2. 你优化了什么？提升了多少？**
> 同一套 20 题固定评测集上：**检索命中率 20% → 40%**、**防幻觉 F1 0.667 → 0.824**、**总正确率 40% → 55%**。关键一步是 **TOP_K 4→8**（机制：期望段从第 5 名回到窗口内）。**并且我知道每一步各贡献多少**——逐步骤贡献表 12 行、失败尝试 8 条。
> [数学加分] 我报的是"**两个统计估计之差**"，且口径写死（20 题 / `runs=3` / `k=8` / 模板 v1 / `patch=on` / `qi=off`）；n=20 的 95% CI 约 ±0.22，所以我只讲"提升 20 个百分点"，不抠小数点。

**Q3. 你的 SFT 数据哪来的？为什么值得信？**
> **论文 90 条**（从 GMR 论文正文与图表说明人工提取，带 `source.page + chunk_id + quote`，**逐字回查 90/90**）+ **公开行业资料 111 条**（公司年报/公告/官网、国家标准、权威媒体，每条带 URL 与原文摘录，26 个机构、最大占比 10.8%、泄漏 0）。合成数据**如实标注为合成**，不混为一谈。
> ⚠ **边界**：**行业资料不在知识库里 → 无法逐字回查，这条我在报告里写明了**，没有假装能回查。
> 最值钱的一条：三花智控**年报（乐观叙事）与 GDR 监管问询（"尚未形成量产订单"）口径相反——两条都收**。一份真实数据集应该同时保留"公司叙事"和"监管口径"。

**Q4. 为什么做机器人领域？**
> 领域有**公开、可核对**的语料（论文、年报、国标），适合做"真实数据"；且机器人文档**专名密集**（GMR / embodiment gap / LAFAN1 / PHC / ProtoMotions），**天然能暴露检索失败**——这正好让"优化"有靶子。

**Q5. 这个项目你最满意的一点？**
> **"可信"**：数字只从 `run_log.txt` 抄、F1 必带混淆矩阵、对外引用的行必须 `runs=3` 且一致率 ≥0.93、每个"提升"都能说出由哪一步贡献。**我还主动降低了两次数字**（人工改判 `MANUAL_FIXES`）。

### 模块 B：架构与选型（Day18~20）

**Q6. 四层架构怎么拆的？为什么这么拆？**
> **数据层**（PDF → chunk → bge → Chroma）/ **检索层**（Top-K，k=8）/ **生成层**（模板 09 + 3B 模型）/ **交付层**（引文白名单）。拆层的意义是**归因**：出问题时能立刻回答"是哪一层坏的"（三组指标分别对应这三层）。
> [数学加分] `P(答案|问题) ≈ P_生成(答案 | 模板09(检索(问题)))`——**端到端条件概率分解成逐层条件概率**，每层独立调优、出错能定位到层。

**Q7. 切块策略？为什么？**
> 中文按语义/长度切块，保留段落边界，**块内保留 `[资料§N]` 编号**供引用与判据（`source_chunk`）对齐。→ 第三周已实测 GMR 论文 9 页 → **105 chunk**。

**Q8. 为什么自己的手写检索要和 LangChain 对拍？**
> **证明懂原理**：手写归一化 + 余弦 + `argsort`，与框架版逐题一致 → 说明我不是"只会调包"，换实现/换版本我的理解都在。

**Q9. 为什么检索用 `k=8` 而不是更大？**
> 实测 **4→8 是唯一稳定有效的优化**；继续加大没测出收益，且**上下文变长有副作用**（day16 记录 Q1 答得更差：热词段稀释；R3 未复现，属低概率抖动，不当作稳定效应）。
> [数学加分] 这题是个**偏差-方差**问题：k 太小 → 期望段掉出窗口（**偏差**，系统性漏召回）；k 太大 → 无关段落稀释注意力 + 成本上升（**方差/噪声**放大）。k=8 是当前语料下的经验最优。

**Q10. 为什么 6G 显存够用？**
> 3B 4bit（NF4）加载 **1.92GB**、训练前 1.98GB、**训练峰值 2.11GB**（<6GB）；LoRA 只训 **0.4827%** 参数（14,966,784 / 3.10B），只存 adapter（`adapter_model.safetensors` 57MB）。

### 模块 C：评测体系与"尺子"（Day16 · 本周方法论核心）

**Q11. 为什么"先修尺子再谈提升"？**
> 因为**提升 Δ = 优化后的估计 − 优化前的估计**；尺子有**偏差**（判据过严 → 假阳性）或**方差**（单次抖动），这个差就没有意义。所以顺序是：**先修偏差（判据补丁）→ 再压方差（`runs=3` + 一致率）→ 然后才敢说"优化提升了多少"**。
> 而且我做了**新旧尺子交叉验证**：新尺子跑旧口径，检索 2/10、防幻觉 6/10 与第三周分毫不差 → 说明后续的 R2 提升不是"换尺子换出来的"。

**Q12. 怎么保证"同一个配置"的可比性？**
> 同脚本、同库、同 20 题、同判据口径、**只改一个变量**；并用**单变量自检**做免费体检：**改检索的轮次，生成层指标不应系统性变；改生成/数据的轮次，检索两列必须逐位相同**。实测 R4/R5/F3v2/F3v3/F4o 五轮的检索两列都与 R3 **一字不差（4/10、5/10）**，说明实验没脏。

**Q13. `--runs 3` 投票解决了什么？**
> 单次生成的随机性（`T=0.2` 下同配置 B0 跑出生成 1/10 vs 2/10、F1 0.750 vs 0.667）。输出**一致率**回答"这轮数字稳不稳"。
> [数学加分] 这是**蒙特卡洛重复 → 取众数**的降方差手段，本质和 Dropout（对子网络做集成）同源：**用多次独立的噪声实现换一个更稳的估计**。

**Q14. 双轨检索判据为什么要两列？**
> strict 偏严（必须召回标注的 `source_chunk`，与首版口径可比）；loose 治反例（Q4 那种"没召回该段却答对了"）。**两列并列报 = 口径透明**，让读者自己判断。

**Q15. 20 题的结论可信吗？**
> **n=20 的 95% CI 约 ±0.22** → 我对外只说**量级与归因**，不抠小数点；并且用 `runs=3` 投票 + **一致率 ≥0.93** 作为"数字稳"的门槛（低于门槛的轮次只作对照、不当成绩）。**扩大样本（n≥60）是下周第一件事。**

**Q16. 你的 F1 是"召回率"还是"精确率"？**
> 都不是——是**防幻觉**的二分类 F1（把"该拒答就拒答"当作正类）：**TP** = 资料外题如实拒答、**FP** = 资料内题被拒答（该答却拒答＝过度保守）、**FN** = 资料外题编造、**TN** = 资料内题答对。我**每次都写上 TP/FP/FN/TN**，因为**同一个 F1 可能来自完全不同的结构**。
> [数学加分] **F1 是调和平均**：`F1 = 2PR/(P+R)`。P=1、R=0 时算术平均是 0.5（显得还行），调和平均是 **0**（直接露馅）——这就是选调和平均的原因：它惩罚极端不平衡。

**Q17. 那个 `FP=1` 是不是说明模型变差了？**
> **有一次不是**：`R4c`/`R5b` 的 FP 是**判据假阳性**——答案中间出现拒答词（如"① …[2]；② …[52]；资料中没有提及③ …"），而规则只看"答案里有没有拒答词"。这条我在报告里明说，**没有把 F1 整块算成"答错"**。
> [数学加分] 这是**测量误差**问题：判据本身有误分类率，所以读指标前要先评估"尺子准不准"（和 Q11 同一个思路）。

**Q18. "引文非法 5→0 处"是不是说明答案干净了？**
> **不是**。`strip` 抓的是**数字编号**；交付答案里仍有 **23 处非数字伪引文**（`[资料©]`、`[resourceright]`、`[资料第Ⅱ节]`）——模型在用"引文的样子"伪装内容。这个边界我写在报告里。

### 模块 D：检索层优化（Day17~19 · 负结果最多、机制最硬）

**Q19. bge instruction 前缀为什么反而更差？**
> 我按 bge 官方文档给查询侧加了 instruction 前缀，**结果检索命中率从 20% 掉到 0%**。逐题追查发现：**前缀并没有让向量"变差"，而是把几段关键资料从第 4 名推到第 5 名**——k=4 时刚好掉出窗口所以全灭；把 k 提到 8 之后它们又在窗口内了。这说明**前缀的效应与 k 有交互**，也说明"官方推荐做法"在具体语料上不一定有效，**必须用自己的固定评测集验证**。
> 补充两个细节：① 我**先证明"变量真接上了"再下结论**（向量层 `cos(base, qi)=0.9108`、`same=False`；检索层 dry-run 的 Top-K 顺序真的变了）；② 简单相加两个变量的效果会预测错（2/10 ≠ 实际 3/10），所以**单看主效应会骗人，必须先固定另一个变量再比**。

**Q20. TOP_K 4→8 为什么有效？**
> 期望段从"第 5 名"回到窗口内——**这是本病唯一稳定有效的优化**（检索 20%→40%、总 40%→55%）。
> [数学加分] 这是**排序 + 截断**的经典权衡：检索的"排名质量"没变，只是**截断阈值**变松，把原本"排在第 5 名"的相关段落纳入上下文。

**Q21. HyDE 的 10/10 能当成绩吗？**
> **不能**——那是**人工手写的理想英文查询**（上界/开卷），只能证明"**瓶颈在查询侧的语言错位**"；模型自动改写的**真实现落在 50%（hyde 档）**。
> [数学加分] 上界回答"**瓶颈在哪**"，不回答"**能提升多少**"——这两件事必须分开说，否则就是把"可达最优"当成"实际成绩"。

**Q22. 改写为什么没有净增益？**
> 三档（term/hyde/both）总正确率 **45%/50%/55%，无一档超过基线 55%**。**"检索涨、生成崩"是结构性的**：`hyde` 档检索 loose 涨到 8/10，代价是 out 从 7 掉到 4——**拿"假设答案片段"当查询，检索到的段落更像答案本身，资料外题就"有话说"了**。
> 我还做了**改写产物质检"四看"**（回 `chunks.json` 计数）：① 改写器**编造实体**（`Generalized Mean Regression`，库内真词是 `General Motion Retargeting`，计数 **0**）；② **真实存在但语义错位**（`4,096 parameters` —— 库里 4096 是**仿真次数**，最危险）；③ **多一个连字符丢 BM25 信号**（`LAFAN1` → `LAFAN-1`，被切成 `lafan`+`1`）；④ **指令泄漏**（`可能出现的表述：` 混进英文查询，7 题）。

**Q23. 混合检索（RRF）为什么一开始有害、后来翻正？**
> **plain（中文查询）**：`vector` 4/10、`bm25` 4/10、`hybrid` **3/10**，但**两通道并集 7/10**——高度互补（`vector` 丢的全是专名题、`bm25` 丢的全是中文题）。融合反而掉一题，三个机制：① BM25 对中文**近零信号**却被**等权融合**（等于给有效排序掺一半噪声）；② `1/(60+rank)` **把名次差压平**（第 1 名 0.0164 vs 第 8 名 0.0147，只差 11%）；③ RRF **只看名次、不看这一路可不可信**。
> **改写之后（term 档）**：`hybrid` **3/10 → 6/10**（首次超过最好的单通道），**但三通道并集恒为 7/10** ⇒ **改写做的是"命中集合重排"、不是净增益**；价值在**兑现率 3/7 → 6/7**。
> 一句话机制：**错的不是融合，是"在什么查询下融合"**——中文查询下 BM25 是瞎的，融合等于掺噪声；改写后两路都有信号，融合才正常。

### 模块 E：生成层与防幻觉（Day19）

**Q24. 模板 09 是怎么写的？为什么这么写？**
> 模板里带三件事：**出处格式 `[资料§N]`**、**拒答出口句**（"资料中没有提到"）、**防幻觉约束**（不许编编号/数字）。**v1 是实测最稳的一版**——我做过**逐句消融**（v2/v2a/v2b），三档全线回退。

**Q25. 模板 v2 三档为什么全退？怎么归因的？**
> 逐句消融结果是 F1 **0.824 → 0.462 / 0.571 / 0.706**（防幻觉 7/10 → 3/4/6）。**归因锁死在一句提示语②**"只有当资料确实找不到相关信息时才拒答；**资料里有依据就照实回答**"——**带 ② 的两档 out 只有 3~4/10，不带 ② 的有 6~7/10**（差 2~4 题，超出波动）。
> **机制**：**out 题的 Top-K 永远返回 8 条**（检索总会给你东西），② 等于告诉模型"**有东西就是有依据**"。
> ⚠ **不能简化成"留 ③④ 去掉 ②"**：v2b 的 F1 0.706 **仍低于 v1 的 0.824** → 正确说法是"**这一版提示词对生成层没有净收益**"。

**Q26. "误读型幻觉"为什么提示词治不了？**
> 我把三条典型 out 题逐句回 `chunks.json` 核对"是编的还是抄的"，发现**没有一条是凭空编造**：**Q11** 把资料里的伪影/指标定义/用户研究结论逐条搬来、**统一贴上「缺点」标签**（唯一凭空的是"缺点"这个框）；**Q14** 是 **chunk 76 原文照抄**，错在**答非所问**；**Q18** 把**参考文献页码**当"被引次数"（`pp. 425–432` → `425`）、把**参考文献编号 `[41][42][43]`** 当段落号。
> **结论**：模型"看过了"、不认为自己在编 → **"禁止编造数字/引用"这类提示词天然治不了它们**（也解释了 v2b 只治住 Q18、治不住 Q11）。

**Q27. 引文强制白名单为什么是"零副作用"？`retry` 为什么反而更差？**
> **strip（就地剪除非法编号）**：交付口径非法引用 **5→0 处**、剪除 13 处、**F1 逐格不变（0.824）**、判定与拒答**零翻转** → 达标且零副作用。**retry（点名非法编号重答一次）**：F1 0.824 → **0.737**（**FP 0→2**）→ 负结果，不采用。
> **`retry` 更差的原因与模板 ② 同型**：**给 3B 任何"允许拒答"的措辞，它就把出口当答案**（Q3 本来 ✅ 被改成拒答、Q1 交出半截答案、Q5 交出**空字符串**）。
> **`strip` 为什么"救不回 F1"**：Q18 那句 `[1][36]…[84] = 7。` 剪完仍剩 `[84] = 7。`——**它本来就不是拒答句**，剪引用改变不了"该拒没拒"这个事实。⇒ **`strip` 是"交付前保险"，不是"效果优化"**。

**Q28. 你怎么保证"不幻觉"？（三层框架）**
> **分三层说**：① **检索层**——保证资料进上下文（k=8 + 出处编号）；② **生成层**——模板约束 + 拒答出口；③ **交付层**——**引文白名单**（非法编号剪除，零副作用）。并**如实说**三层都治不了"**误读型幻觉**"（内容确实取自检索但被用错）——那要靠**数据 / 更大模型 / 后处理**。

**Q29. 为什么要有"轮内双口径"（`answer_raw` / `refused_raw`）？**
> 因为一旦引入**会改答案的后处理**（引文白名单），**跨轮比较在生成层就失效了** → 判断兜底有没有副作用，**只能靠轮内 raw vs delivered 对照**。实测 `strip`：13 处剪除、**判定与拒答零翻转**。
> [数学加分] 这是个**测量学**问题：**测量工具改变了被测对象**（后处理改了答案），所以原来的纵向可比性声明作废，必须换一个**同轮内**的对照口径。

### 模块 F：真实数据与微调（Day18~20）

**Q30. 换真实数据后效果变差，是不是说明真实数据没用？**
> **不能说这个。** 那一轮（F3v2）是「**真实 201 条**」vs「**合成 300 条**」——**"来源"和"数量"两个变量同时变了**，退化完全可能来自样本少了 99 条。所以我补了 **v3 配比版**（真实 201 + 合成 99 = 300）把"数量"对齐：**实测 F1 只有 0.429**（防幻觉 3/10，只比 v2 的 0.333 回了 1 题），**仍远低于基线 0.824** ⇒ 数量对齐**解释不了**这个差距 ⇒ **主因是"这批真实数据与评测集的分布不匹配"**（v2 数据里 111 条 / 55% 是行业语料，而评测题出自论文）。
> **边界**：这只能说明"这批真实数据的分布不适合这套评测题"，**不能**说"真实数据无用"；而且 F3v3 比 F3v2 略好（0.429 > 0.333），说明**掺合成有微弱正作用**。
> [数学加分] 这是**相关 ≠ 因果**的教科书案例：**混杂因素（confounder）就是样本数量**，所以必须**补样对齐**把它拆开——"先控制变量，再谈归因"。

**Q31. 采集和校验是怎么做的？**
> **六查校验器**：条数门槛 / 必填字段 / 空值重复 / **source 可追溯（`quote` 逐字回原文）** / **数据泄漏**（与 `eval_questions.json` 比对，阈值 0.7）/ 类目与机构分布。
> **"补短板"是方法论重点**：第 1 批 80 条（市场类 40% 超标、公司经营仅 8.8%）→ 第 2 批 **+31 条只补短板** → 最大类目 40% → **28.8%**；**"市场与产业链"仍超标（28.8% vs 建议 ~15%）如实写出**——**"没有为了分布好看去删已有数据"**（删掉才是造假）。
> **采集纪律**：只采公开、可引用来源；**不引聚合站**（必须回溯到公司公告 / 官方站点 / 国家标准 / 权威媒体）；不转载大段原文。

**Q32. QLoRA 你训了什么？训练侧怎么确认"训练本身没问题"？**
> 4bit **NF4** 量化的基座 + LoRA（`r=8, alpha=16`），3 epoch、`lr=2e-4`、batch 2 × 梯度累积 8；**只存 adapter**（57MB），**只训 0.48% 参数**。
> 看四个数确认训练正常：`train_loss=2.199` / `eval_loss=2.388`（正常收敛没崩）、`train_runtime=671.4s`（36 步）、**显存 allocated 峰值 2.11GB**（<6GB）、**可训练参数 14,966,784（0.4827%）**。

### 模块 G：双模型对比 & "为什么选 RAG"（Day20 · 本周最硬结论）

**Q33. 微调到底带来了多少提升？**
> **实测结果是负的，照写**：同一把尺子、同库同参、**检索两列逐位相同（4/10、5/10）**，**原模型 F1 0.947（9/0/1/10）、总正确率 80%**，**微调 0.824（7/0/3/10）、55%** ⇒ **这版微调在防幻觉上是负收益**。不是"个别题原模型更好"，而是**原模型在两个生成类指标上全面占优**。
> **机制假说**（本轮未单独验证）：3B 容量有限，微调把"照本宣科 / 该拒就拒"的能力挤掉一部分，模型变得更"愿意顺着上下文说"。
> **边界三句必须同时写**：① 只能说"**这版微调在防幻觉上是负收益**"，**不能**推广成"微调无用"；② 微调收益在**风格 / 术语 / 格式遵循**（可展示，但不是本评测集的判据）；③ n=20、CI≈±0.22，但 **−0.123 的 F1 差 + 全项同向**足以支撑"负收益"这个**量级**判断。

**Q34. 为什么用 RAG 而不是直接微调？（用实测回答）**
> 因为**知识会变、要出处**：文档问答必须能给出 `[资料§N]`；微调改的是"说话方式/领域语感"，**改不了"事实从哪来"**。本项目两条都做了（RAG 主线 + QLoRA 副线），并在 F3/F4 里实测了"换训练数据到底影响哪一层"——**结果反而证明了这个判断**：**原模型（F1 0.947）比微调（0.824）更好，说明知识确实来自检索层，不是来自微调**。
> [数学加分] 用条件概率看：RAG 是**改变条件**（把"资料"放进条件里 → `P(答案 | 问题, 资料)`），微调是**改变分布的形状**（`P_θ(答案 | 问题)` 的 θ 变了但不带新事实）。**前者能引新知识，后者只能改表达。**

### 模块 H：交付与上线工程（Day18~20 · 最"像真做过"的一类）

**Q35. 说一下你印象最深的一个坑。**
> **`.gitignore` 只管"未跟踪文件"**：我把 57MB 的 adapter 权重提交过一次，之后**再加规则也拦不住**，而且 `git status` 里它**根本不显示**——"看起来很干净"是假象。修法是四步：确认提交没 push → 加规则 → `git rm -r --cached`（保住磁盘文件）→ 改写那笔提交；**验收判据**是 `git rev-list --objects main | Select-String "adapter_model"` **返回空**。

**Q36. 还有别的坑吗？**
> **`git push` 三层坑串联**：① 代理开着 ≠ git 在用（要显式 `-c http.proxy=...`）；② Git LFS 的"锁校验"API 经代理断（本项目根本没有 LFS 文件，只关 `locksverify` 即可）；③ Git for Windows 默认 TLS 后端经代理握手失败（换 `http.sslBackend=openssl` + `HTTP/1.1`）。**关键认知：它们是串联的，修好一层又报新错是正常的。**
> **文档上的坑**：`--date` 占位符被抄了 4 次（教程里写 `--date 9/23` 当占位，结果每轮都带着"计划日"进日志）→ 改成 `--date 填你的执行日` + 红字警告。**教训：模板里的示例值一定会有人照抄，所以要让它抄不出错。**

**Q37. 在线 Demo 上线时踩了哪些"不报错也查不出来"的坑？**
> 四个，都是**静默错误**：
> ① **出处重复**（有效命中从 4 段掉到 2 段）——`Chroma.from_documents(...)` **不传 `collection_name`** → 同进程**追加**到同一 collection（实测 **105 → 210 条**）→ 每次建库给**唯一 `collection_name`**；
> ② **线上出处编号与离线评测表对不上**（13/20 不一致）、每次建库结果都不同——`chromadb` 的 **`hnsw:search_ef` 默认只有 10**（比库容量 105 还小），而本语料是同篇论文段落、余弦分挤在 0.8~1.0 窄带 → 边界必抖 → 显式 **`hnsw:search_ef: 200`**（> 段数 → 退化为穷尽搜索）→ **20/20 一致**；
> ③ **第一次提问就 `IndexError`、页面 500**——`if progress:` 会调用 `gr.Progress.__len__()`，其实现是 `self.iterables[-1].length`，**一次进度都没报过时越界** → 判空写 `progress is not None`；
> ④ **间歇性 `sqlite3.OperationalError: no such table: collections`**——内存库的 `LockPool` 把连接放在 `threading.local()`、`_connections` 只存**弱引用** → **建库线程一退出，内存库可能整体销毁** → 改 `persist_directory` **落盘**。
> **一句话放进汇报**：给在线 Demo 加了个"默认知识库"，顺手把**近似检索参数**这个隐形变量钉住了——现在**线上页面显示的出处编号和离线评测表是同一套口径，别人可以自己验证**。

**Q38. 环境上出过什么事故？**
> 我在共享的 `llm` 环境里跑了发布包的 `requirements.txt` → **41 个包被降级** → `app.py` 起不来。根因是 **`gradio 4.44.0` 只写 `pydantic>=2.0`（无上界）**，而 pydantic ≥2.11 的 Schema 变更让 `gradio_client` 抛 `TypeError`——**服务能起、每个请求 500**，`--check` 查不出来因为它不碰请求路径。
> 修复：按 pip 卸载日志逐包装回 + requirements 补 **`pydantic==2.10.6`**；并在干净环境 `demo` 里做**单变量对照实验**（`2.12.0` 复现 → `2.10.6` 通过）→ **pin 是实证过的修复，不是"试试看"**。
> **两条可复用判据**：① **`pip install -r` 是一条会改环境的写操作**——跑之前先问"这份清单是给谁的环境用的"；② **"服务能起" ≠ "服务能用"**——`--check` 只构建界面、不碰请求路径，必须用 `.get_api_info()` **真冒烟**。

**Q39. 你怎么保证评测数字可复现？**
> **数字只有一条通道**：各结果目录 `run_log.txt`（唯一原始来源）→ `collect_finals.py` **机器抄录**（不手抄）→ **F1↔混淆矩阵自洽校验 + 一致率 ≥0.93 门槛 + 轮次目录存在校验** → `定稿数字表.md`（唯一数字源）→ 报告/博客/README/简历 → `check_release.py`（发布前机器拦：占位符 `__`、数字对不上、密钥、体积）。
> **为什么必须机器对账**：**"多跑投票"防的是随机误差，"照抄混淆矩阵"防的是人为笔误**。day18 真踩过一次——把 R1R2 的 **F1 写成 0.889（那其实是精确率 P，真值 0.842）**，根因是**抄错了混淆矩阵一个格子**（`FP=0` 而非 `FP=1`）。**尺子不会算错，错的是把数字搬进文档的那一步。**

**Q40. 线上 Demo 的数字和你的评测数字对得上吗？**

### 模块 I：统计八股（Day16~20 · 概率语言，差异化王牌）

**Q41. 过拟合是什么？怎么处理？**
> 过拟合 = 模型把训练集的"噪声"也学进去了 → **训练集表现好、测试集表现差**。处理分三层：**数据层**（更多真实数据、增强）、**模型层**（降容量、Dropout）、**训练层**（L1/L2 正则、早停）。

| 手段 | 一句话直觉 | 数学视角 | 本项目对应物 |
|---|---|---|---|
| **L2 正则（Ridge）** | 惩罚"权重太大" | 加 `λ‖w‖²`，等价对权重加**高斯先验** | 生成温度低 = 输出分布更集中 |
| **L1 正则（Lasso）** | 把不重要的权重压成 0 | 等价**拉普拉斯先验 → 稀疏解**（自动特征选择） | 检索只保留 Top-K |
| **早停** | 验证集不再变好就停 | 在 U 型曲线上找谷底 | 微调只跑 3 epoch |
| **Dropout** | 训练时随机关掉神经元 | ≈ 对子网络做**集成**，降方差 | **同题多跑取多数投票** |
| **更多真实数据** | 根本解、但最贵 | 直接降低估计方差 | **HR 意见③ 就是这个** |

> [数学加分] 我还会用验证集曲线判断是欠拟合还是过拟合——**这也是我在 RAG 评测里坚持固定 20 题、每题多跑取多数投票的原因：先保证这把尺子能区分"真提升"和"随机波动"**。

**Q42. 偏差-方差权衡怎么讲？**
> `E[(y − f̂)²] = Bias² + Variance + σ²`。
> **本周的现场实例**：判据过严（Q5 答对却判错）= **尺子的系统性偏差**；同配置两次跑出生成 1/10 vs 2/10、F1 0.750 vs 0.667 = **方差现场演示**；3B 在中英跨语言上的能力上限 + n=20 抽样波动 = **不可约噪声 σ²**。
> **降方差的四招**：① 多测取多数（`runs=3`）② 固定评测集与配置（受控实验）③ 降低随机性（低温、`repetition_penalty`）④ 更大的 n（20 → 100）。

**Q43. 逻辑回归 → 评估指标 → 交叉验证 → 特征工程 → 样本不均衡 → 过拟合，怎么串成一条线？**
> **主轴 = "建模全流程其实是在反复问同一个问题：这个结论能不能推广到没见过的新数据"**：① **逻辑回归**建模概率（sigmoid + 交叉熵 = 极大似然）；② **评估指标**是量尺（混淆矩阵 → P/R/F1，阈值同时改 P 和 R）；③ **交叉验证**是防自欺（测试集只能看一次）；④ **特征工程**是把信息喂进去；⑤ **样本不均衡**是提醒你别被数字骗（换 F1 而非准确率）；⑥ **过拟合**是这个问题的名字。
> **我项目里用同一套思路做 RAG 评估**：固定评测集（③）、分层指标 + F1（②）、判据校准防系统性偏差（④）、in/out 各 10 条故意配平（⑤）、多跑投票降方差（⑥）。

**Q44. RAG 评测怎么翻译成统计学语言？**
> 检索命中率 strict = **Recall@K**；防幻觉 F1 = **混淆矩阵口径的 F1**；FP = **假阳性**（该答却拒答＝过度保守）；FN = **假阴性**（该拒答却编造）；`--runs 3` 投票 = **降方差**（蒙特卡洛重复取众数）；n=20 的置信区间 = **±0.22 量级**；数据自检 = **测量误差**（先修仪器再量数据）；数据泄漏检查 = **训练集/测试集独立性**（阈值 0.70，命中 0 条）；同评测集前后对比 = **配对实验**。

**Q45. 本周的三句"统计纪律"是什么？**
> ① **"统计不是算数，是你凭什么这么说的纪律"**——我报的每个数都能指到一个文件；
> ② **"相关 ≠ 因果"**——F3v2 看起来"真实数据害了模型"，那是相关，**混杂因素（数量）**拆开后才谈得上因果；
> ③ **"小样本只谈量级"**——n=20、CI≈±0.22，所以我说"提升 20 个百分点"，不说"提升 20.0%"。
