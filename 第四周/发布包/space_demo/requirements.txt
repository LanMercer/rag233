# =============================================================================
# 本文件是「在线 Demo」的依赖清单。三个"新容器必崩"的坑都在这里钉住，别删。
# =============================================================================
#
# ★ 坑 0（2026-09-22 魔搭部署实测）：平台的 Gradio SDK 版本必须与本文件一致。
#   魔搭新建创空间默认 SdkVersion = gradio 6.17.3，而本项目代码按 4.44.0 写。
#   两边不一致时，容器里 pip 解析 gradio 会冲突 → 应用起不来 →
#   页面报「Could not load this space」/ 网关 502（但创空间状态仍显示 Running）。
#   → 创建/设置创空间时把 Gradio 版本选成 4.44.0。
#
# ★ 坑 1（2026-09-20 实测）：必须 pin pydantic 的上界。gradio 4.44.0 只写
#   pydantic>=2.0（无上界），而 pydantic>=2.11 把 dict 字段的 JSON Schema 从
#   additionalProperties:{} 改成 true（布尔），gradio_client 1.3.0 的 get_type()
#   里 `if "const" in schema` 拿布尔做 in → TypeError。
#   表现为【服务能起，但首页与每个请求都 500】。
#
# ★ 坑 2（2026-09-22 实测）：必须 pin starlette 的上界。starlette 0.47.0（2025-05-29）
#   删除了旧版 TemplateResponse(name, context) 签名，而 gradio 4.44.0 的
#   gradio/routes.py 仍按旧签名调用 → 模板名被当成 request、dict 被当成模板名
#   → jinja2 模板缓存 TypeError: unhashable type: 'dict'
#   → 【服务能起，但首屏 500】；紧接着 gradio 启动自检 url_ok 拿不到 200，
#   还会误报 "When localhost is not accessible..."。
#   注意：不要按某些资料写成 starlette<0.40 —— fastapi 0.141.x 要求 starlette>=0.46.0，
#   会变成 ResolutionImpossible。0.46.2 里旧签名分支仍在（只发 DeprecationWarning），
#   已验证可用。
#
# ★ 镜像建议：选预装 torch 的镜像（如 ubuntu22.04-py311-torch2.9.1-modelscope1.35.0），
#   否则 sentence-transformers 会从零拖一个 Linux CUDA 版 torch（800MB~2.5GB），
#   免费 CPU 档很容易在构建阶段超时/爆盘。
# =============================================================================
