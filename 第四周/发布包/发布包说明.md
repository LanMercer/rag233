# 发布包说明（A/B 双通道 · 对外展示内容唯一出口）

> **这个文件夹是什么**：把项目里**适合对外展示**的内容集中打包，供两条通道发布——
> - **A 线（GitHub 博客）**：把 `blog\` 里的文章 + `blog\assets\` 里的图片/GIF **复制**到你现有的博客仓库，发一篇展示页。
> - **B 线（HuggingFace Spaces）**：把 `space_demo\` **作为独立仓库推送**到 HuggingFace，得到一个可交互的在线 Demo。
>   **B 线硬性规定**：生成层用 **DeepSeek API**（`deepseek-chat`），**必须在页面/README/文章三处标注"生成层 ≠ 本项目微调模型"，且评测数字只归属本地 Qwen 版本**（详见 `..\01-第四周详细计划.md` 第 7.2 节）。
> **核心原则**：本项目是"源"，发布包是"对外内容"；源文件在项目内维护，**只把发布包复制/推送出去**。模型权重、adapter、向量库、训练脚本、日报**一律不进发布仓库**。
> **为什么这样分层**：数字要到 D5 才定稿（优化前后对比、F1…），博客/在线页写的是**结果**；源只保留一份，避免"改了两处对不上"。

## 二、体积预算表（复制过去会不会很大？不会）

| 内容 | 是否进发布包 | 预估体积 | 说明 |
|---|---|---|---|
| 展示文章 `.md` | ✅ | < 50 KB | 纯文本 |
| 架构图 `.png` | ✅ | 100 KB ~ 1 MB | 已有，直接复制 |
| 优化前后对比图 `.png` | ✅ | 100 KB ~ 300 KB | D5 生成 |
| 演示录屏 `.gif` | ✅（**唯一大头**） | **3 ~ 15 MB** | 录 15~20 秒、720p、降帧压缩；过大就改传视频平台嵌链接 |
| 向量库 `chroma_db\` | ✅（B 线可选） | 1 ~ 3 MB | GMR 论文约 105 chunk，很小 |
| `bge-small-zh-v1.5` 模型 | ❌ | ~95 MB | **运行时从 HF 下载**，不进仓库 |
| `Qwen2.5-3B-Instruct` 权重 | ❌ | ~6 GB | **永不进仓库**；B 线用 DeepSeek API 代生成 |
| LoRA `adapter` | ❌（B 线可选） | 20 ~ 30 MB | 静态博客不需要；在线 Demo 用 DeepSeek API 代生成也不需要 |
| 训练/评测脚本、日报、日报教程 | ❌ | — | 博客只放链接指向 GitHub 代码库 |

> **一句话结论**：发布包通常 **< 20 MB**（几乎全是 GIF）。**只要不复制模型权重/adapter/大向量库，就不会大。**
> **GIF 压缩建议**：录屏工具导 720p、15 秒；用 ScreenToGif / ffmpeg 降帧到 10~12 fps；仍 >20 MB 就把视频传 B 站/YouTube，博客里嵌播放器。

## 三、A 线：GitHub 博客发布步骤

1. **准备素材**：把 `第三周\day13\项目架构图.png` 复制到 `blog\assets\`；D5 把 `优化前后对比.png`、`demo演示.gif` 也放进 `blog\assets\`。
2. **回填文章**：打开 `blog\项目展示页.md`，把 `__` 占位符替换为 D5 定稿数字（检索命中率、生成正确率、F1、提升百分点），补上演示 GIF 与代码库链接。
3. **复制到博客仓库**：把 `blog\项目展示页.md` 与 `blog\assets\` 下的文件**复制**到你现有博客仓库对应目录（文章按你博客的命名/位置约定放，图片放静态资源目录）。
4. **本地预览**：按你博客的本地预览方式起服务，确认图片/GIF 能正常显示、代码块排版正常。
5. **push 并记链接**：`git add . && git commit -m "新增：机器人领域RAG问答系统项目展示页" && git push`，把生成的公网 URL 记到 `发布包说明.md` 底部（或第 5 节链接清单）。
6. **验收**：用手机（不连本地网络）打开链接，图片/动图/文字齐全，**不需要你的电脑开着**。

## 四、B 线：HuggingFace Spaces 发布步骤

> 目标形态：点开链接就能"选示例问题 → 看带出处的答案 + 召回片段"。**生成层使用 DeepSeek API**（免费 CPU 跑不动 3B），检索层（bge + Chroma + 模板 09）在 CPU 上真实运行。
> **⚠️ 强制标注**：页面、本目录 `README.md`、A 线文章**三处**都必须写明"检索层真实运行；**生成层为 DeepSeek API，非本项目微调模型**；评测数字只归属本地 Qwen2.5-3B-Instruct-LoRA 版本"。

1. **本地跑通**：在 `space_demo\` 下 `python app.py`，确认能检索、能调用 DeepSeek API 拿到答案（本地测试可先设 `$env:API_KEY`）。
2. **配密钥**：把 DeepSeek 端点/密钥/模型名写成环境变量读取（`API_BASE_URL=https://api.deepseek.com/v1/chat/completions` / `API_KEY` / `MODEL_NAME=deepseek-chat`），本地测试用临时环境变量，**不要把 key 写进代码**。
3. **建 Space**：HuggingFace → New Space（SDK 选 **Gradio**，硬件选 **CPU basic（免费）**）。
4. **推送**：把 `space_demo\` 作为该 Space 的仓库推送（或网页上传 `app.py` / `requirements.txt` / `README.md`）。
5. **配 Secrets**：Space → **Settings → Variables and secrets** 填入 `API_BASE_URL` / `API_KEY`（Secrets），`MODEL_NAME=deepseek-chat`（Variables），保存后重启 Space。
6. **验收**：公网打开 Space，换一台设备也能用；页面显著位置注明"**检索层为项目真实实现；生成层使用 DeepSeek API（性能强于本地 3B 且未加载本项目 LoRA adapter），非本项目微调模型；评测数字只归属本地 Qwen 版本**"。
7. **记录链接**：把 Space URL 记到第 5 节链接清单，并回填简历/README/效果评估报告。
