   - 命令行参数设计：

     | 参数 | 默认 | 作用 |
     |---|---|---|
     | `--profile` | `lora` | 选原模型 / 微调模型（对应 `config.json` 的两个 profile） |

### D2 · 9/21 周一 · day17：复跑基线 + 首轮检索实验（O0 后半 + O1-R1/R2）

**主线（4~5h）：**

1. **O0 收尾：投票机制 + 复跑基线**
   - 实现 `--runs` 多为多数投票（同一题跑 N 次，判分结果取众数；同时记录"一致率"看稳定性）。
   - **复跑基线**：`python eval_v2.py --profile lora --top-k 4 --temperature 0.2 --runs 1`，**期望复现：检索 2/10、生成 2/10、防幻觉 6/10、F1≈0.667**。
     - 复现不出：先查服务是否是微调模型（`/v1/models`）、向量库/embedding 是否与建库一致、评测题是否改动，**查明原因再往下走**。
2. **O1-R1：bge query instruction 前缀**
   - 原理：bge 官方要求**查询侧**加"为这个句子生成表示以用于检索相关文章："（**段落侧不加**），当前 `HuggingFaceEmbeddings` 默认不带 → query 与 document 编码方式不对称，系统性欠对齐。
   - 做法（先核对本机安装版本支持哪种）：`inspect.signature(HuggingFaceEmbeddings.__init__)` 看是否支持 `query_instruction`；支持就直接传，不支持就写一个薄封装在 `embed_query` 里加前缀。**注意：检索与建库必须用同一编码约定；改动只影响 query 侧。**
3. **O1-R2：TOP_K 4 → 8**
   - 直接 `--top-k 8` 跑（`eval_v2.py` 已参数化）；观察：命中率是否上升、上下文变长后生成是否退化（模板 09 限"≤3 句"，`max_tokens=512` 是否够）。
4. **跑三组对比 + 写实验日志**：`baseline(k=4)` vs `+instruction(k=4)` vs `+instruction(k=8)`，把三组数字填入 `实验日志.md`（**一次只改一个变量**）。
5. **D1 一键启动脚本雏形**：`start.bat` / `start.py`——检查环境 → 提示启动服务命令 → 拉起 `app.py`（先做雏形，D3 完善）。
6. **验收**：基线复现已确认；实验日志 ≥3 条（含基线）；能说出"哪一步让数字动了多少"。

**零散时间：** 力扣 70 ｜ 统计八股：偏差-方差权衡
**产出：** `eval_v2.py`（完整）、`实验日志.md`（首轮 3 条）、`start.bat`（雏形）、`第四周\day17\` 结果目录

## 五、本周常见坑位与避坑

| 坑位 | 应对 |
|---|---|
| 多个变量一起改、说不清是谁起的作用 | **每轮只改 1 个变量**，单独重跑 20 题，结果写进 `实验日志.md` |
| 6G 显存同时跑"服务 + 训练"→ OOM（`os error 1455` / 崩溃） | **串行**：训练前先停服务；训练确认峰值 <6G；`low_cpu_mem_usage=True` |
| UI 里直接加载模型导致显存爆 | UI **只调 HTTP 接口**（8000 端口），不加载模型本体 |
| `build_index.py` 会清库重建 → 实验库互相覆盖 | 改成按配置存不同 `persist_dir`（如 `chroma_500` / `chroma_800`），建"实验库矩阵" |
| bge instruction 前缀加错位置 | **只 query 侧加**，段落侧不加；建库与检索编码约定保持一致 |
| TOP_K 调大后上下文变长、生成退化或被截断 | 观察 `max_tokens=512` 是否够；必要时模板限句更严；对比时同时看命中率与生成率（别只看检索） |
| 投票机制（`--runs 3`）耗时 ×3 | 只在关键轮次用；日常实验 `--runs 1`，定稿数字用 `--runs 3` 或 5 |
| Gradio 中文乱码 / 上传文件路径含中文/空格 | 统一 UTF-8；路径用 `pathlib`；上传后先落盘再读 |

### 7.1 三种"在线展示"方式对比（选 A+B）
