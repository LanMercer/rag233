## 一、本周核心方法论（比任何单点技术都重要）

### 1.1 受控实验（Controlled Experiment）：优化 = 只改一个变量

| 要素 | 本周做法 | 为什么必须这样 |
|---|---|---|
| **固定评测集** | 20 题（资料内 10 + 资料外 10），全程不变 | 换卷子就没法比；固定卷子才能做"配对实验" |
| **只改一个变量** | 每轮只动 Top-K / 前缀 / 模板 / 数据 / adapter 中的**一个** | 同时改两个就**说不清是谁起的作用**（F3 的教训） |
| **单变量自检** | 改检索的轮次，**生成层指标不应系统性变**；改生成/数据的轮次，**检索两列必须逐位相同** | 这是判断"实验是否脏了"的**免费信号**：R4/R5/F3v2/F3v3/F4o 五轮的检索两列都与 R3 **一字不差（4/10、5/10）** |
| **可复现** | 一切写作"同脚本、同库、同参、只改 X"；脚本跨天**逐字节复制**（并用 AST 指纹证明逻辑未变） | 面试官要能"照着你说的重跑一遍" |

> **一句话**：优化 = 在固定评测集上做**受控实验**——"**只改一个变量 → 看指标变化**"。

### 1.2 一把尺子的两个敌人：**偏差（bias）与方差（variance）**

```
E[(y − f̂(x))²] = ( E[f̂(x)] − f(x) )² + E[( f̂(x) − E[f̂(x)] )²] + σ²
                    └──── Bias² ────┘      └──────── Variance ────────┘   └ 噪声 ┘
```

| 敌人 | 本周的现场表现 | 应对机制 |
|---|---|---|
| **偏差**（系统性偏离） | Q5 答对（"a diverse LAFAN dataset"）却因关键词 `LAFAN1` 被判错 = **尺子刻度偏严** | `KEYWORD_PATCH` 判据补丁（用**覆盖表**而非改原 json，加开关，只放宽到前缀） |
| **方差**（自己抖动） | 同配置 B0 与 day14 跑出生成 1/10 vs 2/10、F1 0.750 vs 0.667 = **方差现场演示** | `--runs 3` **多数投票** + 报**一致率**（≥0.93 才算"数字稳、可对外引用"） |
| **不可约噪声 σ²** | 3B 模型在"中文问句 ↔ 英文论文"上的能力上限；n=20 的抽样波动 | 只能靠**扩样本**（n≥60）与**更强模型/API**，不在本轮预算内 |

> **顺序纪律**：**先把尺子的偏差修掉 → 再压方差 → 然后才敢说"优化提升了多少"**。因为
> **提升 Δ = 优化后的估计 − 优化前的估计**；尺子不准或抖动大，这个差就没有意义。

### 1.3 数字只有一条通道（证据链）

```
各结果目录 run_log.txt（唯一原始来源）
        │  ← collect_finals.py「机器抄录」（不手抄）
        ▼
  F1↔混淆矩阵自洽校验  +  一致率 ≥0.93 门槛  +  轮次目录存在校验
        ▼
      定稿数字表.md（唯一数字源）
        ▼
优化成果报告 / 博客文章 / README / 简历 / 周汇总（所有对外文字）
        ▼
  check_release.py（发布前机器拦：占位符 `__`、数字对不上、密钥、体积）
```

> **为什么必须机器对账**：**"多跑投票"防的是随机误差，"照抄混淆矩阵"防的是人为笔误**。day18 真踩过一次——把 R1R2 的 **F1 写成 0.889（那其实是精确率 P，真值 0.842）**，根因是**抄错了混淆矩阵一个格子**（`FP=0` 而非 `FP=1`），于是谬误自洽地"算"出来了。**尺子不会算错，错的是把数字搬进文档的那一步。**

### 1.4 报告负结果 = 判断力的证据（不是失败）

**本周共记录 8+ 条"改了但没用 / 反而更差"的尝试**，且**每条都给了机制**：

| 尝试 | 数字变化 | 机制 |
|---|---|---|
| bge instruction 前缀 | 检索 strict 20% → **0%** | **排名位移**（chunk 3 第 4→5 名，k=4 掉出窗口） |
| RRF 混合检索（中文查询下） | 4/10 → **3/10** | BM25 对中文近零信号却**等权融合** + `1/(60+rank)` 压平名次差 |
| 查询改写三档 | 总 55% → **45% / 50% / 55%**（无一超基线） | `term` 伤专名；`hyde` 让 out 题"有话说" |
| 模板 09 v2 / v2a / v2b | F1 0.824 → **0.462 / 0.571 / 0.706** | **归因锁死一句提示语②**"资料里有依据就照实回答" |
| 引文兜底 `retry` | F1 0.824 → **0.737**（FP 0→2） | 给 3B 任何"允许拒答"的措辞，它就把出口当答案 |
| F3 真实数据 v2 | F1 0.824 → **0.333** | 来源与数量未拆开（后补 F3v3 拆开：**分布不匹配**） |
| **F4 微调 vs 原模型** | 微调 0.824 **<** 原模型 **0.947** | 3B 容量有限，微调把"该拒就拒"挤掉一部分（假说） |

> **面试价值**：报告的价值**不在数字好看，而在每一步的贡献可归因**。被问"你做了什么优化"，答"我试了四类，三类没有净增益，机制分别是 X/Y/Z，所以最终只保留了 Z"——**比"我涨了 15 个点"更难被追问倒**。

## 二、板块 A：评测体系（"尺子"是怎么造的）

### 2.1 三类指标 + F1（分层归因的评测）

| 指标 | 定义 | 统计对应 | 定稿数字（R3） |
|---|---|---|---|
| **检索命中率 strict** | Top-K 是否召回标注的 `source_chunk` | **Recall@K**（偏严） | 4/10 = **40%** |
| **检索命中率 loose** | 期望关键词是否落在 Top-K 上下文里 | 宽松版召回（治"没召回该段却答对了"的反例） | 5/10 = 50% |
| **生成正确率** | 资料内 10 题是否命中期望关键词 | 分类正确率 | 4/10 = **40%** |
| **防幻觉正确率** | 资料外 10 题是否如实拒答 | 分类正确率 | 7/10 = **70%** |
| **防幻觉 F1** | 把"该不该拒答"当二分类算 F1 | **混淆矩阵 + F1** | **0.824**（TP7 / **FP0** / FN3 / TN10） |
| **总正确率** | 20 题里答对的比例 | 总体点估计 | 11/20 = **55%** |

**为什么不用一个"总正确率"糊过去**：一个总数会把"**没召回**"和"**没答对**"混在一起；拆开才能**把低分定位到层**。
**双轨为什么并列报**：strict 偏严（第三周旧口径，便于与首版比），loose 治反例；**两列同时报 = 口径透明**，读者自己判断。

### 2.2 防幻觉 F1 的混淆矩阵（必须能当场画出来）

把 20 题当二分类："真实该不该拒答"（正类 = **该拒答**，即资料外题）vs "模型拒不拒答"：

|  | 模型拒答 | 模型作答 |
|---|---|---|
| **资料外（应拒答）** | **TP**（真防住，如 7） | **FN**（幻觉漏网，如 3） |
| **资料内（应作答）** | **FP**（该答却拒答＝过度保守） | **TN**（正常作答，如 10） |

- 精确率 **P = TP/(TP+FP)** = 7/(7+0) = 1.000（拒答时"拒得对不对"）
- 召回率 **R = TP/(TP+FN)** = 7/(7+3) = 0.700（该拒的题"拒住了多少"）
- **F1 = 2PR/(P+R)** = 0.824（**调和平均**：P=1、R=0 时算术平均 0.5 显得还行，调和平均是 0 直接露馅）

> ⭐ **读表纪律**：**同一个 F1 可能来自完全不同的结构**，所以引用 F1 **必须写括号里的 TP/FP/FN/TN**。
> ⭐ **两个读数坑（本周踩了两次）**：
> - **坑A**：`FP` 按 `refused` 字段统计，**只比 `correct` 会漏报**（Q1 的 `correct` 两次都 ❌、只有 `refused` 从 False→True，它让 FP +1 却不进"判定翻转"名单）。
> - **坑B**：**`引文非法 0 处` ≠ `答案干净`** —— `strip` 只认 `[数字]` 形态，R6 交付答案里仍有 **23 处非数字伪引文**（`[资料©]`、`[resourceright]`、`[资料第Ⅱ节]`）——**模型在用"引文的样子"伪装内容**。

### 2.3 一致率与 n=20 的置信区间

- **一致率** = 同题 3 次判定的多数占比；**≥0.93 才算"数字稳、可对外引用"**（日常实验 `runs=1`、定稿 `runs=3`）。
- **n=20 的 95% 置信区间约 ±0.22** → **只谈量级与归因，不抠小数点**（说"提升 20 个百分点"，不说"提升 20.0%"）。
- **报告数字必说口径**：20 题 / `runs=3` / `k=8` / 模板 v1 / `patch=on` / `qi=off`。

> **面试话术（30 秒）**：
> "我的评测不是'跑个分'，而是一次**受控实验**：固定卷子、每题多跑取多数降方差、判据双轨透明、每一步只改一个变量——**这套纪律跟做 A/B 测试和假设检验是同一套思路**。而且我知道 n=20 的置信区间大约 ±0.22，所以我只讲'提升几个百分点、提升几道题'，不在小数点后两位上做文章。"

## 三、板块 B：检索层优化（O1 线，全是"数据说话"）

### 3.1 检索链路与两个"旋钮"

```
用户问题 → [查询侧编码] → 向量/关键词检索 → Top-K 段落 → 拼上下文（带 [资料§N] 编号）
                ↑                    ↑
         bge instruction 前缀     TOP_K（k=4 / k=8）
```

| 变量 | 结论 | 数字 |
|---|---|---|
| **TOP_K 4→8** | ⭐ **唯一稳定有效的优化** | 检索 strict **20% → 40%**、总 **40% → 55%** |
| **bge query instruction 前缀** | ❌ **负贡献（假设证伪）** | 检索 strict **20% → 0%**、总 40% → 35% |
| **chunk_size 矩阵 / 混合检索** | 被决策门否决（"几乎没动"侧）/ 中文查询下 RRF 反而掉题 | hybrid 4/10 → **3/10** |

### 3.2 bge instruction 前缀：一个"官方推荐反而变差"的完整案例 ⭐

- **背景**：bge 官方要求**查询侧**加"为这个句子生成表示以用于检索相关文章："（**段落侧不加**）；当前 `HuggingFaceEmbeddings` 默认不带 → query 与 document 编码方式不对称、系统性欠对齐。
- **本机实测支不支持**：`inspect.signature` 被 `**kwargs` 吞掉看不出来 → 再查 `model_fields`（字段里**没有**）+ 读 `embed_query` 源码（**也没拼前缀**）→ 确认不支持 → 走**薄封装**（只重写 `embed_query`，**段落侧一字不动 → 不用重建向量库**）。
- **两级验证"变量接上了没有"**：① 向量层 `cos(base, qi)=0.9108`、`same=False` → 前缀确实进了编码；② 检索层 dry-run 里 Q2 的 Top-K 从 `[14,22,1,9]` 变成 `[14,22,9,1]` → 排序真的动了。**先证明"变量接上了"，再跑全量下结论**——避免"改了半天其实没生效"的假实验。
- **结果与机制**：strict **20% → 0%**。逐题追查发现前缀**不是让语义变差**，而是把期望段**整体下压 1 名**：
  - Q5：`[103,4,25,3]`（chunk 3 第 4 名 ✅）→ `[103,25,74,4]`（跌出前 4 ❌），k=8 时回到第 5 名 ✅；
  - ⇒ **k=4 时第 5 名看不到 → 命中集合 `{Q5,Q9}` → `{}`；k=8 时第 5 名仍在窗口内** → **"前缀在 k=4 有害、k=8 不致命"的交互效应来源**。
- **两个变量不可加**：用 day16 R2（k=8 无前缀）交叉验证，简单相加预测 2/10 ≠ 实际 3/10 → **存在交互效应（interaction）**，"单看主效应会骗人，必须先固定另一个变量再比"。

> **面试可直接讲**："我按 bge 官方文档给查询侧加了 instruction 前缀，**结果检索命中率反而从 20% 掉到 0%**。逐题追查发现：前缀并没有让向量'变差'，而是把几段关键资料**从第 4 名推到第 5 名**——k=4 时刚好掉出窗口，所以全灭；把 k 提到 8 之后它们又在窗口内了。这说明**前缀的效应与 k 有交互**，也说明'官方推荐做法'在具体语料上不一定有效，**必须用自己的固定评测集验证**。"

### 3.3 数据自检（O1-R8）：先查卷子，再怪检索

| 判定 | 条数 | 含义 |
|---|---|---|
| ✅ 标注自洽（关键词能在标注段落里字面命中） | **9/10** | 检索没召回它 → **真失败** |
| ⚠ 疑似标注错位（关键词只在别处） | **0/10** | —— |
| ❌ 标注 chunk 不存在 | **0/10** | —— |
| ❓ 需人工读原文（多为中英翻译题） | **1/10**（Q8） | 人工读 chunk 3 → **标注正确** |

> **一句话结论**：`source_chunk` 标注可信 → **检索未命中属真实失败，瓶颈在检索侧、不在标注侧**。
> **边界（必须说）**：脚本**只做字面匹配**，它证明的是"关键词的字面形态出现过"，**不能替你做语义判断** → 报告要写"**经人工读原文核对后确认**"，而不是"程序证明标注都对"。

### 3.4 混合检索（BM25 + 向量 + RRF）与"改写之后才翻正" ⭐

- **plain（中文查询，现状）**：`vector` **4/10**、`bm25` **4/10**、`hybrid` **3/10**、**`vector ∪ bm25 = 7/10`**。
  - **两通道高度互补**（并集是任一单通道的 1.75 倍）；**失败模式互补**——`vector` 丢的全是**专名题**（Q1/Q7），`bm25` 丢的全是**中文题**（Q2/Q5/Q6/Q9，直接 `top=[]`）。
  - **但融合反而掉一题**，三个机制：① BM25 对中文近零信号却被**等权融合**（等于给有效排序掺一半噪声）；② `1/(60+rank)` **把名次差压平**（第 1 名 `1/61≈0.0164` vs 第 8 名 `1/68≈0.0147`，**只差 11%**）；③ RRF 只看名次、不看"这一路可不可信"。
- **改写之后（term 档）**：`hybrid` **3/10 → 6/10**（首次超过最好的单通道），**但上界一点没涨**（三通道并集恒为 7/10）→ **改写做的是"命中集合重排"、不是净增益**；融合的价值在**兑现率 3/7 → 6/7**（把并集里已有的题真正捞进 Top-8）。
- **旋钮**：`rrf_k`（60→10）**不敏感**、`pool`（20→10）**敏感**（丢 Q8）→ **别缩池子**。

> **一句话机制**：**错的不是融合，是"在什么查询下融合"**——中文查询下 BM25 是瞎的，融合等于掺噪声；查询改写后两路都有信号，融合才正常。

### 3.5 HyDE 与查询改写：**上界 ≠ 成绩** ⭐

- **HyDE（Hypothetical Document Embeddings）** = 先"假设一个答案片段"再拿它去检索，让查询更像文档。
- **人工手写的理想英文查询（上界）**：三通道 **strict 10/10** → 同一套库、同一套判据，**只换查询语言 → 40% → 100%** ⇒ **瓶颈在查询侧的语言错位（中文问句 ↔ 英文段落）**。
  - ⚠ **这是"上界"不是"成绩"**：等于开卷考试，只能回答"**瓶颈在哪**"，不能回答"**能提升多少**"。
- **模型自动改写的真实现（三档）**：`term` / `hyde` / `both` → 总正确率 **45% / 50% / 55%（无一档超过基线 R3 的 55%）**；F1 **0.706 / 0.571 / 0.625**。
  - **"检索涨、生成崩"是结构性的**：`hyde` 档检索 loose 涨到 **8/10**，代价是 out 从 7 掉到 4 —— 拿"假设答案片段"当查询，检索到的段落**更像答案本身**，out 题变得"有话说"。
- **改写产物质检"四看"（回 `chunks.json` 计数，把"像是幻觉"变成"计数为 0 的幻觉"）**：

| 漏损类型 | 实例 | 库内真实计数 |
|---|---|---|
| ① **改写器编造实体** | `Generalized Mean Regression`（库内真词是 `General Motion Retargeting`） | **0** 次（真词 7 次） |
| ② **真实存在但语义错位** ⭐最危险 | Q3 编成 `University of Science and Technology of China`；Q15 写 `4,096 parameters`（库里 `4096` 是**仿真次数**） | **0** 次（`Stanford` 7 次） |
| ③ **多一个连字符丢 BM25 信号** | `LAFAN1` → `LAFAN-1`（`TOKEN_RE` 切成 `lafan`+`1`） | `LAFAN-1` **0** 次（`LAFAN1` 10 次） |
| ④ **指令泄漏** | `可能出现的表述：` 混进英文查询（**7 题**） | —— |

> **"像真词"的伪实体比乱码更坏**：`Generalized Mean Regression`（统计学里真存在的另一个术语）、`GMRES`（数值线性代数算法名）会**稳定地把排名带偏**。

## 四、板块 C：生成层优化与防幻觉（O2 线）

### 4.1 模板 09：三件事 + 逐句消融

**模板 09 v1（实测最稳的一版）里带三件事**：
1. **出处格式** `[资料§N]`（让答案可核验）；
2. **拒答出口句**（"资料中没有提到"）；
3. **防幻觉约束**（不许编编号/数字）。

**逐句消融（本周最"硬"的一次归因）**：

| 轮次 | 模板构成 | 防幻觉（out） | F1 | 总正确率 |
|---|---|---|---|---|
| R3 `v1`（基线） | —— | **7/10** | **0.824** | **55%** |
| R5 `v2` | ①②③④ | **3/10** | 0.462 | 40% |
| R5a `v2a` | ①②④ | 4/10 | 0.571 | **35%** |
| R5b `v2b` | ③④ | 6/10 | 0.706 | 50% |

> **归因锁死在一句提示语**：**②"只有当资料确实找不到相关信息时才拒答；资料里有依据就照实回答"**——
> **带 ② 的两档 out 只有 3~4/10，不带 ② 的有 6~7/10**（差 2~4 题，超出波动）。
> **机制**：**out 题的 Top-K 永远返回 8 条**（检索总会给你东西），② 等于告诉模型"**有东西就是有依据**" → 它把**检索到的相邻话题段落当依据答了**。
> ⚠ **不能简化成"留 ③④ 去掉 ②"**：v2b 的 F1 0.706 **仍低于 v1 的 0.824** → 正确说法是"**这一版提示词对生成层没有净收益**"。

### 4.2 "误读型幻觉"：提示词治不了（本周认知上最重要的一步）⭐

把三条典型 out 题**逐句回 `chunks.json` 核对"是编的还是抄的"**，发现**没有一条是凭空编造**：

| 题 | 真相 | 教训 |
|---|---|---|
| **Q11**（缺点？） | 把资料里的**伪影 / 指标定义 / 用户研究结论**逐条搬来、**统一贴上「缺点」标签**（唯一凭空的是"缺点"这个框） | 语义误读 |
| **Q14** | **chunk 76 原文照抄**，错在**答非所问** + 引用格式崩坏 | 答非所问 |
| **Q18** | 把**参考文献页码**当成"被引次数"（`pp. 425–432` → `425`）、把**参考文献编号 `[41][42][43]`** 当成段落号 | 编号体系张冠李戴 |

> **结论**：模型"看过了"、不认为自己在编 → **"禁止编造数字/引用"这类提示词天然治不了它们**（这也解释了 v2b 只治住 Q18、治不住 Q11）。
> **可讲的三层防幻觉框架**：① 检索层——保证资料进上下文（k=8 + 出处编号）；② 生成层——模板约束 + 拒答出口；③ 交付层——**引文白名单**。并**如实说三层都治不了"误读型幻觉"**——那要靠**数据 / 更大模型 / 后处理**。

### 4.3 引文强制白名单（O2-G3）：唯一零副作用的工程收益 ⭐

| 策略 | 做法 | 结果 |
|---|---|---|
| `record` | 只记录非法引用（基线） | —— |
| **`strip`** ⭐ | **就地剪除**不在上下文里的编号 | 交付口径非法引用 **5 → 0 处**、剪除 13 处、**F1 逐格不变（0.824）**、判定与拒答**零翻转** → **达标且零副作用** |
| `retry` | 点名非法编号**重答一次** | F1 0.824 → **0.737**（**FP 0→2**）→ **负结果，不采用** |

- **`retry` 为什么更差**：**与模板 ② 同型** —— 给 3B 任何"允许拒答"的措辞，它就把**出口当答案**（Q3 本来 ✅ 被改成拒答、Q1 交出半截答案、Q5 交出**空字符串**）。
- **`strip` 为什么"救不回 F1"**：Q18 那句 `[1][36]…[84] = 7。` 剪完仍剩 `[84] = 7。`——**它本来就不是拒答句**，剪引用改变不了"该拒没拒"这个事实。⇒ **`strip` 是"交付前保险"，不是"效果优化"**。
- **轮内双口径（今天的设计）**：一旦引入"会改答案"的后处理，**跨轮比较在生成层就失效** → 判断兜底有无副作用**只能靠轮内 `correct_raw`/`refused_raw` vs 交付的对照**。

### 5.2 采集与校验纪律（能讲出"凭什么是真的"）

- **六查校验器**：条数门槛 / 必填字段 / 空值重复 / **source 可追溯（`quote` 逐字回原文）** / **数据泄漏**（与 `eval_questions.json` 比对，阈值 0.7）/ 类目与机构分布。
- **"补短板"是方法论重点**：第 1 批 80 条（市场类 40% 超标、公司经营仅 8.8%）→ 第 2 批 **+31 条只补短板** → 最大类目 40% → **28.8%**；**"市场与产业链"仍超标（28.8% vs 建议 ~15%）如实写出**——**"没有为了分布好看去删已有数据"**（删掉才是造假）。

### 5.3 真实 vs 合成对照微调：**拆变量**才叫归因 ⭐

| 轮次 | 训练集 | 来源 | 数量 | 生成(in) | 防幻觉(out) | F1 | 总正确率 |
|---|---|---|---|---|---|---|---|
| F3v1（=R3） | 合成 300 | 全合成 | 300 | 4/10 | **7/10** | **0.824** | 55% |
| F3v2 | 真实 201 | 全真实 | **201** | 5/10 | 2/10 | **0.333** | 35% |
| **F3v3** | **真实 201 + 合成 99** | 混合 | **300** | 5/10 | **3/10** | **0.429** | 40% |

- **F3v2 不可归因**："来源"与"数量"两个变量**同时变了**。
- **F3v3 把数量对齐到 300** → 防幻觉只回了 **1 题**（2/10→3/10），仍远低于 R3 的 7/10 ⇒ **"差的这 99 条"最多解释一小部分 ⇒ 主因是"数据分布与评测集不匹配"**（v2 数据里 **111/201 = 55% 是行业语料**，而评测题出自 GMR 论文 → **领域适配被摊薄**）。
- **判读规则先写死（避免跑完"看图说话"）**：若回到 R3 水平 ⇒ 主因是**数量**；若仍 ≤3/10 ⇒ 才轮到谈**分布不匹配**。→ 本轮落在**情况 B**。
- **⚠ 三条边界**：① F3v3 比 F3v2 略好 ⇒ 掺合成有**微弱正作用**；② **不能**写成"真实数据没用"——只管"这批真实数据的分布不适合这套评测题"；③ 真实数据的价值在**交付物层面（可追溯、可逐字回查）**，不在"同规模下必然涨分"。
- **"相关 ≠ 因果"（统计语言的翻译）**：F3v2 看起来"真实数据害了模型"，**那是相关、不是因果**——两个变量同时变了；**混杂因素**就是样本数量，所以要**补样对齐**把它拆开。

### 5.4 双模型对比（F4）：**逆预期反例成了主结论** ⭐⭐

| 轮次 | 服务招牌名 | 检索 strict/loose | 生成(in) | 防幻觉(out) | F1（TP/FP/FN/TN） | 总正确率 | 一致率 |
|---|---|---|---|---|---|---|---|
| **F4o**（原模型） | `Qwen2.5-3B-Instruct`（**无后缀**） | 4/10、5/10 | **7/10** | **9/10** | **0.947**（9/**0**/1/10） | **80%** | **1.0** |
| **F4l**（微调） | `Qwen2.5-3B-Instruct-LoRA` | 4/10、5/10 | 4/10 | 7/10 | 0.824（7/0/3/10） | 55% | 0.950 |
| **差值（微调 − 原模型）** | —— | **0** | **0** | **−3/10** | **−2/10** | **−0.123** | **−25pt** | —— |

- **✅ 自检通过（本轮最关键的判据）**：**检索两列逐位相同（4/10、5/10）** → 两组只差 adapter，**差异可干净地归因到"微调"这一个变量**。
- **结论（照写）**：**不是"个别题原模型更好"，而是原模型在两个生成类指标上全面占优** ⇒ **这版数据/配置的 LoRA 在"资料外拒答"上是负收益**。
- **机制假说（本轮未单独验证）**：3B 容量有限，微调把"照本宣科 / 该拒就拒"的能力挤掉一部分，模型变得更"愿意顺着上下文说"。
- **⭐ 边界三句必须同时写**：① 只能说"**这版微调在防幻觉上是负收益**"，**不能**推广成"微调无用"；② 微调收益在**风格 / 术语 / 格式遵循**（可展示，但不是本评测集的判据）；③ n=20、CI≈±0.22，但 **−0.123 的 F1 差 + 全项同向**足以支撑"负收益"这个**量级**判断。
- **⭐ 顺带得到一条正面结论**：原模型在**检索层完全一样**的情况下靠"读好上下文 + 该拒就拒"拿到 80% → **知识确实来自检索层**，空间在**生成层的遵从性**上 —— 这正是"**为什么选 RAG 而不是直接微调**"的**实测回答**。

### 6.4 环境隔离：一条"把口号变成实物"的纪律 ⭐

- **事故**：在共享的 `llm` 环境里跑 `发布包\space_demo\requirements.txt` → **41 个包被降级** → `app.py` 起不来；根因是 **`gradio 4.44.0` 只写 `pydantic>=2.0`（无上界）**，pydantic ≥2.11 的 Schema 变更让 `gradio_client` 抛 `TypeError`（**服务能起、每个请求 500**，`--check` 查不出来因为它不碰请求路径）。
- **修复**：按 pip 卸载日志逐包装回 + `requirements.txt` 补 **`pydantic==2.10.6`**；并在干净环境 `demo` 里做**单变量对照实验**（`2.12.0` 复现 → `2.10.6` 通过）→ **pin 是实证过的修复，不是"试试看"**。
- **两条可复用判据**：① **`pip install -r` 是一条会改环境的写操作** —— 跑之前先问"这份清单是给谁的环境用的"；② **"服务能起" ≠ "服务能用"** —— `--check` 只构建界面、不碰请求路径，必须用 `.get_api_info()` **真冒烟**。
- **附带一条**：`.condarc` 在中文 Windows 上被 conda 用 **GBK** 读 → **必须纯 ASCII**（写了中文注释会让 `conda --version` 都报错，还伪装成"conda 坏了"）。

## 七、板块 F：统计建模副线（本周零散时间，覆盖风控岗）

### 7.1 过拟合处理（day16）

| 手段 | 一句话直觉 | 数学视角 | 本项目对应物 |
|---|---|---|---|
| **L2 正则（Ridge）** | 惩罚"权重太大" | 加 `λ‖w‖²`，等价对权重加**高斯先验** | 生成温度低 = 输出分布更集中 |
| **L1 正则（Lasso）** | 把不重要的权重压成 0 | 等价**拉普拉斯先验 → 稀疏解**（自动特征选择） | 检索只保留 Top-K |
| **早停（early stopping）** | 验证集不再变好就停 | 在 U 型曲线上找谷底 | 微调只跑 3 epoch |
| **Dropout** | 训练时随机关掉神经元 | ≈ 对子网络做**集成**，降方差 | 同题多跑取多数投票 |
| **更多真实数据** | 根本解、但最贵 | 直接降低估计方差 | **HR 意见③ 就是这个** |

### 7.2 偏差-方差权衡（day17）

见 §1.2。**降方差的常规手段**：① 多测取多数（`--runs 3`）② 固定评测集与配置（受控实验）③ 降低随机性（低温、`repetition_penalty`）④ 更大的 n（20 → 100）。

### 7.3 6 节串线（day18/19/20）：从"逻辑回归"到"过拟合"一条线

**主轴 = "每一步都在回答同一个问题：这个模型能不能泛化？"**

| 环节 | 在回答什么 | 关键动作 | 与本项目对照 |
|---|---|---|---|
| ① 逻辑回归 | 建模"**概率**"而非硬分类 | sigmoid 压到 (0,1)；损失 = **交叉熵 = 极大似然** | RAG = 条件概率分解 `P(答案\|问题) ≈ P_gen(答案 \| 模板09(检索(问题)))` |
| ② 评估指标 | "**好**"怎么量 | 混淆矩阵 → P/R/F1；**阈值同时改 P 和 R** | **防幻觉 F1 = 混淆矩阵口径** |
| ③ 交叉验证 | **别用训练集自评** | K 折 / 留出法；测试集只能看一次 | 20 条固定评测集 = 留出测试集；**不能拿它调参调到满足** |
| ④ 特征工程 | 让**信号**可被模型用上 | 归一化 / 交互项 / 分箱 / one-hot | **chunk 切分与改写查询** = 给检索器"造更好的特征" |
| ⑤ 样本不均衡 | **别被多数类骗了** | 重采样 / 类权重 / **换指标（F1 而非准确率）** | out/in **各 10 条故意配平**；按真实分布准确率会虚高 |
| ⑥ 过拟合 | **训练好 ≠ 泛化好** | 正则化 / 早停 / dropout / 更多数据 | **"背评测题"= 过拟合**；**"合成数据 = 模板套壳" = 高偏差** |

### 7.4 RAG 评测 ↔ 统计评估 的对照表（差异化王牌）⭐

## 九、综合自查卡（Q&A 表）

> 盖住右列，出声自问自答；答不满 30 秒或含糊的，回去补。

| 问题 | 答案要点 |
|---|---|
| 为什么"先修尺子再谈提升"？ | 提升 Δ = 优化后估计 − 优化前估计；尺子有偏差（判据过严）或方差（单次抖动），这个差就没意义 → 先修偏差（判据补丁）、再压方差（`runs=3` + 一致率） |
| 怎么保证"同一个配置"的可比性？ | 同脚本、同库、同 20 题、同判据口径、只改一个变量；并用"改检索的轮次生成层不变 / 改生成/数据的轮次检索两列逐位相同"做**单变量自检** |
| `runs=3` 投票解决了什么？ | 单次生成随机性（同配置跑出 1/10 vs 2/10）；输出**一致率**回答"这轮数字稳不稳" |
| 双轨检索判据为什么要两列？ | strict 偏严（与首版可比）、loose 治反例；**两列并列报 = 口径透明** |
| 为什么 n=20 只谈量级？ | 95% CI ≈ ±0.22；所以讲"提升几个百分点"，不抠小数点 |
| F1 的四个格子怎么摆？ | TP 真拒答 / FP 该答却拒答 / FN 幻觉漏网 / TN 正常作答；**F1 必带矩阵** |
| `FP=1` 一定是模型变差吗？ | 不一定——可能是**判据假阳性**（答案中间出现拒答词，规则只看"有没有拒答词"）；已踩两次 |
| "引文非法 0 处"是不是答案就干净了？ | **不是**——正则只认 `[数字]`，R6 仍有 23 处非数字伪引文（`[资料©]`） |
| bge instruction 前缀为什么是负的？ | **排名位移**（chunk 3 第 4→5 名撞上 k=4 窗口），不是语义变差；且与 k 有**交互** |
| TOP_K 4→8 为什么有效？ | 期望段从"第 5 名"回到窗口内；是本病唯一稳定有效的优化 |
| HyDE 的 10/10 能当成绩吗？ | **不能**——那是人工手写的理想查询（上界/开卷），只能证明"瓶颈在查询侧"；真实现落在 50% |
| 改写为什么没有净增益？ | `term` 伤专名、`hyde` 伤拒答；**四类漏损机制**（编造实体 / 语义错位 / 连字符丢 BM25 信号 / 指令泄漏） |
| RRF 为什么一开始有害、后来翻正？ | 中文查询下 BM25 近零信号却被等权融合 → 掺噪声；改写后两路都有信号 → 融合翻正（**兑现率 3/7→6/7、上界不变**） |
| 模板 v2 三档为什么全退？ | **归因锁死一句提示语②**"有依据就照实回答"——out 题 Top-K 永远 8 条，等于"有东西就是有依据" |
| "误读型幻觉"提示词为什么治不了？ | 回库核对发现**三条里没有一条凭空编造**（语义误读 / 答非所问 / 编号张冠李戴）→ 模型"看过"、不认为在编 |
| 引文白名单为什么是"零副作用"？ | 轮内 raw vs delivered **逐题零改动**、判定与拒答零翻转、F1 逐格不变；它只改交付形态，不改生成 |
| 为什么 `retry` 反而更差？ | 给 3B 任何"允许拒答"的措辞，它就把出口当答案（Q3 被改成拒答、Q5 空字符串）→ 与模板②同型 |
| 真实数据为什么值得信？ | 论文 90 条**逐字回查 90/90**；行业 111 条**带 URL/日期/原文摘录**、26 机构、最大占比 10.8%；合成数据如实标注；**不能逐字回查的（行业）如实说明** |
| 真实数据为什么没涨分？ | "来源"与"数量"一开始同时变 → 补 F3v3 拆开：数量对齐到 300 后 F1 仍只有 0.429 ⇒ **主因是分布不匹配**（55% 是行业语料）；**不能**说"真实数据无用" |
| 原模型为什么比微调好？ | 同库同参、**检索两列逐位相同**、只差 adapter → 差异纯在生成层：原模型 0.947/80% vs 微调 0.824/55% ⇒ **这版微调在防幻觉上负收益**；边界三句同时说 |
| 线上出处为什么本地对不上？ | `hnsw:search_ef` 默认只有 10（比库 105 还小）+ 余弦分窄带 → 边界抖；显式设 200 → 20/20 一致 |
| 出处为什么会重复？ | `Chroma.from_documents` 不传 `collection_name` → 同进程追加到同一 collection（105→210） |
| 内存向量库为什么不能在 Gradio 里用？ | `LockPool` 把连接放 `threading.local()`、`_connections` 只存弱引用 → 建库线程一退出内存库可能销毁 → 间歇性 `no such table` |
| `.gitignore` 为什么拦不住笔误？ | 只管"未跟踪文件"；已进过提交的加规则也拦不住、`git status` 里还不显示 → 要 `git rm -r --cached` + 改写未 push 的提交 |
| 数字为什么会写错？ | **多跑投票防的是随机误差，照抄混淆矩阵防的是人为笔误**；唯一解法是"文档数字 ↔ `run_log.txt` 逐行对账" + 机器校验 F1↔矩阵自洽 |

## 十、面试一句话速查（用概率语言讲）

| 讲什么 | 概率语言版 |
|---|---|
| **优化** | 优化 = 在**固定评测集**上做**受控实验**（只改一个变量 → 看指标变化）；"提升 X 个百分点" = 两个**统计估计之差** |
| **评测** | 检索命中率 = **Recall@K**；防幻觉 F1 = **混淆矩阵口径**；一致率 = **重复实验的众数占比**；n=20 → CI≈±0.22 |
| **偏差-方差** | 判据过严 = 尺子的**系统性偏差**；单次抖动 = **方差**；合成数据套模板 = **高偏差（欠拟合）**；背评测题 = **过拟合（高方差）** |
| **检索优化** | TOP_K 4→8 = 在**排序名次**上做文章（期望段回到窗口内）；前缀的效应与 k **有交互**（排名位移 1 名撞窗口边界） |
| **HyDE** | 用"假设答案"当查询 = 提升**对齐**，但它**不区分"资料里到底有没有答案"** → 帮 in、害 out |
| **防幻觉** | 三层：检索层保证资料进上下文 / 生成层模板约束 + 拒答出口 / 交付层引文白名单；三层都治不了**误读型幻觉** |
| **真实 vs 合成** | 一次**拆变量**：把"数量"对齐（201+99=300）后差距仍在 ⇒ 主因是**分布不匹配**，不是数量；**相关 ≠ 因果** |
| **为什么选 RAG** | 实测回答：原模型在检索层一样的情况下 F1 0.947 > 微调 0.824 ⇒ **知识来自检索层**，微调管风格、RAG 管事实 |
| **数字可信性** | 唯一来源 `run_log.txt` → 机器抄录 + F1↔矩阵自洽校验 → 定稿数字表 → 所有对外文字；**负结果照写** |

**30 秒开场白（可直接用）**：
> "我是数学（概率统计）背景，能真正用概率语言理解大模型。第四周我把机器人领域 RAG 问答项目从'跑通了流程'整改成'**能被别人使用、有前后对比、数据真实**'的形态：**同一套 20 题固定评测集**上，检索命中率从 **20% 提到 40%**、防幻觉 F1 从 **0.667 提到 0.824**，**每一步单独重跑、贡献可拆解**；数据侧把 300 条合成整改成 **201 条可追溯真实数据**；并且我**主动拆变量、把两轮逆预期结果（真实数据不涨分、原模型优于微调）当成主结论写进报告**——因为我报的是跑出来的数，不是想要的数。"
