### 1.2 全周知识链条（一段话串讲，用概率语言）

Transformer = **翻译/生成机**：词先进 `Embedding`（词→数字向量）加 `位置编码`（给词编座位号），再进 `Encoder`（阅读理解部）并行读完整个句子，每个词带上"上下文信息"的表示；`Decoder`（写作部）逐词生成，每步只看到已生成的词，最后 `Linear + Softmax` 输出**下一个词的概率分布**。

注意力 = **对 Value 的加权平均**：Q（想查什么）问，K（提供什么主题）答，相似度经 `softmax` 变成概率分布当权重，再对 V（提供什么内容）加权——每一步都在算一张**转移概率矩阵**（每行和为 1）。多头 = 多组 Q/K/V 并行 = 同时算好几张转移概率矩阵，每组关注一种关系。位置编码 = 用不同频率的 sin/cos 给每个词编唯一"座位号"（频率指纹），因为注意力**不分先后**。

层的标准零件三件套：`残差连接`（恒等映射的高速公路）、`LayerNorm`（给每层数据算标准分）、`FFN`（每个词独立的非线性思考）。预训练模型 = 学出语言先验的通用底座；微调 = 在底座上继续训练定向到任务；LoRA = 冻结底座、只训练低秩增量 B·A——用不到 1% 的参数完成微调。

> 按主题分 7 个模块。每题给：**你该说的核心答案** + **[数学加分]** 概率/统计视角。先自己开口讲一遍，再看参考答案。

### 模块 A：Transformer 整体结构

**Q1. 简单讲讲 Transformer 的整体结构？**
> Transformer 由 Encoder（编码器）和 Decoder（解码器）两部分组成，各自堆叠 N 层（原论文 N=6）。输入词先过 Embedding（把词变成数字向量），加上位置编码后进入 Encoder；Encoder 并行读完整句，输出每个词"理解上下文之后"的表示；Decoder 逐词生成，内部有带掩码的注意力（只能看到已生成的词）、对 Encoder 输出的交叉注意力，以及前馈网络；最后经过 Linear + Softmax 输出下一个词的概率分布。
> [数学加分] 可以补一句：整个模型的每一步输出都是一个概率分布 `P(下一个词 | 上文)`，这正好是概率论里的条件分布。

**Q2. Encoder 和 Decoder 的区别？**
> Encoder 是"读"：并行处理整句，每个词都能看到整句其他所有词（双向）；Decoder 是"写"：逐词生成，每步只能看到自己已经生成的词（单向，靠掩码 mask 实现右移一位），并且还会再和 Encoder 的输出做一次交叉注意力，去"参考"输入句子的信息。
> [数学加分] Encoder 的注意力权重是"整句范围内"的信息收集；Decoder 的掩码注意力相当于给"未来词"的概率设成 0——这很像条件概率里"只用过去预测未来"的因果结构。

**Q3. 为什么 Decoder 要带掩码（mask）？**
> 防止 Decoder 在预测第 t 个词时偷看到第 t 个词之后的内容。生成是逐词往右推进的：第 t 步只能依赖 1~t-1 个已生成的词。如果不加掩码，训练时模型会"作弊"——答案就在输入里，就学不会真正的生成。
> [数学加分] 掩码 = 把未来位置的注意力权重强制设为 0 再归一化，本质是"截断信息流"，对应因果性/条件分布的时间顺序。

**Q4. 模型的输出为什么叫"下一个词的概率分布"？**
> 最后一层 Linear 先把向量算成每个候选词的"分数"（logits），再经过 softmax 归一化成一个概率分布，每个词对应一个 0~1 的概率、所有词加起来为 1。生成文本 = 从概率分布里取最大（贪心）或按概率抽样。
> [数学加分] 对数学专业来说这非常自然：softmax 本质就是把实数的 logits 变成合法的概率分布；温度 temperature 可以理解为对分布"熵"的调节——温度高分布更均匀、输出更多样。

**Q5. 数据在 Transformer 里是怎么流动的？**
> `词 → Embedding → + 位置编码 → Encoder（N 层）→ Decoder（N 层）→ Linear → Softmax → 概率分布`。中间每一层（Encoder/Decoder）只改变表示的内容、不改变张量形状：`(seq_len, batch, d_model)` 进、`(seq_len, batch, d_model)` 出，直到最后的 Linear 才把维度压到词表大小。

### 模块 B：注意力机制（本周最核心，务必讲顺）

**Q6. Q、K、V 分别是什么？**
> Q（Query）="我想查什么"，拿去和所有 K 比对；K（Key）="我能提供什么主题"，被 Q 比对；V（Value）="我能提供什么内容"，是被加权平均的对象。一句话：**Q 问、K 答、V 给**。Q/K 决定"该关注谁"，V 决定"从被关注者那里拿走什么内容"。

**Q7. 自注意力是怎么计算的？**
> 三步走：① `scores = Q·Kᵀ/√d`：Q 和所有 K 做点积算相似度，除以 √d 做缩放；② `weights = softmax(scores)`：把分数归一化成权重（概率分布）；③ 输出 = `weights·V`：按权重对 V 做加权平均，得到融合了上下文的新表示。所谓"自"注意力，就是 Q、K、V 都来自同一条句子（句内互相关注）。
> [数学加分] 用矩阵形式看：这一层做的是 `softmax(QKᵀ/√d)·V`，就是一次"加权平均"，权重由相似度分布决定。

**Q8. 为什么注意力要除以 √d？（高频，数学背景加分点）**
> 因为 Q 和 K 是 d 维向量，做点积相当于 d 个分量的乘积求和。假设各分量独立且方差接近 1，那么 d 个分量求和的方差 ≈ d（方差的可加性）；除以 √d 之后方差回到约 1，防止分数过大。分数过大 → softmax 会退化成一冷一热的 "one-hot" 分布 → 梯度消失，学不动。
> [数学加分] 这正是概率统计里的方差标准化：`(和 - 期望)/标准差` 里的标准差就是 √d。这句话一出来，"为什么数学背景适合算法岗"就不用多解释了。

**Q9. 为什么用 softmax 而不用别的归一化？**
> softmax 输出天然是一个合法的概率分布：非负、和为 1；同时它平滑可导，且能保留"相对大小"——大的分数仍占主导，但不会像 argmax 那样不可导、一刀切。它跟概率模型的联系最直接，所以成为标配。

**Q10. 为什么说注意力权重矩阵是一张"转移概率矩阵"？**
> 注意力权重矩阵是方阵、每格在 0~1 之间、每行和为 1——和马尔可夫链的转移概率矩阵长得一模一样。第 i 行表示"词 i 从各个词那里收集信息的比例"。我亲手算过一张 3×3 的：猫[0.576 0.212 0.212] 每行和为 1。
> [数学加分·面试话术] "每一步都在算一张转移概率矩阵：softmax 保证每行是概率分布，注意力输出就是按这个分布对 Value 加权平均——本质上是一个'信息收集'的概率过程，和我学的概率统计是同一套语言。"

**Q11. 自注意力（Self-Attention）和普通注意力/交叉注意力有什么区别？**
> 区别在 Q/K/V 的来源：自注意力的 Q、K、V 都来自同一条序列（句内互相关注）；交叉注意力（如 RAG 里）K/V 来自"查到的文档"、Q 来自"我的问题"，是两个不同来源做信息交换。第一周学的自注意力是基础，第二周 RAG 的交叉注意力就是"文档当 K/V、问题当 Q"。

**Q12. 注意力机制的计算复杂度？**（可能被追问，会一点即可）
> 一次注意力要算 `n×n` 的相似度矩阵（n 是序列长度），所以复杂度是 O(n²·d)。这也是长文本处理费算力的原因之一。第一周只要求知道"有这回事"，进阶的稀疏注意力/FlashAttention 放到后续八股整理。

### 模块 C：多头注意力

**Q13. 为什么需要多头注意力？**
> 一句话里同时存在多种关系（语法搭配、指代、远近关系……），单头注意力只有一组 Q/K/V，一次只能关注一种关系，忙不过来。多头 = 多组 Q/K/V 并行，让模型同时从多个"视角"看同一句话。
> [数学加分] 多头 = 同时算好几张转移概率矩阵：每个头一张，代表一种关注视角。我亲手验证过：2 个头时，头 1（看身份）近似对角矩阵，头 2（看动物类别）让"猫""狗"互相关注——同一句话两个头给出两张完全不同的转移概率矩阵。

**Q14. 多头注意力具体怎么做？**
> 三步：① 分头：把 Q/K/V 按维度切成 num_heads 组，每组维度 = d_model ÷ num_heads；② 并行：每个头独立做一遍自注意力三步走；③ 并头：把所有头的输出按列拼接回 d_model 维。代码里分头是切列 `Q[:, h*head_dim:(h+1)*head_dim]`，并头是 `np.concatenate(heads, axis=1)`。

**Q15. 每个头关注的东西一样吗？**
> 不一样，是训练中自动分化的——有的头关注语法、有的关注指代、有的关注位置远近，没有人手动指定。这是模型自己"涌现"出来的分工。

**Q16. 你手写过注意力，和官方实现对比过吗？**（问项目/代码）
> 我在第一周手写了一个多头注意力，并用 `torch.nn.MultiheadAttention` 和它对答案，最大误差只有 5e-07——证明手写逻辑和官方实现是同一件事，官方只是封装好了 + 用训练学出来的 W。我会写公式、会看形状、会对答案，不是只会调包。

### 模块 D：位置编码

**Q17. 为什么需要位置编码？**
> 因为注意力**不分先后**：把句子打乱顺序，注意力输出只会跟着乱、模型察觉不到顺序变了。于是"我爱你"和"你爱我"在模型眼里可能被当成同一句。要让模型知道词序，必须显式把位置信息喂进去。
> [数学加分] 用概率语言说：注意力对输入的排列是"交换对称"的（置换后输出只跟着换位置），缺少顺序信息就学不到"谁先谁后"这种依赖。

**Q18. 位置编码长什么样？是加还是拼？**
> 原版用不同频率的 sin/cos 组合：偶数维 `sin(pos/10000^(2i/d_model))`、奇数维 `cos(...)`，每个位置得到一个唯一向量，称为"频率指纹"（和信号处理/傅里叶分解同源）。它**加**在词向量上（不是拼接）。Qwen 等新模型用的是 RoPE（旋转位置编码），目的相同、实现不同。

**Q19. 如果关掉位置编码会怎样？**
> 我用 seq2seq demo 做过灵魂实验：把位置编码关掉，数字倒序任务 loss 几乎不降——模型根本学不会"倒序"这种依赖顺序的任务。反过来也验证了位置编码必不可少。

### 模块 E：结构图三件套（残差 / LayerNorm / FFN）

**Q20. 残差连接（Residual Connection）的作用？**
> 公式 `x + 子层(x)`：把子层的输出和输入原样相加。作用有二：① 给梯度留一条"直通的高速公路"，信息能从最后一层沿捷径传回最前面，解决深层网络梯度消失；② 即使某些层学不到东西，模型也至少不会变差（恒等映射保底）。
> [数学加分] `x` 就是恒等映射，每一层 = 恒等映射 + 小扰动，这是我在概念笔记里的总结。残差可以理解为让每层只学"差值/变化量"。

**Q21. LayerNorm 的作用？**
> 对每个词的特征向量做归一化：`(x - 均值)/标准差 × γ + β`，让数值均值为 0、方差为 1，再乘可学习缩放 γ、加可学习偏移 β。作用：数值稳定、训练更快更不容易发散。
> [数学加分] 这就是统计学里的**数据标准化**（算标准分）——和考试标准分是同一个操作：全班均分 70 标准差 10，你考 80 就是 +1 个标准差。一句话：给每一层的数据算"标准分"。

**Q22. FFN（前馈网络）的作用？**
> 公式 `FFN(x) = W2·ReLU(W1·x + b1) + b2`：两层线性夹一个 ReLU 激活。作用：注意力负责让词与词"交换信息"（开会），FFN 负责每个位置独立地"加工信息"（开完会各自回工位写总结）。
> [数学加分] FFN = 对每个词做一次非线性变换；两层线性 + 非线性激活能逼近任意函数（万能近似），给模型提供表达能力——否则多层线性叠起来还是线性。

**Q23. 标准的"子层包装"顺序是什么？**
> `子层 → 残差加法 → LayerNorm`，即 Pre-LN：每个子层（注意力/FFN）外面包一层残差 + LayerNorm。这也是 Qwen 等现代模型沿用的结构。

### 模块 F：预训练 / 微调 / LoRA（Day5 认知，第三周已实战）

**Q24. 预训练、微调、LoRA 的区别？**（面试一句话版）
> 预训练 = 在海量通用数据上学出"语言先验"的通用底座（Qwen/GPT/Llama 都是）；微调 = 在底座上用任务数据继续训练，把通用能力定向到我的任务；LoRA = 冻结底座权重，只训练一个低秩增量 B·A（r 很小），以不到 1% 的参数代价完成微调，省显存还保留底座知识。

**Q25. 什么是"灾难性遗忘"？**
> 完整微调（所有参数都继续训练）在学会新任务时，会把底座原来学好的通用/旧任务能力冲掉。我亲手验证过：任务 A 的误差从 0 涨到 3.93。LoRA 的价值正在于此——它只调低秩增量、不动底座，保留旧知识。

**Q26. 为什么微调的改动量 ΔW 是低秩的？LoRA 凭什么能用 B·A 近似？**
> ΔW = 微调后权重 - 预训练权重。真实微调中学到的改动只集中在少数几个"方向"上，绝大多数方向几乎不动——表现在矩阵上就是奇异值只有少数几个大的、后面迅速衰减（我验证过：512×512 的 ΔW 前 16 个奇异值大、之后全是 0）。所以可以用低秩乘积 B·A（B 是 d×r、A 是 r×d，r << d）近似，r=16 时近似误差仅 1.63e-15，几乎无损。
> [数学加分] 这正是 SVD/低秩近似的应用——可以延伸提一句 Eckart–Young 定理（在固定秩下，SVD 截断是最优低秩近似），这是线性代数的本行内容。

**Q27. LoRA 为什么省显存？给个数。**
> 参数账：一个 d×d 的权重矩阵，全量微调要训 d² 个参数，LoRA 只训 2dr 个（B 和 A）。d=3584、r=8 时从 12,845,056 → 57,344，节省 99.55%。对 Qwen2.5-7B：全模型 76.1 亿参数，LoRA 只训练 q/k/v/o 的增量约 642 万个 = 全模型的 0.084%。另外，训练一个参数要存"参数 + 梯度 + 优化器状态"约 3 份，训练量小 3 个数量级，6G 显存才跑得动。

**Q28. LoRA 的秩 r 大小怎么影响效果？**
> r 越小，低秩增量越"温和"：保留旧知识多、学新任务少；r 越大越接近完整微调：新任务学得好、但忘得也多（越接近灾难性遗忘）。实际中 r=8~16 是常见取值。选 r 本质是在"学新任务"和"保留底座能力"之间做权衡。

### 模块 G：Qwen 部署与量化（环境相关面试）

**Q29. 你的显卡只有 6G 显存，怎么本地跑 Qwen？**
> 用**量化**：把参数从 16/32 位压到 4/8 位来省显存。我第一周跑了算账脚本定方案：Qwen2.5-3B-Instruct + 4bit（NF4 格式，bitsandbytes 实现）≈ 3.0GB，6G 显存舒适运行；7B 4bit ≈ 5.6GB 需要 8G 显卡；7B fp16 约 15GB，6G 根本装不下，所以第一步选 3B 4bit。
> [数学加分] 量化 ≈ 用更少比特去存参数，会牺牲一点精度换来能跑；可以联系"信息压缩"来理解，面试不用深。

**Q30. `torch.cuda.is_available()` 是干嘛的？你装环境的坑有哪些？**
> 它是验证 PyTorch 能否调用 GPU 的开关，第一周跑出 True 就说明环境 OK。踩过的坑：① conda 服务条款没接受，创建环境被拒 → `conda tos accept`；② 新版 transformers 要求 torch≥2.6，但显卡驱动最高只支持 cu121（torch 2.5.1）→ 换 safetensors 格式迷你模型绕开；③ VS Code 的 PowerShell 里 `conda activate` 不生效 → `conda init powershell` + 重开 VS Code。经验：**用 Anaconda 虚拟环境隔离，坏了重开不影响系统。**

**Q31. bitsandbytes 是什么？NF4 呢？**
> bitsandbytes = 一个专门做低精度量化的库；NF4（NormalFloat4）= 它提供的一种 4bit 量化格式，专为神经网络参数分布设计、效果好，是 4bit 加载的推荐格式。

### 模块 H：Python/刷题中的数学谈资（零散时间素材）

**Q32. 你第一周刷的题里，哪道能体现数学思维？（拿 169. 多数元素举例）**
> 多数元素 = 找数组中出现次数超过一半的数。我用摩尔投票（Boyer-Moore）：两个不同的数互相抵消，因为多数元素超过一半，所以"每遇到一个不同数就抵消一次它也抵消不完，最后剩下的必胜"。用概率直觉讲就是——占比超过 1/2 的阵营，无论怎么配对抵消都剩得下。O(n) 时间、O(1) 空间。

**Q33. 你有独立跑通代码验证模型原理的经历吗？**（讲项目能力）
> 有。第一周我从零手写了多头注意力和官方对答案（误差 5e-07）、用 numpy 手算 3×3 注意力权重矩阵、还训练了一个 seq2seq 数字倒序小模型（loss 收敛到 0、新样本 10/10 全对）。我是从公式和矩阵层面理解这些机制的，不是只会调用 API。
