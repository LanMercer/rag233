### 1.4 看懂脚本的 3 段（跟着代码走一遍）

打开 `positional_encoding_demo.py`，它做 3 件事：

**第 1 段：用 sin/cos 公式生成位置编码**

```python
pe[:, 0::2] = np.sin(position * div_term)   # 偶数维度用 sin
pe[:, 1::2] = np.cos(position * div_term)   # 奇数维度用 cos
```

- `div_term` 是**一组递减的频率**（不同维度用不同频率）——这就是视频里"不同位置不同波形"的代码来源；
- 偶数维用 sin、奇数维用 cos，合起来每个位置就有了唯一编码（不需要记住这个公式，知道"用不同频率的正弦余弦组合出唯一座位号"就够了）。

**第 2 段：热力图可视化**——把 20 个位置的编码画成热力图，存成 PNG。

**第 3 段：关键实验**——用 3 个词"我 爱 你"，分别算**不加位置信息**和**加位置信息**两种情况下，"我爱你"和"你爱我"的注意力输出，对比它们是否一样。**结果请亲眼确认**：不加位置信息 → 两个句子输出完全一样（只是换了顺序）；加了位置信息 → 不一样了。这就是位置编码存在的意义。

> 💡 第 3 段的实验原理（可看可不看）：注意力是"排列等变"的——打乱输入顺序，输出只是跟着打乱，模型本身**察觉不到顺序变化**。只有把"第几个"这个信息显式加进向量，模型才能区分顺序。

### 2.1 视频 4 讲了什么（先剧透）

视频 4 讲的是**多头注意力（Multi-Head Attention）**。单头注意力的局限是：**一组 Q/K/V 只能关注一种关系**。但一句话里同时存在好几种关系——词性搭配、指代关系、远近关系……一个头忙不过来。

多头注意力的做法（一句话版）：

> **把 Q/K/V 切分成好几组，每组独立算一遍注意力，最后把结果拼起来。** 每组头关注一种关系 = 多个"视角"并行。



### 2.2 三个关键问题（看完视频要能答）


| 问题           | 答案（用自己的话写下来）                     |
| ------------ | -------------------------------- |
| 多头和单头比，多了什么？ | 多组 Q/K/V 并行，每组的维度更小（总维度不变，分给每个头） |
| 每个头关注的东西一样吗？ | 不一样，训练中自动分化：有的头看词性、有的看指代、有的看位置远近 |
| 多头的结果怎么合并？   | 每个头输出拼（concat）起来，再乘一个矩阵变回原维度     |




### 2.3 用你的数学背景：多头 = 多张"转移概率矩阵"（今天第 2 句要背的话）

> **多头注意力 = 同时算好几张不同的"转移概率矩阵"（每张代表一种关注视角），再把它们的结果拼起来。**

你在 Day 3 学会了"一张注意力权重矩阵 = 一张转移概率矩阵"。今天升级：**几个头 = 几张转移概率矩阵同时算**。视频里那些"每个头关注不同区域"的动画，翻译成数学语言就是"不同的转移矩阵"。

### 3.2 逐段看懂脚本（跟着代码走一遍）

**第 1 段：造输入**——3 个词、6 维向量。前 3 维是"身份"（one-hot，猫/追/狗），后 3 维是"类别"（猫和狗都带"动物"、追带"动作"）。这是为了让两个头**有东西可看**：头 1 只取前 3 维就能区分"是谁"，头 2 只取"类别"维度就能看出"猫和狗是一伙的"。

**第 2 段：分头（关键！）**

```python
head_dim = d_model // num_heads      # 6 // 2 = 3，每头 3 维
qh = Q[:, h*head_dim : (h+1)*head_dim]   # 切第 h 组的 3 个维度
```

- "分头"不是复制数据，而是**切维度**：6 维向量切两半，头 1 用前 3 维、头 2 用后 3 维；
- 这就是"总维度不变、分给每个头"在代码里的真面目。

**第 3 段：每个头独立算一遍 Day 3 的三步走**

```python
scores = qh @ kh.T / np.sqrt(head_dim)   # 相似度 + 缩放（Day 3 学过的 /√d）
weights = softmax(scores)                # 每行和为 1
head_out = weights @ vh                  # 加权平均
```

和 Day 3 的手算**完全同一个流程**，只是换成了"每个头各自算一遍"。

**第 4 段：并头**

```python
out = np.concatenate(heads, axis=1)      # (3,3)+(3,3) → (3,6)
```

两个头的结果左右拼起来，恢复成 6 维。

**第 5 段：和官方对答案**

```python
mha = nn.MultiheadAttention(d_model, num_heads, ...)
out_t = mha(X_t, X_t, X_t)               # PyTorch 现成的多头注意力
```

把同一份输入喂给 PyTorch 官方模块，和你的手写结果对比，**最大误差只有小数点后 6 位**——证明你写的和官方做的是**同一件事**，只是官方用了训练学出来的 W 矩阵、还封装成了黑盒。

> 面试谈资：当你能说出"多头 = 切维度分头、每头独立算注意力、再拼接"时，你已经比 90% 只会调 `nn.MultiheadAttention` 的人更懂它了。

（先解释一下这条命令在干嘛：`inspect` = Python 自带的"偷看工具"，能直接读出某个东西的源码；`nn.Transformer` = PyTorch 里现成的 Transformer 模型，你 Day 4 的脚本全在用。整句话的意思就是：把 `nn.Transformer` 的源码打印出来。）

**你会看到**：一长串源码，开头是 `class Transformer(Module):`。**注意核心结构不在最后几行，而是在** `def __init__(` **之后大约第 100 行的地方**（`__init__` = 模型的"出生构造"函数，建模型时先执行它）。往上/下滚动找到这两行——它被 `self.encoder` 和 `self.decoder` 开头的语句拼起来，**核心结构就是这两行**：

```
self.encoder = TransformerEncoder(encoder_layer, num_layers)   # 编码器：N 层
self.decoder = TransformerDecoder(decoder_layer, num_layers)   # 解码器：N 层
```

这证明官方 Transformer = **编码器 + 解码器两大件**，每一件又是"用同一个 layer 复制 N 份"叠出来的。

然后**再输入第 2 条命令**，才能看到每一层里面是什么（`TransformerEncoderLayer` = 编码器"一层"的完整定义，它是和 `Transformer` 并列的另一个类，必须单独查）：

```
python -c "import inspect, torch.nn as nn; print(inspect.getsource(nn.TransformerEncoderLayer))"
```

在输出里往下翻到 `self.self_attn = MultiheadAttention(...)` 和 `self.linear1 / self.linear2`、`self.norm1 / self.norm2` 这几行，你会发现**每一层里面**就是 Day 2 结构图上的那 4 个小方块：

```
TransformerEncoderLayer（编码器的每一层）:
    多头注意力 (self.self_attn)  →  残差 + LayerNorm (self.norm1)
    前馈网络 (self.linear1/linear2) →  残差 + LayerNorm (self.norm2)
```

> 💡 如果你在源码里看到 `Add & Norm` 的图样，实际代码里它是两行：一行是残差 `x = x + 子层输出`，一行是 `LayerNorm`（归一化）。Day 5 补结构图时会细讲。

这正是你在 Day 2 结构图上画的"方框里的 4 个小方块"——**今天你亲眼看到了它们的代码版本**。

**你会看到**（关键输出长这样）：

```
===== 1. 构造一个 6 维的小 Transformer（2 层）=====

===== 2. 喂入假数据并逐层打印形状 =====
源句子 src 的形状 : (5, 3)     ← (序列长度=5, 批量=3)
目标句子 tgt 形状 : (4, 3)     ← (序列长度=4, 批量=3)
词嵌入之后      : (5, 3, 6)     ← (5, 3, 6) = 序列长度×批量×维度
编码器输出      : (5, 3, 6)     ← (5, 3, 6)，长度和维度都不变
解码器输出      : (4, 3, 6)     ← (4, 3, 6)，跟着目标串长度走
输出层(Linear)  : (4, 3, 12)    ← (4, 3, 12) = 每个位置 12 个词的分数
softmax 之后    : (4, 3, 12)    ← 每行和为 1，就是概率分布
```

**先认识三个词：序列长度 / 批量 / 维度**（这是看懂所有形状的基础，2 分钟）

上面反复出现的 `(序列长度, 批量, 维度)` 三个词，分别代表：


| 词        | 英文      | 大白话                                                         | 对应 `(5, 3, 6)` 里的 |
| -------- | ------- | ----------------------------------------------------------- | ----------------- |
| **序列长度** | seq_len | **一句话里有几个词**（机器翻译里是"源句有几个词/目标句有几个词"）                        | `5`               |
| **批量**   | batch   | **一次同时喂给模型几个句子**（GPU 擅长并行算，一次喂一批比一次喂一个快得多）                  | `3`               |
| **维度**   | d_model | **每个词用一串多长的数字表示**（Day 2 的 Embedding = 词 → 一串数字，这串数字有多长就是维度） | `6`               |


把三个词连起来看一个具体例子：

> 假设模型**同时读 3 个句子**（批量=3），每句话 **5 个词**（序列长度=5），每个词用一个 **6 维向量**表示（维度=6）——那么整个输入就是形状 `(5, 3, 6)` 的一个"数据块"。

生活类比（班级点名册）：**批量** = 这次点名叫几个班的人来；**序列长度** = 每个班来了几个人；**维度** = 每个人的信息卡片上登记了几项内容（身高、体重、视力……）。一张"数据块" = 把一批班的花名册叠在一起。

所以脚本里那行输出 `(5, 3, 6) = 序列长度×批量×维度`，读出来的意思就是：**"5 个词 × 3 个句子 × 每词 6 个数字"**。

### 4.3 看懂形状的 3 条规律（重要，背下来）


| 张量                 | 形状（batch_first=False）          | 大白话                 |
| ------------------ | ------------------------------ | ------------------- |
| 词嵌入 / 位置编码之后       | `(seq_len, batch, d_model)`    | "几个词 × 几个句子 × 每词几维" |
| Encoder 输出（memory） | `(src_len, batch, d_model)`    | 编码器只改内容，不改形状        |
| Decoder 输出         | `(tgt_len, batch, d_model)`    | 解码器输出目标语言每个位置       |
| 最终输出               | `(tgt_len, batch, vocab_size)` | 每个位置是"下一个词的得分/概率分布" |


> **规律 1：Transformer 里"序列长度"永远在第 0 维、批量在第 1 维**（PyTorch 默认 `batch_first=False`）——这和 numpy 里"矩阵行×列"的直觉不一样，习惯它。
> **规律 2：Encoder/Decoder 只做"内容变换"，不改变序列长度和维度**——形状就是 `(长度, 批量, 维度)` 进、`(长度, 批量, 维度)` 出。
> **规律 3：模型最后一步 = 把"每维分数"变成"每个词的分数"**——`Linear` 把 `d_model` 维压到 `vocab_size` 维，配合 softmax 就是"下一个词的概率分布"（呼应 Day 2 那句"输出 = 概率分布"）。



### ✅ 第 4 步验收标准

1. 能说出官方 Transformer = Encoder + Decoder，每层 = 多头注意力 + 前馈（各带残差/LayerNorm）；
2. 跑通 `transformer_shape_demo.py`，能照着终端输出说出"Encoder 进 5×3×6 出 5×3×6"这类形状；
3. 能说出序列长度 / 批量 / 维度分别代表什么（一句话里有几个词 / 一次喂几个句子 / 每个词用几个数字）；
4. 记住 3 条规律（尤其"序列长度在第 0 维"）。

### 5.2 先回答一个问题：这个 demo 是机器学习 / 深度学习吗？（2 分钟）

**是，而且是标准得不能再标准的深度学习流程。** 先拆开两个词：


| 名词                         | 大白话                                                   |
| -------------------------- | ----------------------------------------------------- |
| **机器学习**（Machine Learning） | 让计算机从**数据**里自动学规律，而不是程序员手写规则（比如不写"if 第一位是1就输出1"这种死规则） |
| **深度学习**（Deep Learning）    | 机器学习的一个分支，用**神经网络**（很多层可学习的函数叠起来）来学，大模型就是深度学习的产物      |


判断一段代码是不是机器学习/深度学习，就看它有没有"五件套"。**这个 demo 五件套一个不缺**：


| 五件套        | 本 demo 里的对应物                                | 一句话作用              |
| ---------- | ------------------------------------------- | ------------------ |
| 1. 模型      | `Seq2Seq`（Embedding + Transformer + Linear） | 神经网络：把输入变成预测       |
| 2. 数据      | `make_batch` 随机生成的"数字串 → 倒序"样本对             | 学习的"课本"            |
| 3. 损失函数    | `nn.CrossEntropyLoss`                       | 一把"打分尺"：预测离正确答案差多远 |
| 4. 优化器     | `torch.optim.Adam`                          | 按分数调整模型参数，让分数越来越低  |
| 5. 训练 + 测试 | 训练循环 + 新样本测试                                | 调好参数 + 验证学会没有      |


> 一句话：**训练 = 让模型自己找到"把数字倒过来"的规律；测试 = 验证它真的学会了而不是死记硬背。** 你以后跑的大模型（Qwen、GPT）就是把这套流程放大几百万倍。



### 5.3 它如何训练？—— 一个循环四步走（10 分钟，对应 `train_one_batch` 函数）

训练就是**把一个循环重复几千次**。每次处理"一批"样本（`BATCH_SIZE = 128`，即 128 个"数字串→倒序"样本），做 4 件事：

```
① 造一批数据（make_batch）      → 拿 128 个新样本当"题目+标准答案"
② 前向传播（喂给模型）           → 模型读题、吐出一个"预测分布"（猜：下一位是几）
                                 （训练时用"教师强制"：解码器喂的是真实目标串，
                                   让模型只专心练"预测下一个数字"这一件事）
③ 算损失（CrossEntropyLoss）     → 拿打分尺量：预测分布 和 标准答案 差多远 → 一个数字 loss
④ 反向传播 + 更新（backward+step）→ 算出每个参数该往哪调（梯度），
                                 Adam 按梯度把参数调准一点点
```

- `loss.backward()` = 反向传播：从"最终分数"倒着算回去，得出**每个参数**该往哪个方向调多少（这就是"学习"的数学本质，利用你学过的链式法则求导）；
- `optimizer.step()` = 真正动手改参数（Adam = 一种聪明的调参算法，会自适应每次调的步子大小）；
- 重复循环：`80 个 epoch × 每 epoch 40 批 = 3200 次调整`。`epoch` = 把所有"题目"从头到尾过一遍的次数。

**你怎么看出它学会了？** 看每 10 个 epoch 打印的那一行：`loss` 从 **1.856 一路降到 0.000**，示例输出从 `[X]` 全部变成 `[OK]`——loss 越小 = 模型猜得越准 = 参数调得越到位。

### 5.4 它如何测试？—— 用没见过的新样本（10 分钟，对应 `generate` 函数）

训练完，模型参数**不再更新**，进入测试阶段：

```
① model.eval() + @torch.no_grad()
       → 关掉 dropout（训练时的随机扰动）、关掉梯度记录，让输出稳定可复现
② 喂一个"从没见过"的输入（make_sample 新生成）
       → 模型自己从"起始符"开始逐字生成：
       贪心解码 = 每步从"下一个字符的概率分布"里挑概率最大的字符，
       拼到已生成的结果后面，再喂回模型猜下一位，直到输出"结束符"
③ 和标准答案比对 → 数对了几个 → 正确率 10/10
```

**为什么要用"没见过"的样本测？** 这很关键：如果只测背过的题，分数再高也没意义——可能只是死记硬背。测试用的是**新随机样本**，模型必须靠"真学会了倒序规律"才能答对，这正是机器学习和死记硬背的本质区别（学的是规律，不是答案本身）。

### 5.5 看懂这个 demo 的 4 段（跟着代码走一遍）

**第 1 段：任务与数据**——每次随机生成 2~8 位数字，目标 = 倒序。选"倒序"这个任务有讲究：**它必须靠位置信息才能做对**——不记住"第 1 位的数字要挪到最后"，模型根本学不会。所以这个 demo 是今天主题（位置编码）的活教材。

**第 2 段：模型 = 编码器 + 解码器（对照第 4 步的形状）**

```python
self.transformer = nn.Transformer(d_model=64, nhead=2,
    num_encoder_layers=2, num_decoder_layers=2, ...)
```

- `src`（源数字串）先进**编码器**，得到记忆 `memory`；
- `tgt`（目标串，从"起始符"开始）进**解码器**，参考 memory，逐步预测下一个数字；
- 训练时用"教师强制"（喂真实目标）；生成时用"贪心解码"（每步取概率最大的字符，喂回下一步）——这两种模式第 5 段代码会分别演示。

**第 3 段：训练循环**——即 5.3 节讲的"四步走"：造数据 → 前向传播 → 算 `CrossEntropyLoss` → `loss.backward()` + `optimizer.step()`。你不需要看懂梯度怎么算，只要看懂"loss 一路下降、示例输出越来越准"。

**第 4 段：生成函数（贪心解码，重点看，即 5.4 节测试用的那一套）**

```python
for step in range(max_gen):
    logits = model.step(...)            # 拿"已生成的部分"预测"下一个字符"
    next_id = logits.argmax(-1).item()  # 取概率最大的那个字符
    if next_id == EOS: break            # 遇到结束符就停
    dec_ids.append(next_id)
```

> 这就是大模型生成文本的**最简版本**：每步从"下一个词的概率分布"里挑最大的，拼上去，再继续。第 2 周调 `temperature` 时，你还会回到这个函数——`argmax` 换成"按概率抽样"就是采样生成。

今天刷题专题进入**哈希计数**（哈希表的另一个经典用法：数每个字符/元素出现多少次）。去 [https://leetcode.cn](https://leetcode.cn) 做：

1. **242. 有效的字母异位词**——判断两个字符串是否由相同的字母组成（字母相同、顺序不同）
2. **383. 赎金信**——判断杂志的字母能不能拼出勒索信（字母够不够用）

**思路提示（想 10 分钟后再看）：**

- **242 的思路**：用哈希表（Python 里就是 `dict` 或 `collections.Counter`）统计第一个字符串里每个字母出现次数，然后遍历第二个字符串逐个"消耗"，最后看有没有没消耗完的。**异位词 = 两个字符串的"字母计数表"完全一样**。
- **383 的思路**：和 242 几乎同一个套路——统计杂志的字母计数，再检查勒索信的每个字母够不够用。**能一眼看出"这俩题是一个模子"就是进步**，面试时这叫"举一反三"。

### B. Python 语法速查（今天补 2 个点：文件读写 + 异常处理）

为什么现在学？因为下周开始你要写"读文档、存结果"的脚本（RAG 就是读文件 + 处理），而模型推理时经常遇到"文件不存在""数据格式不对"这类错误——不会异常处理，脚本一崩就白跑。

**1. 文件读写（10 分钟学会）**

```python
# 写入文件："w" = 覆盖写，"a" = 追加写，encoding="utf-8" 保证中文不乱码
with open("我的笔记.txt", "w", encoding="utf-8") as f:
    f.write("今天学会了多头注意力\n")
    f.write("位置编码=给词编座位号\n")

# 读取文件："r" = 只读
with open("我的笔记.txt", "r", encoding="utf-8") as f:
    content = f.read()
print(content)
```

> `with open(...) as f:` 的意思是"用完了自动关闭文件"，**永远用它，别用裸的** `open/close`——这是 Python 老手的习惯。

**2. 异常处理（10 分钟学会）**

```python
try:
    n = int("abc")          # "abc" 转不成整数，会报 ValueError
except ValueError as e:     # 捕获这个错误，不让脚本崩掉
    print("转换失败:", e)
finally:                    # 无论有没有错，这段都会执行
    print("这一步总会执行")
```

> 大白话：`try` = 试试这段可能出错的操作；`except` = 出错就执行这里，程序不崩；`finally` = 收尾动作（比如关文件）。

> 小练习（顺手做）：写一个小脚本，读一个**不存在的文件**，用 `try/except FileNotFoundError` 捕获，打印"文件不存在，请检查路径"，而不是让程序报错崩溃。

> 推荐快速资料：廖雪峰 Python 教程（[https://liaoxuefeng.com/books/python/](https://liaoxuefeng.com/books/python/)），只读"文件读写"和"错误处理"两节，20 分钟搞定。

## 📎 附录一：要点导读（看完视频和代码后对照自查）



### 导读 1：多头注意力（对应第 2、3 步）

- **为什么需要多头**：一个头只能关注一种关系，一句话里关系很多，一个头忙不过来；
- **怎么做**：把 Q/K/V 按维度**切分成 num_heads 组**（每组维度 = d_model / num_heads）→ 每组独立算一遍注意力（Day 3 的三步走）→ 把结果**拼接**回原维度；
- **多头 = 多张"转移概率矩阵"**：每个头一张，代表一种关注视角；
- **官方代码**：`torch.nn.MultiheadAttention(embed_dim, num_heads)`，输入输出都是 `(seq_len, batch, d_model)`。



### 导读 2：位置编码（对应第 1 步）

- **为什么需要**：注意力不分先后，"我爱你"≠"你爱我"但模型看不出区别；
- **是什么**：给每个位置一个唯一编码，**加**在词向量上（不是拼接）；
- **代码长什么样**：偶数维用 sin、奇数维用 cos，不同维度用不同频率，每个位置得到唯一"频率指纹"；
- **新模型还用它吗**：Qwen 等新模型用 RoPE（旋转位置编码），目的相同、实现不同，本周不深入；
- **验证**：关掉位置编码 → 倒序任务学不会 → 位置编码必不可少。



### 导读 3：`torch.nn.Transformer` 结构（对应第 4 步）

```
Transformer
 ├─ Encoder（编码器，读）    = N 层 TransformerEncoderLayer
 │    └─ 每层 = 多头注意力 + Add&Norm + 前馈网络 + Add&Norm
 └─ Decoder（解码器，写）    = N 层 TransformerDecoderLayer
      └─ 每层 = 带掩码多头注意力 + Add&Norm + 多头注意力 + Add&Norm + 前馈 + Add&Norm
```

- 输入输出形状（`batch_first=False`）：一律 `(seq_len, batch, d_model)`；
- 最终 `Linear` 把 `d_model` 压到 `vocab_size`，配合 softmax = "下一个词的概率分布"。
