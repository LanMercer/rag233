## 第二部分 · Transformer 整体结构

| 部件 | 大白话 | 关键点 |
|---|---|---|
| Encoder（编码器） | 阅读理解部 | 整句并行读完，输出每个词"理解了上下文"的表示 |
| Decoder（解码器） | 写作部 | 逐词生成，每步只能看到已生成的词（右移一位） |
| Embedding（嵌入） | 词 → 数字向量 | 计算机只认数字 |
| 输出 | 下一个词的概率分布 | Linear 算分数 → Softmax 变概率 → 取最大/抽样 |

- Encoder 和 Decoder 都堆叠 **N 层**（原论文 N=6），层内结构相同。
- 数据流：`词 → Embedding → 位置编码 → Encoder → Decoder → Linear+Softmax → 概率分布`。
- 注意力在这个流里的具体计算环节：`scores = Q·Kᵀ/√d → softmax → ×V`（每层都有）。

## 第三部分 · 注意力机制（Day 2 + Day 3）

### 3.1 三个角色

- **Q（Query）** = 我想查什么 → 拿去和所有 K 比对
- **K（Key）** = 我能提供什么主题 → 被 Q 比对
- **V（Value）** = 我能提供什么内容 → 被加权平均

> 一句话：**Q 问，K 答，V 给。**

### 3.2 计算流程（三步走）

```
Q = X·Wq    K = X·Wk    V = X·Wv     （X = 词向量矩阵，W 为可学习的变换矩阵）
scores = Q·Kᵀ / √d                    （相似度 + 缩放）
weights = softmax(scores)             （每行归一化，每行和为 1）
输出 = weights · V                    （加权平均，融合上下文）
```

### 3.3 数学视角（差异化谈资）

- **softmax 输出 = 概率分布**（非负、和为 1）；
- **注意力权重矩阵 ≈ 转移概率矩阵**（每行和为 1、每格 0~1）——第 i 行 = 词 i 从各词收集信息的比例；
- **为什么除以 √d**：d 个独立分量乘积求和，方差 = d（方差可加性）；除以 √d 让方差回到 1，防止分数过大 → softmax 退化成 "one-hot" → 梯度消失；
- 点积相似度 ≈ 余弦相似度 × 向量长度（Q·K 同时包含"方向是否一致"和"长度"）；
- 自注意力 = Q、K、V 都来自同一条句子（句内互相关注）。

### 3.4 亲手算出来的例子（3 词 one-hot 词向量）

```
猫 [0.576 0.212 0.212]
追 [0.212 0.576 0.212]
狗 [0.212 0.212 0.576]
```

- 每行和为 1 → 每行是概率分布；
- 对角线最大 → 最关注自己（one-hot 只有自己和自己像）；
- **词向量改造实验**：给"猫""狗"加共享"动物"维度后，"猫""狗"对彼此的权重明显变大（0.212→0.468），"追"被忽略（0.212→0.063）→ 词向量承载语义，注意力自动聚焦同类词。

## 第四部分 · 多头注意力（Day 4）

### 4.1 为什么需要

- 单头注意力只能用一组 Q/K/V，**一次只能关注一种关系**；
- 一句话里同时有"词性搭配、指代关系、远近关系……"，一个头忙不过来。

### 4.2 怎么做（三步）

```
1. 分头：把 Q/K/V 按维度切成 num_heads 组（每组维度 = d_model ÷ num_heads）
2. 并行算：每个头独立算一遍三步走（Q·Kᵀ/√d → softmax → ×V）
3. 并头：把所有头的输出按列拼接，恢复成 d_model 维
```

- 代码里的分头：`Q[:, h*head_dim:(h+1)*head_dim]`（切列）
- 代码里的并头：`np.concatenate(heads, axis=1)`（拼列）

### 4.3 数学视角 + 亲手验证过的例子

- **多头 = 多张"转移概率矩阵"并行**：每个头一张，每行和为 1，代表一种关注视角；
- 亲手验证（2 头、6 维、3 词"猫/追/狗"）：
  - 头 1（看"身份"）→ 权重矩阵近似**对角矩阵**（每个词关注自己）；
  - 头 2（看"动物类别"）→ "猫""狗"互相关注（权重 ≈ 0.49），"追"被忽略；
  - 同一句输入，两个头给出**两张完全不同的转移概率矩阵**。
- 每个头关注的东西训练中自动分化（语法 / 指代 / 远近……）。
- **和官方对答案**：手写 vs `torch.nn.MultiheadAttention(embed_dim, num_heads)` 最大误差 **5e-07** → 做的是同一件事，官方只是封装 + 用训练学出来的 W。

## 第五部分 · 位置编码（Day 2 + Day 4）

### 5.1 为什么需要

- 注意力**不分先后**：打乱句子顺序，注意力输出只跟着乱，模型察觉不到顺序变化；
- "我爱你"和"你爱我"在模型眼里可能是同一句话。

### 5.2 是什么（代码形式）

```
偶数维: pe[pos, 2i]   = sin(pos / 10000^(2i/d_model))
奇数维: pe[pos, 2i+1] = cos(pos / 10000^(2i/d_model))
位置编码 = 不同频率的正弦/余弦组合，每个位置一个唯一向量
```

- 位置编码**加**在词向量上（不是拼接）；
- 可视化：`positional_encoding.png` 热力图——每一行是一个位置的"频率指纹"，互不相同。

### 5.3 数学视角 + 关键实验

- 不同维度用不同频率 → 每个位置得到唯一**"频率指纹"**（和信号处理 / 傅里叶分解同源）；
- **关键实验**：不加位置信息，"我爱你 / 你爱我"的注意力输出**完全一样**（只是顺序被换）；加上位置信息后**不一样了**；
- **灵魂实验**：把 seq2seq demo 的位置编码关掉 → **倒序任务 loss 几乎不降** → 位置编码必不可少。

## 第六部分 · torch.nn.Transformer 结构与张量形状（Day 4，代码级）

```
Transformer
 ├─ Encoder（读） = N 层 TransformerEncoderLayer
 │    每层：多头注意力 → Add&Norm → 前馈网络 → Add&Norm
 └─ Decoder（写） = N 层 TransformerDecoderLayer
      每层：带掩码多头注意力 → Add&Norm → 多头注意力 → Add&Norm → 前馈 → Add&Norm
```

- 张量形状（`batch_first=False`）：一律 `(序列长度, 批量, 维度)`；
- Encoder/Decoder 只改内容不改形状：`(长, 批, 维)` 进 → `(长, 批, 维)` 出；
- 最后 `Linear`：`d_model` 维 → `vocab_size` 维，配合 softmax = "下一个词的概率分布"；
- 训练四步走：造一批数据 → 前向算 loss → `loss.backward()` 反向传播（链式法则）→ `optimizer.step()` 改参数（Adam）；
- 实测：seq2seq 数字倒序 demo 80 epoch × 40 批 = 3200 次调整，loss 1.856 → 0.000，测试 10/10。

## 第七部分 · 结构图三件套（Day 5）

| 组件 | 公式 | 作用 | 一句话 |
|---|---|---|---|
| 残差连接 | `x + 子层(x)` | 防梯度消失、保底不更差 | 高速公路 |
| LayerNorm | `(x-均值)/标准差 × γ + β` | 数值稳定、训练快 | 算标准分 |
| 前馈网络 FFN | `W2·ReLU(W1·x+b1)+b2` | 每词独立加工 | 开会后的总结 |

- 标准"子层包装"模式：**子层 → 残差加法 → LayerNorm**；
- 数学视角：残差 = 恒等映射 + 小扰动；LayerNorm = 数据标准化；FFN = 非线性变换（万能近似）；
- 定稿图 `transformer_structure_full.png`：上半整体结构 + 下半 Encoder 单层内部解剖图，右侧附"每个组件的作用"速查表。

## 第八部分 · 预训练 vs 微调 vs LoRA（Day 5）

### 8.1 三个概念

- **预训练（Pre-training）**：在海量通用文本上训练，学语言一般规律 → 得到"通用底座"（Qwen / GPT / Llama 都是）。概率语言：学先验分布 `P(下一个词 | 上文)`。
- **微调（Fine-tuning）**：在底座上继续训练，专攻你的任务。概率语言：把先验分布往任务方向"拉一拉"。
- **LoRA（Low-Rank Adaptation，低秩适配）**：冻结底座权重 W0，只训练低秩增量 B·A（ΔW ≈ B·A），参数从 d² 降到 2dr。

### 8.2 LoRA 的数学本质（亲手验证过的数字）

- **微调的改动量 ΔW = Wf - W0 是低秩的**：demo 里 8×3 的 ΔW 奇异值 `[2.45, 2.00, 1.41]`，秩最多 3；
- **LoRA 用 B·A 近似 ΔW**：B 是 d×r、A 是 r×d，r << d；
- **demo 的 r=1/2/3 对比**：r 越小越"温和"（保留旧知识多、学新任务少），r 越大越接近完整微调（新任务学好、忘得也多）；
- **真实大矩阵模拟**：512×512 的 ΔW，前 16 个奇异值大、之后全为 0，用 r=16 近似误差仅 1.63e-15 → 几乎无损；
- **完整微调会"灾难性遗忘"**：任务 A 误差从 0 涨到 3.93（把旧任务冲掉了）→ 这就是 LoRA 的价值：只调增量，不动底座。

### 8.3 参数账（为什么 LoRA 省显存）

| 指标 | 全量微调 | LoRA（r=8） |
|---|---|---|
| 单个 d×d 矩阵 | d² = 12,845,056 | 2dr = 57,344 |
| 节省比例 | —— | 99.55% |
| Qwen2.5-7B 全模型（q/k/v/o，28 层） | 76.1 亿 | 642 万（0.084%） |

- 公式：节省比例 = `1 - 2r/d`；
- 训练一个参数要存"参数 + 梯度 + 优化器状态"约 3 份 → LoRA 训练量小 3 个数量级，6G 显存才跑得动；
- 面试常说的"LoRA 只训练不到 1% 的参数" = 0.084%。
