## ① 一句话总结（面试版，背下来）

> **预训练 = 在海量通用数据上学出"语言先验"的通用底座；微调 = 在底座上继续训练，把通用能力定向到我的任务；LoRA = 冻结底座权重，只训练一个低秩增量 B·A（r 很小），用不到 1% 的参数完成微调，省显存还保留底座知识。**

## ② 结构图三件套（今天新增，配定稿图截图）

| 组件 | 公式 | 作用 | 一句话 |
|---|---|---|---|
| 残差连接 | `x + 子层(x)` | 防梯度消失、保底不更差 | 高速公路 |
| LayerNorm | `(x-均值)/标准差 × γ + β` | 数值稳定、训练快 | 算标准分 |
| 前馈网络 FFN | `W2·ReLU(W1·x+b1)+b2` | 每词独立加工 | 开会后的总结 |

- 标准"子层包装"模式：**子层 → 残差加法 → LayerNorm**；
- 数学视角：残差 = 恒等映射 + 小扰动；LayerNorm = 数据标准化；FFN = 非线性变换（万能近似）。

## ③ 预训练 / 微调 / LoRA（今天新增重点）

### 3.1 三个概念

- **预训练（Pre-training）**：在海量通用文本上训练，学语言一般规律 → 得到"通用底座"（Qwen / GPT / Llama 都是）。概率语言：学先验分布 `P(下一个词 | 上文)`。
- **微调（Fine-tuning）**：在底座上继续训练，专攻你的任务。概率语言：把先验分布往任务方向"拉一拉"。
- **LoRA（Low-Rank Adaptation）**：冻结底座权重 W0，只训练低秩增量 B·A（ΔW ≈ B·A），参数从 d² 降到 2dr。

### 3.2 LoRA 的数学本质（亲手验证过的）

- **微调的改动量 ΔW = Wf - W0 是低秩的**：奇异值只有少数几个大的（demo 里 8×3 的 ΔW 奇异值 `[2.45, 2.00, 1.41]`，秩最多 3）；
- **LoRA 用 B·A 近似 ΔW**：B 是 d×r、A 是 r×d，r << d；
- **demo 的 r=1/2/3 对比**：r 越小越"温和"（保留旧知识多、学新任务少），r 越大越接近完整微调（新任务学好、忘得也多）；
- **真实大矩阵模拟**：512×512 的 ΔW，前 16 个奇异值大、之后全为 0，用 r=16 近似误差仅 1.63e-15 → 几乎无损；
- **完整微调会"灾难性遗忘"**：任务 A 误差从 0 涨到 3.93（把旧任务冲掉了）。

### 3.3 参数账（为什么 LoRA 省显存）

| 指标 | 全量微调 | LoRA（r=8） |
|---|---|---|
| 单个 d×d 矩阵 | d² = 12,845,056 | 2dr = 57,344 |
| 节省比例 | —— | 99.55% |
| Qwen2.5-7B 全模型（q/k/v/o，28 层） | 76.1 亿 | 642 万（0.084%） |

- 公式：节省比例 = `1 - 2r/d`；
- 训练一个参数要存"参数 + 梯度 + 优化器状态"约 3 份 → LoRA 训练量小 3 个数量级，6G 显存才跑得动。

## ④ Qwen 部署硬件方案（今天确认，第 2 周照做）

- **6G 显存首选：Qwen2.5-3B-Instruct + 4bit（NF4）**：权重 1.54GB + 开销 ≈ 3.0GB，舒适运行；
- **次选：Qwen2.5-1.5B + fp16**（≈4.3GB）；
- **7B 4bit ≈ 5.6GB**：8G 显卡可行（周计划成立），6G 勉强、需 CPU 卸载，不推荐第一步就上；
- 量化（Quantization）= 把参数从 16/32 位压到 4/8 位省显存；bitsandbytes 是实现 4bit 的库，NF4 是其推荐的量化格式；
- 第 2 周用 `torch.cuda.memory_allocated()` 实测显存，和测算表对上。
